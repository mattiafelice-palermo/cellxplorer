## Goal

Make the backend Excel capability from 039.1–039.2 a normal **user-visible Neware source format**
through every existing CellXplorer import and source-lifecycle path.

At the end of this child, users must be able to select, inspect, preview and import a supported
Neware `.xlsx` export in the same Inbox workflow used for `.nda/.ndax`. The registered source must
then participate in the same online/offline/changed checks, cache preparation, source replacement,
continuation ordering and recovery behavior.

This child is deliberately about **format exposure and lifecycle integration**, not new scientific
logic. It must preserve the current bounded import-performance architecture introduced by the
recent import optimization work.

## Current verified import architecture

### Bounded inspection — `backend/app/services/import_inspection.py`

The current import path deliberately separates expensive filesystem/parser work from DB writes.
Important anchors:

- `FileInspection`;
- `_HEADER_CACHE_LIMIT = 1024`;
- `remember_header_metadata` / `cached_header_metadata` keyed by `(hash, size, mtime_ns)`;
- `inspect_file`;
- `inspect_files`;
- `INSPECTION_PROCESS_THRESHOLD = 25`;
- bounded worker count `min(4, ...)`;
- one-file sampling before optional multiprocessing;
- source size/mtime re-check after hash/metadata read;
- immutable DB identity snapshot and matching.

Current `inspect_file` rejects anything outside `.nda/.ndax` and calls the shared:

```python
parsing.compute_hash(path)
parsing.read_header_metadata(path)
```

039.3 must extend this seam; it must not bypass it for Excel.

### Import router — `backend/app/routers/files.py`

Important anchors:

- `import_filename_allowed` currently allows `.nda/.ndax`;
- `_inspect_import_path` consumes an `import_inspection.FileInspection`;
- `_metadata_preview` exposes curated normalized fields;
- `cell_metadata_from_header` explicitly stores only curated Cell-level metadata;
- the complete source header is deliberately **not** expanded into `CellMetadata`;
- staged upload/direct path/folder browsing/preview/raw-data/registration paths;
- native Windows file/folder picker paths;
- background scientific preparation after registration.

The comment in `cell_metadata_from_header` documents a critical performance invariant: expanding a
full source header into Cell metadata previously created roughly 977 extra rows per Cell and made a
1,000-file import appear frozen. Excel support must not regress that architecture.

### Background scanner — `backend/app/services/scanner.py`

Current module contract says it scans `.nda/.ndax` and preserves hash identity/relinking.

Relevant lifecycle invariants include:

- source signature = `(size, mtime_ns)`;
- `_require_signature` detects a changing source during reads;
- current-version raw/cycle cache checks;
- background/copy-preparation behavior;
- existing SourceFile update/replacement logic;
- old cache removal only after successful replacement/adoption.

### Persistent scientific hierarchy

Current `AGENTS.md` locks the user-facing hierarchy as:

```text
Cell → ordered SourceFiles
```

with exactly one internal compatibility `Test` row per Cell.

039.3 must not reintroduce a user-visible/multi-Test model. A Neware Excel source is just another
`SourceFile` in the same Cell chain.

## Locked extension contract

Final supported import extensions after this child:

```text
.nda
.ndax
.xlsx   # only if workbook structure is recognized as Neware
```

Still unsupported:

```text
.xls
.xlsm
.csv
arbitrary .xlsx
```

The extension lets a file enter inspection. The parser structure check decides whether the `.xlsx`
is actually a supported Neware export.

## Centralize supported source extensions

Avoid maintaining several independent literal sets that can drift.

Introduce or reuse one canonical backend constant/function at the parser/import boundary, for
example:

```python
SUPPORTED_NEWARE_SOURCE_EXTENSIONS = frozenset({".nda", ".ndax", ".xlsx"})


def source_filename_allowed(filename: str) -> bool:
    return Path(filename or "").suffix.lower() in SUPPORTED_NEWARE_SOURCE_EXTENSIONS
```

The exact owner may be `parsing.py` or another small existing source-format policy owner after code
review. Requirements:

- `files.py`, `import_inspection.py` and `scanner.py` use the same canonical set/predicate;
- frontend display text may duplicate human-readable strings but must not become the backend source
  of truth;
- retain `import_filename_allowed` as a compatibility wrapper if current tests/callers rely on it;
- do not create an unnecessary generic cycler-adapter framework.

## `import_inspection` integration

### Extension acceptance

Update `inspect_file` so `.xlsx` enters the exact same bounded inspection sequence:

```text
stat
→ extension check
→ sha256
→ parsing.read_header_metadata
→ restat
→ reject if size/mtime changed
→ remember header metadata in parent process cache
→ return immutable FileInspection
```

No Excel special case may open the full `record` sheet during metadata inspection.

### Large batch behavior

Preserve exactly:

- one sampled source first;
- serial inspection for small batches;
- bounded process pool only above the current threshold;
- worker count cap;
- order restoration;
- parent-process header cache population;
- truthful phase/progress estimates.

Do not introduce an inner workbook process/thread pool. The outer import strategy already controls
parallelism.

### Failure behavior

An unrelated `.xlsx` should fail inspection with a concise message derived from the Excel parser,
for example:

```text
Not a recognized Neware Excel export: required record sheet is missing.
```

It must not become a successful inspection with empty metadata followed by an apparently valid Cell.

A workbook whose **optional** metadata is incomplete may still inspect successfully if its required
raw structure remains valid, consistent with 039.1/039.2 capability rules.

### Inspection metadata cache

Continue caching the normalized header result under:

```text
(hash, size, mtime_ns)
```

Do not cache open workbook handles or worksheet objects.

## Import router integration

### File-name policy

`import_filename_allowed` must accept `.xlsx` through the shared extension policy.

Update all backend error text that currently states only `.nda/.ndax` are supported.

Preferred wording:

### Full header storage

On registration:

- preserve the complete flattened source header in `SourceFile.header_meta` exactly once per source;
- preserve the current curated `CellMetadata` path;
- do not expand `Excel.Original.*` leaves into thousands of Cell metadata rows;
- do not add one DB record per point/cycle/step.

### Source file persistence

Persist normal source fields:

```text

filename
size
ext = "xlsx"
hash
metadata identity fields
parser version
parse status/counts/capacity summaries
```

No schema migration is required.

### Exact duplicate / possible update matching

Preserve current matching policy:

- hash identity is exact duplicate;
- soft identity uses filename plus metadata combinations/thresholds;
- do not weaken matching because Excel may expose fewer barcode/channel values;
- do not match on filename alone.

When Excel metadata lacks optional identity fields, fewer soft matches are preferable to false
source-update matches.

## Source checking and conservative updates

Verify `.xlsx` through the current SourceFile lifecycle.

### Unchanged source

When path exists and hash/size match:

```text
location_status = online
```

and no reparse is required merely because the extension is Excel.

### Offline source

Missing workbook follows normal offline handling.

### Changed source

When workbook bytes change at the same path:

- detect changed size/mtime/hash through current policy;
- do not adopt while the file is still changing;
- parse the replacement through the shared Excel parser;
- validate it before making new scientific cache/current source state durable;
- update parser/cycle counts/capacity summaries through normal paths;
- invalidate only dependent analyses/artifacts under current source lifecycle;
- remove old checksum cache only according to existing successful replacement rules.

Do not add workbook-specific sleep/retry heuristics unless current source-monitor logic already
requires them.

### Replacement failure

If a previously valid `.xlsx` is replaced by corrupt/unrelated workbook bytes:

- report parse/update failure;
- do not mark invalid new bytes as successfully parsed;
- preserve the existing recoverability guarantees of the source-update subsystem;
- do not delete the last usable cache before successful adoption.

Use current source-update tests as the authority for exact relational state on failure.

## Continuation/multi-source behavior

A `.xlsx` source may participate in a Cell's ordered source chain just like `.nda/.ndax`.

Do not special-case continuation semantics by format.

039.3 must prove that mixed-format chains are accepted **only when the existing continuation
compatibility rules allow them**. The source format itself is not scientific evidence that two files
belong to one continuation.

Preserve:

- ordered `TestFile.position` compatibility storage;
- one internal Test per Cell;
- source boundary/provenance;
- final-source tracked-tail policy;
- explicit continuation compatibility/acknowledgement rules.

Do not broaden compatibility merely to make an Excel test pass.
