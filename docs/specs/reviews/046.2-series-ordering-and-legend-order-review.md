## Findings

### R1 — Medium: A pending reorder can overwrite a newly applied palette

Affected files:
- `frontend/src/features/analyses/editor/plotting/SeriesStyleModal.tsx`

**Current**

A drag reorder calls `patchBaseStyle({ series_order: ... })`. `patchBaseStyle(...)` builds a complete `PlotStyle` snapshot from the modal's current `draftBaseStyle`, and `commitBaseStyle(...)` stores that full snapshot in `pendingBase` for a 250 ms debounced commit. When the timer fires, it runs `Object.assign(next, toApply)` against the then-current parent style.

The Palettes tab remains open during drag by locked design, and `applyScratchPalette()` calls `onApplyPalette(...)` immediately without first flushing or reconciling `pendingBase`.

Therefore this valid sequence can lose the palette change:

1. Palettes is open.
2. Reorder a series; a full pre-palette `PlotStyle` snapshot is now pending.
3. Click **Apply palette** before the 250 ms timer fires.
4. The parent applies the new palette.
5. The pending full snapshot then commits and overwrites the palette fields with their stale pre-Apply values while adding `series_order`.

The pure `applyPaletteToStyle(...)` test only proves that palette application preserves an order that is already in the same style object; it does not cover this modal debounce race. This violates 046.2's explicit requirement that changing `series_order` must not rewrite palette/custom-colour state.

**Target**

A series-order update and Palette Apply must compose regardless of timing. Persisting `series_order` must not write stale unrelated `PlotStyle` fields over a later palette/style change.

**Acceptance criteria**

- Reorder followed immediately by **Apply palette** preserves both the new order and the newly applied palette.
- Palette Apply followed by an order commit likewise leaves palette/custom-colour state intact.
- The fix does not make drag reorder switch away from Palettes.
- Existing debounced All-series/base-style editing remains correct.
- Add focused regression coverage for the state-composition policy if the fix extracts a pure helper; otherwise document the exact code path inspected and retain the final browser matrix item for this interaction.
