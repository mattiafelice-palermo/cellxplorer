## Findings

### R1 — Medium: Registered Excel Rate Capability regression does not verify extracted capacities

Affected files:
- `tests/test_neware_excel.py`
- `docs/specs/039.4-neware-excel-analysis-regression-and-closure.md` (implementation/acceptance record after the fix)

**Current**

The generated registered Excel rate fixture deliberately writes charge capacities `10.2`, `10.5`, and `11.0` mAh for the `0.2C`, `0.5C`, and `1.0C` charge steps. The end-to-end test then calls the real `rate_capability.compute()` path, but asserts only the three recognized rates, `status == "matched"`, `point_count == 3`, the missing discharge family and provenance. It never inspects the returned rate points’ `capacity_mah` values.

The generic Rate Capability tests independently prove the canonical extractor’s CC-only rule, but 039.4 explicitly requires the Excel integration fixture to prove both that CC-only extraction uses the Excel-derived raw counters correctly and that the resulting rate-condition capacities match known fixture values. The current Excel test would still pass if those three capacities were positive but numerically wrong.

**Target**

Keep production Rate Capability logic unchanged unless the new assertion exposes a real defect. Strengthen the registered/cache-backed Excel regression so the final result proves that each detected charge-rate point carries the expected capacity from the generated workbook.

**Acceptance criteria**

- The Excel Rate Capability integration test asserts the three returned charge points correspond to `0.2C`, `0.5C`, and `1.0C` and have capacities `10.2`, `10.5`, and `11.0` mAh respectively, using an appropriately strict floating-point tolerance.
- The assertion is made on the output of the existing registered/cache-backed `rate_capability.compute()` path, not by re-reading the fixture directly or introducing an Excel-specific calculation.
- Existing operational-cutoff/pairing behavior remains unchanged and the test continues to prove provenance/source identity.
- The 039.4 implementation record/checklist is updated to reflect this completed numeric verification.
- The implementer reruns the focused Excel + Rate Capability tests and the child-required final verification appropriate for this follow-up, recording exact results truthfully.
