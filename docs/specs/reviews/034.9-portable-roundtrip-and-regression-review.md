## Assessment

New portable reports now serialize a Cell-level ordered `sources` chain, omit Test envelopes, keep
original-file download order, and import a new Cell with exactly one internal Test row. The closure
is not complete, however: the advertised 17-case regression corpus is predominantly declarative
metadata rather than executable evidence, and the untrusted portable chain parser silently
normalizes malformed source positions, duplicate source IDs, and arbitrary multiple legacy Test
envelopes.

The assessment above describes the pre-implementation review state. The final implementation and
integrated verification are recorded below.

- Valid multi-source round-trip recreates one internal Test row and the original hash order.
- Internal Test names are not exported as portable scientific structure.

## Follow-up tasks

### R1 — High: the 17-case closure corpus is not 17 executable regressions

**Affected files**

- `tests/fixtures/multi_source_continuation_corpus.json`
- `tests/test_multi_source_regression.py`
- `tests/test_portable_analysis.py`
- relevant focused tests from Specs 034.1–034.8
- parent/034.9 implementation and closure records

**Current**

The JSON fixture lists 17 case IDs, but `test_multi_source_regression.py` primarily asserts that the
17 labels exist and exercises one reversed-order stitch. `test_portable_analysis.py` adds one valid
portable round-trip. Listing a case in JSON is not automated evidence that the behavior works.

The closure record therefore overstates coverage for cases including:

- missing local labels;
- incomplete boundary cycles;
- timestamp gaps and overlaps;
- changed device/channel/protocol;
- duplicate hash and already-linked source rejection;
- missing middle cache;
- tracked-tail change after reorder;
- scheduled tail-only selection;
- prevention of a second internal Test row through every supported workflow.

Some individual behaviors may be covered elsewhere, but 034.9 does not map each required corpus
case to an executable assertion, and the closure record does not identify that evidence.

**Target**

Turn the corpus into executable, reusable test cases or provide an explicit case-to-test matrix that
points to existing focused assertions. Every one of the 17 required scenarios must have a test that
constructs the condition and verifies the scientific/lifecycle outcome; an ID-presence assertion is
not sufficient.

Prefer small synthetic frame/source builders shared by focused tests. Do not create a monolithic
end-to-end test or add private Neware files.

**Acceptance criteria**

- Every corpus ID maps to at least one named executable test.
- Each test creates the condition rather than merely checking fixture text.
- Duplicate/already-linked cases verify zero partial relational writes.
- Missing-middle-cache cases verify no compacted partial scientific series.
- Reorder cases verify global cycles, cache/provenance invalidation, and tracked-tail change.
- Monitoring cases verify scheduled tail-only versus manual all-source scope.
- The one-row cases verify import, attach, reorder, detach, and portable round-trip cannot create a
  second internal Test row.
- The parent/034.9 closure record includes the case-to-test matrix and exact command results.

### R2 — High: portable import silently normalizes malformed or multiple-chain input

**Affected files**

- `backend/app/services/portable_analysis.py`
- `tests/test_portable_analysis.py`
- `docs/portable-analysis-html.md`

**Current**

`_portable_source_ids` treats the portable report as follows:

- new `sources` entries are filtered and sorted using `int(position or 0)`;
- duplicate/missing/non-dense positions are not rejected;
- duplicate source IDs are not rejected at chain parsing time;
- the old `tests` envelope fallback concatenates every envelope into one chain.

Portable HTML is explicitly untrusted. The current parser can therefore silently reinterpret a
malformed package or a package containing several Test envelopes as one valid Cell source chain.
It may also defer duplicate failures to database constraints, producing an unclear error instead of
a deterministic atomic validation response.

Backward compatibility with the old portable format is still valid, but that historical format
represented the same single internal container. It should accept exactly one legacy envelope, not
flatten arbitrary multiple envelopes.

**Target**

Add one strict Cell-chain decoder used by inspection and import.

For the current `sources` shape, require:

- a non-empty list;
- every entry is an object with a known `source_id`;
- unique source IDs;
- integer positions forming exactly `1..N` with no gaps or duplicates;
- either no `tracked_tail` fields or exactly one true value on position `N`.

For the legacy Test-envelope shape, require exactly one envelope with a non-empty, unique ordered
`source_ids` list. Reject zero or multiple envelopes with a clear unsupported/malformed portable
structure error; do not flatten them.

Perform all structure validation before resolving/reusing sources or writing database rows.
Inspection and import must report the same deterministic error.

**Acceptance criteria**

- Valid current and valid one-envelope legacy reports remain importable.
- Duplicate position, missing position, non-integer position, duplicate source ID, wrong tail flag,
  unknown source reference, and multiple legacy envelopes each fail with structured 400/422 detail.
- No Cell, Test, TestFile, SourceFile, or Analysis row is partially written after any failure.
- Inspection and import agree on validity and source order.
- New exports continue to emit only the Cell-level `sources` shape.
