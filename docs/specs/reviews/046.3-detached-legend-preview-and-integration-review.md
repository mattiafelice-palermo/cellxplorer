## Findings

### R1 — Medium: `legendonly` systematically fades every detached legend entry

Affected files:
- `frontend/src/features/analyses/editor/plotting/legendPreview.ts`
- `frontend/tests/legendPreview.test.ts`

**Current**

`buildLegendPreview(...)` converts every surviving user-facing trace to:

```ts
legendTrace.visible = "legendonly";
```

The CellXplorer frontend declares Plotly.js `^2.35.3`. In Plotly.js `v2.35.3`, `src/components/legend/draw.js` explicitly sets legend-group opacity to `0.5` whenever `trace.visible === "legendonly"`.

That means the detached preview does not show the effective line/marker presentation at its real visual strength: every legend symbol/text is muted by Plotly's hidden-trace treatment, on top of any series opacity already copied from the source trace. This contradicts 046.3's requirement for a faithful legend preview of effective colours/styles.

The current pure test asserts only that `visible === "legendonly"`; it therefore pins the cause rather than the required visual semantics.

**Target**

Suppress scientific drawing without putting every legend entry into Plotly's hidden/disabled `legendonly` visual state.

**Acceptance criteria**

- Normal detached legend entries render with their effective line/marker/opacity presentation, not Plotly's automatic 0.5 `legendonly` fade.
- The detached plot still retains no scientific x/y/customdata arrays and does not draw the real scientific curves.
- User-facing names, line/marker/mode/opacity/group/rank metadata remain preserved.
- Add/update focused transformation coverage so the helper no longer relies on `visible: "legendonly"` as the mechanism for suppressing scientific drawing.

### R2 — Medium: Large detached legends are clipped with no usable scrollbar in the bundled Plotly version

Affected files:
- `frontend/src/features/analyses/editor/plotting/SeriesStyleModal.tsx`
- `frontend/src/features/analyses/editor/plotting/legendPreview.ts`
- `frontend/tests/legendPreview.test.ts`

**Current**

The detached Plotly instance uses:

```ts
staticPlot: true
```

and `buildLegendPreview(...)` tries to bound overflow with:

```ts
legend.maxheight = LEGEND_PREVIEW_MAX_HEIGHT - 24;
```

Two runtime facts matter for the Plotly version CellXplorer declares (`2.35.3`):

1. `v2.35.3/src/components/legend/attributes.js` has no `maxheight` legend attribute, so that property is unsupported/ignored.
2. `v2.35.3/src/components/legend/draw.js` explicitly enters the non-scrollbar branch whenever `gd._context.staticPlot` is true, even when the legend content exceeds the effective height.

The surface itself remains bounded, but once enough entries exceed the available height the extra legend items are clipped and the user cannot scroll to them. The implementation comment that Plotly `maxheight` handles overflow is not true for the bundled runtime.

**Target**

Keep the detached legend passive and bounded while allowing every legend entry to remain reachable in the Plotly 2.35.3 runtime. Do not depend on an unsupported legend attribute.

**Acceptance criteria**

- A large vertical/multi-row legend stays within the bounded detached surface and all entries remain reachable through local legend scrolling or another bounded mechanism.
- Legend item/double-click actions still cannot change analysis state, selection, preview visibility, or legend membership.
- The solution works with the repository's current Plotly 2.35.3 dependency; remove reliance on unsupported `legend.maxheight` unless the dependency is deliberately upgraded as an explicit scoped decision.
- Add focused policy/config coverage where practical, and retain the final browser matrix check for many/long entries.
