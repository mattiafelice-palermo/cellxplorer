## Architectural decision handed to 050.14

050.13 selects the following direction for productionization:

1. request-local owner Cell/source/scalar resolution reused across miss-request work;
2. one shared authoritative scientific/source fingerprint deriving the existing scientific and render cache keys;
3. request-local validated stitch-plan reuse with the real read-time freshness/publication check retained;
4. persistent bounded Python processes for eligible broad ordinary Time/Capacity requests, with four workers preferred only when host CPU/memory evidence supports them and serial/smaller fallback otherwise;
5. compact Time/Consecutive response slimming (`display_x` canonical; avoid redundant `time_s`; skip expensive phase classification where the consumer contract permits it);
6. adaptive display-point density based on viewport and visible Cell count while preserving full export and mandatory extrema/source boundaries;
7. retain direct persisted result-cache hit bypass;
8. do not productionize Rust, rejected sort/filter/mapping/gather micro-optimizations, write-behind cache complexity or a new serializer dependency unless post-integration profiling creates new evidence.
