## Review-process observations

Three findings across five children, plus one follow-up caused by a **reviewer** error:

- **040.1 R1** — the knowledge doc claimed validation ran in `parse_timeseries` when it ran in
  `cache.build`. Stale text from a moved implementation, in the section written for the Parent 041
  adapter author.
- **040.2 follow-up** — the reviewer accepted "`InvalidSourceFormatError` is unused, so skip it."
  Valid with one adapter family, wrong with three. Surfaced by a user question, not by review.
- **040.4 R1** — the two-electrode "no new controls" guarantee rested on one inline expression with
  no test and no manual check.

The recurring pattern is worth carrying into Parent 041: **the defects were never in the numbers.**
They were in documentation that contradicted code, and in guarantees asserted by inspection rather
than protected by something executable. The scientific output was correct at every single stage.

A process rule also emerged and held: after 040.3, "stop and report before refreshing a golden"
became a hard rule, and 040.4 complied. Refreshing a golden and regressing look identical in a
passing test run; only an out-of-band baseline distinguishes them. Parent 041 should keep that rule
and keep an independent baseline.
