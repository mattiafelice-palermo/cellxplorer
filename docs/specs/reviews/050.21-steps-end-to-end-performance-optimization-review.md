## Review summary

050.21 is review-clean. The implementation removes repeated Steps block/group work and request-local duplicate protocol reconstruction while preserving the established Steps scientific path.

`step_blocks.per_block()` still delegates CV classification to `calc._cv_charge_by_cycle()`. The retained `_aggregate_block_rows()` path consumes the already normalized/record-ordered block frame once, derives compact monotonic block ranges, converts the required numeric/timestamp columns once, and reproduces the previous reductions: per-step `max(time_s)` for phase duration, per-step finite `(max - min)` capacity deltas clipped at zero, block timestamp min/max, phase/overall voltage means, programmed-step bounds/counts, occurrence and cycle bounds. The existing charge/discharge/rest status masks are unchanged.

`analysis_engine.compute_steps()` also adds request-local protocol reconstruction reuse keyed by effective parser identity, nominal capacity and exact header metadata. This key covers the inputs/identity boundary relevant to reconstruction, stays local to one compute request, and does not affect exact persisted-result hits.

The implementer reports a final six-Cell forced-miss p50 of **132.69 ms** versus a current-head baseline of **203.69 ms** and the locked 050.17 baseline of **193.85 ms**. That is a **34.9% reduction** versus current head and **31.5%** versus the locked baseline, exceeding the 174.5 ms acceptance target. `step_block_extraction` falls from 69.24 ms to 40.53 ms; protocol reconstruction falls from six calls to one at 9.68 ms. The one-Cell miss remains effectively flat at 38.21 ms versus 38.00 ms baseline, and the six-Cell exact persisted hit improves from 15.57 ms to 13.61 ms.

The final route does not justify process concurrency inside this child under the locked gate. The remaining work is split across data access/stitching and a ~40.5 ms block extraction boundary; there is no demonstrated >=100 ms independent CPU block after serial/vectorized cleanup. Cross-family large-Cell concurrency is now separately scheduled under 050.23.
