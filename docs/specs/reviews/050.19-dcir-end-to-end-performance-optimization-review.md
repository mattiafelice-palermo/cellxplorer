**Current**

The residual-attribution round retains two production optimizations plus many `_dcir_profile_span()` context-manager boundaries inside `compute_dcir()`. The evidence demonstrates local child reductions, especially protocol-cache bookkeeping, but does not demonstrate a complete-route improvement from this tranche.

The immediately preceding five-repetition R1 checkpoint was **139.27 ms p50 profiled / 138.67 ms unprofiled median** for six Cells. The current five-repetition checkpoint is **172.15 ms p50 profiled / 165.81 ms unprofiled median**. The current spec calls the route noisy and explicitly does not claim a speedup, but the child contract requires retained optimization tranches to earn their place at complete-route level.

Additionally, `_dcir_profile_span()` is implemented as a generator-based context manager around many production-path boundaries. When `profiling is None` it skips timing state, but the context manager is still created, entered and exited; therefore the instrumentation is not structurally zero-overhead on normal DCIR misses.

**Target**

Close the review round with controlled complete-route evidence for the newly retained production changes. Either:

1. demonstrate with a paired/controlled benchmark that the current head is route-neutral or faster than the pre-residual-attribution R1 checkpoint under equivalent conditions; or
2. remove/rework changes that do not earn a route-level benefit, especially normal-path profiling scaffolding, while preserving the already captured diagnostic evidence and R1 source-reuse implementation.

Do not reopen DCIR scientific formulas, persistent caching, concurrency, schema/versioning, source ownership or Time/Capacity.
