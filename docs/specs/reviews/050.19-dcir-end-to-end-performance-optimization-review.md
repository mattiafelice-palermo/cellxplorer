## Findings

### R1 — Medium: the per-Cell context still rebuilds identical source-frame/run state once per DCIR series

Affected files:

- `backend/app/services/analysis_engine.py`
- `backend/app/services/dcir.py`
- `scripts/profile_analysis_families.py`
- `tests/test_dcir.py`
- `tests/test_profile_analysis_families.py`
- `docs/specs/050.19-dcir-end-to-end-performance-optimization.md`

**Current**

050.19 successfully moves source/protocol/raw ownership to a request-local per-Cell context, but the reusable boundary stops before the derived per-source occurrence representation.

Inside the configured-series loop, each series still performs:

```python
source_raw = raw.loc[raw["segment"] == source_index].copy()
occurrences = dcir.per_occurrence(source_raw, ...)
```

`per_occurrence()` then reconverts the same source columns to NumPy arrays and rebuilds the same step/cycle/time/record-index run boundaries for that series. On the final six-Cell benchmark, the durable evidence records **12 `dcir_occurrence_extraction` calls** for six Cells because the fixture has two configured series per Cell. The same evidence records **8.84 ms** frame normalization and **5.01 ms** run-boundary construction, a combined **13.85 ms / ~10.5% of route** before considering the repeated source-frame slicing/copy itself. The final scientific-compute root also retains a **34.67 ms direct residual**.

This is precisely the kind of repeated multi-series work sections 7–9 and 13 require the child to continue through after the dominant groupby churn is removed. The route being far below the minimum latency target does not waive the whole-family stop condition.

**Target**

Extend the request-local DCIR Cell/source context far enough that immutable source-frame preparation is performed once per distinct source frame, not once per configured series. A suitable shape would be a compact per-source occurrence/run index containing the normalized arrays and run boundaries/statistics that are independent of the selected DCIR target, with each series evaluating only its target-specific adjacent run pairs.

Do not change scientific formulas, source ownership, ordering, provenance, persistent cache identity, or the exact-hit path. If a proposed sharing boundary is experimentally slower or meaningfully complicates correctness, retain the current code only with controlled complete-route evidence demonstrating that outcome.

**Acceptance criteria**

- For a multi-series Cell, source-frame slicing/copy and normalized run-boundary preparation scale with distinct source frames rather than `(source frame × DCIR series)`.
- Add a focused multi-series regression proving both configured series retain exactly the same results/order/IDs/provenance as the current scientific contract.
- Preserve selective-read vs full-raw fallback parity.
- Re-profile the six-Cell forced-miss route after the change and record the complete-route delta plus updated DCIR substage distribution.
- The final profile must account for the previously material scientific-compute direct residual sufficiently to show whether another repeated series-local boundary remains.
- Re-assess the still-material selective raw/stitch boundary (`36.14 ms` raw materialization; `45.91 ms` inclusive stitch in the current evidence) and either retain it with a concrete measured/architectural reason or pursue a safe route-level improvement if one is available.
- Preserve exact-hit bypass, scientific digest/order parity, SQL boundedness, and no original-source reads.
