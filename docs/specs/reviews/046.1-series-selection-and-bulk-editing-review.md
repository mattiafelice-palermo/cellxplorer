### R5 — Medium: Bulk-colour gating disagrees with the resolver for orphan secondary series

Affected files:
- `frontend/src/features/analyses/editor/plotting/seriesStyling.ts`
- `frontend/tests/seriesStyling.test.ts`

**Current**

`linkedSecondarySeriesKeys(...)` classifies every selected secondary with `link_color === true` (or the plot-wide link default true) as linked. It does not check whether that secondary's primary descriptor actually exists.

The established resolver has a different, deliberate contract: `resolveAllSeriesStyles(...)` looks up `primarySeriesKeyFor(descriptor)` and only links when that primary is present in the resolved descriptor map. If the primary is absent, the secondary is left with its independently resolved colour. Existing tests already pin both the missing-primary resolver behavior and orphan-secondary palette-slot behavior.

Therefore an orphan secondary with linking enabled is currently disabled in the bulk Colour editor even though a colour override would actually take effect. The new policy does not match the effective presentation semantics it is supposed to guard.

**Target**

`linkedSecondarySeriesKeys(...)` must report only secondary series whose colour will actually be replaced by a present linked primary under `resolveAllSeriesStyles(...)`.

**Acceptance criteria**

- If the selected secondary has a present primary descriptor and effective linking is on, it is reported as linked.
- If the selected secondary's primary descriptor is absent, it is not reported as linked even when the plot-wide/default link flag is true.
- Per-series `link_color` overrides continue to beat the plot-wide default.
- Add a focused regression test for the orphan-secondary case.
- Existing missing-primary resolver behavior remains unchanged.

## Decision

**CHANGES REQUIRED — fix R5 only; do not begin 046.2.**
