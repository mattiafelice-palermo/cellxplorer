## Findings

### R1 — Medium: Row keyboard handler intercepts checkbox and preview-eye activation

Affected files:
- `frontend/src/features/analyses/editor/plotting/SeriesStyleModal.tsx`

**Current**

Each concrete row is a focusable `role="button"` whose `onKeyDown` handles Enter/Space and calls `selectConcreteKeys([descriptor.key], ...)`. The row contains its own interactive selection `Checkbox` and preview `ActionIcon`, but their keyboard events are not stopped and the parent handler does not require `event.target === event.currentTarget`.

Therefore Enter/Space on a focused descendant bubbles into the row handler first. For the checkbox this can collapse an existing multi-selection to the single row before the checkbox toggle runs. For the preview eye it calls `selectConcreteKeys(...)`, which changes edit selection and sets `tab = "series"`, directly violating the locked rule that preview-eye interaction must not switch tabs or change edit selection. The parent's `preventDefault()` can also interfere with the descendant's native keyboard activation.

**Target**

Row-level keyboard selection must run only when the row itself is the keyboard target. Descendant controls must keep independent keyboard behavior.

**Acceptance criteria**

- Focusing a row itself and pressing Enter/Space selects only that row and opens Series.
- Focusing a row checkbox and pressing Space toggles that key while retaining the other selected keys; the checkbox action may open Series as specified.
- Focusing the preview eye and pressing Enter/Space toggles preview-only visibility without changing concrete selection or the active Rules/Palettes tab.
- Child controls are not prevented from performing their normal keyboard activation.

### R2 — Medium: Bulk colour silently fails for linked secondary series

Affected files:
- `frontend/src/features/analyses/editor/plotting/SeriesStyleModal.tsx`
- `frontend/src/features/analyses/editor/plotting/seriesStyling.ts`

**Current**

The bulk Colour control is enabled for every multi-selection and applies only `{ color: ... }` through `applySelectedPatch(...)`. However, `resolveAllSeriesStyles(...)` performs secondary linking after base/rules/explicit override resolution: when a secondary series has effective colour linking enabled, its resolved colour is overwritten with the primary series colour.

As a result, a selected linked secondary can accept a bulk explicit `color` override that has no visible effect. The inspector says “Changes apply to all selected series”, but that selected series remains unchanged. The single-series editor already avoids this ambiguity by disabling Colour while that series is linked.

**Target**

Bulk colour editing must be truthful when the selection contains linked secondary series. Do not allow an enabled bulk colour action to write an override that is silently ineffective.

**Acceptance criteria**

- A selection containing a linked secondary cannot silently accept a bulk colour change that leaves that selected series unchanged.
- Either the colour action visibly affects every selected series with explicit, intentional link semantics, or the UI blocks/explains the linked-secondary case consistently with the single-series editor.
- Primary/secondary linking behavior outside the bulk editor remains unchanged.
- Add focused coverage for any extracted policy/helper used to decide bulk colour applicability.

### R3 — Medium: Descriptor pruning can leave the surviving single selection unable to rename its legend

Affected files:
- `frontend/src/features/analyses/editor/plotting/SeriesStyleModal.tsx`

**Current**

When descriptors change, the pruning effect correctly reduces `selectedKeys`. But `activeKey` is only preserved if its current value is already a selected valid key; it is never set to the sole surviving key. In a multi-selection `activeKey` is `null`, so if a descriptor refresh prunes `{A, B}` to `{A}`, `selectedKeys` becomes `{A}` while `activeKey` remains `null` permanently.

The single-series editor still appears because `active` is derived from `selectedKeys`, but `commitLegendName(...)` targets `activeKey` and returns immediately when it is null. Legend-name edits are therefore silently dropped until the user reselects the row.

**Target**

After descriptor pruning, the concrete selection and the key used for single-series actions must remain coherent. A sole surviving selected series must be the target of Legend name edits without requiring an extra reselect.

**Acceptance criteria**

- Starting with two selected series, if descriptor refresh removes one, the remaining series becomes a fully functional single-series editor target.
- Editing Legend name immediately after that pruning writes the override to the surviving key.
- Invalid anchors/keys are still cleared and an empty concrete selection is not converted into All series.

### R4 — Low: Empty concrete selection reports that the plot has no series

Affected files:
- `frontend/src/features/analyses/editor/plotting/SeriesStyleModal.tsx`

**Current**

The user can legitimately reach `selectedKeys.size === 0` with existing descriptors, for example by Ctrl/Cmd-toggling the last selected row off or clearing a selected quantity. In that state `isAllSeries` is false and `active` is null, so the right panel shows “This plot has no series to style yet.” That is factually wrong: the plot still has series; none is currently selected.

**Target**

Distinguish the required “no concrete selection” state from the true “no descriptors exist” state.

**Acceptance criteria**

- With descriptors present and no concrete/Base selection active, the panel says that no series is selected and directs the user to select a series or All series.
- “No series to style” is reserved for an actually empty descriptor list.
- Empty concrete selection remains distinct from `ALL_SERIES_KEY`.
