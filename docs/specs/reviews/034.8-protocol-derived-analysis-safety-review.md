## Assessment

The central backend guard is applied before protocol-derived cache reads, recognition, compute-job
creation, saved-plot artifact/thumbnail access, and warmup. The frontend also presents a calm
unsupported state and disables most guarded actions. Two frontend contract gaps remain: portable
export silently removes guarded saved plots, and the mirrored policy can temporarily fail open when
the locally edited selection contains a Cell not present in the last persisted analysis-detail
payload.

## Confirmed correct by code reading

- `analysis_engine.protocol_analysis_guard` is the single backend support predicate.
- Steps, DCIR protocol discovery/computation, DCIR compute, Chargeability, Rate capability, and
  protocol-derived compute-job creation call the guard before scientific work.
- Guarded saved-plot artifact and thumbnail reads fail before returning stale output.
- Idle warmup does not enqueue guarded saved plots.
- The structured 422 identifies the family, affected Cells, source counts, and supported
  alternatives.
- Mixed single-/multi-source selections fail as a whole.
- Single-source Cells remain supported.
- The active plot area uses an informational warning rather than a destructive application error.

## Follow-up tasks

### R1 — High: portable export silently hides guarded saved plots

**Affected files**

- `frontend/src/pages/AnalysisPage.tsx`
- `backend/app/services/portable_analysis.py`
- portable/frontend policy tests

**Current**

The portable-report options are built by filtering `spec.saved_plots` through
`multiSourceAnalysisPolicy(...).supported`. Guarded Steps/DCIR/Chargeability/C-rate saved plots are
therefore absent from the export dialog. If the user opens portable export from Cycles or
Time/capacity, the report can be produced while silently omitting saved plots that remain part of
the analysis.

This is not fail-closed behavior: the resulting report appears complete but has lost selected saved
views without an explicit decision or warning. The backend guard does reject a guarded view when it
is supplied, but the frontend removes those views before the backend can enforce that contract.

**Target**

Do not filter saved plots invisibly.

Use one explicit behavior:

- show guarded saved plots in the portable dialog as disabled rows with the same scientific
  explanation and require the user to acknowledge that they will be omitted; or
- block portable export while guarded saved plots are selected/present and explain which plots must
  be removed or why only supported views can be exported.

The chosen behavior must make every omitted plot visible before export. The backend must continue
to reject any guarded view that reaches the export request.

**Acceptance criteria**

- A multi-source analysis containing Cycles plus saved Steps and C-rate plots never exports a report
  that silently drops the latter two.
- The dialog names every guarded saved plot and its affected Cells.
- The final request contains only views the user explicitly accepted for export.
- Direct/backend requests containing a guarded view return the structured 422.
- Tests cover export opened from both a supported active tab and a guarded active tab.

### R2 — Medium: the frontend mirror can fail open for a newly edited selection

**Affected files**

- `frontend/src/pages/AnalysisPage.tsx`
- `frontend/src/multiSourceAnalysisPolicy.ts`
- `frontend/tests/multiSourceAnalysisPolicy.test.ts`
- analysis selection/query state tests

**Current**

`selectedSourceCountCells` resolves the current local `spec.selection.entries` against
`analysis.selection_cells` and `analysis.selection_groups` from the last server detail payload.
Any selected Cell not present in those maps is ignored. During local selection editing/import,
there can be a valid current spec entry before the persisted analysis detail has refetched with that
Cell and its `source_count`.

The mirrored policy then reports the guarded family as supported and may start a request. The
backend still rejects it, but the user receives a request failure instead of the required calm
pre-query unsupported state.

**Target**

Resolve the mirrored policy from authoritative source counts for every Cell in the **current local
selection**, including newly added direct Cells and members of newly added groups. Reuse the
already-cached Cell/group data or issue one bounded query; do not guess missing counts as zero.

While any selected Cell count is unresolved, fail closed for protocol-derived families with a short
“Checking source compatibility” state rather than enabling compute/save/export.

**Acceptance criteria**

- Adding a multi-source Cell to an unsaved/local selection immediately blocks guarded families
  without first issuing their compute request.
- Newly added replicate-group members are included.
- Missing/unresolved source counts produce a pending fail-closed state, not `supported: true`.
- Removing the last multi-source Cell restores support once the current selection is resolved.
- Tests cover persisted selection, newly added direct Cell, newly added group, unresolved count, and
  removal.
