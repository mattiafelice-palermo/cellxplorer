## Route/view boundary

`frontend/src/pages/AnalysesIndexPage.tsx` is now a small route adapter. It owns only:

- `useNavigate` and `useSearchParams`;
- translation of `new=1`, `portableImport=1`, and `portableSource` into a typed route intent;
- replacement-based removal of consumed route keys;
- typed navigation callbacks for analyses/plots and Projects folders;
- rendering `AnalysesIndexView`.

It no longer owns React Query calls, mutations, Analysis Database table state, portable import state, or modal content.

`AnalysesIndexView.tsx` owns the extracted collection workflow and receives an explicit route contract rather than raw router objects. Source inspection confirms the required reactive behavior:

- a rising `openPortableImport` intent opens the portable modal;
- `new=1` is handled once, then consumed through replacement navigation;
- `portableSource` is guarded by the last handled source and can react to a distinct source while mounted;
- staged portable state reset consumes `portableImport`/`portableSource` and retains staged-token cleanup;
- successful create/import still clears/invalidate the same analysis/tree query roots and navigates to the resulting analysis;
- existing workspace open/mount/show sequencing and request-animation-frame navigation are preserved.

The additional typed `navigateToFolder` callback is an appropriate route-boundary callback for the existing table behavior; it does not leak router objects into the feature.
