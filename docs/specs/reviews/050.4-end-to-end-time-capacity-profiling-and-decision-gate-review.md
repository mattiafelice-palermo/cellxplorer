The indexed 050.3 reader is working as intended: for one Cell the profile read 3/20 groups for 1-20, 11/20 for 1-150 and 20/20 for All. The existing aggregate `continuous_time_phase_capacity` timing grew from about 53 ms to 198 ms to 418 ms across those one-Cell ranges; it reached about 1.98 s for five-Cell All and 2.62 s for six-Cell All. This makes post-read transforms, not Parquet I/O, the leading normal-view candidate.

Sixteen React Query memory-hit records had a median total interaction of about 34 ms, so exact-repeat client reuse is already fast and does not justify a speculative general RAM cache/prefetch optimization.

Derivative behavior is distinct: one-Cell dQ/dV All took about 3.62 s total, about 3.01 s backend, about 2.30 s in the derivative stage, about 388 ms Plotly, and produced 610 traces. The profile therefore supports treating derivative work as a separate diagnostic hotspot.

The capture did not include a true persisted analysis-result HTTP cache hit. Two five-Cell narrow misses also showed an unexplained ~0.8 s HTTP-minus-backend gap that did not reproduce consistently inside the same capture. These are explicit 050.5 investigation items rather than 050.4 defects.

## 050.4 decision outcome

050.4 has produced enough end-to-end evidence to reject several speculative directions and to justify one further **profiling/design** child before optimization code is selected:

- normal broad/multi-Cell misses are backend/post-read-transform dominated;
- exact React Query memory reuse is already fast;
- dQ/dV has a distinct derivative/trace-count signature;
- persisted-result HTTP-hit cost and the occasional HTTP-minus-backend gap still need controlled backend/route evidence;
- the combined `continuous_time_phase_capacity` stage needs decomposition before choosing reusable exact derived preparation versus a broad-view representation.

Those questions are now owned by active child **050.5 — backend transform profiling and optimization design**. 050.4 itself is review-clean and should not be reopened for the same profiling work.
