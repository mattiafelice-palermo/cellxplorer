## Findings

### R1 — High: incompatible frontend/backend identity comparison

Status: **Resolved in `36aa9ee`**

The original implementation compared the frontend React Query JSON identity with the backend analysis-cache digest. The fix uses only the current frontend query/profile identity for completion while preserving placeholder and supersession guards. Focused regression coverage uses deliberately distinct frontend/backend identity shapes.

### R2 — Medium: React Query memory hits inherited stale backend facts

Status: **Resolved in `36aa9ee`**

Warm client-memory hits are now classified separately as `response_source: "react_query_memory"`, carry zero HTTP time, and do not recycle backend compute/serialization/access facts from the response that originally populated the React Query cache.

### R3 — Medium: actual resolved Cell count was ambiguous

Status: **Resolved in `36aa9ee`**

`selection_count`, unique `resolved_cell_count`, and Plotly `trace_count` now have distinct meanings and fields. Focused tests cover a replicate/group-style selection count that differs from resolved Cell count and a visual trace count greater than Cell count.

### R4 — Medium: profiling repeatedly serialized the full response after its backend timer stopped

Status: **Resolved in `57cff5a`**

The profiled miss path now serializes the scientific result once through the normal fast-JSON path, appends only the small profiling object, and byte-patches `backend_serialize_ms`, `backend_total_ms`, and `response_bytes` without another scientific-body encode. `backend_total_ms` is refreshed after final-body patch preparation; the byte count is then settled without re-encoding the scientific payload. Persisted cache hits continue through the existing body-splice path. Focused route regression checks one scientific serialization on the profiled miss, zero on the persisted hit, and exact returned-body byte count.

### R5 — Medium: the required local profile is not collectable from the installed app without DevTools

Affected files:
- `frontend/src/components/DiagnosticsModal.tsx`
- `frontend/src/features/analyses/editor/performance/timeCapacityPerformanceProfile.ts` only if a minimal UI-facing helper is needed
- focused frontend tests

**Current**

The 050.4 profiler is correct and review-clean, but its only practical control/export path is the developer namespace `window.cellxplorerPerformance.timeCapacity.*`. In the normal packaged Tauri application, that makes the Parent 050 evidence gate needlessly inaccessible to the user and was the reason the workflow entered `BLOCKED`.

The user explicitly changed the accepted evidence-collection UX on 2026-08-21: profiling must be startable/stoppable from the existing Debug/Diagnostics surface and Stop must produce an immediately shareable local JSON file.

**Target**

Implement the normative amendment `docs/specs/amendments/050.4-installed-app-profiling-controls.md` as a thin UI over the existing profiler. Prefer a `Performance` tab in `DiagnosticsModal` with `Start recording` and `Stop recording`, visible status/completed-record count, persistence of recording while the modal is closed, and immediate JSON download on Stop through the existing `saveDownload` abstraction.

Do not create a new profiling subsystem, settings page, persistent telemetry store, scientific cache/version change, or optimization implementation.

**Acceptance criteria**

- `Debug -> Performance` exposes the requested Time/Capacity profiling controls in the installed app.
- Start resets the previous capture and enables the existing profiler.
- Closing/reopening Debug does not stop or reset an active capture.
- Stop disables the profiler, preserves completed records, and immediately exports the exact bounded profiler JSON to a clear timestamped local filename.
- The UI exposes recording state and completed-record count.
- Zero-record Stop/export and repeated Start/Stop cycles are deterministic and harmless.
- The developer `window.cellxplorerPerformance` helper may remain but is no longer required for the user acceptance path.
- Profiling remains local, opt-in, bounded and disabled by default; no external telemetry or persistence is introduced.
- Add focused automated coverage for the control semantics using the repository's existing lightweight frontend test patterns; do not add Playwright/Selenium merely for this change.
- Canonical `python scripts\preflight.py` passes before handoff. Browser/end-to-end timing matrix may remain `NOT RUN` in the implementer environment because the user will collect it from the installed app after this amendment is review-clean.
- No 050.5 or 050.P1 implementation is started.
