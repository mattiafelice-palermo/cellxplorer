## Findings

### R1 — High: incompatible frontend/backend identity comparison

Status: **Resolved in `36aa9ee`**

The original implementation compared the frontend React Query JSON identity with the backend analysis-cache digest. The fix uses only the current frontend query/profile identity for completion while preserving placeholder and supersession guards. Focused regression coverage uses deliberately distinct frontend/backend identity shapes.

### R2 — Medium: React Query memory hits inherited stale backend facts

Status: **Resolved in `36aa9ee`**

Warm client-memory hits are now classified separately as `response_source: "react_query_memory"`, carry zero HTTP time, and do not recycle backend compute/serialization/access facts from the response that originally populated the React Query cache.

### R3 — Medium: actual resolved Cell count was ambiguous

Status: **Resolved in `36aa9ee`**

`selection_count`, unique `resolved_cell_count`, and Plotly `trace_count` now have distinct meanings and fields. Focused tests cover a replicate/group-style selection count that differs from resolved Cell count and a visual trace count greater than Cell count.

### R4 — Medium: profiling repeatedly serialized the full response after its backend timer stopped

Status: **Resolved in `57cff5a`**

The profiled miss path now serializes the scientific result once through the normal fast-JSON path, appends only the small profiling object, and byte-patches `backend_serialize_ms`, `backend_total_ms`, and `response_bytes` without another scientific-body encode. `backend_total_ms` is refreshed after final-body patch preparation; the byte count is then settled without re-encoding the scientific payload. Persisted cache hits continue through the existing body-splice path. Focused route regression checks one scientific serialization on the profiled miss, zero on the persisted hit, and exact returned-body byte count.
