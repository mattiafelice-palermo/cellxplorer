## Final assessment

The previous R1 and R2 implementation is substantially correct:

- Cycles and Time/Capacity use one canonical ordered Cell source chain.
- New result/provenance payloads no longer expose `test_ids`.
- Library and frontend contracts no longer expose `n_tests`.
- Multiple internal Test rows fail before scientific compute and bulk staleness work.
- Boundary markers scan forward to the first finite plotted point in each later source and emit at
  most one marker per source.
- Source-local/global provenance, missing-chain fail-closed behavior, CSV/XLSX columns, cache keys,
  and tracked-tail descriptors remain source-aware.

One half of the locked exactly-one-row invariant is still inconsistent: zero internal Test rows are
rejected by direct scientific resolution but accepted or silently omitted by bulk and Library
paths.

## Follow-up task

### R3 — Medium: zero internal Test rows are not rejected consistently

**Affected files**

- `backend/app/services/analysis_engine.py`
- `backend/app/routers/library.py`
- `tests/test_analysis_staleness.py`
- `tests/test_source_and_replicates.py`

**Current**

The locked architecture requires every Cell to have exactly one internal Test compatibility row.
`require_single_internal_test` correctly rejects both zero and multiple rows when a Cell is resolved
directly.

However:

- `current_cell_hashes` starts its invariant query from `Test`, so a Cell with zero Test rows never
  appears in the grouped result and is silently absent from the returned hash map;
- `_cell_file_summaries` uses the same Test-rooted grouped check and therefore cannot identify a
  zero-row Cell;
- `_ordered_cell_source_files` explicitly returns an empty list when `cell.tests` is empty, causing
  Library detail and summary logic to present the invalid Cell as a valid zero-source Cell.

This contradicts the project rule and the original R1 acceptance criterion that **zero or two**
internal rows fail clearly before compute/cache/provenance/Library work.

**Target**

Use the canonical exactly-one invariant in every Cell source-chain consumer. Bulk checks must include
the relevant Cell rows, not only existing Test rows. A zero-Test Cell must produce the same structured
`single_internal_test_required` invariant detail as a multiple-Test Cell instead of becoming an
empty source chain.

Do not add a migration or normalization path. Normal supported writes must continue creating one row
atomically and preventing a second row.

**Acceptance criteria**

- `current_cell_hashes` rejects a Cell with zero internal rows.
- Library list summaries and Cell detail reject the same Cell rather than reporting `n_files = 0`.
- The error detail contains `code = single_internal_test_required`, the Cell identity, and
  `test_count = 0`.
- Existing tests for two rows continue to pass.
- Focused tests cover zero rows in direct resolution, bulk staleness resolution, and Library
  summary/detail resolution.
- Valid single-source and multi-source Cells retain identical ordering and scientific output.
