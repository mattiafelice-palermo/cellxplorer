## Findings

### R1 — High: compatible placeholder data can still be exported as the current plot

Affected files:
- `frontend/src/features/analyses/editor/families/time-capacity/TimeCapacityPlotCard.tsx`
- focused Time/Capacity query/export policy tests as appropriate

**Current**

050.1 intentionally keeps a previous Time/Capacity result visible while a compatible range/density request is fetching. The card correctly dims the plot while `timeResult.isFetching`, so the on-screen result is visibly provisional. However `currentResult` is also the placeholder result, `PlotHeader.canExport` remains true whenever that placeholder has traces, and `exportPlot()` serializes the currently rendered `traces` / `exportTraces` directly.

A user can therefore change a range such as cycles 1–3 → 1–20 and, during the fetch, export PNG/SVG/PDF from the retained 1–3 placeholder. The export is produced from old data while the surrounding editor/spec already represents the new request. This violates the locked rule that retained data is temporary content rather than the new result and creates a silent scientific-output risk.

The full data-export path is different: it issues a fresh full-resolution backend request and validates the request identity. The defect is specifically the plot/image/vector export path that uses the retained rendered result.

**Target**

A retained Time/Capacity placeholder must never be exportable as though it were the resolved current request. Either disable plot export/export preview while the observer is serving placeholder data, or make the export path obtain and validate a result for the current full data identity before generating the figure. Preserve valid export behavior for an actually current result; do not weaken the exact full-resolution data-export contract.

**Acceptance criteria**

- After a compatible query-key change that is currently displaying placeholder data, PNG/SVG/PDF export cannot serialize that placeholder as the new plot.
- Once the replacement result for the current `dataSignature` resolves, plot export becomes available and uses that result.
- Incompatible changes continue to expose no placeholder at all.
- Add focused regression coverage for the export-readiness policy/state so this cannot regress without a browser-only test.
- Run the focused frontend tests/type check required by the changed helper/component and canonical `python scripts\preflight.py` before handoff.
