### R7 — Medium: Value grouping still bleeds across neighboring exported labels that CellXplorer does not normalize

Affected files:
- `backend/app/services/neware_excel.py`
- `tests/test_neware_excel.py`

**Current**

The new `_find_labeled_value()` stops at the next cell only when that cell's label appears in `_VALUE_GROUP_LABELS`. This fixes bleed across **recognized** metadata labels, but the verified Neware information block contains exported label groups that CellXplorer intentionally does not normalize.

A concrete row already committed in the synthetic verified-layout fixture is:

```text
A: Voltage range | C: 4.2V | D: Curr. lower | F: - | G: - | I: -
```

`Curr. lower` is a real neighboring label but is not in `_TEST_METADATA_LABELS` / `_VALUE_GROUP_LABELS`. If `Voltage range`'s own value at C is blank, the current helper finds no later **recognized** boundary and continues scanning into D, returning `"Curr. lower"` as the `Voltage range` value.

Therefore the current implementation still does not bind a supported label to its verified value group/slot. It remains dependent on whether the following exported label happens to be one CellXplorer normalizes, which is exactly the class of ambiguity R7 was intended to remove.

**Target**

Use the verified positional grammar rather than semantic recognition of the next label. In the observed information layout the groups are approximately A/C, D/F and G/I; equivalently, each label's value belongs to its own fixed group/value position. The optional `unit` Start/End layout likewise places each value in its own bounded group. A missing value must stay missing even if the next group begins with an unsupported label.

Do not add unsupported labels to the normalized metadata map merely to make the boundary detector work.

**Acceptance criteria**

- Add a regression using the existing `Voltage range` / `Curr. lower` row: blank `Voltage range`'s own value while leaving `Curr. lower` present, and assert `voltage_range` remains absent/`None` rather than becoming `"Curr. lower"`.
- Preserve the existing Start-step/recognized-neighbor and unit Start/End no-bleed regressions.
- The production implementation binds values to the verified group/value position and does not depend on whether the neighboring label is recognized by CellXplorer.
- Existing verified real-workbook metadata values remain unchanged.
- No fuzzy or arbitrary row-wide value guessing is introduced.
