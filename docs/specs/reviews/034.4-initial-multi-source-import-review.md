## Assessment

The separate-cell/continued-cell choice, shared source-list extraction, filesystem picker extraction,
server-backed inspection and one-Cell submission path are present. The implementation is not ready
for dependent work because Cell-level metadata remains coupled to mutable per-source drafts,
asynchronous inspection does not converge automatically, acknowledgements can survive changed
facts, and the source-chain editor cannot reliably remove or freeze sources.

The findings below use local review IDs and also name the matching parent review finding from the
cumulative 034.4-034.6 review.

## Confirmed correct by code reading

- Separate cells remains the default when multiple sources are selected.
- Continued mode submits one Cell/Test with an ordered `sources[]` request.
- Replicate grouping is removed from the continued-cell request.
- `ContinuationSourceList`, `ContinuedImportEditor`, and `ImportFilesystemPickerModal` were extracted
  rather than adding all logic directly to `InboxPage.tsx`.
- Blocking, confirmation and informational findings are represented separately.
- Submission remains disabled while the current inspection response is incomplete or blocking.
- The original source files remain separate; the workflow creates a virtual continued Cell.
- No persistent schema or migration change is introduced by this child.

## Follow-up tasks

### R1 — High: Cell metadata is coupled to mutable per-source drafts

**Parent review mapping:** R1

**Affected files**

- `frontend/src/pages/InboxPage.tsx`
- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/tests/multiSourceImport.test.ts`

**Current**

The continued-cell editor receives one active source draft and writes Cell name, notes, Test name,
scientific overrides and presets into that source draft. Submission then finds the first source in
the current visible order and takes Cell-level metadata from that source's draft.

This means a source reorder can silently change which metadata is submitted. Opening raw data also
maps a current-order index back into the original `drafts[]` array, so after reordering the wrong
source can be opened and the active metadata draft can change merely because a raw preview was
requested. The capacity preview is also read from the active draft rather than from a stable
explicit source identity.

Continued mode additionally bypasses the existing separate-import scientific validity checks for
preset, active-mass and nominal-capacity combinations.

**Target**

Create one explicit `continuedCellDraft` independent of source order and source selection.

- Initialise it once from the initial first source.
- Edit Cell-level fields only on this object.
- Reorder, source-row selection and raw preview must not replace it.
- Submit this exact object plus the visible ordered `sources[]`.
- Address source previews by stable `staged_name`, never by positional correspondence between two
  differently ordered arrays.
- Reuse the existing scientific metadata validity rules before enabling submission.

**Acceptance criteria**

- Edit every Cell-level field, reorder sources and submit: request metadata is unchanged.
- Opening raw data for any source does not alter the Cell metadata form.
- After arbitrary reorder, each Raw data action opens the source shown on that row.
- The quick preview names and follows its actual source.
- Invalid mass/preset/capacity combinations keep continued import disabled.
- Tests assert the final request body, not only pure order helpers.

### R2 — High: asynchronous inspection can remain permanently pending

**Parent review mapping:** R2

**Affected files**

- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/src/api.ts`
- `frontend/tests/multiSourceImport.test.ts`

**Current**

The backend can return a successful inspection response with pending sources while deduplicated
cache preparation continues in the background. The frontend query runs once. Once that HTTP request
finishes, `isPending` becomes false even though `inspection_complete` remains false. No polling or
completion-triggered refetch observes the completed cache, so the modal can remain disabled until
the user accidentally changes order or reopens it.

Structured 409/422 mutation responses are flattened to a message string. When a source changes
between inspection and submission, the modal does not refresh findings while preserving entered
Cell data.

**Target**

Implement a convergent inspection state machine.

- Refetch at a restrained interval while any source is pending or `inspection_complete` is false.
- Stop when ready, failed/blocking, modal closed, or source/order identity changes.
- Show preparation state based on inspection content, not only network request state.
- On changed-hash/new-finding submission conflicts, preserve the open modal and Cell draft, refresh
  inspection and display the new findings.
- Do not start duplicate parse/cache work; rely on the existing backend build coordinator.

**Acceptance criteria**

- No-cache, raw-only and cycle-only sources progress from pending to ready without closing the modal.
- Failed preparation becomes a stable visible error rather than endless polling.
- Polling stops immediately when the modal closes.
- Changed-hash submission leaves all user-entered fields intact and refreshes findings.
- Tests use successive mocked pending/ready and conflict/refreshed responses.

### R3 — Medium: acknowledgement identity does not prove the finding is unchanged

**Parent review mapping:** R7

**Affected files**

- `backend/app/services/continuations.py`
- `frontend/src/continuationPolicy.ts`
- `tests/test_continuations.py`
- `frontend/tests/continuationPolicy.test.ts`
- `frontend/tests/multiSourceImport.test.ts`

**Current**

Finding IDs are derived only from finding code and source keys. They do not include semantic values
such as timestamps, gap duration, source hash, protocol signature, capacity values or proposed
order. `preserveAcknowledgements` therefore retains a checked acknowledgement when the finding code
and source pair remain the same even if the facts materially changed.

**Target**

Make confirmation IDs content-sensitive using a canonical semantic fingerprint containing:

- finding code;
- ordered source identity;
- the normalized details relevant to that confirmation.

Presentation-only wording should not invalidate an otherwise unchanged acknowledgement.

**Acceptance criteria**

- An identical finding preserves acknowledgement after refetch.
- Changed gap, overlap, protocol value, source hash or proposed order receives a new ID.
- The previous acknowledgement is cleared when that semantic fingerprint changes.
- Unrelated source changes do not clear genuinely unchanged findings.

### R4 — Medium: the initial source chain cannot be fully edited and disabled drag remains active

**Parent review mapping:** R9

**Affected files**

- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/src/components/ContinuationSourceList.tsx`
- `frontend/src/continuationPolicy.ts`
- `frontend/tests/multiSourceImport.test.ts`

**Current**

The continued-cell editor supports add and reorder but not removal of an already selected source,
even though the specification requires add/remove/reorder to rerun inspection.

`ContinuationSourceList` also sets `draggable` whenever an `onDragStart` callback exists, regardless
of its `disabled` prop. Arrow controls are disabled during inspection/import, but drag/drop can still
change the visible order while the submitted proposal is supposed to be frozen.

**Target**

- Add an explicit remove action for staged sources.
- Re-run inspection and acknowledgement preservation after removal.
- Define the behavior when removal leaves fewer than two sources: either return to separate-cell
  mode or show a clear continued-mode validation state without silently submitting an invalid plan.
- Make `disabled` block drag start, drag over, drop and keyboard moves.
- Freeze visible order once submission begins.

**Acceptance criteria**

- Removing a source reruns inspection and clears obsolete findings/acknowledgements.
- Focus moves predictably to the next surviving source or section heading.
- Disabled lists cannot emit drag or move changes.
- The order visible at submission start remains the submitted order.
- Tests cover removal, acknowledgement invalidation and disabled drag/drop.

### R5 — Medium: shared continuation UI does not meet the locked visual/accessibility contract

**Parent review mapping:** R10

**Affected files**

- `frontend/src/components/ContinuationSourceList.tsx`
- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/src/components/ImportFilesystemPickerModal.tsx`

**Current**

Concrete deviations include:

- findings use colored text without the required severity icon plus text;
- truncated filenames and paths do not consistently expose their full value through a tooltip/title;
- the extracted picker uses fixed pale-gray borders and numbered primary shades rather than
  theme-safe light/dark tokens;
- fixed-width action rows and the two-column editor have no recorded high-zoom verification.

**Target**

Apply the existing visual style guide without redesigning the workflow.

- Pair every finding state with a Tabler icon and explicit text.
- Use semantic theme-safe surfaces and borders.
- Add tooltip/title coverage for every truncated path or filename.
- Ensure controls wrap or scroll deliberately without clipping at supported UI zoom.
- Keep one local primary action and established compact Mantine geometry.

**Acceptance criteria**

Code-level checks plus a user-run manual checklist cover:

- Light, Dark and Auto appearance;
- 70%, 100%, 130% and 160% UI zoom;
- long filenames and paths;
- keyboard-only reorder, removal and acknowledgement;
- pending, blocking, confirmation, error and empty states.
