## Locked correction before implementation

A continued import creates **one Cell with one ordered source chain**. `Test` is an internal database
compatibility row only.

Luna must remove from the user-facing import workflow and request model:

- Test name;
- “Cell/Test” wording;
- any implication that protocol changes create another Test.

The backend may keep one automatically created internal Test row for the Cell. It must not create a
second Test or require the user to know that row exists.

## Confirmed useful work to preserve

- Separate cells remains the default for unrelated multi-file imports.
- One continued cell submits one ordered `sources[]` plan.
- Replicate grouping is excluded from continued mode.
- Shared source-list, continued-editor, and filesystem-picker components were extracted.
- Findings have blocking, confirmation, and informational severities.
- Original source files remain separate.

## Required changes

### R1 — High: remove Test from the import product and API contract

**Affected files**

- `frontend/src/pages/InboxPage.tsx`
- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/src/api.ts`
- `backend/app/routers/files.py`
- import/request tests

**Current**

Continued mode still edits/submits a Test name and describes the result as one Cell/Test.

**Target**

- Show and submit Cell fields only.
- Request contains `cell_name`, Cell metadata/overrides, ordered `sources[]`, and acknowledgements.
- Backend creates one internal Test row automatically.
- No Test field, label, selector, or validation appears in the UI.
- Protocol mismatch remains a finding only.

**Acceptance criteria**

- Continued import request has no user-supplied `test_name`.
- One Cell and one internal Test row are created.
- All ordered sources link to that row.
- No second Test can be created by this flow.
- UI copy consistently says Cell and source chain.

---

### R2 — High: Cell metadata is coupled to mutable per-source drafts

**Affected files**

- `frontend/src/pages/InboxPage.tsx`
- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/tests/multiSourceImport.test.ts`

**Current**

Cell name, notes, scientific overrides and presets are stored in one active source draft. Submission
then chooses metadata from the first source in the visible order. Reordering or opening raw data can
therefore change the draft used for submission or open the wrong source.

Continued mode also bypasses some scientific validity checks used by separate import.

**Target**

Create one dedicated `continuedCellDraft` independent of source order and source preview state.
Address every source action by stable `staged_name`.

**Acceptance criteria**

- Editing Cell fields, reordering, previewing every source, and submitting preserves identical Cell
  metadata.
- Each Raw data action opens the source displayed on that row.
- Quick preview identifies its actual source.
- Invalid mass/preset/capacity combinations disable continued import.
- Tests assert the final request body.

---

### R3 — High: asynchronous inspection can remain permanently pending

**Affected files**

- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/src/api.ts`
- `frontend/tests/multiSourceImport.test.ts`

**Current**

The backend can return `inspection_complete=false` while cache preparation continues, but the
frontend query runs only once. The form can remain disabled indefinitely. Structured submission
conflicts are flattened to a toast rather than refreshing the proposal.

**Target**

- Poll/refetch at a restrained interval while inspection is incomplete.
- Stop on ready, stable failure, modal close, or source/order change.
- Show preparation from response content, not only network state.
- On changed-hash/new-finding conflict, preserve the modal and Cell draft, refresh findings, and
  require current acknowledgements.

**Acceptance criteria**

- Pending sources become ready without closing the modal.
- Preparation failure becomes a stable visible error.
- Polling stops when the modal closes.
- Conflict refresh preserves all user-entered fields and selected sources.
- Tests use successive pending/ready and conflict/refreshed responses.

---

### R4 — Medium: acknowledgement identity does not prove the finding is unchanged

**Affected files**

- `backend/app/services/continuations.py`
- `frontend/src/continuationPolicy.ts`
- backend/frontend continuation tests

**Current**

Finding IDs use the finding code and source keys but omit material values such as hashes,
timestamps, gap duration, protocol values, or proposed order. A previous acknowledgement can remain
checked after the actual warning changes.

**Target**

Generate confirmation IDs from a canonical semantic fingerprint containing finding code, ordered
source identity, and normalized relevant details.

**Acceptance criteria**

- Identical findings preserve acknowledgement.
- Changed gap, overlap, protocol value, hash, or order receives a new ID.
- Presentation-only wording changes do not clear an unchanged acknowledgement.

---

### R5 — Medium: the initial chain cannot be fully edited and disabled drag remains active

**Affected files**

- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/src/components/ContinuationSourceList.tsx`
- `frontend/src/continuationPolicy.ts`
- `frontend/tests/multiSourceImport.test.ts`

**Current**

An accidentally selected source cannot be removed. The list remains draggable when callbacks exist,
even if `disabled=true` during inspection/import.

**Target**

- Add source removal.
- Re-run inspection and acknowledgement preservation after removal.
- When fewer than two sources remain, return clearly to a valid state rather than silently submit
  an invalid continued plan.
- Disable drag start/over/drop and keyboard movement while disabled.
- Freeze visible order at submission start.

**Acceptance criteria**

- Removal refreshes findings and clears obsolete acknowledgements.
- Focus moves predictably.
- Disabled/submitting lists cannot change.
- Submitted order equals the order frozen at submission start.

---

### R6 — Medium: shared continuation UI misses visual/accessibility requirements

**Affected files**

- `frontend/src/components/ContinuationSourceList.tsx`
- `frontend/src/components/ContinuedImportEditor.tsx`
- `frontend/src/components/ImportFilesystemPickerModal.tsx`

**Current**

Findings use color-only text, truncation lacks complete-value access in places, some chrome uses
fixed pale light-mode colors, and high-zoom behavior is unverified.

**Target and acceptance**

- Severity icon plus explicit text.
- Theme-safe surfaces/borders.
- Tooltip/title for every truncated filename/path.
- Keyboard-accessible order/removal/acknowledgement.
- User-run checklist for Light/Dark/Auto, 70/100/130/160% zoom, long values, and all loading/error
  states; record it as not run unless the user performs it.
