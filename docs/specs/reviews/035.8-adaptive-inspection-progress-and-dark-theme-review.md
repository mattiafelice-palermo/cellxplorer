# Review follow-up 035.8 — Adaptive inspection progress and dark-theme import contrast

## Scope

- Use serial inspection for batches of 25 or fewer files to avoid process-pool startup overhead.
- Read one first file as a timing sample, reuse its inspection result, and expose an estimate for
  the selected strategy.
- For larger batches, show worker-startup progress before remaining file reads begin.
- Reserve visible progress for post-read identity matching and response construction, with truthful
  finalization labels instead of appearing stuck near completion.
- Replace fixed light-mode import selection surfaces and controls that lose contrast in dark mode
  with theme-safe Mantine semantic colors.

## Locked behavior

- The threshold is `<= 25` files for serial inspection and `> 25` files for the bounded
  multiprocessing path.
- The first sampled inspection is reused and is never parsed a second time in the same batch.
- The estimate is explicitly approximate and is based on the sampled inspection duration and the
  selected worker count; it must not delay the batch with a separate benchmark pass.
- Progress phases are `sampling`, `starting_workers`, `reading`, and `finalizing`. The visible bar
  reserves the final portion for matching inspected results and constructing the import response.
- Dark-mode import rows must use `light-dark(...)` or Mantine semantic variables. Bare light primary
  shades and fixed dark text are not permitted for ordinary import chrome.

## Verification

- Focused service tests cover the threshold, sample reuse, strategy estimate, startup phases, and
  finalization progress.
- Frontend policy tests cover phase copy, sample-based estimate copy, and the reserved finalization
  range.
- The import flow is checked in Light and Dark schemes in the in-app browser.

## Implementation record

- Adaptive inspection: batches of 25 or fewer use serial reads; larger batches reuse a first-file
  timing sample and inspect remaining files with the bounded process pool.
- Progress: sampling, worker startup, reading, and finalization phases are reported through the
  existing tokenized import job. The raw-read phase stops at 90% and finalization advances through
  99% before completion.
- Theme: import selection rows, quick-access highlights, file icons, and pane borders use semantic
  or `light-dark(...)` colors in both schemes.
- Focused verification: 41 backend import-flow/inspection tests, 6 frontend import-progress tests,
  and TypeScript passed.
- Luna Light full verification: 729 Python tests, 315 frontend tests, and TypeScript passed.
- Manual verification: disposable-data browser check passed in Dark mode; selected-source rows had
  readable theme-aware contrast, and a 99-file batch opened the third modal with only the active
  preview loaded.
- Canonical verification: `python scripts\preflight.py --no-cache` — `PREFLIGHT PASSED`, 5/5
  stages completed successfully. The production bundle emitted only the existing large-chunk
  warning.
- Regression fix: progress polling now continues through the short interval where the inspection
  token exists but the background job has not yet been created, preventing the modal from remaining
  indefinitely at “Working…”.
