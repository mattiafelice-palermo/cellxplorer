## Findings and resolution

### R1 — High: The promotion matrix did not measure the integrated production P4 route

**Resolution: RESOLVED.**

The P4 benchmark now routes through the real analysis endpoint and production `try_compute_family()` while substituting only the already-warm benchmark executor into the application pool lifecycle. Production job construction, eligibility, submission, result transfer, merge/finalization, persistence, and JSON serialization are therefore inside the measured route. The isolated P8 candidate now delegates promoted-family job construction and merge/finalization to the production core rather than maintaining a separate promoted-family scientific merge implementation.

Exact-hit evidence is now observed rather than hard-coded: the profiler spies on `try_compute_family`, production `_worker_jobs`, `_ready_pool`, and pool submission, and reports zero helper/job/pool/dispatch activity on exact hits.

The final matrix in the spec records the required 4/8/12/16 production-route P4 rerun with cross-mode scientific/order parity and the locked promotion gates still satisfied.

### R2 — Medium: P4 Rate Capability rewrote replicate-group selection contexts as direct-Cell contexts

**Resolution: RESOLVED.**

`_merge_rate_capability()` now preserves the `selection_contexts` returned by each one-Cell worker result. The worker request context retains the owner unit's `entry_kind` and `entry_ref_id`, so a replicate-group selection survives the direct-Cell worker split without being rewritten as a user-level direct-Cell selection.

Focused coverage now asserts four-Cell replicate-group context parity and retains scoped exclusion / hidden-replicate-group semantics in the input contract. The direct-Cell matrix also remains parity-clean.

### R3 — Medium: The advertised cache-only Cycles worker could derive and write a missing cycle cache

**Resolution: RESOLVED.**

Worker eligibility now checks the owner process's pending-hash snapshot, raw-cache presence, and the exact parser/calc-version Cycles artifact before job construction or pool acquisition. The worker boundary independently fails closed if its required raw or cycle artifact is absent. Consequently a raw-present / cycles-missing request remains on the established serial/owner path rather than allowing `cache.load_cycles()` to derive and publish inside a spawned worker.

Focused coverage proves the missing-cycle-cache case returns the serial fallback signal before job construction or pool acquisition. The ready-cache production matrix demonstrates the promoted path still executes normally.

### R4 — Medium: Cycles added redundant selection/context work to every result-cache miss

**Resolution: RESOLVED.**

After the exact persisted-hit path, the Cycles route now builds one request context and passes that same object to both `try_compute_family()` and the serial `engine.compute()` fallback. The previous route-level `resolve_selection()` precheck was removed. Exact body hits still return before this context work.

Focused 1-Cell and 3-Cell route tests assert one context build reused by the helper and serial fallback, while the final P4 benchmark measures the corrected production route.

### R5 — Medium: The P8 resident-RSS gate used repeated worker samples and omitted parent RSS

**Resolution: RESOLVED.**

Warm worker acknowledgements are deduplicated by PID and only one RSS value per distinct resident worker is aggregated. Parent RSS is sampled separately and added to the worker total for both P4 and P8 before applying the 1.5× gate. Focused gate-math coverage verifies PID deduplication and parent inclusion.

The implementation record now reports corrected parent-plus-distinct-worker P8/P4 ratios of roughly 1.65–1.72 across the families, all above the 1.5× memory gate. Independently, P8 also fails the required latency improvement, so the production decision remains P4 rather than P8 even without relying on the memory rejection.
