## No silent fallback — the primary review target

The failure hunted here was a requested-but-unavailable channel quietly falling back to `voltage_v`,
which would render a cell-voltage trace under a "working potential" label: plausible-looking, wrong,
and invisible in a passing test run.

`analysis_engine.py:2573-2577` resolves a missing channel to `np.full(len(raw), np.nan)`, matching
the pattern already used for `current_ma`. `test_time_capacity_unavailable_channel_omits_trace_without_fallback`
asserts the trace is non-empty *and* that **every** value is `None`, so a substitution would fail
loudly rather than pass. Properly closed.

## The two decisions the spec refused to make

Both are evidence-based, documented and test-locked.

### Mixed-sample availability — omit per cell

Chosen because the existing architecture already treats any missing column this way (`np.full(nan)`
→ frontend `hasFinitePoint` omission); no "disable the whole selection" behavior existed to extend.
Locked by `test_mixed_selection_omits_per_cell_rather_than_disabling_whole_quantity`.

### Derivatives — primary voltage only

`_derivative_curve` (line 1311) reads `frame["voltage_v"]` unconditionally and was never routed
through a selectable channel, so the spec's "already generic" exception does not apply. Reviewer
confirmed by reading the function. Locked by `test_derivative_view_stays_restricted_to_primary_voltage`,
which proves the derivative trace is identical between the default channel and an alternate
selection. The UI reinforces it by rendering the selector only in voltage/current plot mode.

## R1 — Resolved. The two-electrode UI guarantee had no executable protection.

The headline promise of this child for every existing user is that an ordinary Neware source gains no
new controls. As implemented, that rested on one expression inside a `.tsx` component
(`showVoltageChannelSelector = voltageChannelOptions.length > 1`), with no frontend test and manual
browser checks recorded NOT RUN. The reviewer confirmed the logic was correct by reading it, which is
precisely the kind of guarantee a later refactor breaks silently.

This mattered because backend and frontend can disagree independently: the backend correctly
reporting `available: false` (locked by
`test_time_capacity_two_electrode_fixture_exposes_only_voltage_channel`) does not prevent the UI from
rendering a selector with a single disabled entry, which the spec explicitly forbids.

Resolved in `5440053` by extracting the decision into
`frontend/src/features/analyses/editor/policies/voltageChannelPolicy.ts` as pure functions, following
the established `frontend/tests/*.test.ts` + `node:test` convention used by the other 52 policy tests
— no DOM, no new rendering framework. `frontend/tests/voltageChannelPolicy.test.ts` adds 7 tests, run
by the reviewer:

```text
✔ an ordinary two-electrode source hides the selector entirely
✔ an available electrode potential shows the selector with the full, ordered option list
✔ both electrode potentials available offer all three channels in primary-first order
✔ a saved plot pinned to a now-unavailable channel keeps that option instead of dropping it
✔ counter_potential pinned but unavailable is retained the same way as working_potential
✔ no result yet (voltageChannels undefined) behaves like a two-electrode source
✔ no result yet still retains a pinned electrode-potential selection rather than dropping it
pass 7  fail 0
```

Reviewer confirmed the component now delegates entirely — no duplicated visibility logic remains.

The pinned-but-unavailable behavior is worth naming: a user's explicit channel choice is never
silently dropped from the option list, which is the right call and is now locked rather than
incidental.
