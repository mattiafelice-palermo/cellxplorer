## What was verified as correct

- **Exhaustive three-value channel model.** `frontend/src/appChannel.ts` is an explicit
  `Record<AppChannel, AppBranding>` map with no Stable fallthrough; `parseAppChannel` still throws
  on unsupported non-empty values and still defaults to Stable only for source/browser development.
  `backend/app/services/app_channel.py` resolves through `DATA_DIR_NAMES` / `DEEP_LINK_IMPORT_BASE`
  and keeps packaged missing/invalid channels fail-closed. `src-tauri/src/app_channel.rs` adds
  `AppChannel::Alpha` to every match with exact identifier parsing.
- **Isolation.** `.cellxplorer-alpha`, `cellxplorer-alpha://import-analysis`,
  `com.cellxplorer.desktop.alpha`, autostart value `CellXplorer Alpha`, COLORREF `0x00E84870`, and
  `icons-alpha/icon-256.rgba` (exactly 256×256×4 bytes) are all channel-local. `CELLXPLORER_DATA`
  still overrides every channel exactly. `main.rs` needed no change: it already derives
  `CELLXPLORER_CHANNEL`, `CELLXPLORER_DATA`, tray/notification identity, frame, icon, and
  single-instance/deep-link behavior from `AppChannel`, and scopes `install_instance_id` to Beta.
- **Deep-link crossing is genuinely exact.** `accepts_deep_link` matches the full
  `<scheme>://import-analysis` prefix, so `cellxplorer://import-analysis` does not swallow
  `cellxplorer-alpha://…`.
- **Alpha-as-Stable hazards removed.** Every `APP_BRANDING.isBeta` consumer outside `appChannel.ts`
  is gone. The two gates that previously read "not Beta" — the Settings Beta-install surfaces and
  the post-save `checkForBeta` call — are now `channel === "stable"`, and
  `BetaInstallCoordinator` is `APP_CHANNEL === "stable" && isTauriApp()`. Beta bootstrap remains
  `channel !== "beta"` fail-closed on both the frontend policy and the backend router/service.
- **Temporary updater gate.** `ensure_updater_enabled()` rejects Alpha in `check_app_update`,
  `download_app_update`, and `install_app_update` before any pending-state mutation, and inside
  `validate_release_version`; Stable/Beta accepted-version behavior is byte-for-byte unchanged.
  On the frontend, `shouldShowUpdateUi(..., "alpha") === false` disables automatic discovery, the
  dev mocks, `performCheck`, the power-menu entry, and the Settings controls, with an explicit
  "not enabled yet" alert. Alpha never reaches a Stable or Beta endpoint or version rule.
- **Overlay.** `src-tauri/tauri.alpha.conf.json` mirrors the Beta overlay exactly and overrides only
  product name, identifier, window title (geometry preserved), deep-link scheme, updater endpoint,
  and bundle/NSIS icons; the shared public key, sidecar resource, NSIS template, install mode, and
  capabilities are inherited. `tests/test_app_channels.py` asserts this on the **deep-merged**
  config, not on the overlay alone.
- **Branding.** `alphaPurple` matches the Parent 053 palette exactly with `primaryShade`
  light 7 / dark 6; the header badge is driven by `badgeLabel`, so Stable stays badge-free and Beta
  is untouched. No semantic, scientific, plot, thumbnail, or export color was recolored.
- **NSIS.** The added exact-identifier branch is correctly nested and balanced, keeps the
  unknown-identifier `!error`, and leaves process cleanup scoped to `$INSTDIR`. The Alpha installer
  built from this template, which exercises the branch.
- **Scope discipline.** No tag, release workflow, release-channel script, manifest verifier, or
  `release-channels` branch change. No schema migration, no `CALC_VERSION` change (the
  `backend/app/config.py` edit is a docstring only), no copied app tree.

### Accepted with rationale: local installer-name normalization

`scripts/build-app.ps1` now looks for Tauri's product-derived output (`CellXplorer Alpha_<v>_…`,
with the space Tauri preserves) and renames that exact freshly built artifact — plus its `.sig`
when present — to the locked dotted `CellXplorer.Alpha_<v>_x64-setup.exe`. This also changes Beta's
local artifact name from spaced to dotted.

This is in scope and correct: Parent 053 §4 locks the `CellXplorer.Beta_` / `CellXplorer.Alpha_`
setup prefixes, `scripts/verify_updater_manifest.py` already models published assets as
`product_name.replace(" ", ".")`, and `docs/windows-packaging.md` already documented the dotted
local path. The change makes the local output match documentation that was previously inaccurate.
It is fail-closed (it throws when the exact product artifact is absent) and introduces no
"newest setup executable" discovery. `.github/workflows/release.yml` is unaffected because it
builds through `tauri-action` and GitHub performs the same space-to-dot substitution on upload.

Non-blocking note for 053.2 or later: the lookup now depends on Tauri continuing to preserve spaces
in the NSIS filename. If a future Tauri upgrade emits the dotted name directly, the build throws
with a clear message rather than misbehaving, but accepting either exact name would be more durable.
Do not act on this during 053.1.

## Findings

### R1 — Medium: Alpha icon generation has no deterministic-output or required-frame tests

Affected files:
- `scripts/build_alpha_icons.py`
- `tests/` (new module required, e.g. `tests/test_build_alpha_icons.py`)
- `AGENTS.md` (maintained tree)

**Current**

Spec 053.1 §6.3 requires "deterministic-output and required-frame tests following the current Beta
icon test pattern", and §8 lists "deterministic Alpha icon generation" under required
build/installer coverage. `scripts/build_alpha_icons.py` and the four committed Alpha assets exist,
but no test covers them: there is no `tests/test_build_alpha_icons.py`, and
`tests/test_build_beta_icons.py` was not extended. Nothing in the suite fails today if a later edit
changes the Alpha `.ico` frame set, drops the size-specific `A` for 16/24/32 px, makes regeneration
non-deterministic, or lets the generator write over Stable or Beta assets. The Beta equivalent has
had this protection since Spec 021, so Alpha is the only channel whose committed icon assets are
unpinned.

**Target**

A focused Alpha icon test module mirroring `tests/test_build_beta_icons.py`, discovered
automatically by `scripts/run_backend_tests.py` (`tests/test_*.py` glob) and therefore by canonical
preflight. Skip cleanly when Pillow is unavailable, exactly as the Beta module does.

**Acceptance criteria**

- The committed assets `frontend/public/app-icon-alpha.png`, `src-tauri/icons-alpha/icon.png`,
  `src-tauri/icons-alpha/icon.ico`, and `src-tauri/icons-alpha/icon-256.rgba` are asserted present.
- `src-tauri/icons-alpha/icon.ico` frame sizes are asserted to be exactly
  `[(16,16), (24,24), (32,32), (48,48), (256,256)]`.
- Each committed `.ico` frame is asserted byte-equal to `render_size(recolor_icon(STABLE_ICON), size)`
  for every size in `ICO_SIZES`, so the size-specific badge treatment cannot silently change.
- The 256 px frame is asserted to contain strictly more `BADGE_RGB` pixels than the 16 px frame,
  pinning "ALPHA badge on large frames, dedicated `A` on small frames".
- `src-tauri/icons-alpha/icon-256.rgba` is asserted to be exactly `256 * 256 * 4` bytes.
- Re-running `build_alpha_icons.main()` leaves all four committed Alpha assets byte-identical
  (deterministic regeneration) and leaves `frontend/public/app-icon.png`,
  `src-tauri/icons/*`, and `src-tauri/icons-beta/*` byte-identical.
- `AGENTS.md`'s maintained tree gains the new test module entry, per 053.1 §11's requirement to
  record new icon script/config/test ownership.
- The new module passes inside `python scripts\preflight.py`.

### R2 — Medium: Alpha frontend channel stamp has no crossed-pair or branding-input coverage

Affected files:
- `tests/test_frontend_channel.py`
- `scripts/frontend_channel.py`

**Current**

Spec 053.1 §8 requires that "channel-stamp mismatch fails for every crossed pair" and that "Alpha
branding inputs invalidate stale stamps". `scripts/frontend_channel.py` was extended correctly —
`alpha` is an accepted channel for `write`/`verify` and `BRANDING_INPUTS` now includes
`frontend/public/app-icon-alpha.png` and `src-tauri/tauri.alpha.conf.json` — but
`tests/test_frontend_channel.py` is unchanged. The only mismatch case covered is stable-written /
beta-verified. No test writes or verifies an `alpha` stamp, no test covers the four crossed pairs
involving Alpha, and no test anywhere covers `brandingHash` staleness for any channel. A future
edit could drop `alpha` from either choices tuple, or drop the Alpha branding inputs from the
hash, and the suite would stay green while a Stable-built `frontend/dist` became packageable into
Alpha.

**Target**

Extend `tests/test_frontend_channel.py` so the three-channel stamp contract is pinned end to end,
using the existing temporary-root fixture (`setUp` already materializes every `BRANDING_INPUTS`
path, so Alpha's new inputs are covered automatically).

**Acceptance criteria**

- `write_stamp(root, "alpha")` followed by `verify_stamp(root, "alpha")` succeeds.
- `verify_stamp` raises the "built for channel …" `RuntimeError` for **every** crossed ordered pair
  among `stable`, `beta`, `alpha` (six combinations), not only stable→beta.
- After a successful `write_stamp(root, "alpha")`, mutating `frontend/public/app-icon-alpha.png`
  and, separately, `src-tauri/tauri.alpha.conf.json` makes `verify_stamp(root, "alpha")` raise the
  stale-branding-inputs error — proving the Alpha branding inputs actually participate in
  `brandingHash`.
- `write_stamp` and `verify_stamp` still raise `ValueError` for an unsupported channel value.
- `build_frontend_channel.main(["alpha"])` is asserted to set `VITE_CELLXPLORER_CHANNEL=alpha` and
  to invoke `frontend_channel.py write --channel alpha`, mirroring the existing `beta` assertion.
- Existing Stable/Beta stamp assertions remain unchanged and passing.

### R3 — Medium: No automated proof that Alpha never sees the Stable-only Beta installation surface

Affected files:
- `frontend/src/betaInstaller.ts`
- `frontend/src/components/BetaInstallCoordinator.tsx`
- `frontend/tests/betaInstaller.test.ts`

**Current**

Spec 053.1 §4.1 requires focused Beta installer **and** bootstrap policy tests "where current
binary assumptions would otherwise classify Alpha as Stable", and §8 requires a frontend test that
"Alpha does not expose Stable-only Beta installation". The bootstrap half is covered: the exported
`shouldShowBetaBootstrapUi` helper gained
`assert.equal(shouldShowBetaBootstrapUi("alpha", true, "available"), false)`.

The installer half has no coverage at all. `frontend/tests/betaInstaller.test.ts` is unchanged, and
the gate lives inline in component/JSX code (`BetaInstallCoordinator.tsx:81` and the
`APP_BRANDING.channel === "stable"` conditions in `SettingsPage.tsx`). This is precisely the gate
that read `!APP_BRANDING.isBeta` before this change — the literal Alpha-as-Stable hazard the parent
spec calls out, which would have offered Alpha users Stable's first-Beta-install UX. It was fixed
correctly, but nothing prevents a future edit from reverting it to a "not Beta" form, and
`frontend/src/betaInstaller.ts` is a pure policy module with a dedicated test file, so the
regression is cheaply pinnable.

**Target**

Express the Stable-only Beta-installation gate as a pure, exported, channel-aware policy — the
natural shape is `shouldShowBetaInstallUi(channel, tauri)` in `frontend/src/betaInstaller.ts`,
mirroring `frontend/src/betaBootstrapPolicy.ts` — have `BetaInstallCoordinator` consume it instead
of its inline expression, and cover it in `frontend/tests/betaInstaller.test.ts`. An equivalent
focused test that proves the same property without the refactor is acceptable; an assertion on
component source text is not.

**Acceptance criteria**

- The gate returns `true` only for `stable` in a Tauri app, and `false` for `beta` and `alpha` in
  every combination of Tauri/dev-mock inputs.
- `frontend/src/components/BetaInstallCoordinator.tsx` uses the shared policy rather than an inline
  channel comparison, so the tested policy is the one that actually runs.
- `node --test frontend/tests/betaInstaller.test.ts` covers the Alpha and Beta negative cases
  explicitly and passes.
- Stable's existing first-Beta discovery, notification, protected-install, and scheduling behavior
  is unchanged — the existing 58 focused frontend tests must still pass.
- No new Beta-install capability is exposed to Alpha in `SettingsPage.tsx`; its Beta tiles remain
  `stable`-only.
