## Review summary

050.20 is review-clean. The implementation addresses the measured dominant Chargeability cost first and then removes a second material raw-data cost without changing scientific behavior.

The request-local protocol cache is keyed by the effective parser identity, nominal capacity, and exact header metadata used to reconstruct the protocol. It is owned by one `chargeability.compute()` call, is not persistent or process-global, and permits equal immutable header documents from distinct source files to reuse the same reconstruction while changed parser/header/nominal inputs miss the cache. The returned reconstruction is only read by the Chargeability path, so sharing the request-local object does not introduce mutable cross-source state.

The second retained change uses the existing validated raw-layout sidecar to read only the candidate charge step and the protocol-recorded reference-capacity step. The requested column set covers every field consumed by `_occurrence_rows()` / `_reference_capacity()`. Missing, busy, legacy, corrupt, incomplete, or column-incompatible sidecars return `None` from the existing selective reader and therefore fall back to the canonical full raw cache. The selective helper never opens the original source file.

The final reported six-Cell forced-miss p50 is **83.17 ms** versus a current-head baseline of **188.46 ms**, a **55.9% reduction**, with exact persisted-hit p50 **12.61 ms**. Protocol reconstruction falls from six calls to one, materialized raw rows fall from 122,946 to 1,614, SQL remains 17 statements, response bytes remain 50,441, and the reported scientific/security/order controls are unchanged.

The final measured route no longer justifies additional concurrency under the child contract: the remaining six-Cell occurrence extraction is 13.67 ms and indexed data access is 29.53 ms, while protocol reconstruction is a shared 19.88 ms boundary. There is not a remaining >=100 ms independent CPU block to justify worker/IPC complexity in this child.
