# Review 035.8 — Duplicate Cell names and failed import state

Specification: [`../035.8-lazy-import-preview-and-cache-handoff.md`](../035.8-lazy-import-preview-and-cache-handoff.md)

## Required follow-up

Fix the import editor and registration endpoint so that Cell names are derived from barcode or
filename, duplicate trimmed names are rejected before submission/parsing, and failed background
registration remains editable and retryable.

### Frontend

- Default a Cell name to `file.barcode || filenameWithoutExtension`.
- Keep `remarks` as the description, never as the Cell name.
- Detect duplicate trimmed names before submission, show the conflicting names, disable Import,
  and highlight affected file rows.
- Show “Registration is running” and “Continue in background” only while the registration job is
  actually running.
- When a registration job fails, preserve drafts, stop the running state, re-enable editing, and
  allow retrying with a new job token.

### Backend

- Validate duplicate submitted names before hashing, parsing, continuation checks, or inserts.
- Query existing Cell names once and return structured errors with the conflicting names and
  affected filenames/staged names.
- Distinguish `duplicate_submitted_cell_names` from `cell_name_already_exists`.
- Translate SQLite `IntegrityError` conflicts into the same structured error shape rather than
  exposing SQLAlchemy text.

## Implementation record

Implemented on `feature/spec-035-user-experience-optimization`:

- `InboxPage.tsx` now defaults names to barcode or filename stem, keeps remarks as description,
  blocks duplicate trimmed names before submission, lists the conflicting filenames, and marks
  affected rows.
- Registration controls are derived from the polled job status. Failed jobs hide background
  continuation, preserve drafts, unlock editing, and can be retried with a new token.
- `files.py` validates submitted names before source identity/parsing/continuation work, performs
  one request-scoped existing-name query, returns structured conflict payloads, and translates
  late SQLite integrity conflicts without exposing SQLAlchemy text.
- Added focused backend and frontend policy tests.
