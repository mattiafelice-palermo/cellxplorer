### R2 — High: `gcpl3` invents production cycle semantics from current direction and unvalidated half-cycle progression

Affected files:
- `backend/app/services/biologic_gcpl.py`
- `tests/test_biologic_gcpl.py`
- `tests/test_biologic_closure.py`
- `docs/biologic-mpr-format.md`
- `docs/specs/041.2-gcpl-canonical-timeseries-mapping.md`
- `docs/specs/041.6-scientific-regression-real-file-parity-and-closure.md`
- user-facing support/status documentation that now advertises canonical MPR cycling

**Current**

Before 041.6, the production adapter deliberately failed closed when the decoded half-cycle field progressed because the source cycle semantics had not been independently established; the private sample's ID-468 field was constant zero and no verified full-cycle field existed.

`gcpl3` removes that boundary. `_validate_supported_half_cycle()` now accepts monotonic half-cycle changes as execution-boundary signals, and `_derive_execution_pair_cycles()` assigns a logical cycle by the adapter's own rule: start at cycle 1 and increment when a charge execution follows a discharge execution. The exact verified production MPR dtype does not contain `raw_cycle_index`, so real files using that layout necessarily take this fallback path.

That rule is deterministic but not independently grounded in BioLogic/EC-Lab cycle identity. For example, a discharge-first protocol moves the following charge to cycle 2, while repeated charge-only executions can remain in cycle 1. The synthetic corpus then proves the same convention that the adapter itself invented; it is not an independent semantic oracle. No private file was re-run through `gcpl3`, and no MPT parity evidence exists for this behavior.

This contradicts Parent 041's fail-closed policy for cycle/step mapping that cannot be derived from verified source semantics and the earlier 041.2 acceptance boundary.

**Target**

Do not expose canonical production cycling for a real MPR layout whose cycle identity is not independently established. Restore fail-closed/metadata-only behavior for that layout, including truthful header capability flags, until independent source evidence establishes the exact cycle/half-cycle conversion. Do not derive vendor cycle identity from current direction merely to satisfy the canonical `cycle` field.

If independent evidence is later supplied, encode the exact proven mapping, compare it against independently expected real-file values, and advance the adapter revision for the semantic change.

**Acceptance criteria**

- A production MPR with no independently verified full-cycle mapping does not receive cycles from the charge/discharge execution-pair heuristic.
- Unvalidated non-constant half-cycle progression is not promoted to a trusted execution/cycle semantic signal merely because it is monotonic.
- Header metadata (`canonical_cycling`, `metadata_only`, `cycling_rows`) truthfully reflects whether the supported real-file contract can actually produce validated canonical cycling data.
- Regression coverage restores a fail-closed case for unvalidated cycle/half-cycle semantics, or—if genuine independent evidence is added—tests compare the implemented mapping to that independent evidence rather than only to project-authored synthetic assumptions.
- Real-file canonical support is not advertised in README/changelog/context while the supported real layout remains scientifically unverified.
- Parser identity/revision is advanced again if the canonical mapping semantics change from `gcpl3`.
