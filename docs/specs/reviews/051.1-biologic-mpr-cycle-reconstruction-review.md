## Findings

### R1 — High: Execution-only `Ns` loop inference exceeds the locked cycle-reconstruction contract

Affected files:

- `backend/app/services/biologic_gcpl.py`
- `tests/test_biologic_gcpl.py`
- `docs/biologic-mpr-format.md`
- `docs/agent-knowledge/canonical-cycling-data.md`
- `docs/specs/051.1-biologic-mpr-cycle-reconstruction.md`

**Current**

The active 051.1 spec defines repeated-cycle reconstruction as a validated **declared GCPL loop plus observed execution**. It says a backward `Ns` transition is a cycle wrap only when it matches that declared loop edge; other restarts are ambiguous and must fail closed.

The implementation adds `_infer_execution_loop_structure(...)` and calls it whenever `_declared_loop_structure(...)` returns no loop. One unique observed backward `Ns` edge, a contiguous step range, and charge/discharge semantics can therefore create `protocol_loop_reconstruction` cycles even when the settings do not contain a usable `goto/repeat` declaration. The stable format documentation now describes this broader behavior, but the governing spec does not. The code comment states that this was added because the private EGG cycling source does not persist a non-zero goto/repeat setting.

This is not a cosmetic mismatch: cycle numbers are scientific output. A restart/reset that happens to satisfy the execution pattern can be promoted into a cycle boundary under a rule that was never locked or reviewed as part of 051.1. The private-file success is valuable evidence for such a rule, but it does not by itself define its safe general boundary.

**Target**

Bring the governing spec, production behavior, tests, and stable documentation back to one explicit rule. Either retain the declared-loop-only contract, or explicitly amend 051.1 to authorize a narrowly bounded execution-evidenced loop fallback for source families such as the private EGG file. If the fallback is retained, document exactly what execution evidence distinguishes a deterministic cycling loop from an ambiguous restart and keep all weaker restart/branch shapes fail-closed. Do not use direction-pair heuristics or half-cycle arithmetic.

**Acceptance criteria**

- `051.1` explicitly defines every condition under which a source with no usable declared loop may receive reconstructed cycles, or production no longer performs that fallback.
- The production implementation matches that rule exactly; there is no undocumented second cycle-semantic path.
- Focused negative tests cover restart/reset patterns that are close to the accepted execution-evidenced shape but must remain unsupported, including more than one backward edge and a non-cycling/ambiguous restart.
- If the execution-evidenced fallback is retained, the private EGG source still passes unchanged and the handoff records the observed evidence supporting the rule.
- Declared-loop reconstruction, non-repeating cycle 1, explicit cycle identity, and half-cycle diagnostic-only behavior remain regression-covered.

### R2 — Medium: Cache-hit cycle provenance is guessed from cycle count and can be wrong

Affected files:

- `backend/app/services/cache.py`
- `backend/app/services/parsing.py`
- `tests/test_biologic_closure.py`
- focused cache/parser tests as appropriate

**Current**

On an existing `.mpr` raw+cycle cache hit, `cache.build(...)` reads the cached `cycle` column and sets:

- more than one unique cycle -> `protocol_loop_reconstruction`;
- one unique cycle -> `non_repeating_cycle_1`.

That is not provenance. A one-cycle loop reconstruction is mislabeled as non-repeating, and an explicit full-cycle source with multiple cycles would be mislabeled as protocol-loop reconstruction. The same return value is used by lifecycle promotion through `mark_biologic_mpr_canonical(...)`, so the incorrect label can become persisted capability metadata. In addition, promotion currently writes `single_direction_cycle_verification = "verified"` even for a mixed repeated loop, which is not a truthful statement about that source.

**Target**

Preserve or recover the exact adapter-produced cycle identity (`explicit_full_cycle`, `protocol_loop_reconstruction`, or `non_repeating_cycle_1`) across fresh-build and cache-hit paths without deriving it from the number of cycle labels. Persisted capability metadata must describe only the reconstruction path actually verified; a mixed loop must not claim single-direction verification.

**Acceptance criteria**

- No cache/provenance path infers the cycle-identity source from `nunique(cycle)` or cycle count.
- Fresh parse and subsequent cache hit report the same exact cycle identity for each supported identity source.
- Regression coverage includes at least a one-cycle loop case and an explicit-cycle case so they cannot be mislabeled by cardinality.
- Mixed repeated-loop promotion does not set `single_direction_cycle_verification` to `verified`; single-direction verification remains truthful to its own path.
- Existing cache keys, parser identity (`bm:gcpl10:r1`), and `CALC_VERSION` behavior remain unchanged unless a separately justified versioning requirement is discovered.

### R3 — Low: High-priority repository guidance still describes the pre-051.1 mixed/repeated limitation

Affected files:

- `AGENTS.md`
- `docs/agent-knowledge/README.md`

**Current**

`AGENTS.md` still says mixed, repeated, or otherwise unresolved MPR runs remain metadata-only until cycle identity is independently verified, and describes the verified MPR contract primarily as the narrow charge-only/discharge-only cycle-1 path. `docs/agent-knowledge/README.md` likewise points agents to a generic "fail-closed cycle-identity rule" without acknowledging the reviewed reconstruction boundary. Those statements are now materially stale relative to `gcpl10` and to the updated canonical-cycling/format documents.

**Target**

Update the high-priority guidance to describe the current bounded reconstruction contract while preserving the fail-closed rule for ambiguous restart/branch/control cases and the source-local nature of reconstructed cycle labels.

**Acceptance criteria**

- `AGENTS.md` no longer states that all mixed/repeated supported GCPL MPR files remain metadata-only.
- `docs/agent-knowledge/README.md` points to the current bounded cycle-reconstruction contract rather than the superseded blanket limitation.
- The wording remains consistent with the final R1 rule and does not imply generic cycle inference for unsupported BioLogic techniques or arbitrary pulse/branching protocols.
