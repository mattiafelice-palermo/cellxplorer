The 050.22 handoff closes the former Cycles profiling gap and reports a substantial complete-route improvement, but it is **not review-clean** because one retained NumPy optimization changes the established missing-data semantics of the retention reference.

The profiling architecture itself is directionally correct. Cycles direct-body timers are opt-in, `_cycles_profile_started(None)` returns without calling `perf_counter()`, and the profiler reconciles the direct-body remainder after excluding already nested helper timers. The handoff reports the former ~73.5 ms unexplained scientific remainder reduced to below the largest named direct child before optimization and to 0.84 ms p50 in the final profile.

The retained performance work is also material at the route boundary: the implementer reports a six-Cell unprofiled forced-miss p50 of **103.18 ms** versus the locked 050.17 baseline of **170.99 ms**, with one-Cell p50 **24.62 ms** and six-Cell exact-hit p50 **21.85 ms**. The remaining large measured boundaries are `stitch_cycles` / Parquet materialization and result-cache persistence; the child records a rejected batched cycle-mapping experiment and does not add concurrency.

However, `_retention_reference()` previously used Pandas `Series.max()`, whose default behavior skips NaN discharge-capacity values in the selected first-N cycle window. The new implementation uses `np.max(first_n)`, which propagates a single NaN. That can change the retention reference from a finite capacity to NaN and then suppress `capacity_retention_pct`, `retention_last_pct`, `cycles_to_80_pct`, and percentage fade metrics. The locked child contract explicitly requires missing-data behavior and retention semantics to remain unchanged, so this must be corrected before 050.22 can advance.

## Findings

### R1 — Medium: First-N retention reference no longer skips NaN discharge values

Affected files:
- `backend/app/services/analysis_engine.py`
- focused Cycles/analysis-engine regression tests

**Current**

Before 050.22, `_retention_reference()` selected the configured first-N cycles and evaluated:

```python
first_n = frame.nsmallest(n, "cycle")["discharge_capacity_mah"]
return float(first_n.max()) if len(first_n) else float("nan")
```

Pandas `Series.max()` skips NaN values by default. A first-N reference window such as `[NaN, 5.0, 4.0]` therefore yields a finite reference of `5.0`.

050.22 replaces that with a stable NumPy order followed by:

```python
first_n = discharge_values[order]
return float(np.max(first_n)) if len(first_n) else float("nan")
```

`np.max()` propagates NaN, so the same scientific input yields `NaN`. `add_derived_columns()` then emits all-NaN `capacity_retention_pct`, and downstream retention/SoH metrics may become `None` even though finite reference-capacity data exists in the configured window.

This violates the locked requirements to preserve retention-reference semantics and NaN/missing-data behavior. The committed golden fixture does not exercise this edge case, so its digest parity does not prove equivalence here.

**Target**

Keep the optimized stable NumPy selection if desired, but reproduce the previous `Series.max(skipna=True)` behavior exactly for the selected first-N discharge-capacity values. All-NaN/empty selected windows must retain the previous NaN result; mixed finite/NaN windows must use the maximum finite/non-NaN value.

Do not change the configured-cycle reference mode or any downstream retention formula.

**Acceptance criteria**

- Add a focused regression test in the appropriate Cycles/analysis-engine test module proving that a first-N retention window containing both NaN and finite discharge-capacity values returns the same finite reference as the pre-050.22 implementation.
- Cover the all-NaN first-N case and preserve its NaN result.
- Demonstrate that downstream `capacity_retention_pct` / relevant cell retention metrics remain populated for the mixed finite/NaN case exactly as before.
- Re-run the focused Cycles scientific/golden checks and canonical `python scripts\preflight.py`.
- Re-run the final Cycles profile only if the fix materially changes the optimized implementation path; otherwise the existing performance evidence may be retained with a focused no-regression timing check.
