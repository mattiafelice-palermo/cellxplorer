# 111.2 — Combine, ungroup and tracking

**Status:** Planned implementation step 2 of 7. [Parent contract](111-virtual-cells.md). Depends on [111.1](111.1-virtual-cell-identity.md).

Implement lifecycle operations and their impact previews using the identity and revision from 111.1. Keep the public creation action closed until the end-to-end workflow is ready.

- Preview the ordered members, timestamps, joins, affected watches and saved-analysis references. At commit, recheck the inspected source identities, order, eligibility, memberships and watch state. Use a transaction and retry-safe operation identity so double submission, a concurrent manual attach or a watch pass cannot partly apply the operation.
- Keep A’s and B’s original rows, metadata, folders, tags, replicates and source ownership. During A → B, read growing-file updates only from B’s current tail for this group. Use B’s existing folder, pattern and enablement for discovery. Suppress automatic work for earlier members while retaining their individual preferences and pending candidates. Route a settings edit to its named physical owner.
- Accept a new continuation once, on B. Its file becomes B’s and the virtual cell’s tail. Refresh both affected views and notify each affected analysis once. A physical correction, manual attach, detach or reorder continues through the ordinary impact flow. Include dependent virtual views in that preview. If the physical edit is valid but takes V outside pilot scope, record V’s eligibility change with the edit and expose its review/ungroup path. Reordering the virtual runs requires a fresh preview: explicitly confirm the new adjacent joins and transfer effective tracking to the new last run in the same transaction.
- Ungroup atomically. Present the physical rows independently again. Release tracking delegation, allow each run’s current settings to take effect, and recheck candidate ownership, file stability and order before resuming scans. A previously disabled watch stays disabled. Files accepted on B stay there. Handle a file discovered just before ungroup, a pending approval and a scan retry after ungroup.
- If saved analyses need the virtual definition, retire it from new library selection and retain its final member/source order, joins and scientific reference context. Include these references in hard-removal impact checks. Recombining the same cells creates a new identity. A previously saved analysis can still open the retired one.

**Acceptance.** Test A-on/B-on, A-on/B-off, B settings edited while combined, a growing last MPR, append during ungroup, and repeated combine/ungroup requests. Verify only one cell owns each file, each eligible tail is monitored once, and A and B have their expected settings after ungroup. An unreferenced definition can be removed without deleting either run.
