## Goal

Replace the remaining assumption that one process-global parser version describes every source with a **source-specific parser identity** used consistently by raw/cycle cache lookup, source preparation, multi-source stitching, analysis cache keys and saved-analysis provenance.

This is the highest-risk architectural child in Parent 040. It changes reproducibility/plumbing, not scientific formulas.

At the end of this child:

- each source cache is keyed by that source's effective parser identity;
- `SourceFile.parser_version` stores the effective identity that produced its current canonical raw cache;
- Neware binary and Neware Excel sources may carry different parser identities without invalidating one another;
- stitching loads each ordered source at its own parser identity;
- analysis provenance records parser identity per contributing source rather than one misleading global value;
- existing saved analyses with the legacy provenance shape remain readable and stable;
- current Neware numerical output remains unchanged;
- 040.2's transitional global parser-bundle compatibility is removed or reduced to a narrow backward-compatibility helper with no scientific ownership.

## Current verified architecture to reverify

At `main@1542ff3bed7be31b3b0e1f19282c92598dc0fc06`:

```text
parsing.PARSER_VERSION = 2026.6.11-cxp3
cache raw key          = (file hash, parsing.PARSER_VERSION)
cache cycle key        = (file hash, parsing.PARSER_VERSION, CALC_VERSION)
stitch_raw(...)        = ordered hashes + one parser version
stitch_cycles(...)     = ordered hashes + one parser version + calc version
CALC_VERSION            = 1.6.1
```

Concrete global-version consumers include:

- `cache.schedule_build`, `build`, `build_write_behind`, `raw_path` and `cycles_path` current defaults;
- `scanner._has_current_scientific_cache` and source preparation;
- `scanner.parse_file` / stable replacement, which persist the build result into `SourceFile.parser_version`;
- `analysis_engine.compute*`, which starts from `parsing.PARSER_VERSION`, optionally replaces it from legacy `provenance["parser_version"]`, and passes that one version to all selected sources;
- `analysis_cache.result_key`, which puts one scalar parser version into every scientific result key;
- `stitch_raw` / `stitch_cycles`, which cannot currently load different parser identities within one Cell chain.

`SourceFile.parser_version` already exists as `String(30)`. New identities must fit that field; this child must not solve naming length by adding a migration.

Parent 039 intentionally preserved one Neware bundle across binary/Excel. 040.3 replaces that temporary assumption while preserving old bundle caches/provenance as historical pinned data.

## Locked parser identity

Use the descriptor introduced in 040.2 to compute one deterministic effective identity per source format/adapter, including 040.1's canonical raw version.

Conceptually:

```text
format_id + adapter_revision + canonical_raw_version
```

For Neware binary, include the underlying NewareNDA version when that library can change decoded canonical output.

For Neware Excel, include the CellXplorer Excel parser revision.

The identity string must be:

- **30 characters or fewer** so it fits the existing `SourceFile.parser_version` field;
- deterministic;
- filesystem-safe after current cache sanitization;
- stable across runs/builds for identical parser semantics;
- changed deliberately when canonical parser output semantics change;
- independent of source content hash;
- independent of `CALC_VERSION`.

Do not include Python version, OS version, application patch version or other environment noise unless it actually changes canonical parser meaning.

Prefer a compact documented grammar, for example:

```text
nb:2026.6.11:r1   # Neware binary + NewareNDA version + canonical raw version
nx:3:r1           # Neware Excel adapter revision + canonical raw version
```

The exact tokens are decided in implementation/review, but the maximum length and semantics above are locked.

## Cache API changes

### Paths remain content-addressed

Preserve the existing directory architecture:

```text
CACHE_DIR/<hash[:2]>/<hash>/...
```

Raw/cycle filenames continue to carry parser identity and calc version.

### Remove implicit current global parser defaults from scientific callers

Functions may retain optional defaults for compatibility only where safe, but production scientific/source code should pass the source-specific parser identity explicitly.

Target concepts:

```python
raw_path(file_hash, parser_identity)
cycles_path(file_hash, parser_identity, calc_version)
load_raw(file_hash, parser_identity)
load_cycles(file_hash, parser_identity, calc_version)
```

For build paths where the source path is available:

```python
identity = parsing.parser_identity(source_path)
```

and successful build result persists that identity into `SourceFile.parser_version` through the existing owner.

### Background build de-duplication

Current process-local deduplication keys include the global parser version. Replace with the effective parser identity for the source being built.

Two formats with the same content hash are extraordinarily unlikely but must not collide merely because one global version was assumed.

### Current-cache checks

Any helper such as `_has_current_scientific_cache` must determine the expected parser identity from the registered source's current path/format/metadata or from a stable source descriptor stored/persisted by existing fields.

Do not open/fully parse sources merely to answer list endpoint cache-status questions.

Where `SourceFile.parser_version` already records the successfully used parser identity and the file extension/format is stable, current-version comparison should be relational/cheap.

If the current adapter revision changes, a cheap expected identity can be derived from extension/recognized format policy without full parse.

## Source registration and update behavior

### New registration

On successful scientific preparation:

```text
SourceFile.parser_version = effective parser identity
```

### Existing source after application update

If the expected parser identity for its format has advanced:

- old cache remains a historical reproducibility artifact until normal cleanup policy removes it;
- current source is considered scientifically stale/pending under existing preparation rules;
- rebuild writes a new raw/cycle cache at the new identity;
- do not mutate old cache contents in place.

### Changed source bytes

Existing content-hash replacement rules remain authoritative. Parser-identity migration and source-content replacement are separate dimensions.

## Stitching redesign

Current `stitch.py` accepts only ordered hashes plus one parser version. Replace this with a source descriptor per position.

Preferred simple shape:

```python
@dataclass(frozen=True)
class CachedSourceRef:
    file_hash: str
    parser_version: str
```

or equivalent tuples/dicts already available from `SourceFile`.

Target calls conceptually:

```python
stitch_raw(ordered_sources)
stitch_cycles(ordered_sources, calc_version)
```

where each source includes its own hash/parser identity.

Preserve exactly:

- source order;
- dense observed-cycle mapping;
- `segment` column;
- `source_hash` provenance column;
- incomplete/missing-position fail-closed semantics;
- stable acquisition order within raw source;
- no fabricated local cycles.

Add `source_parser_version` to stitched frame/source-segment metadata only if it materially improves provenance/debugging. Avoid repeating one long parser string on every raw row unless needed; per-segment metadata may be preferable.

## Analysis resolver/provenance

### Ordered source descriptors

Where analysis code currently resolves ordered hashes, extend the resolver so scientific compute can also obtain the parser identity pinned/expected for each source.

Avoid N+1 queries. `preload_cell_sources` and bulk source loaders must retain the state/performance invariants documented in `state-and-performance.md`.

### New provenance shape

Use source-local provenance entries to record parser identity. Conceptually:

```json
{
  "calc_version": "...",
  "sources": [
    {
      "cell_id": 1,
      "file_hashes": ["..."],
      "files": [
        {
          "hash": "...",
          "position": 0,
          "parser_version": "neware-binary:..."
        }
      ]
    }
  ]
}
```

The exact nesting must fit the current provenance owner. Do not duplicate the same arrays in several places merely to preserve a legacy field.

Requirements:

- ordered source hashes remain available for current stale-source comparisons;
- each contributing source parser identity is pinned;
- `CALC_VERSION` remains separately pinned;
- new analysis cache keys change when a contributing source parser identity changes;
- a parser change for an unrelated format/source must not invalidate analyses that do not use it.

### Legacy provenance normalization

Existing saved analyses may carry a single legacy `parser_version` field or a Parent-039 global bundle.

Add deterministic load-time normalization:

- preserve the old value as the parser identity for all sources recorded by that legacy provenance when that is the only truthful historical information available;
- do not rewrite the persisted analysis merely by opening it unless current normalization policy already does so;
- once recomputed under 040.3, persist the new source-specific provenance shape;
- stale/newer-parser badges must compare using normalized provenance without forcing recomputation.

If `analysis_engine.SPEC_VERSION` advances, include focused tests for old-spec loading, normalization and re-save behavior.

## Analysis cache identity

Audit `backend/app/services/analysis_cache.py` and any query/cache key builder.

A scientific analysis result must vary when any contributing source parser identity changes.

Do not use the **current** adapter version blindly for a historical/pinned analysis that explicitly renders old provenance. Preserve the application's existing rule: analyses render from pinned parser/calc versions when the corresponding cache exists; “newer available” is a badge, not a silent recompute.

This means the compute path must be able to request each source's cache at the **pinned source parser identity** from analysis provenance.

## Historical cache loading

This child must preserve reproducibility across parser upgrades.

Required case:

```text
source currently expects parser identity P2
saved analysis provenance pins P1
P1 raw/cycle cache still exists
```

Result:

```text
saved analysis can render using P1 without silently rebuilding/relabeling as P2
```

If P1 cache is missing, preserve current missing-version behavior. Do not reparse current source with P2 and pretend it is P1.

## Portable reports and exports

Audit portable provenance serialization/import.

Portable output must preserve source-specific parser identities when provenance is embedded. Older portable reports with legacy one-parser provenance remain importable/readable according to current compatibility policy.

Do not redesign portable package security or source embedding in this child.

The merge-base schema has `SourceFile.parser_version = String(30)`. Do not add a migration; keep the identity grammar within that existing bound. If implementation discovers a separate persistent fact that genuinely cannot be represented, stop for a parent amendment.
