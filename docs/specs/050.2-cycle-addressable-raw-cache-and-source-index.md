## Goal

Make the **persistent canonical raw scientific cache addressable by source-local cycle** without
changing the scientific content of that cache.

Today a caller that needs a few cycles can project columns with `cache.load_raw_columns()`, but it
cannot avoid materializing the complete Parquet source because the raw writer does not create or
publish a cycle-aware physical layout/index. Child 050.2 establishes that storage/access primitive.
It does **not** yet replace `analysis_engine.compute_time_capacity()`'s current full-stitch path;
that integration belongs to Child 050.3.

The target is:

> Once a source cache has been prepared under the new layout, backend code can resolve an exact set
> of source-local cycles to a bounded set of Parquet row groups and columns, load those groups, and
> return all rows belonging to the requested cycles without reading the rest of the source.

The implementation may measure several physical row-group strategies before choosing one. The
**cycle-addressable contract is locked; the exact row-group target size is deliberately not**.

## Why this is a separate child

This child changes a low-level persistent scientific-cache format and its preparation lifecycle.
The failure modes are different from those of the Time/Capacity analysis itself:

- incorrect row-group/index correspondence could omit scientific records;
- unsafe conversion could damage the only readable cache of an offline source;
- tying the layout to `CALC_VERSION` could invalidate raw data for unrelated calculation changes;
- rewriting raw caches on the request path would simply move the latency problem elsewhere.

The reviewer must therefore be able to prove the storage primitive is correct and safe before
Child 050.3 makes Time/Capacity depend on it.

## Verified current behavior

### 1. Raw caches have no explicit physical-layout version

`backend/app/services/cache.py` currently documents and writes:

```text
CACHE_DIR/<hash[:2]>/<hash>/raw__p<parser>.parquet
CACHE_DIR/<hash[:2]>/<hash>/cycles__p<parser>__c<calc>.parquet
```

`raw_path()` is keyed by source checksum and **per-source parser identity**. `cycles_path()` adds
`CALC_VERSION` because the per-cycle file is derived scientific output.

There is currently no raw-cache physical-layout version or sidecar index.

### 2. The writer does not control row-group organization

`cache._write_atomic()` currently publishes any DataFrame with:

```python
df.to_parquet(tmp, index=False)
os.replace(tmp, path)
```

It does not choose cycle-aware row groups, row-group size, partitions, or a source-cycle index.
Consequently the current cache layout does not promise that a request for cycle 400 can skip the
physical data for cycles 1-399.

### 3. Raw loaders are whole-file or column-only

Current readers are:

```text
cache.load_raw(file_hash, parser_version)
    -> pd.read_parquet(path)

cache.load_raw_columns(file_hash, parser_version, columns)
    -> pd.read_parquet(path, columns=columns)
```

Column projection reduces width but not the current source-wide row materialization requirement.

### 4. Cache building already owns the complete validated frame

`cache.build()` and `cache.build_write_behind()` already have the complete canonical raw DataFrame
in memory when a source is parsed. That is the cheapest and safest point to establish any
cycle-addressable physical layout and source-level access metadata: no second source parse or
request-path scan is necessary.

When only `CALC_VERSION` changes, `cache.build()` deliberately reuses the existing parser-versioned
raw cache rather than rereading the original source. Preserve that separation.

### 5. Existing installations may have only the current legacy raw layout

A user's cache may already contain a valid `raw__p<parser>.parquet` with no new index. The original
source can be online, offline, changed, or absent. Scientific cache cleanup intentionally preserves
a registered source's cache when the source is unavailable because that Parquet data may be the
only locally readable scientific copy.

The new layout must therefore be **backward-compatible and safely preparable from an existing raw
cache without requiring the original source**.

### 6. Current raw stitching discovers cycle labels by scanning raw rows

`stitch.observed_local_cycles()` determines the exact observed numeric source-local labels and
`build_dense_cycle_map()` maps those labels densely into global cycles. Missing local labels are
never invented. `stitch_raw()` obtains those labels only after `cache.load_raw()` has materialized
the whole source.

The cycle-label list is compact metadata and can be established during cache preparation instead.
Child 050.3 will consume it; 050.2 must publish it without changing the mapping rule.

## Locked architecture

### 1. Keep one canonical raw scientific dataset

Do **not** create a permanent second full copy of every source solely for Time/Capacity.

The parser-versioned raw Parquet remains the canonical regenerable raw cache. Child 050.2 may change
its physical row-group layout and add tiny sidecar metadata, but it must not establish parallel
"normal raw" and "Time/Capacity raw" datasets containing the same complete records.

A temporary second file is allowed only during atomic conversion/publication.

### 2. Add an explicit raw physical-layout version

Introduce a cache-format constant owned by the raw-cache layer, for example:

```text
RAW_CACHE_LAYOUT_VERSION
```

Exact spelling may follow the surrounding module if a clearer existing convention exists.

This version describes **physical access layout/index format**, not scientific meaning.

It must be independent of:

- `canonical_cycling.CANONICAL_RAW_VERSION`, which describes canonical field meaning;
- per-source parser identity, which describes adapter + canonical raw semantic identity;
- `CALC_VERSION`, which describes derived scientific calculation meaning;
- `analysis_cache` result schema/generation versions.

The first explicit layout version may treat an existing raw file with no matching index as a
legacy/unprepared layout. Do not rewrite parser identities merely because physical row grouping
changed.

### 3. Preserve the current raw path unless implementation evidence proves a path version is needed

Preferred compatibility shape:

```text
raw__p<parser>.parquet                       # same scientific cache identity
raw_index__p<parser>__l<layout>.json|parquet # tiny regenerable sidecar
```

The sidecar encoding is not locked to JSON versus Parquet. The implementer may choose the simplest
encoding that is deterministic, cheap to read, atomic to publish, and straightforward to validate.
The **logical information contract below is locked**.

Do not add a database column solely to remember this physical layout. File presence + validated
sidecar metadata are sufficient unless implementation evidence proves otherwise; any proposed
relational schema change requires stopping and updating the spec before adding a migration.

### 4. Row groups must be bounded and useful for narrow cycle access

The new raw writer must deliberately create multiple bounded row groups for representative long
sources instead of relying on an uncontrolled writer default.

The implementer must benchmark several plausible row-group targets on representative long data and
record:

- source rows/cycles and Parquet size;
- row-group count and rows/group;
- whole-source read time;
- 1-cycle read time and physical groups read;
- approximately 20-cycle read time/groups;
- a broader few-hundred-cycle read;
- full-range read;
- materialized rows and selected columns;
- peak/working-set memory where measurable.

Do not optimize for a single synthetic tiny fixture. Use at least one representative long real or
approved regression source available to the implementer. If private local production data is used
for timing, record only non-sensitive dimensions/timings in the spec implementation record; never
commit the source.

The exact row-group target is selected from this evidence and recorded in code/comments/tests where
future maintainers can find it. It is **not** a scientific constant and must not enter analysis
cache keys.

### 5. Preserve record content and ordering semantics

Physical optimization must not alter canonical values.

The published optimized raw cache must preserve:

- every column and value produced by the parser for that parser identity;
- every row exactly once;
- `record_index`, `cycle`, `step_index`, `step`, status, time, voltage/current, capacity/energy and
  optional-column semantics;
- null/NaN/timestamp behavior;
- source-local cycle labels, including non-contiguous labels;
- existing downstream ordering semantics.

Do not sort by timestamp. Do not merge, split semantically, synthesize or delete cycles.

If the writer changes physical row order to obtain better grouping, that is a scientific-risking
behavioral change and is **out of scope unless separately justified and parity-proven**. The default
implementation should preserve the existing DataFrame row order and choose row-group boundaries
within that order.

A source-local cycle may span more than one row group when required by row-count bounds. The index
must support one cycle mapping to multiple row groups; correctness is more important than forcing
one-cycle-per-group storage.

### 6. Publish a deterministic source-cycle access index

For each prepared raw cache, publish a tiny index logically containing at least:

```text
layout_version
parser_version
canonical_raw_version (or equivalent validation context)
raw_row_count
raw_column_names
raw_row_group_count

observed_source_cycles: [exact distinct numeric labels in stable sorted order]

row_groups:
  - row_group: int
    row_count: int
    # enough exact information to determine which observed source cycles may occur here

cycle_to_row_groups:
  <source_cycle>: [row_group ids...]

voltage_data_availability:
  voltage_v: bool
  working_potential_v: bool
  counter_potential_v: bool

optional bounded source facts needed later without a full scan:
  timestamp_start: ISO/string/null
  timestamp_end: ISO/string/null
```

Exact serialization shape may differ, but these semantics must be testable.

`observed_source_cycles` must use the same acceptance rules as
`stitch.observed_local_cycles()`:

- numeric;
- finite;
- integer-like;
- exact observed labels only;
- stable sorted order;
- no invented missing labels.

Prefer one shared helper rather than reimplementing cycle-label validation in the index builder and
stitch service independently.

### 7. Voltage availability is full-source data-derived metadata

Spec 040.4 requires Time/Capacity voltage-channel availability to mean: at least one finite value is
actually present in the canonical column for the selected source/selection. This must not be
replaced by schema presence alone.

While the full validated frame is already available during cache build/conversion, compute and
store the finite-data fact for every entry in `canonical_cycling.VOLTAGE_QUANTITIES`.

Examples:

```text
column absent                        -> false
column present but all NaN           -> false
column has >=1 finite numeric value  -> true
```

Do not infer working/counter potential availability merely from format type or header declaration.
Header metadata remains the owner of voltage **role/reference meaning**; this index records bounded
full-source data presence only.

### 8. Timestamp/source descriptor facts may be indexed, not re-scanned

Current Time/Capacity source descriptors may derive source start/end timestamps from the complete
stitched frame. If a timestamp column is present, the raw index may persist bounded source-level
minimum/maximum timestamp facts computed during the same preparation pass.

Do not persist absolute source paths in the index or analysis responses.

### 9. Add a row-group/cycle selective reader

Create one low-level accessor owned by the scientific cache layer (or a narrowly named adjacent
module if keeping `cache.py` readable requires it) with semantics equivalent to:

```python
load_raw_cycles(
    file_hash,
    parser_version,
    source_cycles,
    columns,
) -> DataFrame | None
```

Exact function name/signature may differ.

Requirements:

1. it waits for in-process cache writes using the existing pending-write boundary;
2. it validates/loads the matching current raw-layout index;
3. it resolves requested source-local cycles to only the relevant row groups;
4. it reads only requested columns plus any internal columns needed to filter/restore correctness;
5. it filters the loaded rows to the exact requested cycle set after row-group read, because a row
   group may contain neighboring cycles;
6. it returns **all rows belonging to every requested observed cycle**, preserving their source
   record order;
7. it touches the scientific-cache files so existing LRU accounting still sees use;
8. it does not silently substitute a different parser identity;
9. a missing requested cycle returns no rows for that cycle; it must not be synthesized;
10. malformed/stale index metadata fails safe rather than returning partial/misaligned data.

The accessor must expose enough test/debug instrumentation to assert which row groups/row counts
were read without making timing the only proof of optimization. This can be an internal plan object,
optional diagnostics structure, or mockable row-group reader boundary; do not add user-facing API
noise solely for tests.

### 10. Legacy/unprepared raw caches remain readable

A valid legacy `raw__p<parser>.parquet` with no current index is **not corrupt and not scientifically
stale**.

Child 050.2 must preserve current whole-file readers. The new selective accessor may report
"layout unavailable" / return a distinct fallback signal rather than fabricating an index on the
critical path.

Child 050.3 will use this distinction to choose:

```text
prepared indexed cache -> selective path
legacy valid cache      -> existing full-read path
raw cache genuinely absent -> existing missing-cache behavior
```

Do not classify "index missing" as `cache_missing` in scientific results.

### 11. Never perform full cache conversion on a plot/request critical path

A request discovering an unprepared legacy raw cache must not synchronously:

- parse the original source;
- read the whole raw cache merely to rewrite it;
- calculate a new per-cycle cache;
- block on a multi-hundred-MB conversion before returning a plot.

Layout preparation belongs to normal cache creation or explicit/background scientific preparation.
A request may schedule/mark preparation opportunistically only if that scheduling itself is bounded
and the current request proceeds through the existing safe fallback.

### 12. Existing raw caches can be converted from cache bytes alone

Provide a safe conversion/preparation function for a valid legacy raw cache at an exact parser
identity:

```text
legacy raw parquet
    -> read existing cached scientific records
    -> write candidate optimized raw to a temporary file
    -> build candidate index
    -> validate candidate against original scientific content/metadata
    -> atomically replace raw
    -> publish index last
```

The original source file must not be required for this physical conversion.

Atomicity rule:

- **never publish an index that describes bytes which are not yet the active raw file**;
- publish/replace the raw file first;
- publish the validated index only afterward;
- if the process dies after raw replacement but before index publication, the state is safe:
  valid raw cache + no usable index -> legacy/full-read fallback;
- a failed candidate write/validation must leave the previous raw cache intact.

The index loader must validate enough raw Parquet metadata (e.g. row count/schema/row-group shape or
another deterministic fingerprint) to reject a stale sidecar left beside different bytes.

### 13. Offline sources are protected

A registered offline/changed source may have no readable original file. Its raw cache may be the
only usable copy and must receive stricter handling, not less.

- Never delete its existing raw cache before a validated candidate is complete.
- Conversion from existing raw cache is allowed without source access.
- Existing `cache_maintenance` protection for unavailable sources remains intact.
- Failure to prepare an index must leave the old raw cache usable.
- Do not change `SourceFile.location_status`, `parse_status`, parser identity, cycle counts or
  capacity summaries merely because physical layout preparation failed.

### 14. Historical parser generations stay scientifically gated

Multiple parser-identity raw caches may coexist under one checksum directory for provenance.
Child 050.2 must not treat layout preparation as permission to revive a parser identity that the
canonical-cycling capability layer has retired or marked metadata-only.

It is sufficient for background preparation to guarantee the registered/current usable parser
identity. Historical valid pinned identities may remain legacy and use Child 050.3's safe full-read
fallback unless a later bounded preparation path explicitly upgrades them.

Whatever is implemented, **the presence of a new index must never bypass existing canonical
capability/retired-parser guards**.

## Cache maintenance integration

Keep index/temporary artifacts inside the existing checksum scientific-cache directory so the
current scientific budget, inventory, delete and offline-protection boundaries remain authoritative.

Audit and test at least:

```text
cache_maintenance.inventory()
cleanup_eligible_scientific()
enforce_scientific_limit()
cleanup_offender(kind="scientific", ...)
cache.remove_hash_cache()
cache.pending_hashes() / protect_hash_from_cleanup()
```

Requirements:

- index bytes count as scientific-cache bytes;
- deleting a checksum directory removes raw/index/cycles together as today;
- actively converting a cache is protected from concurrent cleanup;
- no orphan temporary files remain after success/failure;
- access updates continue to make the checksum directory look recently used;
- no new top-level cache category or Settings budget is introduced in this child.

## Background preparation / existing-library behavior

Integrate layout preparation with the existing scientific-preparation architecture rather than
adding a second scheduler.

The implementation must define a bounded predicate for "current raw cache exists but current raw
access layout/index is not prepared" and a background path that can prepare such caches without
blocking list endpoints or ordinary startup rendering.

Do not turn every application startup into a full scan/rewrite of all Parquet bytes.

Acceptable patterns include adapting the existing preparation/backfill work set or adding a bounded
maintenance pass that:

- identifies candidates from compact file/cache metadata first;
- performs expensive conversion only in background;
- is resumable/idempotent;
- respects existing worker/priority limits;
- does not share SQLAlchemy sessions with worker processes/threads;
- does not recreate a scientifically cleaned cache merely because an index is absent.

The exact scheduling mechanism is an implementation decision, but the reviewer must be able to show
that a 1,000-source library is not synchronously rewritten at startup or when opening Time/Capacity.

## Profiling phase — mandatory before choosing row-group parameters

Profiling belongs to the implementer and is part of this child's implementation, not a prerequisite
for writing the spec.

### Baseline measurements

### Candidate-layout measurements

Prototype at least three plausible bounded row-group targets or grouping strategies. For each,
measure the same source with:

```text

~20 cycles
few-hundred-cycle range (or another meaningful broader subset)

```

Record at minimum:

```text

wall time
peak/working-set memory where practical
result equality/parity
```

### Selection rule

Choose a layout that materially reduces narrow-range physical reads without causing unreasonable:

- raw-cache size inflation;
- build/write time;
- full-range read regression;
- row-group metadata explosion;
- thousands of tiny filesystem objects.

Do not choose a row-group target only because it wins one 1-cycle benchmark by a few milliseconds.
The implementation record must explain the trade-off.

## Scientific parity requirements

For the same exact parser identity, the optimized raw cache must be scientifically equivalent to
the legacy raw cache.

Automated parity must cover at least:

- same row count;
- same column set/order unless Parquet round-trip already has a documented stable normalization;
- same `record_index` sequence/order;
- same source-local `cycle` values including gaps;
- same numeric values/null positions for required canonical columns;
- same optional voltage/timestamp columns and null positions;
- same `calc.per_cycle()` output when calculated from legacy versus optimized raw;
- same canonical validation outcome;
- same source finite-voltage availability facts as a full-frame scan.

Use DataFrame-aware equality with appropriate dtype/timestamp handling; do not reduce scientific
parity to a checksum of Parquet file bytes because different row-group encodings are expected to
produce different files.

## Required tests

Add focused automated tests for at least these cases.

### Layout/index creation

1. A synthetic multi-cycle frame produces more than one bounded row group under a deliberately
   small test target and a matching index.
2. Exact observed source cycles are stored; `[1, 2, 4]` remains `[1, 2, 4]`.
3. A cycle spanning multiple row groups maps to all relevant groups.
4. A row group containing multiple cycles maps each cycle to that group.
5. Required/optional columns are recorded correctly.
6. Voltage availability distinguishes absent, all-null and finite channels.
7. Timestamp min/max facts are correct when present and absent when unsupported.

### Selective read

8. Requesting one cycle reads only its mapped row groups, not every row group.
9. Requesting a contiguous range reads the union once, deduplicated.
10. Explicit non-contiguous cycles work.
11. Extra neighboring rows from a shared row group are filtered out after read.
12. Returned requested-cycle rows match the full-frame subset exactly and preserve order.
13. Column projection reads only required columns plus internal cycle/filter columns.
14. Unknown/missing requested cycles return no fabricated rows.
15. Wrong parser identity does not fall through to another identity.

### Compatibility/failure safety

16. Legacy raw with no index remains readable by `load_raw()`/`load_raw_columns()`.
17. Selective accessor reports/falls back safely when the index is absent.
18. Stale/corrupt index is rejected and cannot cause partial data to be returned.
19. Failed conversion leaves original raw bytes/readability intact.
20. Successful conversion publishes raw before index and leaves no temporary files.
21. Conversion works when the original source path is unavailable.
22. Cleanup cannot delete a hash while conversion owns existing protection.
23. Scientific inventory/budget includes the new sidecar bytes.
24. An offline source remains protected from automatic scientific cleanup.
25. No `SourceFile` scientific/lifecycle scalar is changed by a layout-only conversion failure.

### Existing calculations

26. `calc.per_cycle()` parity holds across legacy and optimized raw.
27. Existing stitch tests remain unchanged: dense observed global numbering and missing-middle
    semantics are not modified in this child.

## Acceptance criteria

Child 050.2 is complete only when all of these are true:

### Correctness

- Optimized and legacy raw caches contain the same scientific records/values for the same parser
  identity.
- The index lists exact observed source-local cycles and exact row-group membership without
  inventing missing labels.
- Selective reads return the same rows as filtering the full source frame.
- Voltage finite-data and timestamp index facts match full-frame truth.
- Existing per-cycle calculation output is unchanged.

### Performance structure

- Representative long prepared sources have deliberate bounded row groups rather than one
  uncontrolled whole-source access unit.
- A narrow-cycle selective read demonstrably touches fewer than all row groups when the requested
  cycles occupy only a subset of the source.
- Tests can assert physical groups/rows read, not only elapsed time.
- Exact row-group parameters are justified by recorded implementation profiling.

### Lifecycle safety

- Legacy caches remain scientifically valid and readable.
- No plot request is forced to rewrite a legacy whole-source cache.
- Offline-source conversion cannot destroy its only readable raw cache.
- Cache cleanup/budget/accounting includes the sidecar and cannot race an active conversion.
- No source/parsing/calculation identity is falsely changed by a layout-only operation.

### Scope

- `compute_time_capacity()` still uses its existing path after this child.
- No overview cache or RAM LRU has been introduced.
- No relational migration or scientific-version bump occurred without an explicit amended rationale.
