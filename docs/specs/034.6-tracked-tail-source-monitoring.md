# 034.6 — Tracked-tail source monitoring

**Status:** Plan
**Parent:** [034 — Multi-source cell continuations](034-multi-source-cell-continuations.md)
**Depends on:** 034.3
**Scope:** Scheduled automatic checks inspect only each active Cell’s final ordered source.

## Current behavior

- `backend/app/routers/library.py::_cell_source_files` collects every source from every Test of each
  selected active Cell.
- `start_source_check_job` uses that helper for manual, tray, and scheduled triggers.
- `backend/app/services/source_monitor.py::_run_scheduler` starts metadata scans with
  `trigger="scheduled"` and optional automatic adoption.
- Consequently a continued Cell would repeatedly stat/hash historical files, and scheduled
  auto-update could adopt changes to a source that should be frozen.

## Locked selection rules

Add an explicit source scope to the internal selector/job contract:

- `all_ordered_sources`
- `tracked_tails`

Do not infer scope indirectly from `changed_only`.

| Trigger/operation | Scope |
|---|---|
| scheduled monitor | tracked tails |
| scheduled auto-update | tracked tails |
| retry of scheduled work | the same captured tracked tails |
| manual Check sources | all ordered sources |
| manual Check and update | all ordered sources |
| tray action explicitly initiated by user | all ordered sources |
| portable export preflight | all ordered sources (owned by portable service) |

For each Cell, tracked tail means the final file by Tests ordered by `Test.id`, then
`TestFile.position`. A Cell with no sources contributes no job. Complete Cells remain skipped by
the existing default.

## Concurrency and reorder behavior

- Capture source IDs and hashes when the job starts. A retry must not silently switch to a newly
  reordered tail halfway through one scheduled run.
- A later scheduled run uses the new order.
- If a captured source is detached before adoption, skip it safely and report the reason; never
  attach/adopt it again.
- Preserve current file-stability window, batching, low-impact priority, idle scheduling, retry
  deadlines, and “already running” coalescing.
- Scheduled work must never upgrade an already-running manual all-source job into tail-only or vice
  versa. Store scope in the job snapshot and return it through the activity API.

## Performance

Select tails without N+1 queries. A bounded eager-load or SQL window/subquery is acceptable; add a
query-count assertion if the test harness supports it. The result must be one source per Cell, not
one per Test.

## User-visible activity

Background activity descriptions distinguish:

- “Checking current source for N cells” for scheduled tail scans;
- “Checking all N source files” for explicit integrity scans.

Per-file statuses continue to describe the actual file. Historical sources keep their last known
status; they are not falsely marked online merely because the scheduled scan skipped them.

## Acceptance

- A three-source active Cell contributes one scheduled job item: its final source.
- Two active Cells contribute at most two tail items regardless of historical source count.
- Manual check/update includes all sources.
- Complete Cell filtering and explicit `include_complete` behavior remain unchanged.
- Reorder affects only subsequent jobs; in-flight jobs stay deterministic.
- Scheduled adoption cannot update a detached or historical source.
- Activity text and job metadata state the actual scope.
