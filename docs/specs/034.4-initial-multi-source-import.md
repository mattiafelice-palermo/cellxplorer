# 034.4 — Initial multi-source import

**Status:** Plan
**Parent:** [034 — Multi-source cell continuations](034-multi-source-cell-continuations.md)
**Depends on:** 034.2, 034.3
**Scope:** Inbox/import UX for creating one Cell from an ordered source chain.

All UI work must follow
[`../agent-knowledge/visual-style-guide.md`](../agent-knowledge/visual-style-guide.md).

## Current behavior

`frontend/src/pages/InboxPage.tsx::ImportModal` maintains one `ImportDraft` per selected source,
says “One selected file will become one cell,” and submits `drafts.map(...)` to
`POST /api/imports/cells`. The Inbox also displays an Alert saying concatenation is intentionally
unsupported. Existing file/folder selection, metadata preview, raw-data preview, replicate
grouping, presets, and folder placement must remain intact.

## Target workflow

When at least two sources are selected, the import modal offers:

- **Separate cells** — current behavior and default for unrelated batch imports.
- **One continued cell** — one Cell/Test with the ordered sources.

Remember the choice only for the open modal; do not persist a global preference.

### Continued-cell editor

Show:

1. one Cell name, description, Test name, scientific overrides, presets, and folder targets;
2. an ordered source list with filename, detected start/end time, local cycle range/count,
   protocol summary/signature status, and findings;
3. a clear `Historical source` label on every non-final entry and `Tracked tail` on the final
   entry;
4. **Use suggested order** when the server suggestion differs;
5. drag handles plus keyboard-accessible Move up/Move down actions;
6. explicit checkboxes for findings requiring acknowledgement;
7. blocking findings adjacent to the affected source and a disabled primary action;
8. import/parse progress using the existing job/progress style.

The word “merge” may appear in explanatory copy, but the UI must say originals remain separate and
CellXplorer is creating a virtual continued Cell.

### Shared component extraction

Avoid further growth of `InboxPage.tsx`:

- create `frontend/src/components/ContinuationSourceList.tsx` for ordered entries/findings/tracked
  tail presentation;
- extract the existing reusable filesystem selection modal into
  `frontend/src/components/ImportFilesystemPickerModal.tsx` so 034.5 can select more sources
  without duplicating browse/Tauri behavior;
- keep import-plan state transitions in `frontend/src/continuationPolicy.ts`, not inline effects.

If extracting the picker would materially rewrite unrelated Inbox behavior, preserve its visible
contract and cover the extraction with focused tests; do not redesign it.

## Important product rules

- Replicate grouping applies only to Separate cells mode. In One continued cell mode, hide or
  disable it with a short explanation; multiple sources are not replicates.
- Cell metadata defaults to the first source in the current order but remains explicit editable
  Cell data. Reordering later must not silently rewrite entered values.
- Adding/removing/reordering selected sources re-runs inspection. Preserve acknowledgement only
  for finding IDs that still exist unchanged.
- The submitted order is exactly the visible order.
- The final visible source is the tracked tail.
- Do not allow a source already registered to another Cell.
- If submission reports a changed hash/new finding, keep the modal open, refresh findings, and do
  not partially clear the draft.
- Remove the obsolete “Concatenating…left out” Alert and update all one-file wording.

## Loading, failure, and accessibility

- Display inspection/parsing progress immediately; never show an empty editor that looks ready.
- A pending source cannot be submitted.
- Long paths/filenames truncate with full value in a tooltip.
- Reordering works without drag-and-drop.
- Findings use icon + text, not color alone, and remain legible in dark mode.
- Primary button follows the existing teal/blue application channel token; warnings stay semantic
  amber/red rather than Beta branding.
- Focus returns predictably after reorder/removal and the modal has labelled controls.

## Acceptance

- Separate-cell import is behaviorally unchanged.
- Continued mode creates one request with one Cell and ordered `sources[]`.
- Suggested/manual order, tracked tail, compatibility findings, and acknowledgements are visible.
- Replicates cannot be confused with continuation sources.
- Existing metadata/raw preview and folder placement remain available.
- Submission failure cannot leave the UI claiming a partial success.
- Light/dark, truncation, keyboard reorder, and loading/error states follow the visual contract.
