# 034.4 — Initial multi-source import

**Status:** Plan — architecture corrected 2026-07-31  
**Parent:** [034 — Multi-source cell continuations](034-multi-source-cell-continuations.md)  
**Depends on:** 034.2, 034.3  
**Scope:** Inbox/import UX for creating one Cell from one ordered source chain.

All UI work must follow
[`../agent-knowledge/visual-style-guide.md`](../agent-knowledge/visual-style-guide.md).

## Locked product model

The user creates either separate Cells or one continued Cell. There is no user-facing Test entity.

```text
One continued Cell
├── source 1
├── source 2
└── source 3
```

The existing `Test` table remains an internal compatibility container. Continued import creates
exactly one internal Test row and links every selected source to it. The form must not show or submit
a Test name.

## Current behavior to correct

The first implementation added Separate cells / One continued cell selection and an ordered source
editor, but it still stores a `test_name` and describes the result as one Cell/Test. Remove this
terminology and contract without changing separate-cell import behavior.

## Target workflow

When at least two sources are selected, offer:

- **Separate cells** — existing default for unrelated batch imports.
- **One continued cell** — one Cell with one ordered source chain.

Remember the choice only for the open modal.

### Continued-cell editor

Show:

1. one Cell name, description, scientific overrides, presets, and folder targets;
2. one ordered source list with filename, detected start/end time, observed local cycle range/count,
   protocol summary/signature status, and findings;
3. `Historical source` on every non-final entry and `Tracked tail` on the final entry;
4. Use suggested order when it differs;
5. drag plus keyboard Move up/down actions;
6. remove action for accidentally selected sources;
7. explicit acknowledgement checkboxes where required;
8. blocking findings adjacent to affected sources and a disabled primary action;
9. import/parse progress using existing job/progress patterns.

Do not show:

- Test name;
- Target Test;
- Test cards;
- per-Test tails;
- any explanation implying that protocol changes create separate Tests.

The UI may explain that originals remain separate and CellXplorer creates a virtual continuous Cell.

## Shared component rules

- Keep `ContinuationSourceList.tsx`, `ImportFilesystemPickerModal.tsx`, and
  `continuationPolicy.ts` as shared focused units.
- Avoid broad growth of `InboxPage.tsx`.
- Preserve existing file/folder selection, metadata preview, raw preview, folder placement, presets,
  and separate-cell replicate grouping.

## Important product rules

- Replicate grouping applies only to Separate cells mode.
- Cell metadata lives in one dedicated `continuedCellDraft`, independent of source order and source
  preview selection.
- Reordering, opening raw data, or changing the previewed source must not alter Cell metadata.
- Source actions use stable `staged_name`, never correspondence between differently ordered arrays.
- Adding/removing/reordering sources reruns inspection.
- Preserve acknowledgement only when the exact semantic finding remains unchanged.
- The submitted order is exactly the visible order.
- The final visible source is the one tracked tail.
- Protocol differences are expected restart findings and are not a reason to split the Cell.
- Submission conflicts keep the modal open, preserve the Cell draft, and refresh findings.
- Remove obsolete one-file/concatenation wording.

## Loading, failure, and accessibility

- Poll/refetch while inspection is incomplete or cache preparation is pending.
- Stop polling on ready, stable failure, modal close, or proposal change.
- A pending source cannot be submitted.
- Long values truncate with full tooltip/title.
- Reordering/removal works without drag-and-drop.
- Disabled/submitting state blocks drag, drop, keyboard movement, and removal.
- Findings use icon plus text and remain legible in dark mode.
- Focus returns predictably after reorder/removal.

## Acceptance

- Separate-cell import is unchanged.
- Continued mode creates one Cell request with ordered `sources[]` and no user-visible Test field.
- Backend creates/reuses one internal Test row only.
- Cell metadata is stable across reorder and source previews.
- Sources can be removed/reordered and inspection converges automatically.
- Suggested/manual order, one tracked tail, findings, and acknowledgements are visible.
- Protocol mismatch never creates or suggests another Test.
- Existing metadata/raw preview and folder placement remain available.
- Submission failure cannot claim partial success.
