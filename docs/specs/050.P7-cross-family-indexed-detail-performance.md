## Historical purpose

The question was whether Steps, DCIR, Chargeability and Rate Capability could avoid full-source raw materialization on genuine analysis-result-cache misses by planning exact protocol executions first and then reading only implicated Parquet row groups/columns.

Cycles was the reference/control because interactive cycle quantities are already served from prepared per-cycle summaries rather than point-level raw traces.

## Historical observations to preserve

The accepted 050.2/050.3 architecture provided bounded raw Parquet row groups, a validated source-layout index, exact observed source-local cycles, cycle-to-row-group mapping and safe selective cycle access.

The former 050.8 investigation observed potential opportunities in:

- **Steps:** configured protocol targets can often be identified before full `stitch_raw()` materialization;
- **DCIR:** rest/pulse targets can be identified early, provided exact adjacency/completeness context is retained;
- **Chargeability:** measurement/reference step identities can be resolved from protocol information before full raw loading;
- **Rate Capability:** paired charge/discharge protocol steps can be resolved before execution extraction;
- **Cycles:** should remain a prepared/result-cache control rather than being forced through raw-detail access.

These observations may inform 050.16, but 050.16 must re-measure the current branch and is free to reject them.

## Historical architecture idea

The old design proposed:

1. preserve exact persisted analysis-result-cache hits as the primary reopening path;
2. add a small regenerable step-index -> raw-row-group access sidecar;
3. build/rebuild it from validated cache bytes or an already available canonical frame, never by reopening original source files on an interactive request;
4. add one bounded exact detail reader that loads implicated row groups/columns then filters exact logical rows;
5. take the current complete legacy path immediately when metadata is absent, stale, corrupt or busy;
6. keep scientific planning in family owners rather than inventing one generic protocol-analysis engine;
7. enable indexed production access per family only when both structural and wall-time evidence support it.

050.16 retains only those ideas that still survive current profiling and adds the later Spec 050 lessons that P7 did not know about.

## Scientific boundaries retained as historical constraints

### Steps

Selective reads must include complete selected step executions and preserve occurrence numbering, direction/rest semantics, quantities, labels, provenance and badges.

### DCIR

Every row required for current reference/rest, pulse, duration, adjacency and completeness checks must be present. Do not change formula, filters or sign conventions.

### Chargeability

Preserve execution grouping, reference capacity, SoC derivation, current/C-rate conversion, normalization, fingerprints and provenance.

### Rate Capability

Preserve current charge/discharge pairing, CC/CV companion requirements, cutoff validation, sweep recognition and extraction.

### Cycles

Use as cache-native control. Do not introduce raw-detail access for architectural symmetry.

## Historical cache/lifecycle constraints

- access metadata is optional/regenerable;
- interactive requests never wait for access-index preparation;
- original source files are not reopened merely to prepare performance metadata;
- stale metadata cannot remain authoritative after raw replacement;
- canonical raw bytes do not change solely to add an index;
- no relational migration is implied.
