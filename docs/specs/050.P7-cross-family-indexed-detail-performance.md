## Purpose

Retain the former 050.8 design question while deprioritizing it behind the cross-Cell execution study now owned by 050.9-050.11.

The question is whether Steps, DCIR, Chargeability and Rate Capability can avoid full-source raw materialization on genuine analysis-result-cache misses by planning exact protocol executions first and then reading only implicated Parquet row groups/columns.

Cycles remains the reference/control because interactive cycle quantities are already served from prepared per-cycle summaries rather than point-level raw traces.

This proto authorizes no code change.

## Motivation to re-verify on promotion

The accepted 050.2/050.3 architecture provides bounded raw Parquet row groups, a validated source-layout index, exact observed source-local cycles, cycle-to-row-group mapping and safe selective cycle access.

Protocol-derived families often know relevant step/execution identities before point-level rows are required. The former 050.8 investigation therefore proposed a small step-index-to-row-group access index and family-specific planners.

The old prototype observed potential opportunities in:

- **Steps:** configured protocol targets can often be identified before full `stitch_raw()` materialization;
- **DCIR:** rest/pulse targets can be identified early, provided exact adjacency/completeness context is retained;
- **Chargeability:** measurement/reference step identities can be resolved from protocol information before full raw loading;
- **Rate Capability:** paired charge/discharge protocol steps can be resolved before execution extraction;
- **Cycles:** should remain a prepared/result-cache control rather than being forced through raw-detail access.

These are historical observations. Re-inspect them against current code if P7 is promoted.

## Leading architecture if still justified

1. preserve exact persisted analysis-result-cache hits as the primary reopening path;
2. add only a small regenerable **step-index -> raw row-group** access sidecar, separately versioned from scientific/cache meaning;
3. build/rebuild it from validated cache bytes or an already available complete canonical frame, never by reopening original source files on an interactive request;
4. add one bounded exact detail reader that loads implicated row groups/columns then filters exact logical rows;
5. take the current complete legacy path immediately when metadata is absent, stale, corrupt or busy;
6. keep scientific planning in family owners rather than inventing one generic protocol-analysis engine;
7. enable indexed production access per family only when both structural and wall-time evidence support it.

The access sidecar is physical metadata, not a prepared scientific result, and does not itself justify a `CALC_VERSION` bump.

## Scientific boundaries

### Steps

Selective reads must include complete selected step executions and preserve source/continuation/global-cycle order, occurrence numbering, direction/rest semantics, quantities, labels, provenance and badges.

### DCIR

Every row required for current reference/rest, pulse, duration, adjacency and completeness checks must be present. If exact context cannot be proven from a reduced plan, use the legacy full-raw path. Do not change formula, filters, sign conventions or payload semantics.

### Chargeability

A planner may use reconstructed protocol/candidate information to identify measurement and reference/preparation steps before raw loading, but must preserve execution grouping, reference capacity, SoC derivation, current/C-rate conversion, normalization, fingerprints and provenance.

### Rate Capability

A planner may derive measurement and paired charge/discharge step identities before loading raw detail, including CC/CV companions required by existing completion validation. Current pairing/sweep recognition/extraction remains authoritative.

### Cycles

Use as cache-native control. Do not introduce raw-detail access for architectural symmetry.

## Required evidence after future promotion

Profile the then-current production branch before implementation and compare indexed vs forced-legacy behavior per family.

At minimum record:

- exact persisted result-cache hit behavior;
- row groups/rows/columns physically read;
- backend wall time;
- family planning/extraction time where material;
- access-index preparation/fallback behavior;
- peak memory where relevant;
- complete scientific payload/golden parity;
- continuation/provenance parity.

Read reduction by itself is not acceptance. A path can read substantially fewer groups and still show little wall-time benefit.

## Cache/lifecycle constraints

- metadata is optional/regenerable;
- interactive requests never wait for access-index preparation;
- original source files are not reopened merely to prepare performance metadata;
- stale metadata cannot remain authoritative after raw replacement;
- canonical raw bytes do not change solely to add this index;
- 050.6 prepared Time/Capacity data is not invalidated solely for this proto;
- no relational migration is implied.
