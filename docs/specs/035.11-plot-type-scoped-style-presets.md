## Goal

A preset relevant to one plot type must not appear for unrelated plots or apply incompatible axis
settings. Universal presets remain reusable but are restricted to visual properties that are truly
safe across plot families.

## Universal versus family presets

### Universal preset (`plot_family: "all"`)

May contain only shared visual presentation, subject to actual support in every target plot:

- font family/sizes/weights;
- general line width/style;
- marker size/symbol;
- primary categorical palette/custom sample colors where the target supports them;
- legend visibility/layout/position;
- plot/background/grid appearance that is genuinely shared;
- export dimensions/presentation settings that do not alter data or axes.

Must not contain or apply:

- x/y/y2 titles;
- axis ranges/modes/ticks;
- `axis_scopes`;
- secondary-axis family behavior;
- CE-specific palette/style;
- quantity-specific trace colors/settings;
- Steps/DCIR/Chargeability/C-rate scientific or detector settings;
- any `computation`, `presentation.quantity`, protocol, filter, or selected-series field.

Implement an explicit allowlist, not a blacklist.

### Family preset

May store the full style state valid for that family, including its scoped axes and supported
family-specific presentation fields. It still must not store scientific-computation settings.

A family preset is offered only when its family equals the active plot family.

## Backend data and compatibility

Presets remain JSON in `AppSetting`; no database migration.

Expand Pydantic/API literals. Add a normalization helper, preferably in a focused service or
settings-policy module:

```python
def normalize_plot_style_preset(preset: dict) -> PlotStylePreset:
    ...
```

Rules:

- missing legacy family defaults to `all`;
- existing `cycles` and `time_capacity` remain unchanged;
- existing `all` presets remain loadable;
- legacy universal unsafe fields are ignored on application through the universal allowlist;
- optionally report `ignored_legacy_fields` in read responses or derive a frontend warning without
  changing stored data until save;
- saving Settings rewrites normalized safe JSON;
- one default is allowed per family, including `all`;
- duplicate names are scoped by family as today;
- invalid/unknown family on write returns a clear 422;
- one malformed stored preset must not silently make the endpoint return an empty list and hide all
  unrelated valid presets.

For malformed persisted JSON:

- if the top-level JSON is unreadable, retain the existing safe fallback and expose/log one useful
  diagnostic through existing patterns;
- if individual entries are invalid, normalize valid entries and surface enough warning information
  for Settings to tell the user that specific presets were skipped;
- never execute/evaluate stored content.

## Universal allowlist implementation

Implement pure functions in both layers only where necessary:

```text
frontend/src/plotPresetPolicy.ts
backend/app/services/plot_style_presets.py   # optional if backend sanitizes writes
```

Frontend functions should include:

```ts
sanitizeUniversalPlotStyle(style: Partial<PlotStyle>): Partial<PlotStyle>
applyPlotPreset(current, preset, activeFamily, options): PlotStyle
availablePlotPresets(presets, activeFamily): PlotStylePreset[]
```

Applying a universal preset must leave every non-allowlisted field byte-for-byte unchanged,
including all axis scopes.

Backend write validation should prevent newly saved universal presets from retaining unsafe fields;
frontend filtering alone is insufficient for API callers.

## Shared frontend selector

Extract a reusable component:

```text
frontend/src/components/PlotStylePresetSelector.tsx
```

Responsibilities:

- filter Universal plus active family;
- label scope clearly;
- apply universal preset through the allowlist;
- apply family preset through current range/tick options where relevant;
- save current style as:
  - active family by default;
  - Universal only through an explicit choice;
- show default marker;
- loading/error/empty states;
- clear an incompatible selected preset ID when active family changes.

Use it inside the existing `PlotStylePanel` rather than maintaining a second Cycles/Time-capacity
implementation.

## Specialized plot families

For Steps, C-rate, Chargeability, and DCIR:

- add a compact preset selector to the existing plot/settings toolbar;
- do not copy the entire Cycles style panel;
- use the current tab’s scoped style owner and final Plotly layout/trace builders;
- do not move detector, protocol, series-selection, or scientific settings into presets;
- do not claim a universal/family field was applied if that specialized plot ignores it.

For each specialized family, document and test the supported style subset. When a shared visual
property is currently absent:

- wire the final layout/trace builder to the existing `PlotStyle` field if this is small and
  consistent; or
- omit that field from that family’s applicable subset.

Do not introduce parallel plot-rendering implementations.

## Settings editor

The preset table/editor must:

- show family as a column/badge;
- filter by family;
- create/edit/delete without moving a preset to another family accidentally;
- require an explicit confirmation when changing an existing preset’s family if that remains
  allowed;
- warn when a legacy universal preset contained ignored axis/family-specific fields;
- allow one default per family;
- preserve valid presets when another stored item is malformed;
- keep long names usable and keyboard accessible.

Universal creation copy must say that axes and plot-specific settings are not included.

## Application semantics

- Cycles sees Universal + Cycles only.
- Time/capacity sees Universal + Time/capacity only.
- Steps sees Universal + Steps only.
- C-rate sees Universal + C-rate only.
- Chargeability sees Universal + Chargeability only.
- DCIR sees Universal + DCIR only.
- Switching tabs clears an incompatible selected preset ID from local selector state.
- Applying Universal leaves all axis and family-specific fields unchanged.
- Applying a family preset affects only the active family’s scoped style.
- Applying one family preset does not overwrite another family’s `axis_scopes` entry.
- Saved plots and portable reports use the resulting normal Analysis spec; no separate preset
  dependency is embedded.
- Presets are editing conveniences. Existing saved plots do not retain a live link to the preset.
- Deleting or editing a preset does not retroactively change saved plots.

## Cache, schema, and scientific consequences

- No migration.
- No `CALC_VERSION` bump.
- No analysis result-schema bump solely for style storage.
- Rendered artifact cache invalidation follows the existing Analysis-spec/style signature; verify it
  rather than adding global invalidation.
- Portable report rendering must use the final saved style exactly as the app does.
