## Goal

Add persisted, accessible series ordering inside each existing quantity group and propagate that order to the **real Plotly legend**.

This child does not change the selection/bulk-editing model from 046.1 and does not add the detached legend preview; that belongs to 046.3.

## Current anchors after 046.1

### `frontend/src/features/analyses/editor/plotting/SeriesStyleModal.tsx`

The Series panel already has `seriesGroups` grouped by plot and quantity/axis, concrete selection/checkboxes from 046.1, and preview-only eye toggles. `dnd-kit` is already a dependency and already used in this modal for palette swatches.

Use the existing group boundaries. Do not create another quantity model.

### `frontend/src/features/analyses/editor/plotting/seriesStyling.ts`

`SeriesDescriptor.key` is the stable presentation identity. Existing palette-slot logic deliberately identifies series independently of their displayed row order.

### `frontend/src/api.ts`

`PlotStyle` is the persisted presentation object used by saved plots. Ordering belongs there rather than in local modal-only state.

## A — Persisted order field

Add the optional additive field:

```ts
series_order?: string[];
```

If a current naming convention requires a minor spelling change, keep the exact semantics below and update the spec/review references consistently.

This is presentation state, not scientific sequence. No migration or `CALC_VERSION` bump.

## B — Pure effective-order helper

Add a React-free helper in `seriesStyling.ts` or a tightly related plotting-policy module, conceptually:

```ts
orderedSeriesDescriptors(descriptors, storedOrder)
```

Required behavior:

1. known keys present in `storedOrder` appear in stored order;
2. known descriptors absent from `storedOrder` follow in their normal descriptor order;
3. stale/unknown stored keys are ignored;
4. duplicate stored keys never duplicate rows;
5. inputs are not mutated;
6. output is deterministic.

Do not alter the existing quantity-group order.

## C — Group-local reordering

Add a compact drag handle to each concrete row in the expanded Series panel.

Use the existing `dnd-kit` stack rather than a new dependency.

A row may only reorder inside its current `seriesGroups` quantity.

### Same-group drop

Update that group's relative key order and persist the resulting preference list through the current scoped `PlotStyle.series_order` update path.

Keys belonging to every other quantity retain their relative order.

### Cross-group drop

Reject/no-op safely. Never move a series into another quantity, axis, or plot.

### Tab behavior

Reordering is not an edit-selection action. Dragging must not force Rules or Palettes back to Series.

## D — Keyboard accessibility

Use the established `dnd-kit` keyboard sensor / sortable coordinate pattern, or another existing repository pattern with equivalent keyboard behavior.

Every move handle needs an accessible name identifying the series. Hover must not be the only way to discover or use reordering.

## E — Persist through normal plot-style state

Ordering must survive:

- closing/reopening Series appearance;
- saving/restoring the plot;
- normal analysis spec serialization.

If current plot-style normalization drops unknown optional fields, extend that existing normalization minimally. Do not create another storage location.

## F — Reordering must not recolour series

This is a hard regression guard.

The existing palette-slot/entity identity remains authoritative. Changing row order must not change any series' colour.

Likewise:

- applying/editing a palette must not erase `series_order`;
- changing `series_order` must not rewrite palette/custom-colour state.

Add a focused pure test pinning colour-slot identity before and after order changes.

## G — Real legend order, not scientific trace z-order

The requirement is presentation ordering in the legend. Prefer deterministic Plotly `legendrank` or the current equivalent computed from the effective order.

Do not reorder trace arrays solely to change legend order if doing so changes which overlapping scientific trace is painted on top.

Quantity order in the legend remains the existing group order, then user order within that group.

## H — Supported figure-builder propagation

Propagate effective legend order through the canonical trace/figure builders for every analysis family that already supports Series appearance and has corresponding legend entries.

Do not add family-specific modal state. Do not broaden Series appearance to a previously unsupported family in this child.

## I — Series panel rendering

Expanded rows render in effective stored order. If collapsed mode shows concrete rows, it must use the same order.

Long labels continue to truncate rather than widening the modal.

## Tests

Add focused tests covering:

### Order normalization

- stored known order respected;
- new descriptors appended in original order;
- stale keys ignored;
- duplicate stored keys do not duplicate rows;
- inputs not mutated.

### Group-local move

If extracted as a pure helper:

- same-group reorder changes only that group;
- other groups preserve relative order;
- cross-group move is rejected/no-op.

### Colour identity

Reordering descriptors leaves palette-slot identity unchanged for the same primary/secondary keys.

### Legend order mapping

Effective order maps deterministically to the Plotly legend ranking/order metadata used by figure builders.

All 046.1 tests remain green.
