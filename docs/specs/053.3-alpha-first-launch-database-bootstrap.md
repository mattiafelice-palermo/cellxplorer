## 1. Goal

Give CellXplorer Alpha its own blocking first-launch setup flow with exactly three choices:

- **Start empty**
- **Copy the Stable library**
- **Copy the Beta library**

The copy must carry the user's Cells and their ordered SourceFiles, Analyses and saved plots,
Folders/Projects, replicate groups, and app-managed `imports/` payload into `.cellxplorer-alpha`,
leave the source product completely untouched, and establish no ongoing synchronization.

Achieve this by **generalizing the verified Beta bootstrap machinery over a source channel**, not by
forking a second copy of it. Beta's released behavior, marker filenames, endpoints, and decision
semantics must not change.

## 2. Why this child exists

Parent 053 originally forbade any Alpha copy of Stable or Beta data (§6.1, §13). The user amended
that on 2026-08-27. Children 053.1 and 053.2 were implemented and reviewed under the original rule
and are not reopened by this child; the amended §6.1 is the governing requirement from here on.

## 4. Locked model

### 4.1 Source channels

Alpha's setup flow offers exactly two copy sources — `stable` and `beta` — plus start-empty.
Source selection is an explicit three-value decision; there is no default source and no
"whichever exists" inference. Alpha is never a copy source. Stable and Beta never gain a copy flow.

### 4.2 Generalize, do not fork

Rework the existing modules so the source channel and the destination channel are parameters:

- replace `stable_library_root` / `stable_database_path` / `inspect_stable_database` with
  channel-parameterized equivalents (for example `source_library_root(channel)`,
  `source_database_path(channel)`, `inspect_source_database(channel)`), keeping thin
  Stable-named wrappers only where existing call sites justify them;
- rename `StableInspection` to a source-neutral name carrying the inspected channel, or add the
  channel field; every inspection result must say which product it describes;
- `stage_stable_copy` becomes a source-parameterized `stage_source_copy(db, source, …)`;
- `beta_is_pristine` becomes a destination-parameterized pristine check;
- the Rust `live_beta_is_pristine`, `bootstrap_gate_required`, `resolve_and_verify_stage*`,
  `activate_staged_copy`, and marker helpers take the destination root and marker names as
  parameters rather than assuming Beta.

Do not create `alpha_bootstrap.py`, `alpha_bootstrap.rs`, or an `AlphaBootstrapCoordinator` that
duplicates existing logic. One implementation, two destinations.

### 4.3 Beta compatibility is byte-exact

Beta's observable contract must not change:

- marker filename stays `beta-bootstrap.json` and apply-failure stays
  `beta-bootstrap-apply-error.json` in `.cellxplorer-beta`;
- `MARKER_SCHEMA_VERSION` and `MANIFEST_SCHEMA_VERSION` stay `1` for Beta, and an existing Beta
  marker written by a released build must still be accepted unchanged;
- `/api/beta-bootstrap/*` paths, payload field names, and status codes stay exactly as they are;
- `apply_beta_bootstrap` and `beta_bootstrap_gate_required` keep their command names and Beta gating;
- Beta's decision vocabulary (`copied`, `empty`, `current`) is unchanged;
- `SCIENTIFIC_PREPARATION_KEY` keeps its literal value `beta.scientific_preparation`. It is a
  persisted `app_settings` key inside copied databases; renaming it would strand in-flight Beta
  preparations and require a migration. Document that the name is historical and channel-neutral in
  meaning.

### 4.4 Alpha-local naming

Alpha uses its own marker filenames inside `.cellxplorer-alpha`:

```text
.cellxplorer-alpha\alpha-bootstrap.json
.cellxplorer-alpha\alpha-bootstrap-apply-error.json
.cellxplorer-alpha\bootstrap\<token>\
```

A file named `beta-bootstrap.json` must never appear in the Alpha root. The `bootstrap/` staging
subdirectory name, staged database name, manifest name, lock name, token format, and 24-hour stage
retention are shared and unchanged.

### 4.5 Alpha decision vocabulary

The Alpha marker records exactly one of:

```text
empty
copied-stable
copied-beta
current
```

`current` keeps its existing meaning (acknowledge an already-populated destination library without
copying). The marker additionally records the source channel, the source database instance UUID,
and the source schema revision for a copy decision, using the existing marker fields plus one
explicit `sourceChannel` field.

## 5. Status contract

Generalize the status payload so per-source facts are per source rather than Stable-only.

For Alpha, `GET /api/alpha-bootstrap/status` must return, in addition to the existing
setup-state/decision/pristine/marker/stage/preparation fields:

```jsonc
{
  "channel": "alpha",
  "sources": [
    {
      "channel": "stable",
      "productName": "CellXplorer",
      "databasePath": "C:\\Users\\example\\.cellxplorer\\cellxplorer.db",
      "exists": true,
      "compatible": true,
      "blockingReason": null,
      "schemaRevision": "…"
    },
    { "channel": "beta", "productName": "CellXplorer Beta", "…": "…" }
  ]
}
```

Rules:

- both source entries are always present, in the fixed order `stable`, `beta`;
- `compatible` is false with an exact human-readable `blockingReason` when the source is missing,
  empty, corrupt, unrecognized, or its schema revision is newer than this Alpha build supports;
- a blocked source never blocks the other source or `Start empty`;
- `blockingReason` names the product, not just "the library";
- Beta's existing `stableDatabaseExists` / `stableDatabaseCompatible` / `stableDatabasePath` /
  `copyBlockingReason` fields remain in the Beta payload unchanged. The Alpha payload may carry the
  new `sources` array only, or both, but must not silently change Beta's field meanings.

## 6. API surface

Add an Alpha router mirroring the Beta one, gated to the Alpha channel with 404 off-channel:

```text
GET  /api/alpha-bootstrap/status
GET  /api/alpha-bootstrap/preparation-status
POST /api/alpha-bootstrap/preparation-background
POST /api/alpha-bootstrap/stage-copy      { "source": "stable" | "beta",
                                            "confirmReplaceExistingLibrary": bool }
POST /api/alpha-bootstrap/discard-stage   { "token": "…" }
POST /api/alpha-bootstrap/start-empty
POST /api/alpha-bootstrap/use-current
```

Both routers must delegate to the same generalized service functions. `stage-copy` rejects a
missing, unknown, or `alpha` source with 422 before any staging work begins. The Beta router keeps
its exact current request/response shapes; adding a source field to the **Beta** endpoint is out of
scope.

## 7. Snapshot rules

Reuse Spec 022 §8–§9 exactly, with the source generalized:

1. resolve the source root from the source channel helper, never from a caller-supplied path;
2. assert the source is exactly that channel's `cellxplorer.db`, and assert the staging directory is
   under `.cellxplorer-alpha\bootstrap\<token>\`;
3. open the source read-only; require `PRAGMA integrity_check` = `ok`;
4. reject a source schema revision newer than this Alpha build supports;
5. copy with `sqlite3.Connection.backup()`; integrity-check the staged file;
6. write a **new** database instance UUID into the staged copy; never retain the source UUID;
7. write the pending scientific-preparation marker into the staged copy;
8. rewrite only the `source_files.path` rows that pointed inside the **source product's**
   `imports/` so they point inside `.cellxplorer-alpha\imports\`; leave external paths untouched;
9. copy those managed import payloads into the staged `imports/`, verifying size and SHA-256 against
   the database checksum where available;
10. re-verify the source database SHA-256 **and** mtime are unchanged after copying, and fail with a
    retryable error that names the source product if it changed;
11. record source channel, source instance UUID, source revision, copied-import inventory, and the
    staged digest in the manifest;
12. `PRAGMA journal_mode=DELETE` and remove sidecars so exactly one plain file is handed over.

Never copy `cache/`, `logs/`, `backups/`, `downloads-history.json`, pending portable-import staging,
temporary files, or `-wal` / `-shm`. Alpha regenerates caches normally.

**Live-source safety.** Beta may be running while Alpha copies it. The read-only open plus the
digest/mtime re-verification is the contract; do not add locking to another product's root, do not
signal or stop another product's process, and do not write anything — not even a lock file — outside
`.cellxplorer-alpha`.

## 8. Activation

Reuse the existing Rust activation path with the destination generalized:

- validate the token, manifest, staged digest, and staged file inventory before stopping the backend;
- refuse unexpected staged content;
- move the live database and `imports/` aside to the existing rollback names, move the staged
  content in, write the marker, then delete the rollback copies;
- on any failure, restore the rollback content and write the apply-failure marker;
- relaunch through `src-tauri/src/relaunch.rs`, never a fixed sleep or `AppHandle::restart()`;
- expose the Alpha commands as `apply_alpha_bootstrap(token, confirm_replace_existing_library)` and
  `alpha_bootstrap_gate_required`, or as channel-generic commands that fail closed for Stable.
  Whichever shape is chosen, Stable can invoke neither, and Alpha can invoke neither Beta command.

### 8.1 Alpha install-instance acknowledgement

`beta_installer::current_beta_install_instance_id()` reads `InstallInstanceId` from the uninstall
key hardcoded to `BETA_PRODUCT_NAME`, and `main.rs` passes `None` for every non-Beta channel. Alpha
therefore currently has no install-instance identity, which would weaken
`marker_acknowledges_install` for Alpha.

Add a channel-scoped lookup that reads **the running product's own** uninstall key
(`CellXplorer Alpha` for Alpha), and pass it where `main.rs` currently passes `None`. Reading
another product's uninstall key remains forbidden by Parent 053 §6.2; this reads only Alpha's own.
Behavior when the value is absent (source builds, portable runs) must match Beta's existing
`None` handling exactly.

## 9. Frontend

Extend the existing coordinator and policy rather than adding a parallel component:

- `shouldShowBetaBootstrapUi` becomes a channel-aware gate that returns true for Beta **and** Alpha
  and false for Stable; Beta's existing behavior for every input it already handles is unchanged;
- `main.tsx`'s launch gate calls the matching command for the running channel and stays false for
  Stable;
- the blocking modal keeps its current geometry, no close button, no Escape/outside dismissal, and
  one explicit required choice.

Alpha modal content:

```text
Set up CellXplorer Alpha

Alpha keeps its library separate from CellXplorer and CellXplorer Beta. You can start
empty, or copy a one-time snapshot of one of your existing libraries. The library you
copy from is not modified, and the two stay independent afterwards.

[Copy Stable library]  [Copy Beta library]  [Start empty]
```

Rules:

- three actions; the two copy actions are individually disabled with their exact `blockingReason`
  as visible text or tooltip when that source is unavailable;
- `Start empty` is never disabled;
- during staging all three are disabled with the existing indeterminate loader; do not invent a
  percentage;
- if the Alpha library is already populated, copying requires the existing explicit
  replace-confirmation before staging;
- the destination product name in every string is "CellXplorer Alpha", and source strings name
  "CellXplorer" or "CellXplorer Beta" exactly;
- follow `docs/agent-knowledge/visual-style-guide.md`; Alpha's primary remains `alphaPurple` and the
  destructive replace-confirmation stays red.

Extend the dev mock modes so the three-choice surface, a blocked source, both-sources-blocked, and
the copy-error path are reachable without a real installation.

## 10. Tests

### Backend (`tests/`)

- Alpha status lists both sources in fixed order with exact per-source availability and reasons.
- Missing / corrupt / future-revision / unrecognized source is blocked with a product-named reason
  while the other source and `Start empty` stay available.
- `stage-copy` from Stable and from Beta each produce a staged database with a **new** instance UUID,
  the pending preparation marker, rewritten managed-import paths under `.cellxplorer-alpha\imports`,
  untouched external paths, and a manifest recording the source channel.
- Cells with ordered SourceFiles, Analyses with saved plots, Folders/Projects, and replicate groups
  are all present in the staged copy with their relationships intact.
- The source database file, its sidecars, its `imports/` payload, and its whole root are
  byte-identical before and after staging, for both sources.
- A source modified mid-copy fails with the retryable product-named error and leaves no partial
  staging.
- `source: "alpha"`, an unknown source, and a missing source are rejected 422 before staging.
- Every Alpha endpoint 404s in Stable and Beta; every Beta endpoint 404s in Alpha and Stable.
- `start-empty`, `use-current`, `discard-stage`, stage-token reconciliation, and stale-stage cleanup
  behave for Alpha exactly as the existing Beta tests assert for Beta.
- Alpha marker filenames are used and `beta-bootstrap.json` never appears in the Alpha root.
- **Regression:** the complete existing `tests/test_beta_bootstrap.py` suite passes unchanged. Do
  not weaken or rewrite its assertions to accommodate the generalization.

### Rust

- Destination-parameterized pristine check, gate requirement, stage verification, activation, and
  rollback for an Alpha root.
- Alpha marker acknowledgement with and without an install-instance id.
- Stable cannot invoke either bootstrap command; Alpha cannot invoke the Beta command and vice versa.
- Existing Beta activation and rollback tests pass unchanged.

### Frontend

- `shouldShowBetaBootstrapUi`-equivalent returns true for Beta and Alpha, false for Stable, across
  every Tauri/mock combination.
- Alpha renders three actions; each copy action disables independently with its reason; `Start
  empty` is always enabled.
- Alpha strings name the correct destination and source products.
- Existing Beta bootstrap tests pass unchanged.

## 13. Out of scope

- any ongoing synchronization, mirroring, or write-back between products;
- copying **from** Alpha to anything;
- copying `cache/`, `logs/`, `backups/`, or download history;
- schema migrations, `CALC_VERSION` changes, parser changes, or scientific behavior changes;
- changing Beta's released bootstrap behavior, marker names, endpoints, or decision vocabulary;
- Alpha release publication, tags, or `release-channels` writes (053.2 owns those and they are
  complete);
- selective/partial copy, merge, or de-duplication between libraries;
- a Stable- or Beta-side "send to Alpha" action.
