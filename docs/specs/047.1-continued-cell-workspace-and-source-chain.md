- each source has a stable session color on its number;

# A — Adopt Step-3 fill/pane geometry

Keep the top-level mode selector in `ImportModal`.

For continued mode, the content under the selector becomes:

```tsx
<Stack style={{ flex: 1, minHeight: 0 }}>
  <ContinuedCommandRow />
  <Group
    align="stretch"
    wrap="nowrap"
    style={{ flex: 1, minHeight: 0, minWidth: 0 }}
  >
    <SourceChainPane />
    <PreviewPane />
    <CellDraftPane />
  </Group>
</Stack>
```

Exact component names are not mandated. The flex behavior is.

Requirements:

- mode selector: `flex: none`;
- command row: `flex: none`;
- pane row: `flex: 1`, `minHeight: 0`, `minWidth: 0`;
- each pane is a bordered `Paper` and owns its own scrolling where needed;
- source and Cell-draft pane headers remain visible while their content scrolls;
- Preview may scroll internally only if required; do not make the entire Step 3 scroll;
- no `overflow-x: hidden` workaround that merely clips inaccessible content.

Initial widths:

```text
Source chain   300–330 px
Preview        flex: 1; min-width ~480–520 px
Cell draft     360–400 px
```

Tune only enough to fit the existing `ImportModalShell` at the supported desktop geometry.

# C — Compact source-chain pane

## C1 — Import-specific compact presentation

Prefer extending `ContinuationSourceList` with a presentation variant rather than forking all source
interaction.

For example:

```ts
type ContinuationSourceListVariant = "default" | "compact-import";
```

or equivalent focused props.

**Default behavior must remain backward-compatible** for existing-cell continuation surfaces.

Compact import rows show:

1. numbered source circle;
2. drag handle;
3. filename;
4. small inspection/ready status where useful;
5. Historical source / Tracked tail badge;
6. one compact metadata line:
   - local cycle range/count when known;
   - start time or concise time range when known;
7. up/down actions;
8. remove action.

Do not show in the compact row:

- full path;
- full hash;
- protocol signature;
- raw-data button;
- per-source findings.

Those belong elsewhere.

## C2 — Geometry

Use:

- `Paper withBorder p="xs"`;
- `gap` of roughly 4–6 px;
- `Text size="sm"` filename;
- `Text size="xs" c="dimmed"` metadata;
- `ActionIcon size="sm"` or existing compact equivalents;
- no oversized vertical whitespace.

At normal 100% UI zoom, one ordinary row should remain approximately in the current compact source /
loaded-file footprint (~88–104 px), not expand into a multi-paragraph card.

This is a usability target, not a reason to hardcode a pixel height that clips text.

## C3 — Drag-and-drop remains first-class

Preserve current:

```tsx
draggable={Boolean(onDragStart) && !disabled}
```

and `onDragStart` / `onDrop` behavior.

The drag handle must remain visible.

Do not make the whole row a drag-only inaccessible control.

Keep up/down controls:

- up disabled at first row;
- down disabled at last row;
- buttons use existing `moveSource(...)` semantics;
- each has tooltip and accessible label.

## C4 — Row selection

Add an explicit selected source key for preview/details:

```ts
selectedSourceKey: string | null
```

Use stable source key / `staged_name`, never array index.

Expected behavior:

- entering continued mode → first source selected unless an existing valid selection is preserved;
- clicking a non-action part of a row selects it;
- using drag/up/down does not lose selection;
- reordering selected source keeps the same source selected;
- removing the selected source selects the nearest surviving row;
- adding more sources preserves the existing selection;
- raw/action button clicks do not accidentally trigger reorder.

Selected state uses the normal theme-safe primary selected surface/outline. It is independent from the
source's identity color.

# D — Stable session source colors

## D1 — Data shape

Use a small React-free helper/policy, for example:

```ts
type SourceColorAssignments = Record<string, string>;

assignContinuationSourceColors(
  previous: SourceColorAssignments,
  orderedKeys: string[],
  palette: string[],
): SourceColorAssignments
```

Exact naming is flexible.

Rules:

- existing key keeps its assigned color;
- new key gets the next unused palette slot;
- surviving keys do not change color after reorder/removal;
- removed keys may be dropped from returned active mapping;
- deterministic for identical previous mapping + keys;
- palette overflow uses the existing plot palette's normal repeat/overflow behavior rather than
  generating random colors.

## D2 — Palette source

Use the existing CellXplorer app plot palette.

Do **not** use Mantine semantic `teal/orange/red` state colors as the source identity system.

If importing the palette directly from the analysis feature would make a poor dependency, move only
the shared palette definition to a neutral module and keep `plotStyle.ts` using that same definition.

## D3 — Number-circle treatment

Render the visible source number (`1`, `2`, ...) using that source's color.

The circle may use:

- filled source color with readable foreground; or
- a source-colored border/background treatment if the fill has poor contrast.

The number remains present in every case.

Do not recolor status badges, destructive controls, selection outlines, or semantic alerts with the
source identity color.

# F — Footer-owned continued submission

Spec 036 requires navigation/primary decision actions in the sticky footer.

## F1 — Expose submission state to `ImportModal`

Today `ContinuedImportEditor` computes `canImport` and calls `onImport(...)` internally.

Change that ownership without duplicating continuation policy.

A suitable contract is:

```ts
export type ContinuedImportSubmissionState = {
  canSubmit: boolean;
  order: string[];
  acknowledgedFindingIds: string[];
  metadataOnlySourceKeys: string[];
};
```

and a prop such as:

```ts
onSubmissionStateChange: (state: ContinuedImportSubmissionState) => void;
```

The child remains responsible for continuation-specific order/inspection/acknowledgement state.
`ImportModal` receives the current immutable projection needed to submit.

Do not use a DOM-query or hidden-button click to submit.

## F2 — Footer action

When idle and `continuedMode === true`, `ImportModalShell.actions` shows:

```text
Cancel                         Import one continued cell
```

The primary button is disabled when `submissionState.canSubmit` is false or ordinary edit/registration
locks apply.

On click:

1. freeze/copy the current `order`;
2. freeze acknowledgement IDs and metadata-only source keys;
3. create the normal import job token;
4. use current `continuedCellDraft`;
5. call the existing `save.mutate({ mode: "continued", ... })`.

No second primary import button remains inside `ContinuedImportEditor`.

## F3 — Registration state unchanged

After accepted registration:

- existing progress slot;
- existing commit boundary;
- existing Continue in background;
- existing Done/autoclose

remain exactly the current `ImportModal` policy.

Do not build a continued-mode-specific registration UI.

- preserve current calculation of preset nominal capacity from active mass;
- preserve field validation;
- no new source-level metadata editing.

Avoid broad extraction/refactoring of the separate-cell detail editor merely for visual deduplication.
A small shared form component is acceptable only if it cleanly preserves both modes and reduces real
duplication.

# H — State reset / mode switching

Verify these transitions explicitly.

### Open modal

- continued mode defaults false as today;
- continued Cell draft initializes once from the first draft;
- source-color assignments initialize only for staged sources;
- selected source defaults to first staged key.

### Separate → continued

- no batch preview parsing;
- source order starts from current staged order;
- existing Cell draft is preserved for the open session;
- first/valid selected source shown.

### Continued → separate → continued

Within the same open Step-3 modal:

- do not silently mutate staged files;
- do not leak replicate assignment into continued request;
- preserving continued draft/order is acceptable and preferable unless existing reset policy already
  intentionally resets it.

### Add more

- append unique staged drafts using current identity handling;
- existing colors unchanged;
- new source assigned next color;
- current selected source retained.

### Remove

- order, color mapping, selected key and acknowledgement state remain internally consistent;
- at one remaining source show the existing continued-mode fallback and allow switch to Separate cells.
