## 1. Goal

Reduce the remaining backend latency of Time/Capacity derivative views (`dQ/dV` and `dV/dQ`) by removing repeated per-segment control/string-processing overhead inside the existing exact derivative calculation.

This child is deliberately narrower than a general derivative redesign. It must preserve the current derivative numerical algorithm, NaN placement, segmentation, response shape, provenance, downsampling and Plotly trace contract. It is an exact runtime optimization only.

The user-visible reason for this child is already measured. In the installed-app profile supplied for 050.4, one-Cell `dQ/dV` scaled from 347.5 ms total for cycles 1-3 to 628.6 ms for 1-20 and 3,616.1 ms for All. The All request spent 3,013.5 ms in the backend, of which 2,295.5 ms was the derivative stage; frontend Plotly completion was 387.6 ms with 610 traces. The backend derivative stage was therefore the dominant measured cost.

050.5 then localized the backend derivative stage on the committed 71,190-row / 193-cycle golden source. After the review-fix instrumentation, the All-cycle median derivative total was 978.2 ms, decomposed approximately as:

| derivative sub-stage | All-cycle median |
| --- | ---: |
| segment scan/grouping | 44.3 ms |
| segment preparation | 5.9 ms |
| rolling smoothing | 175.2 ms |
| gradient | 25.7 ms |
| ratio/filter | 9.8 ms |
| **post-gradient postprocess** | **700.5 ms** |
| unbucketed | ~16.8 ms |

The postprocess bucket is therefore the first optimization target. 050.6 changes phase/capacity preparation but does not change `_derivative_curve()`'s per-segment derivative algorithm, so this derivative hotspot remains independently justified.

## 2. Locked decisions

1. **Backend-only child.** Do not change the frontend derivative trace architecture in 050.7. The hundreds-of-Plotly-traces issue remains a separately measurable possible 050.8+ concern.
2. **No derivative scientific redesign.** Preserve the current smoothing, gradient, ratio, threshold, outlier, phase and absolute-discharge rules exactly.
3. **No new derivative cache.** Do not persist dQ/dV/dV/dQ arrays, add a RAM LRU, precompute range-specific derivatives, or change 050.6 prepared-data ownership.
4. **No approximation or multiresolution derivative path.** Interactive and full-resolution calculations remain exact under the current contract.
5. **Remove redundant per-segment work first.** Whole-request invariants should be classified once and sliced by segment instead of rebuilt through pandas string operations hundreds of times.
6. **Preserve segment semantics exactly.** Contiguous derivative runs remain keyed by the current `(cycle, segment, phase)` rule, in the same source/order sequence.
7. **Keep the numerical kernels unchanged in this child unless exact equivalence is proved.** The current pandas centered rolling mean, `np.gradient`, division direction, denominator threshold, percentile/span outlier rule and factor, and discharge absolute-value rule are the reference behavior.
8. **Do not chase a timing target by changing science.** If the safe control-flow/allocation optimization does not materially improve the derivative stage, record that result and return to review rather than modifying numerical semantics to make the benchmark pass.
9. **No migration/version bump.** This is data-access/control-flow work returning the same scientific result. Do not change SQLite migrations, `CALC_VERSION`, parser identity, canonical raw version, prepared-derived generation, analysis-result schema version, or analysis-cache scientific key semantics.
10. **050.P1 remains planning-only and untouched.**

## 3. Current implementation anchors

### Backend derivative function

`backend/app/services/analysis_engine.py`

```text
_derivative_curve(...)
```

Current exact flow for each Cell/unit:

```text
allocate x_out/y_out
-> convert voltage/cycle/segment/phase/capacity arrays
-> scan contiguous (cycle, segment, phase) run
-> test phase eligibility
-> slice q/v and finite rows
-> pandas centered rolling mean for q and v
-> np.gradient(q_s), np.gradient(v_s)
-> dQ/dV or dV/dQ ratio
-> denominator < 1e-10 -> NaN
-> non-finite derivative -> NaN
-> for this segment only:
     slice status Series
     astype(str)
     str.lower()
     str.contains("cv")
     str.contains("cccv")
     mask explicit CV-only rows
-> compute 5th/95th percentile Q/V spans
-> reject derivative magnitude > 50 * local scale
-> abs(discharge) when enabled
-> assign segment into x_out/y_out
```

The repeated status classification is scientifically invariant for the selected frame but is currently rebuilt independently for every eligible segment. 050.5 showed the surrounding postprocess block dominates broad derivative runtime.

### Shared status helper

`backend/app/services/calc.py`

```text
status_matches(...)
```

Repository tests already establish the helper's case-insensitive/distinct-status behavior. Reuse the existing helper/pattern rather than creating another status taxonomy.

### Profiling aggregation

- `backend/app/services/time_capacity_profiling.py`
- `scripts/profile_time_capacity_transforms.py`

050.5 already exposes the bounded derivative sub-stage timers and segment/row counts. Extend/reuse these measurements rather than inventing a second profiler.

### Frontend trace construction — out of scope

`frontend/src/features/analyses/editor/families/time-capacity/TimeCapacityPlotCard.tsx`

`timeCapacityTracesForResult()` currently emits one derivative Plotly trace for each finite contiguous `(cycle, phase)` run. 050.7 must leave this behavior unchanged. The profiler should continue reporting the existing trace-count evidence so Parent 050 can decide later whether a frontend-only follow-up is worth it.

## 4. Required target behavior

### 4.1 Classify explicit CV-only status once per selected frame

Before entering the per-segment numerical loop, derive one boolean array aligned one-to-one with `frame` rows:

```text
explicit_cv_only[i] = status contains "cv" AND status does not contain "cccv"
```

Use the existing status-matching semantics. A frame without `status` must produce an all-false mask, matching current behavior.

Inside each eligible derivative segment, apply only the corresponding boolean slice to the already-computed derivative array. Do not construct/lower/search a pandas string Series again for that segment.

Required semantic parity includes:

- `CV_Chg`, other explicit CV spellings already matched by current substring semantics -> masked;
- `CCCV_Chg` -> not masked by the explicit-CV rule;
- charge/discharge/rest phase behavior unchanged;
- missing/NaN/non-string status values retain current effective behavior;
- mixed status values inside one contiguous segment retain row-local masking.

### 4.2 Bound contiguous-run discovery without changing grouping

The implementation may precompute contiguous run boundaries once from the already materialized `cycle`, `segment`, and `phase` arrays instead of performing the nested row-by-row end scan for every run.

If changed, the boundary list must be exactly equivalent to the current loop:

```text
same start/end indices
same run order
same key = (cycle, segment, phase)
same eligible segment count
same output segment count
```

This is a control-flow optimization only. Do not merge runs across cycle, source/segment, or phase boundaries.

### 4.3 Preserve numerical operations

For every eligible run, preserve the current operation order and settings semantics:

- select absolute or specific capacity according to `derivative_specific`;
- force an odd smoothing window as currently done;
- `min_periods = min(window, 3, finite_count)`;
- centered rolling mean for Q and V with the existing pandas behavior;
- `np.gradient` on smoothed arrays;
- `dQ/dV = dq/dv` and `dV/dQ = dv/dq`;
- denominator magnitude `< 1e-10` becomes NaN;
- non-finite derivative becomes NaN;
- explicit CV-only mask is applied row-wise;
- Q and V 5th/95th percentile spans and the current local-scale equation are unchanged;
- values above `scale * 50.0` become NaN;
- discharge derivative uses `abs()` only under the existing setting;
- `x_out` / `y_out` placement and NaN gaps are unchanged.

Do not replace the rolling calculation with convolution/SciPy, alter percentile interpolation/methods, change gradient edge handling, or change thresholds in this child.

### 4.4 Diagnostics remain truthful and bounded

Keep the existing derivative diagnostics:

```text
input_rows
segments_processed
eligible_segments
finite_input_rows
output_finite_rows
output_segments
phase_rows
segment_scan / segment_prepare / rolling / gradient / ratio_filter / postprocess timings
```

If status classification or boundary preparation becomes a whole-request stage, either:

- account for it in the existing closest stage without double counting; or
- add a small bounded diagnostic timer with a clear name.

Ordinary non-profiled scientific responses must not gain profiling fields.

### 4.5 Frontend and response contract stay unchanged

The backend response must remain byte-/value-equivalent in scientific fields for the same request. In particular do not change:

- `derivative_x` / `derivative_y` values or NaN/null positions;
- `cycle`, `phase`, source provenance or boundary arrays;
- selected/full detail semantics;
- display downsampling point budget;
- frontend trace grouping/count;
- hover/export metadata;
- React Query/persisted-result cache identity.

## 5. Performance evidence and decision boundary

Use the existing disposable profiling harness and committed golden source. Record a paired before/after measurement on the same machine/runtime for at least:

| scenario | reason |
| --- | --- |
| dQ/dV 1-3, 1 Cell | guard small-range overhead/regression |
| dQ/dV 1-20, 1 Cell | common moderate interaction |
| dQ/dV All, 1 Cell | dominant measured broad case |
| dV/dQ All, 1 Cell | ensure inverse derivative mode benefits without semantic drift |
| dQ/dV All, derivative-specific capacity on/off where fixture metadata permits | normalization-path coverage |

Use at least five repetitions per scenario after one non-recorded warmup when practical. Record median derivative total and every existing derivative sub-stage. Keep selected rows, segment counts, finite rows, output segments, returned points and frontend trace count alongside timing so a faster result cannot hide dropped work.

The implementation goal is a **material reduction in All-cycle derivative-stage time**, with 25% as the decision threshold for the paired same-machine median. The 1-3 case must not show a repeatable material regression (>10% median) attributable to the optimization.

If the safe invariant/precomputation work does not reach the 25% broad-stage threshold, do not modify derivative formulas. Hand the measured result back to review with the remaining sub-stage decomposition; the reviewer will decide whether another exact optimization is justified.

The implementation record must not compare absolute wall times from different machines as if they were a benchmark regression.

## 12. Implementation record

Implemented on `feature/runtime-performance-optimization` as an exact backend control-flow
optimization. `_derivative_curve()` now classifies the aligned frame-wide explicit-CV mask once

contiguous `(cycle, segment, phase)` run boundaries once, preserving the original order and keys.

discharge absolute-value option, x/y assignment, response shape and cache/version contracts were
left unchanged. The new `derivative_status_classification` timer is included in the bounded
profiling projection; ordinary responses remain unprofiled.
