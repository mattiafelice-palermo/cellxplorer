## Locked final component boundary

### `AnalysisEditor.tsx`

The feature component receives an already-resolved analysis identifier and optional embedding
behavior. Its public surface should remain minimal, equivalent to:

```ts
export interface AnalysisEditorProps {
  analysisId: number
  workspaceVisible?: boolean
}
```

Use the repository's current optional/default prop style, but preserve these meanings:

- `analysisId` identifies the analysis document and all related queries/mutations;
- `workspaceVisible` preserves the current embedded workspace visibility behavior and defaults
  exactly as the route path currently does.

`AnalysisEditor` must not call `useParams`, know route URL construction, or import a page. It owns
the analysis editor's query/mutation/controller state and screen composition.

### `AnalysisPage.tsx`

The page remains compatible with both the router and the current explicit-ID embedding API. Its
only responsibilities are:

- read the route analysis id when no override is provided;
- select the effective id using the existing precedence and invalid-id behavior;
- pass `workspaceVisible` through with the existing default;
- render `AnalysisEditor`.

Conceptually:

```tsx
export function AnalysisPage({ analysisIdOverride, workspaceVisible = true }: AnalysisPageProps) {
  const params = useParams()
  const analysisId = /* preserve current parsing and fallback behavior */
  return <AnalysisEditor analysisId={analysisId} workspaceVisible={workspaceVisible} />
}
```

This is illustrative, not permission to alter invalid/missing-id UX. The route file must not
re-export plotting, visibility, family, artifact, portable, or editor helpers.

### Workspace composition

`features/analyses/workspace/AnalysisWorkspaceContent.tsx` should import and render
`AnalysisEditor` directly when embedding the editor. This establishes the required direction:

```text
route page -> feature editor
workspace -> feature editor
feature editor -> families/policies/artifacts/portable
```

No module under `features/analyses/` may import from `pages/`.
