## 1. Goal

Add Home as a safe frontend-only view in the single-analysis editor **without changing the analysis
scientific tab domain**.

This child owns:

- Home tab/header navigation;
- fresh-open landing behavior;
- session workspace restoration;
- explicit deep-link precedence;
- draft/saved-plot leave protection when entering Home;
- unmounting the scientific family panel while Home is active.

This child does **not** implement the final dashboard. Use a minimal repository-styled Home
placeholder if needed so the navigation/state behavior can be reviewed independently before 048.2.

## 2. Locked parent decisions inherited here

- `home` is not an `AnalysisTabKey`.
- Do not edit `ANALYSIS_TAB_KEYS` to include Home.
- `activeTab` continues to mean an actual scientific/settings tab.
- Home is the default fresh-open view when no explicit `?plot=` / `?tab=` target exists.
- An already-mounted analysis restores its Home/family view from session-only workspace state.
- A deep link bypasses Home.
- Entering Home from a dirty saved plot/new draft must use the current save/discard/cancel machinery.
- Home does not start computation or mount a hidden scientific panel.
- Existing `keepMounted={false}` behavior remains load-bearing.

## 4. Target state model

Preserve:

```ts
activeTab: AnalysisTabKey
```

for the actual analysis/settings tab.

Add one frontend-only view discriminator with equivalent semantics to:

```ts
type AnalysisEditorView = "home" | "analysis";
```

and:

```ts
activeView: AnalysisEditorView
```

Do not key existing per-tab maps by `home`. Existing structures such as `lastPlotIdByTab`,
`normalWorkspaceByTab`, and `draftPlotByTab` remain keyed only by `AnalysisTabKey`.

### Workspace state shape

Extend `AnalysisWorkspaceEditorState` with the frontend-only view field. The value is stored only in
the existing module/session workspace map; it must not be written to `AnalysisSpec` or sent to the
backend.

Use a backwards-safe default for any in-memory state shape that lacks the new field during hot
reload/development. A fresh editor defaults to Home.

## 5. Tab header behavior

### 5.1 Add Home first

The visible analysis header order becomes:

1. Home
2. Time / capacity
3. Cycles
4. Steps
5. C-rate
6. Chargeability
7. DCIR
8. Recap
9. Settings

Use `IconHome` (or the repository-standard Tabler home icon available in the installed version),
not a custom glyph.

### 5.2 Header value is UI-only

`AnalysisTabHeader` may use a local union such as:

```ts
type AnalysisEditorNavKey = "home" | AnalysisTabKey;
```

for Mantine's visual tab value. This type must remain local/frontend-only and must not replace the
API/domain `AnalysisTabKey`.

### 5.3 Clicking the currently remembered family from Home must work

Because `activeTab` retains the last scientific tab while Home is active, the current early-return
pattern equivalent to:

```ts
if (next === activeTab) return;
```

must not prevent navigation from Home back to that family.

The no-op condition should apply only when that family is already the visible analysis view.

## 6. Fresh-open and restoration behavior

### 6.1 Fresh open without explicit target

When the analysis detail becomes available and no valid `plot`/`tab` deep link is being handled:

- set/retain `activeView = "home"`;
- do **not** call `resolveColdOpenWorkspace(...)` merely to populate a hidden family;
- do not apply a saved plot/draft snapshot for the default `activeTab`;
- do not start family compute.

`activeTab` may keep its existing safe default (currently Cycles on the authoring baseline) as the
remembered family, but it is not visible until the user chooses it.

### 6.2 Existing session workspace state

If `getAnalysisWorkspaceEditorState(...)` returns valid state for the same analysis/data
fingerprint:

- restore its `activeView`;
- restore `activeTab` and the existing plot/draft/normal workspace state exactly as before;
- if the saved session view is Home, do not unnecessarily reapply a family snapshot.

### 6.3 Close/reopen

The current workspace cleanup on closing an analysis remains authoritative. Once its session state
is cleared, opening it again is a fresh open and therefore lands on Home.

Do not add localStorage or backend persistence to make Home survive application restarts.

## 7. Explicit deep-link precedence

Preserve current URL semantics.

### `?plot=<id>`

If a valid saved plot is requested:

1. mark the editor view as analysis/family;
2. route through the existing exact saved-plot opening path (`openSavedPlotDirect` or its current
   canonical equivalent);
3. activate `plot.tab`;
4. preserve current plot restoration/editing semantics.

### `?tab=<AnalysisTabKey>`

If a valid tab is requested:

1. mark the editor view as analysis/family;
2. activate the requested real tab through existing tab activation logic;
3. preserve current cold-workspace behavior for that tab.

### Invalid deep links

Keep existing invalid/missing-target handling unless a current test shows a different canonical
behavior. Do not treat `?tab=home` as valid.

## 8. Home navigation and dirty-state guard

Create a dedicated Home navigation request, e.g. conceptually:

```ts
activateHome()
```

It must share the same leave policy as `activateAnalysisTab(...)`.

### Normal workspace

If no unsaved plot work is at risk:

- clear stale `plot`/`tab` search params through the same search-param ownership used by family
  navigation;
- set `activeView = "home"`;
- preserve `activeTab` as the remembered last family;
- clear only transient active-saved-plot state that the existing leave path already clears;
- do not destroy per-tab normal/draft snapshots beyond current policy.

### Dirty new plot

Entering Home must open the same current confirmation used when leaving for another family.

- Save → save through current draft policy, then Home.
- Discard → current discard-new-plot path, then Home.
- Cancel → no state change.

### Dirty saved plot

Same rule:

- Save/update → existing saved-plot commit path, then Home.
- Discard → existing discard-edited-saved-plot path, then Home.
- Cancel → remain on plot.

### Follow-up navigation target

If the current save implementation models post-save navigation with a typed `afterSave` target,
extend that target minimally to represent Home rather than adding a second asynchronous save path.

Example acceptable shape:

```ts
{ kind: "tab"; tab: AnalysisTabKey } | { kind: "home" }
```

The exact type name may differ. The requirement is that Home reuses the canonical save completion
path.

## 9. Opening a saved plot from Home

048.2 will call the existing saved-plot opening handler. Prepare the editor contract so that a
Home-origin plot open:

- switches to `activeView = "analysis"`;
- activates `plot.tab`;
- restores that exact saved plot through the same canonical path used by `SavedPlotsPanel`;
- does not create a parallel Home-specific restoration implementation.

If `openSavedPlotDirect` is currently internal to `AnalysisEditor`, pass a callback to
`AnalysisHome` in 048.2 rather than exporting editor internals unnecessarily.

## 10. Render/mounting behavior

When Home is active:

- render a full-width Home region below the analysis tab header;
- do not render the scientific `<Tabs ...>` family body at all, or otherwise ensure no family
  panel/Plotly component is mounted;
- do not render the analysis sample sidebar or plot-style sidebar.

When an actual analysis tab is active:

- retain the current `Tabs value={activeTab} keepMounted={false}` family body unchanged;
- preserve the existing loading, compute, sidebar, saved-plot, and style-panel behavior.

Do not remove or weaken the current explanatory `keepMounted={false}` invariant unless the code
structure makes the comment obsolete and an equivalent guard is still explicit.

## 11. Minimal Home placeholder for this child

Until 048.2, the Home panel may contain only a repository-styled neutral placeholder, e.g.:

- title/label “Analysis overview”;
- short text that saved plots will appear here.

It must not introduce temporary mock data, fake metrics, or fake plot thumbnails.

Do not spend review effort polishing this placeholder; 048.2 replaces it.

## 12. Tests

Add focused frontend tests for the new navigation policy/state boundary. Prefer pure policy tests
where possible rather than testing Mantine rendering through a heavyweight browser framework.

Suggested new test file:

```text
frontend/tests/analysisHomeNavigation.test.ts
```

If the live branch already contains a better matching test module, extend it instead of duplicating
coverage.

Required test cases:

1. Home is the default view for a fresh analysis with no explicit target.
2. `activeTab` remains a valid `AnalysisTabKey`; Home is not accepted as one.
3. A valid `?tab=` request selects analysis view + requested tab.
4. A valid `?plot=` target selects analysis view + the plot's owning tab/path.
5. Session workspace state can restore Home.
6. Session workspace state can restore an actual family.
7. Home → remembered active family is not incorrectly treated as a no-op.
8. Dirty new plot → Home produces the same Save/Discard/Cancel decision path as tab navigation.
9. Dirty saved plot → Home produces the same Save/Discard/Cancel decision path.
10. Cancel preserves the current plot and keeps analysis view active.
11. Save/discard completion can target Home without a second save implementation.
12. Home state is stripped from backend/persisted `AnalysisSpec` payloads by construction.

Also run the existing draft/workspace policy tests affected by the edit.
