## Parent

`055-plot-workflow-polish.md`

## Goal

Provide an explicit CellXplorer interaction to show only one selected plot series, plus a clear way to restore all series, and disable Plotly's default legend double-click isolation behavior.

The user should not need to remember Plotly-specific double-click semantics.

## Locked decisions

- CellXplorer owns series visibility semantics.
- Plotly legend **double-click isolation/restore is disabled**.
- Add an application action equivalent to `Show only this series`.
- Add an application action to restore the full applicable series set.
- The action should operate on the same visibility model used by existing CellXplorer show/hide controls, not on a transient Plotly-only `visible` mutation that disappears on rerender.
- Existing persistent hidden-sample/hidden-series semantics must remain deterministic across saved plots.
- If `Show only` changes persistent saved-plot visibility, it is a real plot edit and may enable `Update`.
- "Restore all" means restore all series that are valid for the current plot context; it must not resurrect samples excluded for reasons outside the relevant visibility layer.
- Do not make hidden protocol segments, diagnostic-cycle filtering, unsupported data, or scientifically excluded samples visible merely because the user chose `Restore all series`.
- Single-click legend behavior must not fight the application state. If current Plotly single-click toggling is not synchronized with persistent visibility, disable it as well and route visibility through CellXplorer controls. The reviewer should prefer one source of truth over mixed behavior.
- The interaction must work with keyboard-accessible controls.
- Avoid family-specific copies if a shared series-visibility policy can cover the common behavior.

## Terminology

### Series

A user-visible plotted trace/series that corresponds to a CellXplorer series descriptor and can be meaningfully hidden/shown through the current visibility model.

Auxiliary traces such as:

- confidence bands;
- helper traces;
- source-boundary markers;
- annotation-only traces;

must not become independent `Show only` targets unless they already represent first-class series to the user.

### Applicable series set

The set of user-visible series that would be shown for the current plot if the user-level visibility layer were reset, after respecting higher-level constraints such as:

- analysis selection;
- protocol filters;
- diagnostic-cycle filtering;
- family-specific data availability;
- explicit scientific exclusions.

## UX specification

### Series action

Expose `Show only this series` from the most direct existing per-series interaction.

Preferred locations, in priority order:

1. existing series/legend context menu if one exists for the family;
2. series style/action menu;
3. a shared app-controlled legend interaction.

Do not add a large permanent button per trace.

The action should identify the series using the repository's stable series descriptor/key, not the rendered legend text alone.

### Restore action

When one or more user-level series are hidden, expose:

`Show all series`

or equivalent concise wording in an obvious plot-level location.

Good candidates:

- plot header action;
- legend/series menu;
- visibility summary control already used by the family.

The action should be disabled/hidden when there is nothing to restore.

### Plotly double-click

Disable Plotly's native legend double-click isolate/restore behavior.

Implementation may use the appropriate Plotly event handler/configuration, but must be verified against the actual `react-plotly.js`/Plotly version in the repository.

Required result:

- double-clicking a legend item does not independently isolate traces;
- it does not mutate Plotly-only visibility that disagrees with the spec;
- it does not cause a subsequent rerender to "snap back" unpredictably.

If the safest common implementation is to intercept `plotly_legenddoubleclick` and return `false`, centralize it where possible.

### Single-click legend behavior

Audit current single-click behavior.

Acceptable outcomes:

A. keep single-click if it already maps deterministically to CellXplorer's persisted visibility model; or

B. disable native single-click and expose the existing app visibility action instead.

Unacceptable:

- native Plotly visibility changes temporarily while saved spec remains unchanged;
- `Update` state does not reflect the actual intended visibility;
- a rerender unexpectedly restores a trace.

Document the chosen behavior in the implementation note.

## Persistence semantics

`Show only this series` should update the same user-level hidden-state representation used by existing analysis visibility controls.

For a saved plot:

- the visibility change is a real edit;
- `Update` becomes enabled;
- saving updates that saved plot's visibility state;
- reopening reproduces the isolated series.

For a new plot/draft:

- the visibility state belongs to the draft workspace;
- saving the new plot persists it.

`Show all series` similarly changes persistent user-level visibility and follows ordinary dirty/save semantics.

Do not modify the analysis-wide sample membership/selection merely to hide traces in one saved plot.

## Helper design

Prefer a pure policy helper along the lines of:

- compute hide-set needed to isolate target series;
- compute restored user-level visibility for applicable series.

The exact data shape should follow `analysisVisibility.ts` and current spec fields.

Keep the helper independent from Plotly trace array indices where possible. Trace indices are fragile because auxiliary traces can be inserted.

## Tests

### Visibility policy

Test at minimum:

- isolate A from `[A, B, C]` hides B/C and leaves A visible;
- isolating already-only-visible A is idempotent;
- `Show all` restores user-hidden B/C;
- higher-level excluded/unsupported series are not incorrectly restored;
- helper traces do not become targets;
- stable series keys, not labels, determine identity;
- saved plot dirty signature changes for a real visibility change.

### Plotly event behavior

Add focused coverage around the shared event policy if practical:

- legend double-click handler prevents Plotly default isolate behavior;
- native behavior cannot leave a transient visibility state diverged from application state.

### Family coverage

At least cover:

- Cycles;
- Time/capacity;
- one family with different trace composition/auxiliary traces.

## Manual checks

For a multi-series saved plot:

1. open the plot;
2. invoke `Show only this series` on series B;
3. confirm only B remains among user-visible data series;
4. confirm auxiliary traces belonging to B behave correctly;
5. confirm `Update` enables;
6. click `Show all series`;
7. confirm applicable series return;
8. double-click a legend item;
9. confirm Plotly does not perform native isolation;
10. save an isolated view, leave, reopen, and confirm persistence;
11. verify a scientifically excluded/filtered series is not resurrected by `Show all`.

Repeat on at least two plot families.

## Acceptance criteria

- A direct `Show only this series` action exists.
- A direct `Show all series` action exists when useful.
- Both use stable application series identity.
- Plotly legend double-click isolation/restore is disabled.
- No mixed transient Plotly-only visibility state remains.
- Saved-plot dirty/save semantics correctly reflect isolation/restoration.
- Reopened saved plots reproduce saved visibility.
- Higher-level scientific filters/exclusions are preserved.
- Keyboard accessibility is preserved.
- Focused tests and canonical preflight pass.

## Out of scope

- new legend redesign;
- arbitrary multi-select visibility editor;
- series grouping hierarchy;
- changing scientific inclusion/exclusion rules;
- changing diagnostic-cycle logic;
- changing series styling.
