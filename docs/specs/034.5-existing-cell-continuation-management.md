# 034.5 — Existing Cell continuation management

**Status:** Implemented — architecture corrected and pushed 2026-07-31
**Parent:** [034 — Multi-source cell continuations](034-multi-source-cell-continuations.md)  
**Depends on:** 034.3 and shared UI from 034.4  
**Scope:** Add, reorder, and detach sources from one existing Cell-level chain.

## Locked product model

The Files tab manages one ordered source chain for the physical Cell:

```text
Cell
├── historical source
├── historical source
└── tracked tail
```

The database’s `Test` row is an internal compatibility container only. The UI must not render Test
cards, Test names, a Target Test selector, per-Test order, or per-Test tails. Every lifecycle action
is defined against the complete Cell chain.

## Current behavior to correct

The first implementation renders one continuation card per `cell.tests`, offers a Target Test
selector, limits reorder to one Test, and describes an earlier Test as having its own tail. These
behaviors are unapproved and must be removed.

## Target Files panel

Render one canonical source inventory for the Cell:

- stable ordered position;
- filename and full-path tooltip;
- observed local cycle minimum/maximum/count;
- detected time range;
- parse/source status;
- hash prefix;
- manual Update action;
- `Historical source` for every non-final item;
- `Tracked tail` for exactly the final item;
- Add continuation, Reorder, and Detach actions.

Do not render a second legacy table with duplicate or contradictory roles.

### Add continuation

- Use `ImportFilesystemPickerModal` and shared inspection/findings UI.
- New sources append to the Cell chain; there is no target selection.
- Multiple staged sources can be removed, manually reordered, or changed to suggested order.
- Review the exact complete proposed Cell chain before mutation.
- Protocol differences remain visible findings and never create another Test.

### Reorder

- Reorder across the entire Cell source list.
- Support drag and keyboard Move up/down.
- Review the complete proposed order, changed boundaries, findings, and old/new Cell-wide tail.
- Submit an exact permutation of all Cell source IDs.

### Detach

- Confirm source identity, affected analysis/plot counts, global-cycle implications, and that the
  original disk file remains untouched.
- Disable detach only when it would leave the Cell with zero sources.
- Do not preserve a source merely because it is the last member of an internal Test container.

## Authoritative review state

Attach, reorder, and detach use one operation-specific server proposal containing:

- complete current and proposed Cell order;
- findings and required acknowledgements;
- inspection readiness;
- old/new tracked tail;
- impact on analyses and saved plots;
- confirmation token where needed.

The preview and final mutation must validate exactly the same proposal. Poll while preparation is
pending. On changed-hash/new-finding conflicts, keep the modal/order/selections open, refresh the
proposal, and require updated acknowledgements.

## Existing-source detail

The frontend must not infer `1..cycle_count`. A bounded Cell-detail endpoint may expose observed
local cycle min/max/count, end time, and protocol signature from current cache evidence. Show
Pending or Unknown when unavailable. Keep Parquet reads off list endpoints.

## Cache and query behavior

After successful mutation:

- replace/invalidate Cell detail;
- invalidate Cell list, Projects tree/metrics, source status, analyses, saved-plot/activity, and
  background-job queries named by the API response;
- do not optimistically invent cycle totals or parse status;
- preserve deterministic order after close/reopen;
- avoid duplicate toasts from mutation and background completion.

## Acceptance

- Files tab shows one source chain and exactly one tracked tail.
- No Test name/card/selector/tail appears anywhere in continuation management.
- Add/reorder/detach operate on the complete Cell chain with one atomic mutation each.
- New imports and lifecycle code never create a second Test for a Cell.
- Cell metadata never changes after adding a continuation.
- Reorder can place any Cell source at any chain position.
- Detach cannot empty the Cell and preserves the disk file.
- Protocol changes are non-blocking findings, not grouping instructions.
- Existing-source cycle ranges are authoritative or explicitly unknown.
- Pending review converges and conflicts refresh safely.
- All affected views refetch with no stale source count/order.
- Long filenames, dark mode, keyboard-only operation, and supported zoom remain usable.
