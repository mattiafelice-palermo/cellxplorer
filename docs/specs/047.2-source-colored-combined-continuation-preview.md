## Goal

Add the useful visual centerpiece of the new continued-cell workspace: one bounded capacity-vs-cycle
preview of the **whole proposed source chain**, with each physical source shown as a different colored
segment in authoritative global Cell cycle numbering.

The plot must remain cheap enough for import UX, must not bypass existing cache/provenance rules, and
must not undo Spec 035.8 by parsing every staged source as soon as Step 3 opens.

---

# Why a dedicated chain-preview path is required

The existing `/api/imports/preview` response describes one physical source and returns that source's
local cycle x-values.

A continued Cell may contain sources whose local cycle labels:

- restart at 1;
- continue from the previous source;
- overlap previous labels;
- contain gaps.

`backend/app/services/stitch.py` already defines the correct application behavior:

```text
observed source-local cycle labels
→ stable numeric order
→ dense global Cell cycles
→ segment provenance retained
```

Therefore React must not create the global x-axis by arithmetic on local preview arrays.

A dedicated backend continuation-preview request provides one authoritative and bounded display
result.

---

# A — New API contract

Add a typed endpoint under the existing import-continuation namespace:

```http
POST /api/imports/continuations/preview
```

Use the same staged source identity inputs as continuation inspection:

```ts
export interface ContinuationPreviewRequest {
  sources: ContinuationInspectSourceRequest[];
  proposed_order: string[];
}
```

Reusing `ContinuationInspectRequest` directly is acceptable if it keeps the contract clear.

## Response

Add a shape equivalent to:

```ts
export interface ContinuationPreviewSegment {
  source_key: string;
  filename: string;
  x: number[];  // global Cell cycle number
  y: number[];  // same quantity semantics as ordinary capacity preview
  global_cycle_start: number | null;
  global_cycle_end: number | null;
  source_cycle_start: number | null;
  source_cycle_end: number | null;
  source_cycle_count: number;
}

export interface ContinuationPreviewResult {
  quantity: string;
  label: string;
  segments: ContinuationPreviewSegment[];
}
```

The exact field naming may follow existing API conventions, but all information above must be
available without frontend inference.

The response is display data only. Source colors are **not** part of the backend response.

---

# B — Backend identity and readiness rules

## B1 — Verify the same source identity contract

For every staged source, use the current inspection proof:

```text
hash + size + mtime_ns
```

Do not trust path alone.

Follow the same unchanged-source rules as current import preview / registration:

- matching fingerprint may reuse the inspected identity;
- changed fingerprint must be revalidated according to current source-change rules;
- changed content returns the existing structured source-changed/conflict behavior;
- never load/write cache content under an unverified stale hash.

Do not create a weaker chain-preview identity path.

## B2 — Use per-source parser identity

Every source is loaded with its own effective parser identity.

Do not reintroduce one global parser version for a mixed chain.

Reuse the current parser/cache identity helpers used by the import/cache path. If a tiny service helper
must be extracted so both ordinary preview and continuation preview resolve identity consistently,
do that rather than duplicating parser dispatch.

## B3 — Preview follows successful continuation preparation

The frontend calls the chain-preview endpoint only after continuation inspection reports:

```ts
inspection_complete === true
```

The preview endpoint is not responsible for starting an uncontrolled second cache-preparation
pipeline.

If a cache needed by the chain is still unavailable due to a race or source problem:

- fail closed with structured detail identifying the affected source(s);
- do not return a partial graph that looks like a complete continuation.

Metadata-only sources cannot supply canonical cycling rows. If one exists in the proposed chain,
combined scientific preview is unavailable for the complete chain. The UI may still preview
individual canonical sources.

# C — Authoritative global cycle mapping

Build ordered cache references for the proposed visible source order and call the existing:

```python
stitch.stitch_cycles(...)
```

or a narrowly extracted equivalent that uses the same `_stitch_ordered` rules.

Do not duplicate:

- `observed_local_cycles`;
- dense cycle-map construction;
- missing-source fail-closed behavior.

The result already includes:

```text
cycle       → global dense Cell cycle
source_cycle
segment
source_hash
```

Use `segment`/ordered identity to divide the preview back into source-colored traces.

### Regression examples

The endpoint must produce consistent global x for all of these:

```text
source A local 1,2,3 ; source B local 1,2
→ global A 1,2,3 ; B 4,5

source A local 10,20 ; source B local 21,22
→ global A 1,2 ; B 3,4

source A local 1,2,4 ; source B local 1,3
→ observed labels only
→ global A 1,2,3 ; B 4,5
```

Do not invent missing local labels.

---

# D — Reuse current capacity-preview semantics

The y quantity and label must be exactly the ordinary import preview's capacity quantity semantics.

Do not create a second interpretation such as "always discharge capacity" if the existing preview
already has fallback/selection behavior.

Preferred implementation:

1. extract the current "build bounded capacity preview from a per-cycle DataFrame" logic from
   `backend/app/routers/files.py` into a focused reusable helper if it is not already one;
2. ordinary `/api/imports/preview` continues to use it;
3. continuation preview uses the same helper on the stitched per-cycle data while preserving
   `segment`.

No scientific calculation meaning changes.

No `CALC_VERSION` bump.

---

# E — Bounded preview sampling

The combined preview is for display only.

Requirements:

- reuse the existing ordinary import preview point budget where practical;
- if the current cap is buried in endpoint code, centralize it once rather than creating unrelated
  caps;
- preserve first/last/boundary representation so every non-empty source segment remains visible;
- do not ship the full per-cycle table merely to draw a small import chart;
- do not downsample data that later become scientific/export inputs — this endpoint is display-only.

A fair per-segment allocation is preferred so a short source is not completely removed by sampling a
long chain.

The response size must remain bounded independently of the total raw-record count.

# F — Frontend request timing

## F1 — No request on Step-3 open

These actions must **not** request a combined preview:

- opening Step 3;
- switching Separate → One continued cell;
- adding drafts before the user requests continuity inspection.

Before inspection, the combined preview area shows restrained copy:

```text
Inspect continuity to prepare the combined preview.
```

No large alert.

## F2 — After explicit inspection

Flow:

```text
user clicks Inspect continuity
→ existing continuation inspection runs/polls
→ inspection_complete
→ combined preview request starts
→ bounded chain preview appears
```

The combined request is one query, not N browser requests.

## F3 — Query identity

Key the frontend query by the proposed ordered source identities, for example conceptually:

```ts
[
  "continued-import-preview",
  order.map(key => `${key}:${hashForKey(key)}`).join("|")
]
```

Include any additional fingerprint value required to prevent stale reuse.

Consequences:

- reorder → a different chain-preview identity;
- source content change → old result not reused as current;
- switching away/back to an unchanged inspected order may reuse the in-session query cache;
- late result for an obsolete order must not overwrite the current plot.

Abort/cancel obsolete requests where the existing API/query architecture supports it.

# G — Preview selector

The center pane supports:

```text
All sources (combined)
Source 1 — filename
Source 2 — filename
...
```

### Combined

- default target once continued mode is ready for chain review;
- uses the new chain-preview endpoint;
- no raw-data table;
- Raw data must not ambiguously claim to represent all files.

### Individual source

- uses the existing lazy `/api/imports/preview` path;
- requests only the selected source if still idle;
- reuses its ready preview state;
- preserves current retry behavior;
- uses that source's session color for the trace.

The selector must not mutate source order or Cell metadata.

---

# H — Plot construction

Create a small React-free presentation helper where useful, for example:

```ts
buildContinuationPreviewTraces(
  preview: ContinuationPreviewResult,
  colorsBySourceKey: Record<string, string>,
): Plotly.Data[]
```

Requirements:

- one Plotly trace per source segment;
- `x` comes directly from backend global-cycle response;
- `y` comes directly from backend preview response;
- trace color comes from the 047.1 source-color map;
- `showlegend: false` on every trace;
- trace name/hover may include source number + filename;
- no bottom/right legend;
- transparent plot/paper chrome consistent with current import previews;
- chart title: `Capacity vs. cycle`;
- x axis: `Cycle number (global)` in combined mode;
- y axis: backend `label`.

### Join markers

Use restrained vertical separators at source boundaries when they improve readability.

Small source-index annotations such as:

```text
1       2       3       4
```

are acceptable.

Do not add a second filename legend.

### Source-color parity

For every visible segment:

```text
left row number color === plot trace color
```

This is an acceptance invariant and needs a pure test where possible.

---

# I — Selection and source summary

Below the plot show a compact **Selected source summary** for the currently selected individual source
row.

Prefer information already present in draft/inspection state:

- filename;
- full path;
- size/format/technique where available;
- local cycle range/count;
- start/end time;
- protocol signature when inspection has produced it.

Do not parse a source again to populate this summary.

Before inspection, show only facts already available from `ImportPreview`; render unavailable values
as `—` or omit the row rather than showing fake data.

Source row click changes summary target without changing Cell draft.

---

# J — Raw data button

Keep one `Raw data` button in the Preview pane header.

Recommended binding:

```text
Raw data target = selected source row
```

This keeps the target unambiguous even while the chart is in combined mode.

Reuse the existing callback from `ImportModal`:

```ts
onRawData(stagedName)
```

and existing `/api/imports/raw-data` modal.

Button rules:

- selected canonical source → enabled;
- metadata-only / non-canonical source → disabled with tooltip;
- no valid selected source → disabled.

Do not add a combined raw-data endpoint in this spec.

---

# K — Error/loading/empty states

### Before inspect

Neutral helper copy only.

### Inspection preparing caches

Use the existing continuation inspection loading state. Keep last valid individual preview visible if
one exists.

### Combined preview loading

Use one compact loader/skeleton in the plot region. Do not stack a second page-level loader.

### Preview failed

Show a concise inline error in the center Preview pane with Retry if appropriate.

Source-change conflict must tell the user to re-inspect rather than retry forever.

### No capacity points

Show:

```text
No capacity preview points were found for this chain.
```

Do not imply import is scientifically invalid merely because the display preview is empty.

### Metadata-only/incomplete canonical chain

State clearly that a **combined cycling preview is unavailable**, while leaving the required
continuity-review/import policy to 047.3.

# Acceptance criteria

047.2 is reviewable when an explicitly requested/inspected continued chain produces one bounded
combined capacity plot in authoritative backend global-cycle numbering; each source is one
source-colored segment whose color matches its left number; the plot has no legend; Raw data remains
an on-demand existing-source action; individual preview stays lazy; Step-3 open causes no all-source
parse; source/cache identity remains safe; incomplete/metadata-only chains fail closed visually; and
no new scientific cache or `CALC_VERSION` meaning is introduced.
