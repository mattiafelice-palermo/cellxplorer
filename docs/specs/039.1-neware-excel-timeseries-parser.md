## Goal

Create the low-level parser for the point-level scientific data contained in a structured Neware
Excel `.xlsx` export.

At the end of this child, given a supported workbook path, CellXplorer must be able to produce a
canonical raw `pandas.DataFrame` with the same scientific meanings expected from the existing
`.nda/.ndax` parser:

```text
record_index
cycle
step
step_index
status
time_s
voltage_v
current_ma
charge_capacity_mah
discharge_capacity_mah
charge_energy_mwh
discharge_energy_mwh
timestamp
```

plus useful auxiliary columns such as total elapsed time and instantaneous power.

This child deliberately does **not** yet make `.xlsx` importable through the UI or scanner and does
not yet integrate metadata/protocol/cache versioning. It proves the most sensitive question first:

> Can the workbook's raw records be mapped deterministically and scientifically correctly into the
> canonical raw structure CellXplorer already understands?

## Current verified implementation

### Existing parser seam

`backend/app/services/parsing.py` currently owns all direct `NewareNDA` integration.

Important anchors:

- `PARSER_VERSION`;
- `RAW_COLUMNS`;
- `parse_timeseries`;
- `_flatten`;
- `read_header_metadata`.

Current `parse_timeseries` calls:

```python
NewareNDA.read(str(path), software_cycle_number=True, log_level="WARNING")
```

then renames NewareNDA columns through `RAW_COLUMNS`.

This child does not replace that binary path. It adds an Excel-specific module that will later be
reached through `parsing.py` dispatch in 039.2.

### Existing raw semantics that matter

`backend/app/services/calc.py` assumes that Neware capacity and energy counters can reset at
executed-step boundaries. Per-cycle totals are therefore formed from per-step deltas, not from one
whole-cycle maximum.

`backend/app/services/step_blocks.py` and Steps analysis need:

- `step_index` for programmed protocol-step membership;
- `step` for each executed occurrence.

`backend/app/services/analysis_engine.py` deliberately handles step-relative time/capacity resets for
Time/Capacity plotting. The Excel parser must preserve those reset semantics rather than flattening
them into already-continuous cycle values.

## Workbook opening and safety

Add `openpyxl` as a backend dependency only if it is not already present when this child starts.
Packaging proof belongs to 039.3; this child only requires the development/test dependency.

Use a bounded read-only workbook path equivalent to:

```python
openpyxl.load_workbook(
    filename=path,
    read_only=True,
    data_only=True,
    keep_links=False,
)
```

Requirements:

- always close the workbook in `finally`/context-style cleanup;
- do not use Excel COM automation;
- do not use LibreOffice;
- do not use `pandas.read_excel` as the primary parser abstraction;
- do not evaluate formulas;
- ignore styles, charts, drawings, macros and external links;
- do not materialize the entire workbook when only the `record`/`step` sheets are needed;
- catch invalid ZIP/XML/workbook exceptions and rethrow a concise parser-domain exception;
- preserve the original exception as `__cause__` for logs/tests;
- user-facing error strings must not dump entire worksheet rows or private metadata.

`data_only=True` can yield `None` for an unevaluated formula. Required scientific fields containing
such a value are invalid; do not evaluate the formula yourself.

## Header/sheet normalization

For lookup only:

1. convert to string;
2. strip leading/trailing whitespace;
3. collapse repeated internal whitespace to one ASCII space;
4. case-fold.

Preserve the original visible header text for diagnostic messages if useful.

Do not:

- fuzzy-match similar words;
- accept translated synonyms without a verified export;
- infer columns by position alone.

If two source headers normalize to the same lookup key, fail as ambiguous.

## Canonical raw mapping

Map the `record` sheet as follows.

| Excel source | Canonical output | Rule |
|---|---|---|
| `DataPoint` | `record_index` | required integer |
| `Cycle Index` | `cycle` | required integer |
| `Step Index` | `step_index` | required integer; programmed step identity |
| derived execution segment | `step` | required integer; unique executed occurrence |
| `Step Type` | `status` | explicit status normalization table |
| `Time(min)` | `time_s` | numeric × 60 |
| `Total Time(min)` | `total_time_s` | numeric × 60; auxiliary but required source field |
| `Voltage(V)` | `voltage_v` | numeric |
| `Current(mA)` | `current_ma` | numeric |
| `Chg. Cap.(mAh)` | `charge_capacity_mah` | numeric, no further unit conversion |
| `DChg. Cap.(mAh)` | `discharge_capacity_mah` | numeric, no further unit conversion |
| derived from `Power(W)` + elapsed time | `charge_energy_mwh` | cumulative within executed charge step |
| derived from `Power(W)` + elapsed time | `discharge_energy_mwh` | cumulative within executed discharge step |
| `Date` | `timestamp` | strict datetime parse |
| `Power(W)` | `power_w` | numeric, preserve source sign |
| `Capacity(mAh)` | `capacity_mah` | optional auxiliary |
| `Spec. Cap.(mAh/g)` | `specific_capacity_mah_g` | optional auxiliary |
| `Chg. Spec. Cap.(mAh/g)` | `charge_specific_capacity_mah_g` | optional auxiliary |
| `DChg. Spec. Cap.(mAh/g)` | `discharge_specific_capacity_mah_g` | optional auxiliary |

### Required output dtypes

The parser should make these deterministic:

```text
record_index                int64
cycle                       int64
step                        int64
step_index                  int64
status                      string/object of canonical status strings
time_s                      float64
total_time_s                float64
voltage_v                   float64
current_ma                  float64
charge_capacity_mah         float64
discharge_capacity_mah      float64
charge_energy_mwh           float64
discharge_energy_mwh        float64
timestamp                   datetime64[ns]
power_w                     float64
```

Optional numeric auxiliaries should be `float64` when present.

## Record ordering and identity

### `DataPoint` is authoritative point order

- Parse it as integer.
- Sort by `DataPoint` if the worksheet is unexpectedly out of order.
- After sorting, require uniqueness and strict increase.
- Preserve one canonical output row per source record.
- Do not deduplicate equal timestamps.
- Do not sort primarily by timestamp.

Duplicate timestamps are legitimate because Neware can record several transitions at the same
second.

### Total elapsed time

Require `total_time_s` to be monotonic non-decreasing after `DataPoint` ordering, allowing only a
tiny floating tolerance such as `1e-9 s`.

A meaningful decrease is invalid because the energy integration and source-order assumptions would
be unsafe.

## Required numeric validation

For each source row:

Required finite values:

```text
DataPoint
Cycle Index
Step Index
Time(min)
Total Time(min)
Current(mA)
Voltage(V)
Power(W)
```

Capacity values must parse numerically and may legitimately be zero. If verified exports establish
that a capacity cell can be blank for a non-applicable phase, normalize that explicitly and test the
rule; do not silently accept arbitrary text.

Reject NaN/±Inf in required scientific fields.

Error messages should identify the source record and column, for example:

```text
Neware Excel record 438 has an invalid Voltage(V) value.
```

Do not dump the whole row.

## Status normalization

CellXplorer downstream code already interprets canonical binary-Neware status strings. Excel labels
must be converted at the parser boundary.

Required verified mappings:

| Excel `Step Type` / `Step Name` | Canonical `status` | Existing protocol type ID |
|---|---|---:|
| `Rest` | `Rest` | 4 |
| `CC Chg` | `CC_Chg` | 1 |
| `CC DChg` | `CC_DChg` | 2 |
| `CV Chg` | `CV_Chg` | 3 |
| `CCCV Chg` | `CCCV_Chg` | 7 |
| `CCCV DChg` | `CCCV_DChg` | 20 |

Create one central explicit alias table in `neware_excel.py` for verified Excel labels.

Rules:

- case/whitespace-normalized lookup is allowed;
- output spelling must match the canonical grammar already consumed by CellXplorer;
- unknown non-empty executed status is fatal in the first implementation;
- do not pass raw `CV Chg` downstream because existing CV/status logic expects canonical forms;
- `Cycle` and `End` are control rows in the programmed plan, not normal point-level executed data.

If later real exports reveal additional Neware labels, add them with a source/test rather than a
heuristic.

## Executed-step reconstruction

This is the core algorithm of 039.1.

### Definitions

```text
step_index = programmed step number exported in record.Step Index
step       = unique executed occurrence across the source file
```

### Why `Step Index` alone is insufficient

The supplied workbook repeats the same programmed step inside a cycle because a loop returns to it.
For example, a programmed step can execute, another control path runs, and that same programmed step
executes again.

If both occurrences receive the same `step`, `calc.per_cycle` and Steps aggregation can merge two
executions incorrectly.

### Boundary rule

After canonical rows are ordered by `record_index`, start a new executed segment on the first row or
when **any** of these changes occur relative to the previous row:

1. `cycle` changes;
2. `step_index` changes;
3. normalized `status` changes;
4. `time_s` decreases by more than numeric noise.

Use a tolerance only for representation noise; for example:

```python
current_time < previous_time - 1e-9
```

Do not require the reset to land exactly on zero.

Assign globally increasing executed step IDs:

```text
first execution  → step = 1
second execution → step = 2
...
```

Every row in one contiguous execution receives the same `step`.

### Supplied-workbook acceptance

The supplied reference workbook must derive:

```text
201 executed step segments
```

and the derived segmentation must expose at least the known case where one programmed step executes
twice in the same cycle as two distinct canonical `step` values sharing one `step_index`.

## Optional `step`-sheet reconciliation

This child should use the supplied workbook's `step` sheet as an independent guard where present.

Expected verified headers:

```text
Cycle Index
Step Index
Step Number
Step Type
Step Time(min)
Oneset Date
End Date
Capacity(mAh)
Energy(Wh)
Oneset Volt.(V)
End Voltage(V)
```

The spelling `Oneset` is part of the observed Neware export. Match it explicitly; do not make a
generic typo-correction system.

### Identity reconciliation

When `step` exists:

- parse `Step Number` as unique increasing integer;
- sort summary rows by `Step Number`;
- require summary-row count == derived execution-segment count;
- sequentially compare:
  - derived canonical `step` == `Step Number`;
  - cycle == `Cycle Index`;
  - programmed `step_index` == `Step Index`;
  - canonical status == normalized `Step Type`.

An identity mismatch is fatal.

### Time reconciliation

For each executed segment, compare:

- first timestamp to `Oneset Date`;
- last timestamp to `End Date`;
- duration to `Step Time(min)`.

Use tolerance:

```text
max(2 seconds, known record interval)
```

For 039.1, if record interval is not yet parsed from metadata, 2 seconds is sufficient for the
synthetic tests and supplied workbook. 039.2 may route the declared record interval into the same
validation helper.

### Voltage/capacity/energy reconciliation

Use these conservative tolerances unless a real source proves they are too strict:

```text
onset/end voltage:
  absolute tolerance = 0.002 V

step capacity:
  max(0.002 mAh, 0.1% of |summary capacity|)

step energy:
  compare derived mWh with Energy(Wh) × 1000
  max(0.01 mWh, 0.1% of |summary energy|)
```

The summary is validation only. Do not write its capacity/energy into canonical raw counters.

### Missing `step` sheet

If `step` is absent:

- keep the boundary-derived canonical `step`;
- do not fail merely because independent validation is unavailable;
- return/retain a capability indicator that 039.2 can expose in metadata;
- Steps analysis is not disabled solely because this summary sheet is missing.

## Energy counter reconstruction

### Why it is needed

The verified `record` sheet contains instantaneous `Power(W)` but not the cumulative
`Charge_Energy(mWh)` / `Discharge_Energy(mWh)` counters emitted by the binary parser.

Existing `calc.per_cycle` expects raw energy counters with per-executed-step reset semantics.
Therefore the Excel parser must reconstruct equivalent cumulative counters from the point-level
power/time data.

### Integration rule

Within each canonical executed `step`, in `record_index` order:

1. first row cumulative energy = `0.0 mWh`;
2. for every subsequent row:

```python
dt_h = max(0.0, total_time_s[i] - total_time_s[i - 1]) / 3600.0
increment_mwh = abs((power_w[i - 1] + power_w[i]) / 2.0) * dt_h * 1000.0
cumulative += increment_mwh
```

3. reset cumulative to zero on every new canonical `step`.

### Direction assignment

Use canonical status/direction, not current sign alone.

For a charge execution:

```text
charge_energy_mwh    = cumulative
discharge_energy_mwh = 0.0
```

For a discharge execution:

```text
discharge_energy_mwh = cumulative
charge_energy_mwh    = 0.0
```

For Rest/non-energy control-like executed records:

```text
both = 0.0
```

Do not use cycle-summary energy as the raw counter.

### Supplied-workbook acceptance

When `calc.per_cycle` is later applied to the canonical raw output, cycle energy should agree with
Neware's cycle summary to about `0.0052 mWh` maximum deviation for the supplied workbook. The formal
cycle-level cross-check is owned by 039.2.

## Capacity counter semantics

Copy the source `Chg. Cap.(mAh)` and `DChg. Cap.(mAh)` values into canonical raw columns without
cycle-level accumulation.

Do not:

- sum them in the parser;
- make them continuous across CC→CV;
- replace them with the cycle summary;
- convert mAh to Ah.

The existing application deliberately handles source counter resets downstream.

## Timestamp semantics

Parse `Date` with strict conversion suitable for the observed Neware values.

Requirements:

- canonical dtype `datetime64[ns]`;
- duplicate timestamps allowed;
- invalid non-empty timestamps fatal;
- do not add timezone semantics that the source does not provide;
- do not reorder records by timestamp.

## Performance requirements

- Iterate the large `record` worksheet sequentially in read-only mode.
- Build the header-index map once.
- Build Python column arrays/lists and construct the DataFrame once.
- Avoid `DataFrame.iterrows()` over the full dataset.
- Prefer vectorized boundary/dtype operations after the single source read when clear.
- Do not open the workbook once per column.
- Do not parse other sheets repeatedly.
- Do not add multiprocessing inside the parser; import-level parallelism already exists outside it.
- Correctness wins over micro-optimization.

Record approximate parse time for the supplied 13,982-row workbook if available, but do not add a
benchmark framework in this child.
