## Goal

Give saved-plot artifacts one explicit home under:

```text
frontend/src/features/analyses/editor/artifacts/
├── DraftPlotCard.tsx
├── SavedPlotsPanel.tsx
├── SavedPlotPreviews.tsx
├── AnalysisCacheWarmupRenderer.tsx
├── CacheWarmupCoordinator.tsx
└── warmupCompletion.ts
```

This child extracts the saved-preview and artifact pipeline from `AnalysisPage.tsx`, moves the
already-separated draft and warmup modules, and reconnects every family through the canonical
trace/layout builders established by 038.1–038.5. It is an ownership move, not a rendering,
caching, scheduling, or product-behavior redesign.

Artifacts are regenerable derivatives of a **saved** plot. A draft plot remains session-only and
must never be submitted to artifact, thumbnail, warmup, or portable-report endpoints.

## Locked ownership and public surface

### `DraftPlotCard.tsx`

Move the existing draft visual component without changing its semantics. It owns presentation of
the amber unsaved-plot card only. The editor continues to own whether a draft exists, when it is
saved or discarded, and the session/workspace state that preserves it while navigating.

The component must not call saved-artifact or portable endpoints.

### `SavedPlotsPanel.tsx`

Extract the panel-level UI and orchestration currently named `SavedPlotsPanel` and
`TabDraftPlotCard`. It owns:

- the ordered saved-plot list within a tab;
- saved-card controls and existing accessible labels;
- placement of the session-only draft card;
- admission of visible/idle saved previews using the current progressive behavior;
- loading, empty, error, and retry presentation already shown in the panel.

It does **not** own analysis-document persistence, active-tab selection, autosave, or PUT request
construction. Those remain with `AnalysisEditor` in 038.8 and arrive through typed props and
callbacks. Do not introduce a second editor state store.

### `SavedPlotPreviews.tsx`

Extract the saved-preview and artifact helpers into this file. It owns:

- artifact and thumbnail lookup;
- the current preference order between a usable thumbnail, a usable artifact, and regeneration;
- family dispatch for Cycles, Time/Capacity, Steps, DCIR, Chargeability, and Rate Capability;
- reuse of each family's canonical trace/layout builders;
- application of the canonical visibility and shared plot-style policies;
- SVG generation, saved-row thumbnail generation, and 4:3 hover-preview generation;
- artifact storage with the current data signature and renderer signature;
- serialized generation, stale-generation handling, and the existing retry limit;
- preview loading, terminal empty/error, cached, and regenerated states;
- `buildPortablePlotSnapshots` (or an equivalently named exported function with the same result
  semantics) for Child 038.7.

The file may export narrow artifact/thumbnail types needed by the database and portable flow.
Avoid exporting internal queue or retry primitives unless a current caller genuinely requires
them.

Do not create a generic scientific figure compiler. Family dispatch may share artifact plumbing,
but each family remains responsible for converting its scientifically typed result into traces
and layout.

### `AnalysisCacheWarmupRenderer.tsx`

Extract the renderless family dispatcher currently in the page. Given one warmup task, it:

- resolves the referenced analysis and saved plot using the existing inputs;
- selects the correct family/policy path;
- mounts the same saved-preview regeneration path used on screen;
- reports exactly one terminal outcome to the coordinator.

It must import from `SavedPlotPreviews.tsx` and the family/policy modules, never from a route page.
It must not duplicate trace construction.

### `CacheWarmupCoordinator.tsx`

Move the coordinator without behavioral cleanup. Preserve:

- the idle/background and hidden-window admission rules;
- the manual warmup event and any exact event name;
- one active task at a time;
- backend task/status coordination;
- the existing five-minute watchdog;
- query invalidations after terminal completion;
- pause/disabled/error behavior;
- token/task scoping that prevents stale callbacks completing a newer task.

Only its import of `AnalysisCacheWarmupRenderer` should materially change.

### `warmupCompletion.ts`

Move the pure terminal-state resolver with its existing API and move/update its test. This is the
regression boundary for the deadlock fixed by Spec 005. Do not inline it into a component.

## Artifact equivalence contract

For the same saved plot, analysis specification, source data, renderer version, and visibility
state, this child must preserve:

1. the family request and result/data signature;
2. the ordered Plotly traces and layout after styling;
3. the artifact lookup/store identity;
4. whether the artifact is considered current, stale, or absent;
5. the SVG used as the portable fallback;
6. the saved-row thumbnail dimensions and crop;
7. the 4:3 hover-preview dimensions and crop;
8. the terminal warmup result and invalidations.

`SAVED_PLOT_THUMBNAIL_RENDER_VERSION` remains unchanged. A move-induced signature or image change
is a regression, not justification for a version bump. Stop and amend the parent if an intentional
visual change is actually required.

## State and failure behavior to preserve

- A missing cached thumbnail may fall through to artifact lookup or regeneration exactly as it
  does now; it must not become a permanent empty card.
- A failed lookup/generation/storage attempt must reach an existing retry or terminal error path.
- Every warmup task must reach exactly one terminal state, including missing analysis/plot,
  unsupported family, query error, empty result, timeout, and renderer failure.
- An old render/query completion must not complete a newly admitted warmup task.
- React Query keys, stale/cache times, `enabled` guards, and invalidations remain byte-for-byte
  equivalent where practical.
- Hidden series and segments remain hidden in cached, regenerated, hover, and portable figures.
- Multi-source provenance and family-specific empty reasons remain visible.
- Draft cards never enter the artifact queue.
