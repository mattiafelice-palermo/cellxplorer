## Additional parent-level locked decisions for 050.8

1. Progressive delivery may expose a complete Time/Capacity scientific series before the overall
   multi-series request is complete, but it does not change scientific computation.
2. Completed series become eligible for display one by one. Intentional batching/coalescing and
   artificial inter-series delay are not allowed without a new user decision.
3. Partial streamed state is ephemeral UI state only. It never becomes completed React Query data,
   persisted analysis result, saved artifact, thumbnail, export or portable-report data.
4. Exact persisted result-cache hits retain a one-shot complete-result fast path.
5. The final assembled result from a streamed miss must be scientifically and structurally equal to
   the ordinary complete Time/Capacity result.
6. Portable analysis remains a complete-result boundary. Format v2, manifest/payload kinds and
   import semantics do not change for streaming.
7. Before selecting the production Plotly update path, benchmark one-series-at-a-time declarative
   React/`Plotly.react()` reconciliation against targeted `Plotly.addTraces()` in the same installed
   runtime. Do not substitute a batched third strategy.
8. Streaming must not share a request-owned SQLAlchemy session across an unsafe worker boundary.
9. No migration, scientific/parser/raw/prepared/result-schema/cache-key version change is implied by
   delivery-only streaming.
10. 050.P1 remains planning-only and out of scope.
