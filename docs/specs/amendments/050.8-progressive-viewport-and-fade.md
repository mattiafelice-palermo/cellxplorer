# Amendment — Spec 050.8 progressive viewport preflight and trace fade

Status: Normative user-directed amendment

Applies to: `docs/specs/050.8-progressive-time-capacity-series-streaming.md` and supersedes the conflicting viewport/fade details in `docs/specs/amendments/050.8-progressive-rendering-stability.md`.

Decision date: 2026-08-22

## Reason

Hands-on review showed that freezing the frame from the first arriving series is still visually wrong. If later Cells span a longer X range or a wider Y range, freezing the first-series frame either clips them until completion or forces a final jump. Reusing the prior request's frame is also wrong when the requested cycle/time extent changes: for example, moving one cycle at a time must move to the new cycle's frame before showing the new series.

The user also explicitly requested a short fade for each newly arriving logical scientific series.

The objective is therefore: **move the axes once to the new request's intended automatic viewport, then reveal the new series one-by-one inside that stable frame.** The viewport decision must not erase the performance gain from progressive streaming.

## Locked decisions

### 1. Manual zoom wins

If the user has an explicit/manual viewport, preserve it. Progressive viewport preflight must not overwrite manual X/Y/Y2/Y3 ranges. The existing reset semantics continue to control when manual zoom is cleared.

### 2. Automatic requests should establish the new request viewport before the first visible series

For an automatic viewport, do not freeze the previous request's range merely because it is compatible, and do not derive the request frame from only the first arriving series.

Preferred sequence:

```text
old complete plot at full opacity
-> new request starts
-> cheaply determine a conservative viewport for the new request
-> apply that viewport once
-> first new logical series appears
-> later logical series appear inside the same frame
-> terminal completion normally requires no viewport change
```

This applies to X as well as Y. A cycle-range or time-range change may therefore move the X viewport once before the new series appears. Later Cells with different test duration must not keep extending/shrinking the X axis one-by-one.

### 3. Viewport preflight must be metadata-first, bounded and non-scientific

Do **not** run a preliminary full scientific pass, construct every complete trace twice, or scan/materialize all selected rows solely to find extrema.

For ordinary Time/Capacity Voltage/Current views, prefer cheap metadata that already exists or can be read without materializing the scientific data, in this order where practical:

1. existing request/cache/index metadata;
2. Parquet footer / row-group statistics for only the row groups implicated by the requested cycles;
3. another equally bounded metadata-only representation already consistent with the local cache architecture.

The current raw cache already maps requested cycles to bounded Parquet row groups. Any viewport preflight should exploit that structure rather than re-reading all data.

The preflight does not need mathematically exact extrema. A conservative envelope that safely contains the eventual plotted data is acceptable and preferred over repeated autoscaling. Apply deterministic padding in the frontend rather than relying on Plotly to choose a different autorange padding as each series arrives.

### 4. Performance guardrail

The metadata viewport step is acceptable only if it is cheap relative to the first useful streamed series and does not materially regress perceived or final latency.

Instrument/measure the viewport-preflight cost. If trustworthy bounds cannot be obtained cheaply for a plot mode, **preserve the streaming performance instead of performing an expensive second pass**.

For such a mode:

- do not duplicate derivative/scientific computation;
- use the best safe bounded fallback available;
- at most one final authoritative viewport correction is allowed;
- return evidence to review if the fallback still causes materially unstable progressive rendering.

Derivative views in particular must not run dQ/dV or dV/dQ twice merely to get Y extrema.

### 5. Trace-local fade is required

Every newly arriving logical scientific series must receive a brief local fade-in, targeted at approximately **100–150 ms** and never exceeding **200 ms**.

The fade must:

- start immediately when that logical series becomes renderable;
- add no intentional delay before rendering;
- not batch/coalesce completed scientific series to make the animation easier;
- apply only to the newly arriving logical series, not the whole figure or axes;
- not animate axis/layout transitions;
- not trigger a Plotly remount/`newPlot` per arrival;
- restore the canonical final opacity/style exactly;
- not affect scientific/export/save/cache/portable data;
- not materially regress per-arrival or final Plotly cost.

If the selected declarative Plotly ownership model cannot implement this safely, do not silently omit the fade. Return the technical evidence to review for a user decision.

### 6. Whole-plot dimming remains removed

The compatible previous complete plot stays at normal opacity until the first current-request series replaces it. Fetching/start must not apply a whole-plot opacity transition.

## Acceptance additions

- A request whose new cycle/time extent differs from the previous request moves to the new automatic X viewport once before the first new series is shown.
- A later Cell with a longer duration does not change X range after progressive rendering has started.
- A later Cell with a wider voltage/current span does not change Y/Y2/Y3 range after progressive rendering has started.
- Automatic viewport preflight is metadata-only/bounded for normal Voltage/Current Time/Capacity paths and its measured cost is recorded.
- No full duplicate scientific pass or duplicate derivative calculation is introduced.
- Manual zoom remains authoritative.
- Each newly arriving logical scientific series visibly fades in over about 100–150 ms (hard maximum 200 ms) without batching or delayed delivery.
- No whole-plot fade or animated axes are introduced.
- Final complete scientific and visual state remains identical to the ordinary complete-result path.
