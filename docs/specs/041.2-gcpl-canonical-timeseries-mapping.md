## Goal

Map the low-level BioLogic GCPL-family records decoded by 041.1 into Parent 040's **CellXplorer canonical cycling DataFrame** with deterministic cycle, programmed-step, executed-step, status, time, current, voltage, capacity, energy and timestamp semantics.

This child is the scientific core of BioLogic cycling support. It must prove that a supported GCPL `.mpr` can be represented in the same canonical model used by Neware without creating BioLogic-specific downstream calculations.

At completion, direct parser-facade calls for a supported GCPL MPR should be able to produce a canonical raw DataFrame that passes `canonical_cycling.validate_raw_timeseries(...)` and can feed existing `calc.per_cycle(...)` in tests. User-facing import/scanner support remains out of scope until 041.4.

## `record_index`

If the MPR data block has no explicit record-number column, assign canonical acquisition ordinal deterministically.

Preferred convention:

```text
1..n_datapoints
```

if that matches current canonical Neware record-index expectations and 040.1 tests. If the post-040 contract uses zero-based indexes, follow that instead.

Requirements:

- unique;
- strictly increasing in decoded record order;
- never derived from timestamp sorting;
- no reordering of binary records after decode.

## Programmed sequence -> `step_index`

Use the independently validated BioLogic sequence identifier (`Ns` or equivalent) from the decoded records as the source of programmed-step identity.

### Numbering normalization

Establish whether the vendor sequence ID is zero-based/one-based by comparing the paired `.mpt` settings/data and the experiment's visible sequence numbering.

Then choose one deterministic canonical normalization:

```text
step_index = source sequence identity transformed only by the documented base adjustment
```

Do not renumber by order of first appearance because loops/restarts may revisit sequences.

For the verified GCPL6 layout, raw `Ns` is zero-based and the canonical rule is
`step_index = raw Ns + 1`. This same adjustment is applied to raw `goto Ns` targets. The exact
rule is recorded in `docs/biologic-mpr-format.md` and covered by full-MPR and mapper tests.

## Executed occurrence -> `step`

Create one globally increasing source-local executed occurrence ID.

A new execution boundary occurs when independently verified signals show a new concrete operation occurrence. Use the smallest reliable union of:

- programmed sequence ID changes;
- explicit sequence-change flag from 041.1 when verified;
- source step-time reset when verified;
- a control-mode transition only when it represents a new canonical step rather than a subphase of the same CCCV execution;
- other explicit vendor execution markers established in the paired corpus.

### Important CCCV rule

Do **not** automatically split one BioLogic GCPL execution into separate canonical programmed steps just because control transitions from galvanostatic to potentiostatic during one sequence.

Parent 040's canonical `step_index` represents programmed operation identity. When one GCPL programmed sequence contains a CC portion followed by a CV portion, prefer to keep one executed `step` and classify the block as a canonical CCCV status if that matches current CellXplorer semantics.

Only split the executed step if paired evidence shows BioLogic itself represents them as distinct sequence executions or existing canonical calculations cannot remain correct otherwise. Such a deviation must be explicit in the review.

## Canonical status classification

Classify each executed block from decoded control mode/current direction and, where required, the block's internal mode history.

Use Parent 040's established canonical status strings exactly.

Target mapping principles:

### Rest

If the programmed/executed GCPL sequence is a true rest/open-circuit/no-current hold under verified BioLogic semantics:

```text
status = Rest
```

Do not label a brief current zero crossing inside a charge/discharge step as Rest.

### CC charge/discharge

A current-controlled block with one nonzero direction and no CV portion maps to canonical CC charge or discharge according to the CellXplorer current sign convention.

### CV charge/discharge

A voltage-controlled block that is independently verified as a standalone CV operation maps to canonical CV charge/discharge.

### CCCV charge/discharge

One executed GCPL sequence containing both current-controlled and voltage-controlled portions in the same direction maps to canonical CCCV charge/discharge when that matches the source's control behavior.

This supports the existing `_cv_charge_by_cycle` logic without teaching `calc.py` BioLogic mode flags.

### Ambiguous mixed direction/control

Fail the supported-GCPL mapping for that execution/file rather than picking a status from the last row.

## Current sign normalization

Parent 040 documents the CellXplorer canonical sign convention based on existing Neware behavior.

Establish BioLogic raw current sign from the paired `.mpt`/known experiment and normalize:

```text
current_ma = raw BioLogic current × deterministic sign factor
```

if required.

Do not change Parent 040's global convention.

Required tests include known charge and discharge segments where the canonical status and current sign agree.

## `total_time_s`

Use BioLogic whole-experiment elapsed time when decoded/validated.

Requirements:

- preserve source record order;
- numeric, finite, non-decreasing within tolerance;
- no artificial reset at cycle/step boundaries;
- no conversion through datetime before storing seconds.

## `time_s`

Prefer a decoded BioLogic step-time field when paired `.mpt` confirms its meaning.

If the supported file variant lacks a stored step-time field, derive:

```text
time_s = total_time_s - total_time_s at first row of executed step
```

with the first row at/near zero under a documented convention.

Do not use cycle-relative time.

## Cycle mapping

Use the strongest vendor-provided cycling identity available in the supported GCPL records.

Priority:

1. explicit verified full-cycle number field, if present and semantically correct;
2. verified half-cycle counter transformed into logical full cycles;
3. only if neither is available, a deterministic charge/discharge execution-pair algorithm explicitly approved by Parent 041 amendment.

### Half-cycle conversion

If the paired corpus only exposes a half-cycle counter, derive the exact full-cycle formula from EC-Lab's own `.mpt` cycle/half-cycle output and document it.

Do not assume `floor(half_cycle / 2) + 1` without empirical confirmation of starting value/direction.

Formation/preconditioning segments before the first logical full cycle must be handled consistently with current CellXplorer cycle semantics. If the source contains rows that EC-Lab does not assign to a full cycle, either map them under a documented source-local cycle convention accepted by the parent or fail that variant; do not silently shift every later cycle.

## Capacity mapping

### Preferred source

Use the BioLogic accumulated charge/capacity field whose meaning is verified against paired `.mpt` output.

Normalize to mAh.

### Separate charge/discharge canonical counters

For each executed block/phase:

- populate the canonical charge counter only for charge-side rows;
- populate the discharge counter only for discharge-side rows;
- use `0` or NaN outside the phase according to the existing Neware canonical contract and `calc.per_cycle` expectations established by 040.1;
- preserve/reset the selected vendor counter in a way compatible with current per-step delta summation.

Do not convert a signed net charge into both columns by absolute value without direction tests.

### Integration cross-check

Independently integrate canonical `current_ma` over `total_time_s` for representative blocks/cycles and compare to vendor-provided capacity. Use this as a test/diagnostic, not a silent replacement.

Define tolerances based on record spacing/float precision and paired ground truth, not arbitrary large percentages.

### Fallback if capacity field absent

If some otherwise supported GCPL variant lacks the verified capacity field, do **not** add a current-integration fallback in this child unless explicitly covered by a parent amendment. Initial support may fail closed with a clear missing-required-column/capability error.

## Primary voltage mapping

For two-electrode GCPL or where one verified full-cell/primary voltage channel exists:

```text
voltage_v = verified primary cell/working voltage according to source configuration
```

For the supplied GCPL6 three-electrode file, final Ewe/Ece/Ecell semantics belong to 041.3. If a directly stored full-cell channel is not yet decoded in 041.2, it is acceptable to defer the supplied file's full three-electrode canonical acceptance to 041.3 while still validating two-electrode/synthetic GCPL raw mapping here.

Do not guess `Ewe` alone is the full-cell voltage for GCPL6.

## Energy mapping decision

During implementation, choose one of these two explicit policies based on actual supported fields and tests:

### Policy A — verified vendor energy fields

Map source charge/discharge energy counters to canonical mWh.

### Policy B — deterministic integration

Derive per-step accumulated energy using:

```text
P = voltage_v * current
integrate |P| over total_time_s within phase/executed step
```

with sign/direction handled explicitly, using trapezoidal integration on synchronized rows and resetting canonical counters per executed step.

Required for Policy B:

- no integration across source time discontinuities;
- no charging energy from discharge rows or vice versa;
- tests with analytic/simple synthetic profiles;
- independent comparison to EC-Lab/exported energy if available.

### Policy C — unavailable

If neither can be validated reliably, leave canonical energy columns absent/NaN and set capability accordingly. Existing cycle energy quantities then truthfully remain unavailable.

The implementation record and review must state which policy is chosen. Do not silently switch per file.

## Timestamp mapping

041.2 may implement a minimal acquisition-start decoder only if 041.1 already established the needed log field independently. Otherwise leave absolute timestamps to 041.3.

Final canonical timestamp rule:

```text
timestamp = verified acquisition_start + total_time_s
```

Timezone handling must follow the source metadata/current application convention and be documented. Do not use local file mtime.

Implemented on the shared `feature/biologic-mpr-gcpl-support` branch after the Sol-approved 041.1
checkpoint.

- Added `backend/app/services/biologic_gcpl.py` as a separate source adapter. Direct
  `parsing.parse_timeseries("*.mpr")`, `source_parser_descriptor`, `parser_identity`, and the
  direct registry now recognize the supported MPR contract; `source_filename_allowed` and the
  Neware import/scanner extension set still exclude `.mpr` until 041.4.
- Record identity is the one-based acquisition ordinal. ID 131 (`Ns`) is a zero-based source
  sequence identity in the verified sample and maps to canonical `step_index = Ns + 1` (`Ns >= 0`);
  the private sample's raw `Ns=1` therefore corresponds to settings sequence 2. The same `+1`
  adjustment applies to raw `goto Ns` targets, with raw target zero retained when a nonzero repeat
  count proves it is a real loop target. Paired MPT confirmation remains pending. The supplied
  sample's ID 468 half-cycle field is constant zero. Non-zero, regressing,
  or resetting half-cycle sequences, and any set counter-increment flag, fail closed until paired
  MPT evidence establishes cycle numbering and formation behavior; no guessed formula reaches
  production. No cycle column is emitted without an independently decoded full-cycle field;
  synthetic semantic records use explicit `raw_cycle_index` only to exercise downstream mapping.
- Executed `step` is a one-based occurrence split by `Ns`/verified cycle/half-cycle changes,
  explicit decoded step-time resets, and entry/exit from mode 3 rest. A verified cycle transition
  is itself an executed-step boundary and cycle values may not regress. The decoded `Ns-changed`
  flag is accepted only when redundant with a real `Ns` transition; an unexplained midstream flag
  fails closed. Repeated
  adjacent mode codes are compressed, but only a chronological mode history of pure CC, pure CV,
  or CC followed by CV is accepted. A CC-to-CV transition remains one occurrence and is classified
  retrospectively as `CCCV_Chg` or `CCCV_DChg`; reversed or re-entering transitions fail closed.
  Mixed direction fails closed. Standalone CV discharge is rejected because the current canonical
  vocabulary has no `CV_DChg` status.
- If an explicitly decoded step-time field is present, it is published directly as canonical
  `time_s` and must reset to approximately zero at every reconstructed executed-step boundary;
  contradictory clock values fail closed. If absent, `time_s` is derived from validated whole-test
  elapsed time.
- The adapter's accepted source-sign factor is `+1` (positive charge, negative discharge), but
  paired MPT semantic parity is not run. Mode-1 ID-5 control values provide current; a mode-2
  block requires an independently decoded measured-current field, and unverified ID-7/time
  reconstruction is rejected. The signed ID-211 counter must agree with current and incremental
  ID-7 direction, remain monotonic within each executed step, and is converted into separate
  non-negative per-step charge/discharge counters. Boundary rows must have zero incremental and
  cumulative capacity transfer because interval ownership is not independently established;
  ambiguous boundary ownership is an unsupported source variant rather than malformed bytes.
  Zero-current active blocks, transferring Rest blocks, inconsistent signs, and error-flagged rows
  fail closed. `integrate_capacity_by_step` is an independent diagnostic only.
