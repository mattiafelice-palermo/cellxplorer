## Goal

Extract the complete Time/Capacity frontend adapter from `AnalysisPage.tsx` into:

```text
frontend/src/features/analyses/editor/families/time-capacity/TimeCapacityPlotCard.tsx
```

One Time/Capacity point represents one raw measurement record inside selected cycles, possibly
after backend-provided derivative calculation and envelope-preserving display sampling. The family
must own configuration/defaults, settings, query/progress, coordinate construction, point
segmentation, canonical traces/layout, live plot, style preview, and ordinary exports.

The backend remains authoritative for continuous stitched time/capacity, source provenance,
ICA/DVA calculation, and downsampling. The frontend must not reconstruct scientific arrays from an
already sampled response.

## Locked result and request contract

Keep `TimeCapacityResult` and `TimeCapacityTrace` in `frontend/src/api.ts`. Do not create a
frontend replacement shape.

The live request remains:

```ts
POST /api/analyses/{analysisId}/time-capacity
{
  spec,
  job_token,
  viewport_width: 1200,
  precision: "standard",
  compact: true,
}
```

Preserve exactly:

- fixed `viewport_width = 1200` in cache identity, rather than using transient DOM width;
- `max_points_per_cell` as the point-density control;
- the existing data signature fields:
  - selection;
  - protocol segments/filter and hidden protocol-segment IDs;
  - explicit/range cycle selection;
  - point limit;
  - X axis, time unit, display mode, and electrode area;
  - derivative view/phase/specific/sign/smoothing settings only for ICA/DVA;
- exclusion of purely client-side `stacked` and current-axis choices from the scientific result
  identity;
- `staleTime` and `gcTime` of 30 minutes;
- previous data as placeholder during background refresh;
- enablement only with at least one selected entry;
- one background token, cache-hit/no-job behavior, 300 ms polling, and delayed token clearing;
- `onReadyChange` semantics;
- no simultaneous generic Cycles compute triggered merely because this family is active.

Changing the data signature can create stale or excessive computation and is out of scope.

## Locked scientific/presentation behavior

### Voltage/current mode

Preserve:

- backend-provided canonical `display_x` when present;
- time scaling without recomputing scientific time continuity;
- capacity coordinates and per-Cell metadata/override handling for mass or area;
- consecutive half-cycle placement;
- overlap reset and mirrored discharge;
- phase/status segmentation so lines do not connect across scientifically separate regions;
- voltage plus optional current subplot;
- left/right current axes and availability checks;
- source-boundary annotations and source provenance export columns;
- current-axis units, labels, and hover data.

### ICA/DVA mode

Preserve:

- backend-returned `derivative_x` and derivative values;
- charge/discharge/both selection;
- mass-specific derivative option;
- absolute discharge derivative option;
- odd bounded smoothing window sent to the backend;
- no client-side recomputation from sampled voltage/capacity arrays.

### Shared plot behavior

Preserve:

- style identity and per-series rules;
- trace ordering and palette order;
- stacked versus flat layout and the Plotly remount at that boundary;
- zoom memory enablement/signature;
- legend dragging;
- WebGL live conversion with SVG-capable canonical export traces;
- delayed progress, cached-content dimming, loading overlay, error, and empty states;
- image/data export and export preview;
- style-modal live preview using the same canonical builders;
- manual-axis resets when changing coordinate/view scale;
- 330/520/310-style compact analysis geometry from the visual guide.

Do not reinterpret the current `stacked` option as the future generalized Top/Main/Bottom panel
model. That design is explicitly outside this parent.

## Target public surface

Export a minimal family surface equivalent to:

```ts
export type TimeCapacityConfig = NonNullable<AnalysisSpec["computation"]["time_capacity"]>

export const DEFAULT_TIME_CAPACITY: TimeCapacityConfig

export function timeCapacityConfig(spec: AnalysisSpec): TimeCapacityConfig

export function timeCapacityTracesForResult(
  result: TimeCapacityResult,
  spec: AnalysisSpec,
): Plotly.Data[]

export function timeCapacityLayout(
  result: TimeCapacityResult | undefined,
  spec: AnalysisSpec,
  traces: Plotly.Data[],
): Partial<Plotly.Layout>

export function TimeCapacitySettings(props: ...): JSX.Element
export const TimeCapacityPlotCard: React.MemoExoticComponent<...>
```

Equivalent descriptive names are acceptable. Do not leave the ambiguous generic
`tracesForTimeCapacity` in the page. Pure coordinate/segment/current helpers may remain private
inside the one family file.

Do not split this child into `query.ts`, `traces.ts`, `layout.ts`, or multiple setting components
unless review demonstrates an unavoidable circular dependency. Cohesion, not a line-count target,
is the locked objective.


Do not alter existing stored specs or introduce a new spec version.
