**Status:** Partial implementation — metadata-only MPR lifecycle is implemented; cycle-ready preview/cache acceptance remains blocked pending an independently verified full-cycle identity

## Goal

Expose the reviewed BioLogic GCPL `.mpr` backend capability through CellXplorer's normal import, source registration, scanner/update, cache-preparation, continuation/provenance and Windows packaged-runtime paths.

This child is deliberately about **source-format exposure and lifecycle integration**, not scientific formula changes or three-electrode plot UX.

**Product boundary for the current real-file evidence:** the recognized production `.mpr` layout
is header-readable, but its records do not yet contain an independently verified full-cycle identity.
The implementation therefore exposes it as an explicit metadata-only source: inspection and header
registration are supported after user acknowledgement, while canonical cycling rows, capacity
preview, background cycling caches, and analysis-ready status are withheld. The synthetic fixtures
used by 041.1/041.2 continue to validate the reader and mapper contract, but they are not a claim
of real-file parity. `.mpt` is not imported or bundled.

At completion users must be able to select and inspect a recognized `.mpr` in the same Inbox workflow used by existing supported Neware sources, and explicitly register a metadata-only source when its cycle identity is not verified. The resulting `SourceFile` participates in online/offline/changed checks and provenance as a non-analysis-ready source using Parent 040's per-source parser identity; cache preparation is intentionally skipped until the cycle identity is resolved.

## Final supported source extensions after this child

Centralized source policy must include:

```text
.nda
.ndax
.xlsx   # structured Neware only
.mpr    # supported BioLogic GCPL-family only
```

Still unsupported:

```text
.mpt    # validation ground truth, not user source format in Parent 041
.xls
.xlsm
.csv
arbitrary .xlsx
arbitrary/unsupported MPR techniques
```

Extension lets a source enter **inspection**. Adapter recognition/technique checks decide whether it is actually a supported source.

## Centralized source-format policy

Use Parent 040's source adapter registry/format recognition as the authoritative backend policy.

Do not create a second independent extension set in `files.py`, `scanner.py`, and `import_inspection.py`.

A small compatibility helper such as `source_filename_allowed(...)` may remain, but it must derive from the adapter registry/current supported-user-import formats.

Low-level 041.1 may structurally read more MPR variants than the product accepts. User import should succeed only when the BioLogic adapter recognizes the file as the supported GCPL-family contract.

## Import inspection

Preserve the bounded architecture established by Specs 035/039.

Required sequence:

```text
stat
→ extension/admission check
→ sha256
→ cheap parsing.read_header_metadata(.mpr)
→ restat
→ reject moving source
→ remember metadata under verified fingerprint
→ return immutable FileInspection
```

### Header-only requirement

041.3 must provide a cheap `.mpr` metadata path. `inspect_file` must use it, not decode all cycling records.

A large folder of MPR files must not parse full datasets merely to open the third import modal.

### Adaptive outer parallelism

Preserve existing strategy:

- one sampled source first;
- small batches serial;
- larger batches bounded process pool;
- current worker cap/half-CPU policy;
- parent-process metadata cache restoration;
- order restoration;
- truthful progress phases.

Do not add an inner thread/process pool inside each MPR parser. Large-batch parallelism happens **between files**.

### Header parser process safety

Ensure memory maps/file handles are opened/closed inside each worker and no unpicklable mmap/view object is returned across process boundaries. `FileInspection` should carry ordinary metadata/strings/numbers only.

## Import error behavior

### Unsupported MPR technique/layout

A valid BioLogic modular file outside Parent 041's supported GCPL contract should fail with concise wording such as:

```text
This BioLogic .mpr uses an electrochemistry technique or file layout that CellXplorer does not support yet.
```

Include a more specific internal error/detail where current API conventions permit it.

Do not report it as corrupt if the reader can identify it as structurally valid but unsupported.

### Corrupt MPR

Use a clear invalid/corrupt source message derived from the MPR error taxonomy.

### Missing optional metadata

If raw GCPL cycling remains scientifically parseable but optional log/reference/protocol metadata are absent under 041.3 capability rules, inspection may succeed with warnings/capability limitations.

### Unrelated file renamed `.mpr`

Fail on magic/structure recognition.

## Capacity preview


Do not add an MPR-specific summary calculation endpoint.

- first cycle-capable preview parses full MPR once if no cache;
- preview returns canonical cycle capacities/times/energy where supported;

- repeated preview uses cache;

## Registration

Register MPR as a `SourceFile` with an explicit capability state:

```text
path
filename
size
ext = "mpr"
hash
header_meta
parser_version = biologic adapter identity
parse/status/count/capacity summaries (metadata-only sources have no cycling rows and unavailable capacity summaries)
```

No point/cycle/step rows are inserted into SQLite.

Metadata-only registration requires an explicit Inbox acknowledgement and queues no cycling-cache
job. The server owns the normalized header; the browser may echo only a typed hash/size/`mtime_ns`
identity receipt. A final source fingerprint pass runs immediately before the relational commit,
including continuation attachment.

Preserve:

- immediate Cell relational registration/background cache preparation established by import performance work;
- fingerprint/hash duplicate handling;
- full header once per source;
- curated `CellMetadata` only;
- folder/replicate assignment behavior;
- one internal Test row per Cell.

## Source lifecycle

### Unchanged source

Current source path/hash/size online behavior remains normal. No MPR-specific polling.

### Offline source

Normal offline handling.

### Changed/growing source

BioLogic may write/extend an MPR while an experiment is running. Preserve the source-signature safety rule:

- size + `mtime_ns` captured around inspection/parse;
- if source changes during read/build, defer/reject adoption;
- do not publish cache for a moving source as final current data;
- normal source monitor may retry later under existing cadence.

If MPR append behavior requires a different stable-file heuristic than Neware only after real evidence, that is a separate parent amendment. Do not add arbitrary sleeps.

### Successful replacement

Use new content hash, new parser-versioned cache and current source-adoption transaction. Remove old cache only under existing successful-replacement policy.

### Failed replacement

Preserve last usable cache/source state as current lifecycle rules require. Do not delete old cache before new MPR validates.

## Continuations / mixed formats

An MPR is another `SourceFile`; format alone neither proves nor forbids continuation.

Preserve Parent 034 rules:

- user-facing Cell → ordered SourceFiles;
- exactly one internal Test;
- source order/provenance;
- current continuation compatibility checks;
- tracked-tail final-source behavior;
- protocol-derived analyses still fail closed for multi-source Cells unless separately reviewed.

Do not weaken compatibility merely to allow Neware→BioLogic mixed-instrument chains.

## Implementation record

Implementation is complete on the shared feature branch and has passed the review-only Sol
approval loop. The centralized admission policy is
`.nda`, `.ndax`, structured `.xlsx`, and `.mpr`; `.mpt`, `.xls`, `.xlsm`, `.csv`, arbitrary
workbooks, and unsupported MPR techniques remain excluded. `.mpr` inspection is header-only and
uses one SHA-256 establishment read plus stat-only guards; the server-owned header cache is not
sent to the browser. The normal import, continued-import proposal, and continuation-attachment
paths carry the server-issued hash/size/`mtime_ns` receipt through the workflow, perform stat-only
intermediate checks, and run a final full fingerprint pass immediately before the relational
commit. Cache and scanner worker results carry the same immutable identity and validate it for both
success and failure, reporting stale results without mutating newer rows. Persisted metadata-only
sources are gated consistently at parse, preview, cache, scanner, cycle, and analysis boundaries;
portable scientific export is included in that boundary, and portable import treats the existing
database capability as authoritative rather than allowing report metadata to rewrite it. The
frontend resolves the same capability from the live draft selection for analysis cards, saved
preview generation, warmup, and portable export. Continuation registration requires an explicit
acknowledgement and queues no cycling work. The current real MPR layout is
`canonical_cycling=false`, `metadata_only=true`: no point/cycle rows or cycling cache are created,
and capacity preview is unavailable with a stable warning. Staged metadata facts are bounded by
both field length and serialized payload size; confirmed missing cache results remain distinct from
stale identity results and unclassified worker failures.
The independent reader uses existing NumPy/pandas plus stdlib code; static module-collection
coverage is present, while packaged smoke is **NOT RUN** in this checkpoint and no MPT parity sample
is available. Verification is green: the full backend suite passes (1,107 tests), the complete
frontend policy suite passes (510 tests), and the TypeScript check passes. The normal Vite bundle
stage remains blocked by the sandbox's `Cannot read directory "../../..": Access is denied`
traversal failure; the required elevated retry is unavailable because the environment usage limit
was reached. Canonical preflight completed with 4/5 stages passing; the only failed stage was the
same sandbox-blocked Vite production bundle. All 67 backend test modules passed in its backend
stage.
