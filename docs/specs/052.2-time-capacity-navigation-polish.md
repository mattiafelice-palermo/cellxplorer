Make the Time/Capacity cycle navigator feel like direct plot navigation rather than a form wrapped around a plot, while keeping one canonical scientific range and preserving the query/cache/runtime guarantees established by Specs 050, 051.2, 052 and 052.1.

This child covers:

1. richer range navigation and history access;
2. live slider-drag feedback without history/autosave/query flooding;
3. better defaults for a brand-new Time/Capacity view;
4. a Time/Capacity Plotly modebar control for the existing canonical grid setting.

No backend scientific calculation, parser, migration, endpoint, or cache-version change is intended.

## Verified current facts that constrain the implementation

At the 052.1 handoff:

- `DEFAULT_TIME_CAPACITY` stores `cycle_start: 1`, `cycle_end: 3`, and `max_points_per_cell: 4000`;
- the default plot style uses `marker_mode: "none"`, which resolves Time/Capacity primary series to line rendering;
- the default plot style owns `show_grid: true`;
- `timeCapacityLayout(...)` reads `style.show_grid` for its axes;
- the Time/Capacity query identity includes `cycle_start`, `cycle_end`, and `max_points_per_cell` and sends the current request `spec` to `/time-capacity`;
- the visible From/To inputs and canonical analysis state must not be mutated for every slider pointer event.

These facts mean live drag preview must be deliberately separated from persisted/history state. Do not obtain dynamic feedback by calling the normal editor `update(...)` path on every pointer movement.

## Locked user decisions

### 1. The slider represents the full current cycle window

Use a range-shaped navigator that visually represents the complete current inclusive window over the full available cycle extent.

Example for cycles `189–208` of `720`:

```text
1 ─────────────[════ current 189–208 ════]──────────────────────── 720
```

Requirements:

- the highlighted segment position is proportional to `start..end` within `1..maxAvailableCycle`;
- the segment width represents the current inclusive cycle-window width;
- dragging the segment moves the whole window horizontally and preserves its width;
- dragging clamps at the lower and upper bounds without changing width;
- the Cycle window size selector remains the owner of resizing the window;
- do not create independently draggable endpoints as a second width-control model;
- the 052.1 anchored-callout geometry remains unless a minor size adjustment is required for usability;
- do not add an `of N cycles` label or other extra chrome.

### 2. Live drag feedback: range boxes and plot follow the drag

While the user is actively dragging the range segment:

- the displayed From and To values update immediately to the transient preview range;
- the plot follows the transient range before pointer release;
- movement should feel continuous enough to understand the current location;
- the transient drag must not create one history entry, autosave mutation, persisted spec mutation, or canonical editor update per pointer event.

Use one explicit transient preview range owned locally by the Time/Capacity frontend path. It may be passed navigator → plot through a narrow ephemeral callback/prop.

The canonical scientific range remains:

```text
spec.computation.time_capacity.cycle_start
spec.computation.time_capacity.cycle_end
```

and is committed exactly once when the drag ends successfully.

#### 2.1 Query/runtime constraint

Do not issue an uncapped request for every raw pointer event.

The preview path must be bounded and cancellation-aware:

- local From/To feedback is immediate;
- no request-per-pixel flood;
- no unbounded concurrent requests;
- superseded requests are aborted where possible and made ineligible to render by request/query identity;
- cached exact preview results may be reused immediately;
- keep the last compatible plot visible while a replacement is pending rather than blanking/flashing;
- release creates one canonical/history step;
- scientific calculations remain backend-owned.

#### 2.2 Two-resolution live scrubbing — user acceptance amendment, 2026-08-24

The user explicitly rejected a slider that waits for a pause and then jumps to one coarse-looking result. Live scrubbing must use two request resolutions while preserving the single canonical plot setting.

**While the pointer is moving:**

- request a deliberately lighter transient preview using `max_points_per_cell = min(userConfiguredMaxPointsPerCell, 1000)`;
- this 1000-point value is a request-only interaction cap; never write it into `spec`, saved plots, drafts, presets, autosave, exports, or the visible Max points per cell control;
- publish the first low-resolution preview immediately and keep advancing to the newest range with short bounded latest-wins coalescing;
- use an interaction cadence around 40 ms as the initial scheduler target rather than the current 120 ms cadence. This is a scheduling target, not a requirement that backend + transport + Plotly must always complete within 40 ms;
- if a previous low- or full-resolution request is still in flight, abort/obsolete it as soon as a newer request becomes authoritative. Never build a FIFO backlog of slider positions.

**When movement pauses but the pointer is still held:**

- after approximately **50 ms without pointer movement**, immediately request the same transient range at the user's full configured `max_points_per_cell` (4000 by default);
- do not wait for pointer release to sharpen the plot;
- while this full-resolution request is pending, the last compatible low-resolution plot remains visible.

**If movement resumes after that pause:**

- immediately abort/obsolete the pending full-resolution request;
- immediately return to the low-resolution preview mode for the newest transient range rather than waiting for the previous throttle window to expire;
- a late full-resolution response for the older transient range must never replace the newer low-resolution/current plot.

**On pointer release:**

- commit the range exactly once to canonical analysis state/history/autosave;
- guarantee the final range resolves at the user's full configured `max_points_per_cell`;
- if an exact full-resolution result for that same range already completed during the 50 ms pause, reuse it through the normal query cache rather than recomputing a semantically identical result.

The intended state machine is therefore:

```text
MOVING
  -> immediate/latest-wins low-resolution preview (<=1000 points per cell)

IDLE >= ~50 ms while still holding
  -> full configured resolution for the same transient range

MOVEMENT RESUMES
  -> obsolete/abort that full-resolution request
  -> immediate low-resolution newest-range preview

RELEASE
  -> one canonical range/history commit
  -> full configured resolution guaranteed
```

If the callout is closed, pointer drag is cancelled, or Escape is pressed before a completed commit, discard the transient preview and restore the canonical pre-drag range without adding history.

### 3. Slider keyboard navigation uses the directional keys

When the range slider/segment itself has keyboard focus:

- ArrowLeft moves the whole current window one cycle earlier;
- ArrowRight moves it one cycle later;
- preserve width and clamp at bounds;
- retain standard focus visibility and Escape behavior;
- do not add PageUp/PageDown, Shift+Arrow, Home/End, or other shortcut families unless required by the chosen accessible primitive.

### 4. Previous View gets a recent-history dropdown

Keep the main Previous View action as one-step back. Add a compact dropdown beside it:

- session-only bounded history;
- approximately 5–10 distinct ranges, newest first;
- compact labels such as `189–208`;
- selecting an older item restores that stack point without pushing the current range and discards more-recent entries above it;
- no adjacent duplicates;
- preserve null-bound/Specific cycles behavior;
- use compact Mantine split/menu geometry.

### 5. Ctrl+click gives first/last-window navigation

Normal semantics remain:

- `‹` previous cycle;
- `«` previous window;
- `›` next cycle;
- `»` next window.

Ctrl+click:

- either left button -> first valid window `[1,width]`;
- either right button -> last valid window `[max-width+1,max]`;
- preserve width/clamp;
- with no reliable maximum, an extreme Ctrl+click is a no-op rather than falling through to a normal action.

Tooltips:

- `‹`: `Previous cycle · Ctrl+click: first window`;
- `«`: `Previous window · Ctrl+click: first window`;
- `›`: `Next cycle · Ctrl+click: last window`;
- `»`: `Next window · Ctrl+click: last window`.

### 6. New Time/Capacity views default to the last 20 available cycles

For a genuinely new/virgin view, once a reliable selected maximum is available:

```text
end   = maxAvailableCycle
start = max(1, maxAvailableCycle - 19)
```

Examples:

```text
max 200 -> 181–200
max 20  -> 1–20
max 12  -> 1–12
```

Safeguards:

- selected maximum comes from the existing relational selected-Cell resolver and is independent of visibility;
- do not overwrite saved/restored plots;
- do not overwrite an edited draft/workspace;
- do not overwrite a user range edit made before the maximum loads;
- do not reinitialize on rerender or later maximum changes;
- do not initialize while Specific cycles is active;
- this is one-time initialization, not follow-latest mode;
- use an explicit/testable virgin-state guard rather than treating numeric `1–3` as permanently untouched.

This supersedes the parent 052 new-view `1–3` decision only for genuine virgin Time/Capacity views.

### 7. New Time/Capacity views default to line-only rendering

A new/virgin Time/Capacity plot resolves to lines without point markers using the canonical plot-style path:

- reuse `DEFAULT_PLOT_STYLE.marker_mode = "none"`;
- do not hardcode Plotly modes per trace;
- do not overwrite saved/restored scoped style;
- do not reset explicit series overrides or presets;
- do not change other analysis-family defaults.

### 8. Time/Capacity Plotly modebar Grid action

Add one Time/Capacity-only custom Plotly modebar action backed by canonical scoped `style.show_grid`:

- button appears with other Plotly actions;
- toggles through the existing plot-style update path;
- Plot Style panel synchronizes immediately;
- saved/draft/export rendering sees the same state;
- accessible action title is `Hide grid` when visible and `Show grid` when hidden;
- avoid duplicate buttons across rerenders;
- preserve `displaylogo: false` and legend editing;
- do not broaden this control to other families in this child.
