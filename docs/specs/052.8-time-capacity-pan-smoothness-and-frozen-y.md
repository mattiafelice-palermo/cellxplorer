# 052.8 — Time/Capacity pan smoothness and frozen Y

**Status:** Active child — implemented
**Parent:** Spec 052 — Time/Capacity cycle navigation
**Repository:** `mattiafelice-palermo/cellxplorer`
**Branch:** `feature/time-capacity-cycle-navigation`
**Reason for child:** user feedback on 052.7. Panning worked, but the y axis rescaled as each buffer landed, making the whole plot blink; and the motion stepped rather than glided.

## Goal

Make the pan continuous and visually stable, and tell the user when holding the y axis still has hidden data from view.

## Root causes

### C1 — The viewport was bound to the wrong state

052.7 derived the visible window from `previewRequest.range`. That only advances when the scheduler *admits a fetch*, so the viewport jumped between admissions instead of tracking the pointer. `cyclePreviewRange` is the state that updates on every pointer move; the viewport now follows it, and the buffer is sized from it.

### C2 — Every pointer move rebuilt the React layout

With the x range inside the `layout` memo, each move produced a new layout object, so react-plotly.js ran a full `Plotly.react` diff per frame. That is the expensive path, and it is what made the motion step.

The axis is now moved imperatively: one `Plotly.relayout` per animation frame, coalescing whatever moves arrived since the last. React keeps a stable layout during the drag and does no per-frame work. The live range is held in a ref that the layout memo reads, so a buffer landing mid-drag rebuilds at the position the pointer is actually at rather than snapping back.

### C3 — Y rescaled on every buffer

Each buffer covers a different cycle span, so autoscaled y moved whenever one landed — the blink. Y is now frozen for the duration of a drag, captured from the live axis as panning begins.

**Freezing is retained after release.** Rescaling on release would reintroduce exactly the blink being removed, one last time. The retained window is dropped when the y quantity itself changes (`view`, `x_axis`, `voltage_channel`, `stacked`, `display_mode`), because a retained range is meaningless once the quantity changes.

## The out-of-view affordance

Holding y still means the position the user settles on may hold data above or below the retained window. Rather than silently clipping it:

- `yDataOutsideRange` checks whether anything inside the visible x window falls outside the retained y window. Only the primary axis counts — the current overlay has its own scale and refitting y would not address it.
- While true, the modebar is pinned open (`displayModeBar: true`) instead of hover-revealed.
- A **Fit Y axis** button is added to the modebar, shown only in this state, highlighted in yellow.
- A bordered bubble appears under the toolbar: *"Some data is outside the current Y range. Use Fit Y axis in the toolbar above to show it all."*

Clicking the button drops the retained range, so the axis returns to normal autoscaling.

Plotly owns the modebar DOM, so the highlight is applied by selector scoped to a `data-tc-fit-y-hint` attribute on this card's container rather than by prop.

## Verification

- focused policy tests: 30 frontend navigation tests, covering buffer sizing, refill thresholds, point scaling, x span resolution, and out-of-view detection (visible-window scoping, secondary-axis exclusion, non-finite handling);
- canonical preflight: **PASS** 4/4;
- browser/manual acceptance: **RUN** — confirmed working by the user.

## Outstanding

- The release jump recorded as K1 in 052.7 is unchanged: the committed range still renders through the per-window path, so x returns to zero-based on release. Deciding whether a committed Time axis should show absolute elapsed time remains a product decision.
- K2 (very fast drags outrunning the buffer) and K3 (buffer sizing tuned on one dataset) from 052.7 are unchanged.
- The retained y window is per-card state and is not persisted with a saved plot.
