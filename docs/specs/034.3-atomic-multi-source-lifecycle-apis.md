# 034.3 — Atomic multi-source lifecycle APIs

**Status:** Plan
**Parent:** [034 — Multi-source cell continuations](034-multi-source-cell-continuations.md)
**Depends on:** 034.1, 034.2
**Scope:** Backend mutation contracts for initial import, attach, reorder, and detach.

## Current hazards

- `backend/app/routers/files.py::create_imported_cells` models one draft as one Cell/source.
- `register_files` can append many files, but it is a low-level route without continuation
  revalidation, cache invalidation, or complete activity semantics.
- `detach_file` can leave an empty Test.
- `reorder_files` accepts a partial list and updates only matching IDs, allowing duplicate
  positions or ambiguous order.
- None of these source-order mutations consistently invalidates affected analysis artifacts.

## Locked API behavior

### Initial import

Evolve `POST /api/imports/cells` so one Cell draft owns `sources[]`:

```json
{
  "cells": [{
    "cell_name": "Cell A",
    "description": null,
    "test_name": "Interrupted cycling",
    "sources": [{
      "staged_name": "...",
      "source_path": "C:\\...",
      "filename": "a.ndax"
    }, {
      "staged_name": "...",
      "source_path": "C:\\...",
      "filename": "a-continue.ndax"
    }],
    "acknowledged_finding_ids": []
  }]
}
```

Keep cell-level metadata/override/preset fields at Cell draft level. Do not duplicate them per
source. Preserve compatibility with current one-source requests during the same application
upgrade by normalizing the legacy flat draft to one `sources[]` entry server-side.

Create one Cell, one Test, one SourceFile/TestFile per ordered source, with dense positions
`0…n-1`, in one database transaction. Folder and replicate-group placement applies to the Cell,
not individual sources.

### Attach continuations

Add:

```http
POST /api/tests/{test_id}/continuations
```

The request contains ordered staged sources plus `acknowledged_finding_ids`. Re-run 034.2
inspection server-side immediately before mutation; never trust a stale client result. Append to
the selected Test in submitted order. The Cell metadata, name, overrides, folder membership, and
replicate membership do not change.

### Reorder

Harden the canonical route (the existing URL may be retained):

```http
POST /api/tests/{test_id}/reorder
{"file_ids": [12, 15, 18], "acknowledged_finding_ids": ["..."]}
```

Require an exact permutation of all current Test source IDs: no missing, extra, duplicate, or
foreign ID. Re-run compatibility findings for the proposed order and require confirmation. Write
dense positions in a transaction.

### Detach

Harden the canonical detach route. Require:

- source belongs to the stated Test;
- at least one source remains;
- an explicit confirmation token/flag from an impact preview;
- no deletion of the underlying original file.

Detaching removes only `TestFile` membership. An unlinked `SourceFile` may remain indexed for
reuse/cleanup according to existing source lifecycle rules; do not invent destructive deletion.

### Impact preview

Add a read-only source-change impact endpoint or extend the existing analysis-usage service so
attach/reorder/detach can show:

- affected Cell/Test;
- old and proposed tracked tail;
- number/titles of affected analyses and saved plots;
- whether global cycle numbering changes;
- whether the operation is destructive (detach) or reversible by reordering.

Use `backend/app/services/analysis_usage.py` patterns and return opaque confirmation data if needed.

## Validation and transaction rules

- Resolve and validate every source, hash, path, finding, Cell, Test, folder, and replicate plan
  before the first membership write.
- A source can belong to one Test only.
- Exact duplicate hash in a chain is rejected.
- Recompute source hashes/stat stability before attaching/importing to close the inspection/write
  race.
- Database membership/order changes use one transaction. A failure leaves the old chain intact.
- Filesystem cache/artifact deletion cannot be rolled back. Perform it only after the relational
  transaction succeeds, and make the post-commit operation idempotent/retryable.
- Queue parsing for every newly attached source through the existing cache-job mechanism.
- Return the complete updated Cell/Test/source order, tracked source ID, invalidated analysis IDs,
  and queued jobs so clients do not need to infer success.

## Invalidation and activity

Extend `backend/app/services/cache_maintenance.py::invalidate_cell_dependents` with clear causes
for:

- `continuation_attached`
- `source_order_changed`
- `continuation_detached`

Delete dependent result/artifact/thumbnail caches immediately after the relational mutation
commits, so stale output cannot remain visible. Defer saved-plot warmup until every newly attached
source cache needed by that analysis is scientifically usable. Provenance order already makes
analyses stale; preserve that mechanism.

Create privacy-safe activity entries containing IDs, filenames, old/new source hash prefixes or
positions, and affected analysis IDs. Do not log raw cycling data or filesystem paths.

## Acceptance

- One request creates one Cell with multiple ordered sources.
- A continuation attaches to an existing Test without changing Cell metadata.
- Reorder is an exact permutation and produces dense unique positions.
- Detach cannot empty a Test and never deletes the original file.
- Every mutation is all-or-nothing at the relational layer.
- Compatibility is revalidated server-side and unacknowledged confirmation findings reject with
  a structured 409/422 response.
- Dependent analysis state/artifacts are invalidated and the mutation is logged.
- Legacy one-file import still works.
