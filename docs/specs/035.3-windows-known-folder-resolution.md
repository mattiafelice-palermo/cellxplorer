# 035.3 — Windows Known Folder resolution

**Status:** Plan  
**Parent:** [035 — User experience and workflow optimization](035-user-experience-and-workflow-optimization.md)  
**Depends on:** Parent only; implement after 035.2 because the shared branch is sequential.  
**Scope:** Backend quick-access path resolution for Desktop, Documents, and Downloads.  
**Review document:** `reviews/035.3-windows-known-folder-resolution-review.md`

## Goal

Make Desktop, Documents, and Downloads quick-access entries work when Windows redirects those
folders to OneDrive or a corporate-managed location.

## Current implementation to verify

`backend/app/routers/files.py::import_quick_access` currently builds:

```python
home = Path.home()
[
    (home, "Home"),
    (home / "Desktop", "Desktop"),
    (home / "Documents", "Documents"),
    (home / "Downloads", "Downloads"),
]
```

The API already marks missing quick-access entries unavailable. Preserve its response shape,
pinning, recent-folder behavior, labels, and ordering.

## Required service

Create a small standard-library service, preferably:

```text
backend/app/services/windows_known_folders.py
```

Expose:

```python
def known_user_folders(home: Path | None = None) -> dict[str, Path]:
    ...
```

Keys:

- `home`
- `desktop`
- `documents`
- `downloads`

## Windows implementation

Use `ctypes` with `SHGetKnownFolderPath`; do not add a package dependency.

Known Folder IDs:

```text
Desktop   B4BFCC3A-DB2C-424C-B029-7FE99A87C641
Documents FDD39AD0-238F-46AF-ADB4-6C85480369C7
Downloads 374DE290-123F-4565-9164-39C4925E467B
```

Requirements:

- call the Unicode API;
- represent GUIDs correctly for the Windows API;
- convert the returned pointer to a Python `Path`;
- release the COM-allocated string with `CoTaskMemFree` in a `finally` path;
- handle HRESULT/API failure independently per folder;
- do not require or add COM apartment initialization for this API;
- do not resolve symlinks in a way that rewrites the user-facing path unnecessarily;
- keep the service import-safe on non-Windows systems.

## Fallback behavior

If the platform is not Windows, the API is unavailable, or one lookup fails:

- Home: `Path.home()`;
- Desktop: `home / "Desktop"`;
- Documents: `home / "Documents"`;
- Downloads: `home / "Downloads"`.

A failed Desktop lookup must not prevent Documents or Downloads from resolving.

## Router integration

`import_quick_access` uses the service result. It still:

- returns Home first;
- then Desktop, Documents, Downloads;
- deduplicates paths case-insensitively on Windows;
- preserves pinned/recent paths;
- reports availability using the final resolved path;
- does not create missing folders.

If a Known Folder resolves to the same path as Home or another standard entry, keep only the first
standard entry and do not duplicate it later through pinned/recent data.

## Required tests

Mock the resolver; tests must not depend on the host machine’s real Windows folders.

- all three Known Folder lookups succeed;
- Desktop is redirected under OneDrive;
- one lookup fails and only that entry falls back;
- non-Windows path uses fallbacks;
- allocated path memory is released when lookup succeeds;
- duplicate paths are returned only once by quick access;
- case-insensitive duplicate handling on Windows;
- unavailable fallback remains present but correctly marked unavailable;
- pinned/recent behavior is unchanged.

## Acceptance criteria

- Redirected Known Folders are usable.
- Standard installations retain current behavior.
- One failed lookup cannot break the quick-access endpoint.
- No new dependency or persistent setting is introduced.
- Non-Windows development/tests can import the service safely.
