## Goal

Make the current-path control behave like a familiar Windows address bar: each path segment can be
clicked to return directly to that ancestor, while manual path entry remains available.

## Locked breadcrumb behavior

The normal view is a compact address bar made of clickable segments.

Example:

```text
C:  >  Users  >  Mattia  >  Experiments  >  Cycling
```

- Clicking a segment navigates directly to that ancestor.
- The final/current segment is visually current but remains clickable.
- The existing parent-folder button remains.
- Segments use button semantics and visible keyboard focus.
- Long paths horizontally scroll or collapse safely; they must not increase the modal width.
- Every segment has a tooltip containing its full target path.
- Navigating through a breadcrumb does not alter current file/folder selection.
- A breadcrumb request uses the same browse loading/error behavior as every other navigation path.

## Editable-path mode

Manual path entry is retained.

Enter edit mode through:

- an `Edit path` action at the end of the address bar;
- `Ctrl+L` while the picker is open;
- clicking non-segment empty space in the address bar when practical without creating ambiguous
  hit targets.

In edit mode:

- show the existing text input populated with the full current path;
- select its text on entry;
- Enter navigates;
- Escape cancels editing and restores breadcrumbs;
- blur cancels only when no navigation is pending;
- a failed navigation keeps edit mode open and preserves the typed value;
- successful navigation returns to breadcrumb mode;
- the input has `aria-label="Current folder path"`.

Do not remove quick access, the parent button, or direct manual path navigation.

## Path parsing contract

Add a pure helper, preferably:

```text
frontend/src/importPathBreadcrumbs.ts
```

Return:

```ts
type ImportPathBreadcrumb = {
  label: string;
  targetPath: string;
};
```

Required Windows rules:

- `C:\` produces one `C:` segment targeting `C:\`.
- `C:\Users\Mattia` produces cumulative targets.
- trailing separators do not create empty segments;
- UNC `\\server\share\folder` starts with one root segment `\\server\share`, then cumulative
  descendants;
- forward slashes received from tests or APIs normalize without corrupting UNC/root meaning;
- repeated separators after a drive root normalize safely;
- relative paths are not expected from the backend; return a safe single segment rather than
  generating incorrect ancestors.

Do not use browser URL path utilities for Windows filesystem paths.

## Component behavior

- Reset selected breadcrumb focus after successful navigation to the current segment.
- Preserve the manually entered path if the server returns a validation/browse error.
- `Ctrl+L` must not trigger when focus is inside another text input in a way that violates normal
  editing behavior; scope the handler to the open picker.
- Keep quick-access and search keyboard shortcuts unaffected.
