## Goal

Make the current Series panel support standard multi-selection and bulk explicit styling.

After this child the user can select one series, several arbitrary series, or every series in one quantity; bulk-edit their appearance; bulk-show/hide them in the legend; and return from Rules/Palettes to Series simply by selecting a series.

This child does **not** implement ordering or the detached legend preview.

## Current anchors

### `frontend/src/features/analyses/editor/plotting/SeriesStyleModal.tsx`

Current concrete selection is one `activeKey`; `ALL_SERIES_KEY` is the separate aggregate/global-settings entry. Rows currently select via `setActiveKey(descriptor.key)`. The eye icon mutates only `previewHidden` and must remain preview-only.

`seriesGroups` already defines the required quantity boundaries:

```ts
{
  key,
  heading,
  items: SeriesDescriptor[]
}
```

The right side already contains Series / Rules / Palettes and the complete current Palettes editor.

### `frontend/src/features/analyses/editor/plotting/seriesStyling.ts`

Use `SeriesDescriptor.key` as selection identity and `SeriesStyleOverride` as the only explicit-edit layer.

### `frontend/src/api.ts`

No new persisted field is required in this child. Existing `series_overrides`, `series_rules`, and `show_in_legend` are sufficient.

## A — Selection state

Replace the one-concrete-series assumption with state equivalent to:

```ts
selectedKeys: Set<string>
selectionAnchor: string | null
```

Keep `ALL_SERIES_KEY` separate from concrete row selection. It is the aggregate entry for effective
per-series appearance values; genuinely global-only settings remain base-style controls.

The UI must distinguish the All series aggregate/global-settings entry, one selected concrete series,
several selected series, and no concrete selection.

Whenever descriptors change, prune selected keys that no longer exist and clear an invalid anchor. Do not silently convert an empty concrete selection into All series.

## B — Desktop selection semantics

### Plain row click

Select only that row and set the anchor.

### Ctrl/Cmd-click

Toggle the clicked row while preserving the rest. Support both `ctrlKey` and `metaKey`.

### Shift-click

Select the contiguous range from the anchor to the clicked row **within the same `seriesGroups` quantity**. If the anchor belongs to another group, treat the clicked row as a new single selection rather than spanning groups.

### Row checkbox

Add a compact checkbox to each expanded concrete row. Clicking it toggles that key while retaining other selected keys.

### Quantity checkbox

Each visible quantity heading gets a tri-state checkbox:

- unchecked — none selected;
- indeterminate — some selected;
- checked — all selected.

Clicking a checked quantity clears that group's keys; otherwise it selects all of them. Ctrl/Cmd selection may span groups.

## C — Selection always enters Series editing

Use one helper for deliberate edit-selection actions rather than scattering unrelated tab changes.

These actions must set `tab = "series"`:

- plain row click;
- Ctrl/Cmd-click;
- Shift-click;
- row checkbox;
- quantity checkbox.

These must **not** switch tabs:

- preview-only eye toggle;
- Series-panel collapse/expand;
- unrelated palette controls.

Required flow:

```text
Palettes open
→ click/check Series B
→ B selected
→ Series tab immediately visible
```

No confirmation or info banner is needed.

## D — Palettes remains unchanged and global

Do not move or redesign the Palettes tab. Preserve its current controls and Apply semantics exactly.

Add only a compact scope cue on or next to the Palettes tab — for example `Global`, `All series`, or an equivalent accessible icon/tooltip. The existing explanatory text inside the tab remains.

## E — Expanded Series-panel row design

Each expanded row should contain compactly:

```text
[selection checkbox]  swatch/name  [preview eye]
```

A quantity heading contains its tri-state checkbox and current label/count.

Requirements:

- selected rows use the theme-safe selected surface;
- long names truncate and expose the full name by tooltip/title;
- preview eye and selection checkbox are visually/semantically distinct;
- collapsed Series mode may stay a simplified picker.

Do not add drag handles in this child; ordering belongs to 046.2.

## F — Pure bulk override helper

Add a React-free helper in `seriesStyling.ts` or a tightly scoped neighbouring policy module, conceptually:

```ts
applySeriesOverridePatch(overrides, keys, patch)
```

It must:

- update only supplied keys;
- merge field-by-field;
- preserve unrelated override fields;
- preserve current `null` fall-through semantics;
- prune empty overrides through the existing pruning logic;
- be deterministic.

Use it for single and multi-series explicit edits where practical so semantics cannot drift.

## G — Multi-selection inspector

### Exactly one selected series

Preserve current behavior: Legend name, rule notice, Reset, and existing appearance controls.

### More than one selected series

Show a clear header such as:

```text
3 series selected
Changes apply to all selected series.
```

Bulk-editable fields must include the current explicit properties that make sense across several series, at minimum:

- colour;
- opacity;
- Line only / Points only / Line + points;
- dash;
- width;
- line shape where already supported;
- marker symbol;
- marker size;
- open/filled marker;
- show in legend.

**Legend name remains single-series only.** Do not overwrite several names.

### Mixed values

Determine shared values from effective `resolvedByKey` values, not merely raw override objects.

```text
all selected values equal → show that value
values differ → show Mixed / indeterminate
```

Opening the multi-editor must not create overrides. Only a user change writes a chosen explicit value to all selected keys.

## H — Bulk legend membership

Provide compact actions for the concrete selection:

- **Show in legend** → apply `{ show_in_legend: true }`;
- **Hide from legend** → apply `{ show_in_legend: false }`.

Use the same bulk override helper. Do not reuse the preview eye. With no concrete selection, these actions are absent or disabled.

## I — Reset selected

For a multi-selection, provide one restrained `Reset selected` action that removes explicit overrides for those keys so base/rules resolve again.

Do not modify rules, All series aggregate semantics, or palette state.
