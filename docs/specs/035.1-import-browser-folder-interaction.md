## Goal

Opening a folder and selecting a folder recursively must be two clearly different actions. A user
trying to browse must not accidentally select hundreds of cycling files.

## Current implementation to verify

At the authoring baseline:

- `frontend/src/pages/InboxPage.tsx::ImportFilesystemPickerModal`
- `toggleEntry`
- the browse-entry row with both `onClick={toggleEntry(...)}` and folder-only `onDoubleClick`
- `selected: Map<string, ImportBrowseEntry>`
- folder and file checkboxes rendered inside the same row
- `navigate(path)` resets search/range-anchor state

The filesystem picker may live in `frontend/src/components/ImportFilesystemPickerModal.tsx` or another current owner. Verify the repository before editing and do not re-inline an extracted component into `InboxPage.tsx`.

## Locked behavior

### Folder row

- Single-click anywhere on the folder row except its checkbox opens that folder.
- Enter on a focused folder row opens that folder.
- Double-click has no separate selection behavior. It may naturally trigger the same navigation,
  but no explicit double-click-only contract remains.
- Opening a folder clears the picker search and range anchor as current `navigate(...)` does.
- Opening a folder does not add or remove that folder or any descendant from `selected`.
- The row cursor and hover state communicate navigation rather than selection.

### Folder checkbox

- The checkbox is the only control that recursively selects/deselects a folder.
- Checkbox click stops row propagation.
- Space on the focused checkbox toggles recursive selection.
- The checkbox exposes the accessible name:
  `Select all importable files in <folder name>`.
- Checked and indeterminate state reflect selected descendant importable files, not merely the
  folder path.
- A folder containing no importable files has a disabled checkbox but remains navigable.

### File row

- Single-click keeps the current file-selection behavior.
- Ctrl/Cmd-click and Shift-click remain available for files.
- File-checkbox click remains equivalent to file-row selection and stops propagation.
- Folder rows are not part of Shift-range file selection.
- Clicking a file row must not navigate.

### Quick-access rows

- Quick-access entries navigate on one click.
- Their pin/unpin controls remain separate and stop propagation.
- This child does not change how quick-access paths are resolved; 035.3 owns that.

## State-policy extraction

Keep event semantics out of ad-hoc JSX conditionals. Add or extend a small pure policy module,
preferably:

```text
frontend/src/importBrowserSelection.ts
```

It should own at least:

- file range/toggle selection;
- folder descendant toggle;
- the rule that row activation for a folder is navigation, not selection;
- active/focus key movement after navigation where the existing component needs it.

Do not create a general-purpose selection framework.

## Loading, accessibility, and layout

- Do not navigate while the clicked row is already the pending current path.
- During browse loading, preserve the current rows or show the established loading state; do not
  flash an empty list that looks like an empty folder.
- Use button/row semantics with `tabIndex`, Enter handling, and visible focus.
- Do not rely on color alone to distinguish selected files.
- Long folder/file names truncate with their full value available in a tooltip.
- Preserve compact Mantine geometry and light/dark behavior.

## Files expected to change

  `frontend/src/pages/InboxPage.tsx` only if the picker still legitimately lives there;

No backend, database, import endpoint, continuation policy, or scientific code changes.

## Required tests

Pure TypeScript tests must cover:

- folder-row activation returns `navigate` and leaves selection unchanged;
- folder-checkbox activation selects all descendant files;
- a second folder-checkbox activation deselects all descendants;
- folder checkbox supports mixed/indeterminate descendants;
- empty folder checkbox is disabled without disabling navigation;
- file click toggles one file;
- Ctrl/Cmd-click adds/removes one file;
- Shift-click extends across visible files only;
- folders are not included in the range;
- navigating resets the range anchor;
- checkbox actions do not also trigger row navigation.

## Acceptance criteria

- A user cannot select a folder merely by trying to open it.
- Recursive folder selection has one clear control.
- Existing file multi-selection remains intact.
- Keyboard navigation and selection are independently operable.
- No import request or data shape changes.
- The picker still supports separate-cell and continued-cell import workflows.
