### Mixed-parser integration test

`tests/test_mixed_parser_integration.py`, 7 tests, `MixedParserIntegrationTests`. Unlike
`tests/test_stitch.py::MixedParserIdentityStitchTests` (040.3 — patches `cache.load_cycles`/
`cache.load_raw` around synthetic hashes/frames to test `stitch.py` in isolation), this registers a
**real** Cell whose two-source chain is exactly the spec's preferred example:

- position 1: the real golden `tests/fixtures/golden_analysis/sources/cycles_time_steps.ndax` binary
  fixture, registered through `scanner.ingest_path(db, path, parse_now=True)` — the genuine
  hash/header/`cache.build` path, not a mock;
- position 2: a generated Neware Excel continuation workbook (self-contained `openpyxl` generator in
  the test module, two clean cycles), registered the same way.

Both go through the real `scanner.parse_file` → `cache.build` path, writing real Parquet caches under
each source's own resolved identity. What it proves:

1. **Distinct, source-specific parser identity.** `source_a.parser_version` starts with `nb:`,
   `source_b.parser_version` starts with `nx:`, and they differ.
2. **Each cache is addressable only at its own identity.** `cache.load_raw(hash_a, identity_a)` and
   `cache.load_raw(hash_b, identity_b)` both return real data; `cache.load_raw(hash_a, identity_b)`
   and the converse both return `None` — caches are keyed per source identity, never a shared bundle.
3. **Ordered stitching with correct segment provenance.** `analysis_engine.compute`'s
   `cell_series[0]["segments"]` has exactly 2 entries, `segments[0]["file_hash"] == hash_a`,
   `segments[1]["file_hash"] == hash_b`; the dense global cycle sequence is the golden source's own
   cycle count immediately followed by the Excel continuation's two cycles, strictly increasing, no
   gap or duplicate.
4. **Provenance names both identities; the human-facing summary is truthfully "mixed".**
   `result["sources"][0]["files"]` contains both `{hash, position, parser_version}` entries with each
   source's own real identity, while `result["parser_version"]` and `result["current_parser_version"]`
   are both the literal string `"mixed"` — never one source's identity silently standing in for both.
5. **Time/Capacity also stitches both sources** (`compute_time_capacity`'s trace covers both
   filenames).
6. **Parent 034's fail-closed guard still applies.** `analysis_engine.protocol_analysis_guard` returns
   the structured `multi_source_protocol_mapping_required` response (naming this Cell in
   `unsupported_cells`, `supported_alternatives: ["cycles", "time_capacity"]`) for all four
   protocol-derived families (`steps`, `dcir`, `chargeability`, `rate_capability`), and returns `None`
   (unguarded) for `cycles`/`time_capacity` — the two alternatives the guard's own message names.
7. **Per-source cache-key resolution.** `analysis_cache.result_key`, called with three provenance
   variants that pin real+legacy identities for both sources, is deterministic for identical input,
   changes when *either* source's pinned identity changes, and the two single-source changes do not
   collide with each other.

Test isolation: an in-memory SQLite `StaticPool` engine per test (matching the existing
`NewareExcelAnalysisIntegrationTests` pattern in `tests/test_neware_excel.py`), and `tearDown` removes
the two written cache directories via `cache.remove_hash_cache`. `setUpClass` skips the whole module

Plotly and posts the final figure for storage — the backend never regenerates one), and the portable
report's CSV export (`portable_analysis.py`'s embedded `<script>`, the `exportCsv` function) reads
`columns`/`rows` derived from the already-embedded Plotly trace data at the time of export, not a
backend-side per-channel computation. There is therefore no backend function that could silently drop
a selected voltage channel between "Time/Capacity API response" and "portable figure" — the same
`voltage_v` array the API returns is what every downstream frontend step carries forward — but
verifying it actually renders correctly in a browser needs a browser. This is the same limitation the
040.4 review already recorded ("Manual browser checks: NOT RUN by either implementer or reviewer").

**New this child: a practical dev affordance for the three-electrode case**, since no shipped adapter
populates `working_potential_v`/`counter_potential_v` and none will until Parent 041.

render the selector. Safety: refuses to run unless `CELLXPLORER_DATA` is already explicitly set (never
inferred/defaulted), refuses if it resolves to the literal `.cellxplorer`/`.cellxplorer-beta` default
