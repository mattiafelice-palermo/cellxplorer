## Core audit: format-neutral downstream science

Search production scientific code for extension/format branches.

The desired shape is:

```text
source format adapter
    ↓
canonical raw/protocol + source-specific parser identity
    ↓
cache/stitch
    ↓
existing scientific services
```

Reject architectures like:

```python
if source_format == "neware_excel":
    use_special_cycle_math()
```

or future-format placeholders inside scientific calculation services.

Format checks are legitimate only where the subject is actually format recognition, metadata/provenance, original-source export, or adapter-specific parsing.

## Multi-voltage closure

Use the synthetic three-electrode-capable canonical path from 040.4.

Verify full roundtrip:

```text
canonical frame
→ raw Parquet
→ selective load
→ stitch
→ Time/Capacity backend
→ frontend figure
→ data export
→ saved plot/artifact
→ portable figure
```

Check numerical identity:

```text
voltage_v == expected primary values
working_potential_v == expected WE values
counter_potential_v == expected CE values
```

Where synthetic data define the relationship, verify:

```text
voltage_v == working_potential_v - counter_potential_v
```

The derivation itself remains adapter-owned; this closure test simply proves preservation.

Also verify ordinary two-electrode fixtures expose no unnecessary auxiliary controls.

## Performance audit

Parent 040 must not regress the performance boundaries established by Specs 035/039.

At minimum inspect/test:

### List endpoints

No source file I/O, parser imports, Parquet reads or N+1 queries for Cell/Analysis/Project lists.

### Import source discovery

Extension/stat enumeration only. No workbook/full parse.

### Inspection

Hash + cheap metadata through bounded adaptive workers. Canonical validation occurs only on full parse/cache build.

### Cache status

Expected parser identity is resolved cheaply from registered format/adapter policy; it must not full-parse every source on startup/list.

### Analysis

Per-source parser descriptors are bulk-loaded with sources; no per-source DB query loops.

Record any benchmark/timing evidence required by current change playbooks when a hot path changed materially.
