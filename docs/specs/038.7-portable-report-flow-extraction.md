## Goal

Extract the complete user-facing portable HTML export/share workflow from `AnalysisPage.tsx` into:

```text
frontend/src/features/analyses/editor/portable/PortableReportFlow.tsx
```

The module owns client-side orchestration: estimating a package, selecting saved plots, checking
original sources, offering source updates, building plot snapshots, requesting the package, and
delivering it through download or share. The backend remains the sole owner of the portable HTML
format, manifest, checksums, embedded source rules, safe import, and validation.

This is a behavior-preserving extraction. No portable format, route, request, UI, or policy change
is authorized.

## Locked client/backend boundary

### Frontend responsibilities

`PortableReportFlow.tsx` owns only:

- opening the existing Export or Share flow from the editor;
- selecting which **saved** plots are included;
- selecting whether original sources are requested where supported;
- requesting and displaying the current size estimate;
- requesting source preflight and presenting source status;
- invoking the existing source-update action when the user chooses it;
- asking the artifact layer to build canonical plot snapshots;
- submitting the current portable-export payload;
- tracking the active action and progress without stale mutation completion;
- downloading the returned package or invoking the existing share mechanism;
- preserving the current prepared-share fallback when direct share is unavailable or cancelled;
- modal focus, dismissal, retry, disabled, loading, success, and error states.

### Backend responsibilities

The existing backend continues to own:

- package and manifest versions;
- canonical analysis/spec/source serialization;
- original-source inclusion and checksum calculation;
- source-change validation and conflict responses;
- package size accounting;
- embedded viewer/runtime content;
- import validation, safe extraction, and round-trip correctness.

The frontend must not recreate package HTML, manifests, hashes, or source archives.

## Component boundary

`PortableReportFlow.tsx` may contain a component plus private hooks or small local components; the
target tree deliberately locks one file, not one React export. Keep the existing trigger controls
in their current visual location in the editor. Two acceptable integration shapes are:

1. a controlled component receiving an `openRequest`/action token from editor buttons; or
2. one module-owned trigger renderer/callback surface that lets the editor place the unchanged
   buttons while the flow owns modal state.

Whichever shape is selected, its public props must be narrow and typed. At minimum the flow needs:

- analysis identity and current analysis title/spec inputs required by the existing requests;
- the current saved-plot collection and selected source-count context;
- the artifact-layer snapshot builder or the typed inputs it requires;
- the existing download/share adapters if they are not already generic utilities;
- a stable way to open Export and Share without duplicating workflow state in `AnalysisEditor`.

Do not pass the entire editor component state object. Do not import `AnalysisEditor.tsx` or a route
page. Do not introduce context/global state just to avoid explicit props.

## Endpoint and payload equivalence

Preserve the exact method, path, fields, omission/null semantics, and error handling currently
used for all four routes:

| Route | Purpose to preserve |
|---|---|
| `GET /api/analyses/{id}/portable-estimate` | Estimate package size for the current choices |
| `POST /api/analyses/{id}/portable-source-preflight` | Classify requested original sources before packaging |
| `POST /api/analyses/{id}/portable-source-update` | Apply the existing user-approved source refresh path |
| `POST /api/analyses/{id}/portable-export` | Build the backend-owned portable HTML package |

Before moving code, capture the actual query parameters and JSON/FormData fields at every call
site. After moving it, compare them directly. In particular preserve:

- saved plot identifiers and ordering;
- generated plot snapshot identity and fallback SVG fields;
- include-original-sources choice;
- multi-source Cell/source identity and ordering;
- requested action (download/share) if sent;
- filename/title normalization;
- server conflict/error bodies surfaced to the user.

Do not add a frontend request schema that silently drops unknown backend fields.

## Saved plots and snapshots

Only saved plots are eligible. Draft plots must not appear in the chooser or snapshot request.

Call the canonical `buildPortablePlotSnapshots` export from
`../artifacts/SavedPlotPreviews.tsx` (or the equivalently named 038.6 export). Preserve:

- saved-plot ordering;
- family dispatch and data signatures;
- hidden-series state;
- styled traces/layout;
- stored-artifact reuse;
- SVG fallback generation;
- empty/unsupported/failure guards;
- current progress accounting.

The portable module orchestrates snapshot creation; it does not compile family figures itself.

## Source preflight and update states

Preserve every existing source classification and user decision. At minimum reverify behavior for:

- available and unchanged sources;
- changed sources;
- unavailable/missing sources;
- sources currently changing or updating;
- preflight failure;
- update failure;
- backend conflict, including HTTP 409 behavior;
- continuing without originals where currently allowed;
- retrying preflight after a successful update;
- multi-source Cells with stable source ordering and per-source findings.

Never silently substitute a changed local file for the version represented by the saved analysis.
Never include originals after the user has chosen not to. Never treat a failed preflight as
approval to proceed.

## State-machine equivalence

The current flow is conceptually one state machine even if implemented with several React states.
Preserve these transitions and guards:

```text
closed
  -> configure/estimate
  -> source preflight (when originals requested)
  -> optional source-update decision
  -> build selected plot snapshots
  -> request portable package
  -> download or share
  -> success/prepared-share/closed
```

Any stage may enter its current retryable or terminal error state. Closing or starting a new
action must invalidate stale completions from the earlier run. Export and Share must not run
concurrently against shared flow state.

Do not broaden this child into a new state-machine library. A local reducer/token is acceptable
only if it demonstrably preserves all current transitions and makes stale-result ownership clear.

## UI and accessibility invariants

- Export and Share triggers stay in the same editor location, order, size, and hierarchy.
- Modal geometry, headings, explanatory copy, plot chooser, source controls, estimate, progress,
  warnings, footer actions, and close behavior remain visibly equivalent.
- Existing light/dark chrome behavior remains; generated plot backgrounds follow the existing
  plot contract rather than the chrome theme.
- Long analysis/plot/source names retain current truncation and accessible title behavior.
- Focus enters the modal, remains trapped as it does today, returns to the invoking control, and
  all controls remain keyboard operable.
- Loading/progress controls cannot be double-submitted.
- Errors remain actionable and do not erase the user's valid choices unnecessarily.

## Query, mutation, and cache invariants

- Preserve existing query keys, `enabled` guards, stale/cache behavior, retries, and mutation
  sequencing.
- Preserve invalidations after source update/export where currently performed.
- Keep hook calls unconditional and above render-time early returns.
- Scope progress and mutation completion to the current analysis and action token.
- Do not persist new portable-flow state in local storage or the analysis specification.
