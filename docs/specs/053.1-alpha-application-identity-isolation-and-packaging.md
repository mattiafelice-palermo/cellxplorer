## 1. Goal

Create a locally buildable and installable CellXplorer Alpha product with the exact identity,
profile isolation, purple branding, and packaging contract locked by Parent 053.

This child ends at build/package and side-by-side identity verification. It does not make Alpha
tags publishable, change the release-channels branch, or publish a GitHub release.

## 2. Current behavior to preserve and extend

The repository currently models exactly stable and beta:

- frontend/src/appChannel.ts declares the two-value AppChannel union and uses a Beta-or-Stable
  branding fallback;
- frontend/src/main.tsx registers betaBlue only when APP_BRANDING.isBeta and runs the Beta bootstrap
  launch gate only for Beta;
- backend/app/services/app_channel.py accepts stable/beta and currently chooses Beta data for every
  non-Stable typed channel;
- src-tauri/src/app_channel.rs owns exact identifiers, product labels, deep links, frame colors,
  icon bytes, data roots, endpoints, and runtime release-version validation;
- src-tauri/tauri.conf.json is the Stable base and src-tauri/tauri.beta.conf.json is the Beta merge
  overlay;
- scripts/build-app.ps1, scripts/build_frontend_channel.py, scripts/frontend_channel.py, and
  package.json accept only Stable/Beta packaging;
- src-tauri/cellxplorer-installer.nsi fails closed for unknown identifiers and derives the profile
  root and brand constants from the exact bundle identifier;
- tests/test_app_channels.py, tests/test_updater_configuration.py, frontend/tests/appChannel.test.ts,
  and Rust unit tests encode the current two-product contract.

Extend these owners. Do not create parallel Alpha copies of the application, backend, updater state
machine, installer template, or build pipeline.

## 4. Exhaustive channel policy

### 4.1 Frontend

Extend frontend/src/appChannel.ts:

- AppChannel is exactly stable | beta | alpha;
- unsupported non-empty Vite values still throw;
- missing Vite channel still defaults to Stable only for source/browser development;
- brandingForChannel uses an exhaustive map or switch, not Alpha-falls-through-to-Stable logic;
- AppBranding carries enough explicit identity to render Stable, Beta, and Alpha without inferring
  product behavior from a generic “preview” boolean;
- use an optional badge label or exact channel check so BETA and ALPHA remain distinct;
- preserve existing exported names where practical to avoid unrelated churn.

Audit existing APP_BRANDING.isBeta users. Beta-only behavior must remain exact:

- Beta bootstrap launch gating runs only in Beta;
- Stable-owned Beta-install controls/providers are available only where their existing policy says
  Stable, never merely “not Beta”;
- Alpha shows neither Beta bootstrap nor Stable's first-Beta-install UX;
- Alpha update UI is hidden or explicitly disabled by the temporary 053.1 fail-closed gate below.

Add Alpha assertions to frontend/tests/appChannel.test.ts and focused Beta installer/bootstrap policy
tests where current binary assumptions would otherwise classify Alpha as Stable.

### 4.2 Backend

Extend backend/app/services/app_channel.py:

- AppChannel includes alpha;
- deep-link map includes cellxplorer-alpha://import-analysis;
- default_data_root maps each channel explicitly;
- add ALPHA_DATA_DIR_NAME = .cellxplorer-alpha and a focused helper only if current call sites need it;
- packaged missing/invalid channel behavior remains fail-closed;
- CELLXPLORER_DATA continues to override all channels exactly;
- source/browser development continues to default to Stable only through the existing explicit path.

Update portable-report/deep-link tests so Alpha-generated links use only the Alpha scheme.

Do not add Alpha bootstrap routers, database-copy services, schema migrations, or profile
synchronization.

### 4.3 Rust

Extend src-tauri/src/app_channel.rs with:

- AppChannel::Alpha;
- ALPHA_IDENTIFIER;
- ALPHA_CHANNEL_ENDPOINT;
- exact identifier parsing;
- product/autostart name CellXplorer Alpha;
- deep-link scheme cellxplorer-alpha;
- native frame COLORREF 0x00E84870;
- embedded src-tauri/icons-alpha/icon-256.rgba;
- default data directory .cellxplorer-alpha.

Every Rust match must remain exhaustive. Unknown identifiers and channels fail closed.

Keep Stable/Beta version rules unchanged in this child. Add the Alpha variant plumbing needed for
compilation, but make Alpha version validation return an explicit temporary “not enabled until
Spec 053.2” error. Child 053.2 owns the final X.Y.Z-alpha.N validator and publication tests.

Verify main.rs passes:

    CELLXPLORER_CHANNEL=alpha
    CELLXPLORER_DATA=<resolved Alpha root>

to the shared sidecar and uses Alpha-local labels, tray identity, notification title, autostart
value, frame, icon, and deep-link acceptance.

### 4.4 Temporary update safety

The Alpha overlay contains its final dedicated endpoint, but no trustworthy Alpha pointer exists
during this child. Until 053.2 removes the temporary gate:

- check_app_update, download_app_update, and install_app_update reject Alpha with one explicit safe
  error before pending state changes;
- automatic Alpha update discovery and update controls are hidden or disabled;
- Alpha never falls back to the Stable or Beta endpoint/version rules;
- Stable and Beta updater behavior remains unchanged;
- focused tests name 053.2 as the only owner allowed to remove the gate.

## 5. Alpha Tauri overlay

Add src-tauri/tauri.alpha.conf.json as a narrow merge overlay over the Stable base. It must override
only:

- productName;
- identifier;
- main window title while preserving the current geometry;
- deep-link desktop scheme;
- updater endpoint;
- bundle icon;
- NSIS installer/uninstaller icons.

It must continue to inherit:

- shared updater public key;
- shared frontend and onedir Python sidecar;
- createUpdaterArtifacts;
- shared NSIS template and installer hooks;
- compression, per-machine mode, resources, capabilities, and Windows updater install mode.

Tests must deep-merge the Stable config with each overlay and assert the resolved three-product
matrix. Grepping the overlay alone is insufficient.

## 6. Purple theme, header, and icons

### 6.1 Theme

In frontend/src/main.tsx register the Parent 053 alphaPurple palette:

    #f3f0ff, #e5dbff, #d0bfff, #b197fc, #9775fa,
    #845ef7, #7950f2, #7048e8, #6741d9, #5f3dc4

Alpha uses primaryShade light 7 / dark 6. Beta keeps betaBlue unchanged; Stable keeps teal.
Prefer an explicit channel-to-theme extension rather than nested Beta/non-Beta ternaries.

### 6.2 Header

Reuse the existing icon/title/badge composition:

    [app-icon-alpha] CellXplorer [ALPHA]

The badge is uppercase ALPHA, white text, alphaPurple.7, compact, accessible, and visible on every
route at supported UI zoom. Stable has no badge and Beta remains unchanged.

Audit channel-brand uses only. Do not recolor:

- success/running teal;
- warning/error semantics;
- scientific trace palettes;
- persisted plot styles;
- thumbnails, exported images, portable figures, or report colors.

Update docs/agent-knowledge/visual-style-guide.md so channel-primary examples name Alpha while
semantic teal remains channel-neutral.

### 6.3 Deterministic icon assets

Add a deterministic Alpha icon generator, preferably scripts/build_alpha_icons.py while preserving
the existing scripts/build_beta_icons.py entrypoint.

Generate and commit the required assets:

    frontend/public/app-icon-alpha.png
    src-tauri/icons-alpha/icon.ico
    src-tauri/icons-alpha/icon.png
    src-tauri/icons-alpha/icon-256.rgba
    any additional sizes required by the current Tauri icon list

Derive from Stable source art:

- replace Stable brand pixels with #B197FC;
- preserve neutral/white/dark pixels and transparency;
- add ALPHA to frames 48 px and larger;
- render a dedicated A for 16/24/32 px frames;
- never modify Stable or Beta committed assets.

Add deterministic-output and required-frame tests following the current Beta icon test pattern.

## 7. Build and installer integration

### 7.1 Build entrypoints

Extend scripts/build-app.ps1:

- ValidateSet accepts stable, beta, alpha;
- default remains stable;
- Alpha deep-merges src-tauri/tauri.alpha.conf.json;
- frontend build receives VITE_CELLXPLORER_CHANNEL=alpha;
- packaging verifies the Alpha frontend stamp;
- channel/config/icon inputs participate in build fingerprints;
- Tauri receives the Alpha overlay only for Alpha;
- output discovery requires CellXplorer.Alpha_<version>_x64-setup.exe;
- no “newest setup executable” fallback is introduced.

Extend:

- scripts/build_frontend_channel.py choices;
- scripts/frontend_channel.py write/verify choices and branding inputs;
- package.json build:frontend:alpha and tauri:build:alpha scripts.

The shared Python sidecar remains one artifact. Skip/install/fingerprint behavior remains unchanged.

### 7.2 NSIS

Extend src-tauri/cellxplorer-installer.nsi's exact BUNDLEID selection:

    com.cellxplorer.desktop.alpha
      -> CX_PROFILE_DATA_DIR .cellxplorer-alpha
      -> CX_BRAND_RGB 7048E8
      -> CX_BRAND_COLORREF 0x00E84870

Preserve fail-closed behavior for every unknown identifier.

The existing product-name-derived install directory, uninstall key, manufacturer product key,
shortcuts, install-instance marker, update mode, process cleanup, and data-preservation choices must
remain shared. Process cleanup stays scoped to the exact installation directory and must not kill
another channel by image name.

Uninstalling Alpha preserves .cellxplorer-alpha by default and may delete only that root after the
existing explicit destructive confirmation. It must never target .cellxplorer or
.cellxplorer-beta.
