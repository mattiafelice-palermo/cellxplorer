# 034.9 — Portable round-trip and multi-source regression closure

**Status:** Plan — architecture corrected 2026-07-31  
**Parent:** [034 — Multi-source cell continuations](034-multi-source-cell-continuations.md)  
**Depends on:** 034.1–034.8  
**Scope:** Portable analysis fidelity, synthetic regression corpus, documentation, and final matrix.

## Locked product model

A physical Cell owns one ordered source chain:

```text
Cell -> ordered SourceFiles
```

The current schema stores that chain through exactly one internal `Test` row and ordered
`TestFile.position` links. `Test` is not a portable product object, user-visible grouping, analysis
scope, lifecycle scope, or monitoring scope. Portable export/import must preserve the Cell and its
ordered original sources, not introduce or expose multiple Tests.

## Portable export/import hazards

- `backend/app/services/portable_analysis.py::_cell_document` currently reaches source order through
  the internal `TestFile.position` links.
- `_analysis_sources` currently deduplicates by source ID and returns database-ID order, which can
  differ from the Cell’s scientific source order.
- Portable import must recreate one Cell, exactly one internal Test row, and the ordered source
  links.
- Source preflight correctly checks originals, but package and embedded-download order must be
  proven for multi-source Cells.

## Portable requirements

- Serialize Cells in the analysis selection’s deterministic order.
- Within each Cell, serialize sources by the Cell’s canonical order, stored internally by
  `TestFile.position` on its one internal Test row.
- `_analysis_sources`, source package documents, embedded bytes, preflight rows, and downloadable
  originals use that same deterministic Cell/source order.
- Preserve distinct filenames, hashes, per-source metadata, source positions, and provenance.
- Do not serialize Test names or multiple Test groups as scientific structure.
- Never flatten a continued Cell into one source or split it into multiple Cells.
- Import recreates exactly one internal Test row for each imported Cell, the same source order, and
  the same tracked tail.
- A partially overlapping import—some hashes already linked to another Cell, some new—continues to
  fail atomically with a clear conflict.
- Reimport may reuse an existing Cell only when its complete ordered source-hash chain matches.
  The same hashes in a different order are not equivalent.
- Embedded ZIP layout remains one folder per Cell with each original source as a separate file.
- Portable HTML remains untrusted/checksummed and never executes imported JavaScript.

## Synthetic regression corpus

Create a small committed synthetic description/fixture set, not Neware binaries copied from the
user. Use patched parser/cache frames and temporary files to cover:

1. normal continuation: local `1…3` + local `1…2`;
2. missing local label: `1,2,4`;
3. incomplete final cycle in the first source;
4. incomplete final cycle in the last source;
5. multi-day timestamp gap;
6. timestamp overlap;
7. reversed user order;
8. changed device/channel;
9. changed protocol signature and numeric step IDs;
10. exact duplicate hash;
11. source already linked to another Cell;
12. missing middle source cache;
13. reorder changes tracked tail and global cycles;
14. scheduled monitor checks only the new tail;
15. portable round-trip retains the exact Cell source order;
16. import and continuation workflows leave exactly one internal Test row per Cell;
17. no supported workflow can create a second Test row for a Cell.

Place reusable JSON/dataframe builders under `tests/fixtures/` or a focused test-support module.
Do not add generated cache artifacts. If the AGENTS tree becomes misleading, update it.

Do not modify the approved Spec 015 golden corpus or regenerate its expected files merely to absorb
additive multi-source output. Single-source golden behavior should remain stable; any intentional
schema addition must be narrowly normalized/approved and explained.

## End-to-end automated assertions

- Initial import and later attach create identical scientific source order for equivalent inputs.
- Every normal Cell has exactly one internal Test row before and after import, attach, reorder,
  detach, portable export, and portable import.
- No API or frontend workflow can create a second Test row for a Cell.
- Compatibility findings and acknowledgements survive the write revalidation contract.
- Cycles and time/capacity output global/local provenance and exclude downtime.
- Reorder invalidates cache keys/artifacts/thumbnails and changes portable source order.
- Detach cannot leave a Cell with zero sources and changes the tracked tail when applicable.
- Scheduled versus manual source scopes differ exactly as 034.6 specifies.
- Four protocol-derived families fail closed without background jobs.
- Portable source preflight checks every original, not only the tail.
- Export without embedded originals still preserves ordered source descriptors/provenance.
- Export with originals downloads each file separately under its Cell folder.
- Imported portable analysis produces the same ordered hashes and supported-plot result projection.
