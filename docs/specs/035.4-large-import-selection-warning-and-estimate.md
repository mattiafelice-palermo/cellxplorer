# 035.4 — Large import selection warning and estimate

**Status:** Plan  
**Parent:** [035 — User experience and workflow optimization](035-user-experience-and-workflow-optimization.md)  
**Depends on:** 035.1–035.3 clean reviews.  
**Scope:** Expanded-selection summary before inspection/import.  
**Review document:** `reviews/035.4-large-import-selection-warning-and-estimate-review.md`

## Goal

When selected folders expand into a large batch, make the consequence explicit before the user
starts inspection. Show file count, total size, contributing roots, and a conservative historical
time estimate when one is available.

## Current implementation to verify

- `backend/app/routers/files.py::list_import_sources`
- `backend/app/routers/files.py::list_import_folder_files`
- `POST /api/imports/list-sources`
- `frontend/src/api.ts::ImportFolderFile`
- `FolderImportSelectionModal`, or its current extracted owner
- selected candidate count and `Continue with N files`
- each candidate already exposes `size`

At the authoring baseline, `relative_path` embeds a root label but does not reliably identify which
selected root produced the file when two roots share the same name.

## API contract

Extend every listed candidate with explicit origin data:

```json
{
  "path": "C:\\data\\batch\\cell.ndax",
  "relative_path": "cell.ndax",
  "filename": "cell.ndax",
  "size": 123456,
  "selection_root": {
    "kind": "folder",
    "path": "C:\\data\\batch",
    "label": "batch"
  }
}
```

For a loose file:

```json
"selection_root": {
  "kind": "file",
  "path": "C:\\data\\cell.ndax",
  "label": "Loose files"
}
```

Requirements:

- preserve current deterministic candidate ordering;
- `relative_path` is relative to the stated folder root for folder candidates;
- the root path is returned only to the local frontend, consistent with existing path exposure;
- identical root labels remain distinguishable by full-path tooltip;
- loose files group under one `Loose files` summary but retain their own source paths;
- no source file is opened, hashed, or parsed in this endpoint;
- de-duplication by resolved path remains intact.

Update `ImportFolderFile` and `ImportFolderSelectionResult` types accordingly.

## Warning threshold and placement

Define one shared frontend constant:

```ts
export const LARGE_IMPORT_WARNING_THRESHOLD = 30;
```

Show a persistent semantic-warning Alert when the currently selected candidate count is greater
than 30.

Example:

```text
You are selecting 214 files (18.4 GB) from 3 locations.
Make sure this is intentional before continuing.

Project A/Cycling   198 files · 17.9 GB
References           12 files · 420 MB
Loose files           4 files · 80 MB
```

Rules:

- Counts and sizes update immediately as checkboxes change.
- The warning remains in the modal body/footer; do not use a transient notification.
- The primary button states `Continue with 214 files`.
- At 30 files exactly, no warning; at 31, show it.
- The user is never blocked solely because the batch is large.
- Use icon plus text, not color alone.
- The summary is collapsed to a compact list when there are many roots, with an accessible
  expand/collapse control.
- A root with zero currently selected candidates is omitted.

## Size and source-summary policy

Add a pure frontend helper, preferably:

```text
frontend/src/importSelectionSummary.ts
```

It returns:

```ts
type ImportSelectionRootSummary = {
  key: string;
  label: string;
  path: string | null;
  fileCount: number;
  totalBytes: number;
};

type ImportSelectionSummary = {
  fileCount: number;
  totalBytes: number;
  roots: ImportSelectionRootSummary[];
  isLarge: boolean;
};
```

- Use exact integer byte totals.
- Format bytes only at the presentation boundary.
- Sort roots by first appearance in the selected candidate list, not alphabetically.
- Do not infer root identity by splitting display strings; use `selection_root`.

## Processing-time history

Add a pure frontend helper:

```text
frontend/src/importTiming.ts
```

Versioned local history:

```ts
type ImportTimingHistoryV1 = {
  version: 1;
  samples: Array<{
    recordedAt: string;
    fileCount: number;
    totalBytes: number;
    blockingSeconds: number;
  }>;
};
```

Storage key:

```text
cellxplorer-import-timing-v1
```

Rules:

- keep at most the 10 most recent successful samples;
- ignore failed/cancelled runs;
- ignore non-finite, zero, or negative values;
- ignore samples with `fileCount < 1` or `totalBytes < 0`;
- child 035.6 records samples after successful blocking inspection/registration;
- do not write history in this child except through tested helper functions;
- no server persistence or telemetry.

## Estimate model

Use a conservative two-component local estimate:

```text
predicted seconds = fixed_seconds_per_file × file_count
                  + seconds_per_GiB × total_GiB
```

Derivation:

- calculate candidate rates from valid local samples;
- use a robust median, not a mean dominated by one antivirus/network outlier;
- cap nonsensical coefficients through documented, broad sanity bounds only to prevent UI overflow,
  not to force a particular speed;
- require at least two valid historical samples;
- return an approximate range around the central estimate;
- round to friendly units (seconds for short work, whole minutes for longer work);
- omit the estimate when unsupported rather than using a generic hard-coded speed.

Copy:

```text
Estimated time to register the cells: approximately 4–7 minutes.
Scientific data preparation continues in the background afterward.
```

The estimate covers blocking file inspection and Cell registration. It excludes:

- time spent browsing/choosing files;
- background scientific-cache completion;
- user editing time in the metadata modal.

Before 035.6 records enough history, show only count and size.
