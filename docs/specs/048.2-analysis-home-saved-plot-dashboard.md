## 1. Goal

Replace the minimal Home placeholder from 048.1 with the approved full-width saved-plot overview.

The finished surface provides:

- four truthful summary cards;
- one compact card for every plot-producing analysis family;
- up to four cached saved-plot thumbnails per family;
- navigation into a family or directly into an exact saved plot;
- a Recently updated plots table;
- complete empty/cache-miss/error, keyboard, dark-mode, and responsive behavior.

The Home dashboard is read-only. It organizes and previews existing saved plots; it does not
recalculate them or create a second saved-plot lifecycle.

## 4. New component ownership

Create a coherent Home surface under the existing analyses feature:

```text
frontend/src/features/analyses/editor/home/
├── AnalysisHome.tsx
└── analysisHomePolicy.ts
```

`analysisHomePolicy.ts` is recommended because grouping/sorting/counting are pure and easy to test.
It should not own React state, API calls, or rendering.

If implementation shows that the pure logic is trivial enough to remain local without harming test
clarity, one component file plus focused exported pure helpers is acceptable. Do not place the
entire dashboard back into `AnalysisEditor.tsx`.

## 5. Component contract

A suitable high-level contract is conceptually:

```ts
type AnalysisHomeProps = {
  analysis: AnalysisFull;
  spec: AnalysisSpec;
  onOpenTab: (tab: AnalysisTabKey) => void;
  onOpenPlot: (plot: SavedAnalysisPlot) => void;
};
```

Use the live editor's existing types/ownership rather than copying data into a new dashboard model
unless a small derived view-model is useful.

Home must not own mutation state for analysis samples, saved plots, or plot styles.

## 6. Family definitions

Use one shared frontend definition for the Home family order/label/icon so the dashboard cannot
silently drift from the visible editor tabs.

Required plot families and order:

```ts
[
  "time_capacity",
  "cycles",
  "steps",
  "crate",
  "chargeability",
  "dcir",
  "recap",
]
```

Exclude `settings`.

Preferred approach:

- either extract a small shared family metadata definition from the existing editor `TAB_DEFS`, or
- define a Home-family list in a pure policy module while keeping labels/icons exactly aligned with
  the current canonical editor labels.

Avoid a broad tab-system refactor for the sake of deduplicating seven labels.

## 7. Pure grouping and sorting rules

Implement/test pure helpers equivalent to:

```ts
groupSavedPlotsByFamily(plots)
recentPlotsForFamily(plots, tab, limit = 4)
recentlyUpdatedPlots(plots, limit = 5)
countFamiliesWithPlots(plots)
```

### Sorting

Primary sort:

```text
modified_at descending
```

Tie breaker:

- preserve original `saved_plots` order if practical; otherwise stable saved-plot ID order.

Invalid/missing timestamps should not crash Home. Treat them as oldest and retain deterministic
order.

### Unsupported/legacy tab value

The runtime API type should prevent unknown tabs. If defensive normalization encounters an unknown
legacy value, do not crash the whole Home page. Omit it from category cards and keep current API
normalization/logging behavior. Do not add a new “Other” scientific family without product approval.

## 8. Summary cards

Render four compact cards in one row at normal desktop width.

### Total plots

Source:

```ts
(spec.saved_plots ?? []).length
```

Label: **Total plots**

### Categories with plots

Count unique plot-producing `tab` values with at least one saved plot.

Label exactly: **Categories with plots**

This avoids implying that the application supports only the currently non-empty categories.

### Last updated

Source: loaded `analysis.modified_at`.

Label: **Last updated**

Use existing date formatting conventions/helper if one already exists nearby. Do not add author
metadata.

### Created

Source: loaded `analysis.created_at`.

Label: **Created**

### Visual rules

- standard bordered Mantine cards;
- compact icon + text hierarchy;
- icons use neutral/channel-safe semantics, not category-specific decorative hues;
- cards are informational, not clickable;
- values remain readable at UI zoom and in dark mode.

## 9. Family-card grid

### 9.1 Layout

Use CSS Grid/Mantine SimpleGrid (or equivalent established primitive) with responsive behavior:

- 3 columns at normal desktop content width;
- 2 columns when available content width is meaningfully narrower;
- 1 column only at small development/browser widths where needed to prevent overflow.

Do not add horizontal scrolling to the dashboard.

The page should remain dense enough that several categories are visible without excessive vertical
scrolling.

### 9.2 Family card header

Each card shows:

- Tabler icon matching the editor family;
- canonical family label;
- saved-plot count with correct singular/plural wording if text is used;
- one subtle family-navigation affordance.

The entire card does not have to be one giant button. Prefer clear nested actions with correct
semantics.

### 9.3 Thumbnail strip

Show the four most recently modified saved plots for that family.

Each tile:

- reserves fixed geometry before the thumbnail loads;
- uses a white plot frame in both UI themes;
- is keyboard focusable/clickable;
- opens exactly that `SavedAnalysisPlot` through `onOpenPlot(plot)`;
- has accessible text including the plot name and family;
- exposes the full plot name via tooltip/title if the visible label is omitted or truncated.

The structural mockup emphasizes the plot image; do not cram full saved-plot metadata beneath every
miniature thumbnail.

If the card contains more than four saved plots, still show only four. **View all plots** opens the
owning family where the existing `SavedPlotsPanel` exposes the full list.

### 9.4 Zero-plot state

Render the family card even with zero plots.

Inside the thumbnail region show a compact neutral state such as:

```text
No saved plots yet
Open Cycles
```

The navigation action opens the family in its normal editor workspace.

Do not display four empty thumbnail boxes.

## 10. Cached-only Home thumbnail path

This is the main performance-sensitive part of 048.2.

### 10.1 Do not use live generation fallback

The existing saved preview components can admit artifact/compute work when generation is allowed.
Home must have a path that stops after thumbnail lookup.

Add or extract a small reusable artifact component/helper, e.g. conceptually:

```tsx
<CachedSavedPlotThumbnail
  analysisId={analysisId}
  baseSpec={spec}
  plot={plot}
/>
```

The exact name is not locked.

### 10.2 Reuse existing thumbnail identity

The new consumer must use the same:

- thumbnail version;
- plot view/signature logic;
- saved selection/visibility meaning;
- endpoint payload;
- cache lookup endpoint;

already used by `SavedPlotPreview` / `SavedTimeCapacityPreview`.

Do not invent a Home-thumbnail cache, new image dimensions, or alternate scientific figure builder.

### 10.3 Cache hit

On hit:

- render the existing cached thumbnail in the fixed frame;
- preserve its white plot background;
- avoid unnecessary decode/re-render work.

### 10.4 Cache miss

On confirmed miss:

- stop;
- render a neutral placeholder, e.g. icon + `Preview not cached` available to assistive text;
- keep the tile clickable so the user can open the plot;
- do not show a loader indefinitely;
- do not call compute/artifact-generation endpoints.

### 10.5 Lookup error

Same visual class as unavailable preview, optionally with tooltip text such as `Preview unavailable`.
Do not emit a page-level red error for one missing thumbnail.

### 10.6 Lookup admission

At most four previews per seven categories are candidates (28 maximum) plus up to five recent rows.
Avoid duplicating identical lookup work for the same plot when it appears both in a family card and
the Recent table.

Preferred options, in order:

1. share/deduplicate cached-thumbnail lookup state by plot/signature through React Query or the
   existing cache hook if already available;
2. reuse the same rendered cached URL/result inside Home;
3. if necessary, use one lightweight Home-level map keyed by saved-plot identity/signature.

Do not issue two independent network lookups for the same thumbnail simply because it appears in
two Home sections.

Avoid introducing IntersectionObserver/schedulers unless measurement shows the bounded lookup set is
still problematic.

## 11. Recently updated plots

Render below the family grid.

### Data

Take up to five saved plots sorted globally by `modified_at` descending.

### Columns

Keep it compact:

- **Plot** — tiny cached thumbnail + saved plot name;
- **Category** — canonical family label, optionally a neutral/light badge;
- **Updated** — formatted `modified_at`.

Do not include:

- Opened by;
- Last opened;
- fake user names;
- per-row delete/edit controls;
- a misleading per-plot sample count that would require interpreting hidden-series state.

### Interaction

The row or explicit plot-name action opens the exact saved plot through `onOpenPlot(plot)`.
Use native button/link semantics for the actionable area.

### Empty state

If there are no saved plots, show a compact neutral sentence. Do not hide the family cards.

## 12. Navigation wiring

### Family navigation

`onOpenTab(tab)` must route through the 048.1 canonical family navigation path so that:

- active view becomes analysis;
- the requested `AnalysisTabKey` becomes visible;
- current cold/normal/draft semantics for that tab remain intact.

### Exact saved plot

`onOpenPlot(plot)` must route through the existing `AnalysisEditor` saved-plot opening handler, not
reconstruct plot state in `AnalysisHome`.

Expected result:

```text
Home thumbnail/row
    ↓
existing editor saved-plot open path
    ↓
plot.tab active
    ↓
that exact saved plot loaded in existing editor
```

## 13. Loading, refresh, and stability

Home derives its data from the loaded analysis object. Follow existing React Query/editor refresh
behavior.

- Do not blank the entire Home surface during an ordinary background refresh if the editor already
  has valid data.
- If saved plots update while Home is mounted, counts/grouping/recent ordering should update from the
  canonical refreshed analysis/spec.
- Do not maintain a second mutable copy of `saved_plots` inside Home.
- Reserve thumbnail dimensions to avoid layout shift when cached images appear.

## 14. Visual implementation details

Follow `docs/agent-knowledge/visual-style-guide.md` rather than literal mockup chrome.

### Required

- Mantine `Paper`, `Group`, `Stack`, `Text`, `SimpleGrid`/Grid or equivalent established components;
- `withBorder`, `radius="md"`, compact `p="sm"`/`md` geometry;
- Tabler icons;
- theme-safe background/border tokens;
- `Text size="sm" fw={700}`-style section/card headings;
- `xs` dimmed metadata;
- channel primary for active/open affordance;
- white scientific thumbnail surfaces;
- no hardcoded pale-gray chrome that disappears in dark mode.

### Avoid

- decorative category-specific color blocks;
- oversized statistic cards;
- large shadows;
- gradients;
- animation beyond ordinary hover/focus transitions;
- ad hoc inline mouseover style mutation;
- tiny unreadable instruction text;
- horizontal scrollbars caused by long plot names.

## 15. Accessibility

- Each saved thumbnail has a real interactive element and an accessible name including plot name.
- Each family-navigation control includes the family name.
- Recent plot rows are keyboard actionable without turning the entire table into invalid nested
  buttons.
- Visible focus rings follow Mantine defaults/theme.
- Full saved plot names are available when thumbnails/labels truncate.
- Category count is not communicated only by color.
- Thumbnail cache miss/error has textual/ARIA meaning, not only a blank rectangle.

## 16. Tests

Create pure policy tests, suggested path:

```text
frontend/tests/analysisHomePolicy.test.ts
```

Required pure cases:

1. all seven family definitions are present in canonical order;
2. `settings` is excluded;
3. saved plots group by `tab` correctly;
4. per-family preview selection is limited to four;
5. per-family selection is `modified_at` descending;
6. deterministic tie behavior;
7. missing/invalid timestamps do not crash and sort as oldest;
8. categories-with-plots count ignores empty families and settings;
9. recently updated list is globally sorted and limited to five;
10. zero-plot input yields all seven empty category models;
11. Recap plots appear in Recap rather than being dropped.

Add focused tests for the cached-only thumbnail helper/component at the lowest practical layer:

- cache hit returns/display path;
- cache miss ends in placeholder state;
- lookup error ends in placeholder state;
- cache miss does not invoke compute/generate code;
- duplicate use of the same plot in family + Recent does not duplicate lookup when the chosen
  implementation promises deduplication.

Run affected existing artifact-policy tests as well.

## 17. Performance verification

This child must explicitly verify the absence of accidental compute.

With an analysis containing saved plots from several families:

1. open Home;
2. inspect network/request logs;
3. confirm thumbnail lookup requests may occur;
4. confirm no family compute endpoints are called solely because Home rendered;
5. confirm no live Plotly graph components are mounted for category thumbnails;
6. confirm category + Recent duplication does not double the same lookup unnecessarily;
7. switch into a saved plot and confirm normal family computation/artifact behavior remains intact.

If opening Home becomes observably slower as saved-plot count grows, profile before adding a new
scheduler. The Home workload should remain bounded by the preview limits, not total plot count.

## 18. Manual browser matrix

Verify with realistic saved-plot data:

### Content

- 0 total plots;
- one category with 1 plot;
- category with exactly 4 plots;
- category with >4 plots;
- several non-empty categories;
- Recap empty;
- Recap non-empty;
- long plot names;
- same timestamp ties.

### Navigation

- category **View all plots** opens correct family;
- category header chevron/action opens correct family;
- each thumbnail opens the exact saved plot;
- each recent row opens the exact saved plot;
- Home remains the active visual tab until a navigation action is taken.

### Preview states

- cached thumbnail hit;
- cache miss;
- lookup error/offline/transient backend failure;
- background cache refresh later makes a thumbnail available without breaking layout.

### Layout/theme

- normal desktop width: 3-column family grid;
- narrower supported desktop width: 2-column grid before overflow;
- small dev width: usable 1-column fallback if reached;
- no horizontal scrollbar from card content;
- light mode;
- dark mode with white scientific thumbnail surfaces;
- application UI zoom if supported by current manual checklist.

### Accessibility

- Tab through Home controls in logical order;
- Enter/Space activation where native semantics support it;
- visible focus indication;
- tooltips/full names for truncated saved plots.

## 19. Cache/schema/science consequences

- Database migration: **none**.
- Backend endpoint/schema: **none expected**.
- `CALC_VERSION`: **no change**.
- Result schema versions: **no change**.
- Thumbnail/artifact cache version: **no change** for a cached-only consumer.
- Scientific calculations: **none**.
- Portable report: **unchanged**.

If the implementation changes thumbnail rendering itself rather than only consuming existing cached
thumbnails, stop and reassess cache-version implications against Spec 038.6 before proceeding.

## 20. Out of scope

- saved-plot mutation/delete/rename from Home;
- persistent “recently opened” tracking;
- user/authorship metadata;
- global New plot button;
- dynamic user-arranged dashboard;
- dragging/reordering category cards;
- alternate Home-specific thumbnail format;
- live plot interaction inside Home thumbnails;
- changes to family scientific controls;
- portable-report dashboard export.

## 21. Acceptance criteria

- [ ] Final Home structure matches the approved composition while using repository-standard visual styling.
- [ ] Four truthful summary cards use existing analysis/spec data only.
- [ ] All seven plot-producing families render in canonical order; Settings does not.
- [ ] Family grid is 3 columns at normal desktop width and degrades without horizontal overflow.
- [ ] Every category shows its saved-plot count.
- [ ] Each category shows up to four most recently modified saved plots.
- [ ] >4 plots never expands the Home card into an unbounded list.
- [ ] Zero-plot families remain visible with a useful navigation empty state.
- [ ] Recap is handled correctly whether empty or non-empty.
- [ ] Home thumbnails use the existing thumbnail cache identity and lookup contract.
- [ ] Cache miss/error produces a stable placeholder and never a permanent loader.
- [ ] Home cache miss does not trigger scientific compute/artifact generation.
- [ ] No live Plotly figure is mounted for Home thumbnails.
- [ ] Duplicate family/Recent representation does not cause wasteful duplicate lookup work.
- [ ] Recently updated plots uses `modified_at`, not invented last-open/opened-by data.
- [ ] Family navigation uses 048.1 canonical activation.
- [ ] Thumbnail/recent click opens the exact saved plot using the current editor path.
- [ ] Dark/light chrome, white plot surfaces, keyboard behavior, truncation, and empty/error states are correct.
- [ ] Focused tests, frontend production build, and final parent preflight pass and are recorded.
