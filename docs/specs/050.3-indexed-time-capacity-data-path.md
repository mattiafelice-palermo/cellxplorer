## Goal

Replace Time/Capacity's current **load and stitch every raw row before cycle filtering** behavior
with a source-index-driven plan that loads only the raw row groups and columns required by the
requested cycles, while preserving the exact existing Time/Capacity scientific result contract.

Child 050.2 provides the persistent primitive:

```text
source-local observed cycles
cycle -> raw row-group mapping
full-source finite voltage-channel facts
bounded source timestamp facts
selective raw-cycle/column reader
legacy-layout safe fallback
```

Child 050.3 makes `analysis_engine.compute_time_capacity()` consume that primitive.

The target user-facing model is:

> Opening or navigating Time/Capacity is a view over prepared scientific data. Changing from one
> cycle range to another must not require materializing unrelated cycles or unrelated source files.

This child deliberately stops short of precomputing a separate all-cycle overview or adding a
backend RAM LRU. After this path is measured, Parent 050 may author reserved Child 050.4 only if the
remaining full-range/working-set cost justifies it.

## Why this is a separate child

050.2 proves a low-level cache can return exact cycle subsets safely. 050.3 changes a scientific
analysis consumer and therefore must separately prove:

- dense global continuation mapping is unchanged;
- source provenance and missing-middle fail-closed semantics are unchanged;
- phase/capacity/derivative/protocol calculations see complete selected cycles;
- voltage-channel availability remains full-source/data-driven even though only selected rows are
  loaded;
- compact plotting and full-resolution exports remain scientifically equivalent to the current
  implementation.

Do not mix new storage-format debugging and Time/Capacity scientific integration into one review
checkpoint.

## Verified current Time/Capacity path before 050.2/050.3

`backend/app/services/analysis_engine.py::compute_time_capacity()` currently performs, per selected
unit/Cell:

```text
resolve ordered sources + pinned parser identities
possibly reparse a missing current raw cache
reconstruct protocol step targets
stitch.stitch_raw(refs)
    -> cache.load_raw() for each source
    -> full pd.read_parquet() for each source
    -> discover observed local cycles from all raw rows
    -> copy/map each full source
    -> concatenate source frames
scan the full stitched frame for voltage channel availability/context
build source descriptors from full frame
only now apply cycles / cycle_start / cycle_end
sort selected rows
continuous time
source provenance arrays/boundaries
phase classification
phase capacity
normalizations
optional derivative
protocol row mask
selected voltage/current arrays
display_x
interactive downsample
serialize response
```

Therefore a request for cycles 400-420 can still pay the raw-I/O, mapping, copy and concatenation
cost of cycles 1-N.

The current ordering is scientifically important in several places. 050.3 must change **what is
loaded**, not casually reorder scientific calculations.

## Locked conceptual separation

### Scientific dataset versus view state

Treat these as **scientific/base data**:

```text
ordered source chain
source checksum + parser identity
exact observed source-local cycles
dense global cycle mapping
record order
source provenance/boundaries
cycle/step/status/time/current/voltage/capacity rows
cell scientific metadata used for normalization
protocol mapping inputs
```

Treat these as **view/request choices over that data**:

```text
cycle range / explicit cycles
voltage versus current display
x-axis choice
units/display mode
plot point budget
style/legend/zoom
```

Derivative settings are derived scientific/render computation over selected complete cycles, not a
reason to reload unrelated cycles.

The implementation does not need to move current backend-owned scientific transformations into the
frontend to achieve this child.

## Locked architecture

### 1. Build a lightweight global stitch plan before raw record loading

For each selected Cell, resolve the ordered `CachedSourceRef` chain exactly as today. Then use the
050.2 source indexes to construct the same dense observed-cycle mapping that `stitch_raw()` would
construct, **without loading full raw frames**.

The logical plan should contain enough information equivalent to:

```text
complete: bool
missing_positions: [...]
legacy_unprepared_positions: [...]

segments:
  - source_hash
    parser_version
    segment                   # zero-based source position
    observed_source_cycles    # exact labels, no invented gaps
    global_cycle_start
    global_cycle_end
    source_cycle_count
    source timestamp/capability metadata

requested:
  - global_cycle
    -> segment/source
    -> exact source_cycle
```

The exact class/dataclass/dict shape is an implementation decision. Prefer one reusable service
rather than embedding cycle arithmetic deep inside `compute_time_capacity()`.

### 2. Reuse the canonical dense-cycle rule

There must remain one conceptual rule for continuation numbering:

```python
observed local labels in stable numeric order
-> build_dense_cycle_map(labels, global_start)
```

Examples that must remain true:

```text
source A labels [1, 2, 4] -> global [1, 2, 3]
source B labels [7, 9]    -> global [4, 5]
```

Do not calculate global offsets as `max-min+1`. Do not infer local label 3. Do not special-case
source labels beginning at 0/1/7.

Share/refactor `stitch.observed_local_cycles()` / `build_dense_cycle_map()` if necessary; do not
create a second subtly different Time/Capacity numbering implementation.

### 3. Preserve missing-middle-source fail-closed behavior

A genuinely missing raw cache in an ordered source chain still makes that Cell scientifically
incomplete. Later sources must not slide earlier or be rendered as a continuous prefix.

Distinguish these states:

```text
A. raw cache absent / invalid scientific source
   -> existing cache-missing + continuation-incomplete behavior; fail closed

B. raw cache exists but 050.2 layout/index absent or unusable
   -> scientific data is still valid; use legacy full-read fallback
   -> do NOT badge as a missing source

C. indexed raw cache available
   -> optimized path
```

If the chain contains any state B source and the implementation cannot safely mix indexed and
legacy reads while preserving one mapping, prefer a **whole-Cell legacy fallback** over a clever
partial optimization. Correctness and simple reviewability take priority.

### 4. Resolve requested global cycles before record loading

Use current `time_capacity_settings()` semantics exactly:

```text
explicit settings["cycles"] if non-empty
otherwise cycle_start/cycle_end bounds
```

Map requested global cycles through the stitch plan to source-local labels.

Rules:

- a range may cross source boundaries;
- explicit cycles may be non-contiguous;
- requested global cycles outside the known chain simply have no rows;
- selecting only cycles from source B must not read source A's raw row groups once the complete
  global mapping is known from indexes;
- global mapping metadata for earlier sources may be read from tiny indexes, but their raw records
  must not be materialized solely to calculate offsets.

### 5. Read only contributing source row groups and required columns

For an indexed narrow request, call the 050.2 selective accessor only for sources that contribute
requested cycles.

The Time/Capacity base column set must be explicit and derived from actual consumers. At minimum,
audit these current needs:

```text
record_index
cycle                       # source-local before mapping
step_index
step/status as required by phase/protocol logic
status
time_s
voltage_v
current_ma
charge_capacity_mah
discharge_capacity_mah
working_potential_v         # when present / selected availability path
counter_potential_v         # when present / selected availability path
timestamp                   # only if a downstream selected-row consumer truly needs it
other canonical optional columns only if actually consumed
```

Do not blindly load every Parquet column "to be safe". Likewise, do not drop a required column
because the default voltage/current view happens not to exercise derivative/protocol behavior.

The implementer should expose one grep-able function that determines the Time/Capacity raw column
projection for a request so tests can lock it.

### 6. Restore stitched columns only on loaded rows

After a selective source read, attach the same stitched provenance concepts as current
`stitch_raw()`:

```text
source_cycle = original source-local cycle
cycle        = dense global cycle
segment      = ordered source position
source_hash  = source checksum
```

Preserve source record order. If multiple source chunks contribute, concatenate only those selected
chunks in canonical source/global-cycle order required by the existing Time/Capacity calculations.

Do not build/copy a complete source-wide DataFrame just to attach these columns.

### 7. Selected cycle rows must be complete before scientific transforms

Every selected global cycle supplied to the current scientific transformations must contain all
canonical rows belonging to that source-local cycle.

This is required because:

- `_continuous_time()` detects step time resets in the selected sequence;
- `_phase_from_raw()` classifies every row;
- `_phase_capacity()` reconstructs phase capacity across step resets;
- derivative smoothing/gradient operates within cycle/segment/phase groups;
- protocol masking needs complete selected-cycle step membership.

A row-group read may include neighboring cycles, but the accessor must filter to exact requested
source cycles **after** loading the relevant groups and before scientific transforms.

Never downsample raw records before `_phase_capacity()`, derivative or protocol masking.

### 8. Preserve current selected-range continuous-time semantics

Current `compute_time_capacity()` applies global cycle filtering **before** `_continuous_time()`.
Therefore a selected range is made monotonic relative to the rows in that selected range; it does
not require replaying earlier cycles merely to reconstruct their elapsed offset.

The optimized path must preserve this behavior unless a separately reviewed scientific/UI decision
changes it.

This is important: do not read cycle 1-399 just to calculate a cycle-400 time axis if the current
code does not do that.

### 9. Preserve current phase/capacity/derivative calculations verbatim where possible

Prefer feeding a smaller but equivalent selected-row DataFrame into existing helpers rather than
rewriting the math.

In particular, preserve:

- charge/discharge/rest classification rules;
- phase capacity reset semantics;
- mass-specific and area-specific normalization;
- custom electrode-area override precedence;
- derivative phase/specific/absolute-discharge/smoothing settings;
- derivative use of primary `voltage_v` regardless of selected auxiliary voltage channel;
- current downsampling envelope/boundary behavior.

Any unavoidable helper refactor must have old/new parity tests before removing the old path.

### 10. Move full-source voltage availability/context off the raw scan

Spec 040.4 intentionally makes the top-level `voltage_channels` availability map **selection-wide
and full-source data-driven**, independent of the currently selected cycle range. This prevents the
working/counter-potential options from flickering as cycle filters change.

The optimized path must obtain the finite-data truth from 050.2 index metadata for every ordered
source, not from the narrow selected raw rows.

Preserve current rules:

```text
selection-level available = any selected source has finite data for that canonical channel
mixed selection           = quantity stays selectable if any cell/source has it
cell/source without data   = its requested trace is all None, never substituted voltage_v
role/reference conflicts   = same mixed/generic label behavior as today
```

Header metadata remains authoritative for voltage role/reference labels. The raw index supplies
finite-data presence; do not invent reference chemistry in the index.

Refactor `_time_capacity_voltage_context()` as needed so it can combine source index availability
with existing header capability metadata without requiring the complete raw frame.

### 11. Build source descriptors without a full raw scan

Current source descriptors combine relational/source facts, stitch segment metadata, timestamps and
missing status.

Under the indexed path, derive:

- source position/hash/filename;
- parser identity;
- global/source-local cycle boundaries/counts;
- missing/complete status;
- tracked-tail information;
- known source timestamp bounds;

from the ordered source rows + stitch plan + 050.2 bounded index facts.

Do not read raw rows merely to calculate descriptor timestamps.

Path-free provenance remains mandatory.

### 12. Preserve source provenance arrays and boundary markers

Returned selected rows must still expose the same response-level arrays used by frontend/export:

```text
source_cycle
source_position
source_filename
source_hash
source_boundary_indices
segments
source_descriptors
```

A range crossing B -> C must include the correct boundary index. A range entirely inside B need not
invent a boundary for source A or C because they have no returned rows; `source_descriptors` still
describes the complete ordered source chain as current semantics require.

Do not change payload meaning silently. If implementation requires a response shape change, stop,
document it, bump only the Time/Capacity result schema version as appropriate, and update saved
preview/export tests.

### 13. Protocol masking stays scientifically identical

`_protocol_step_targets()` may inspect source header metadata/protocol signatures. Preserve that
mapping and badge behavior.

Once selected raw rows are loaded and assigned their `segment`, `_protocol_row_mask()` must receive
the same `step_index`/segment relationship it sees today.

Cover all three modes:

```text
excluded -> emit null gaps without dropping rows
hidden   -> emit null gaps without changing scientific metrics/selection meaning
only     -> mask all non-target rows
```

Do not optimize protocol filtering by dropping rows before phase/capacity/derivative calculations
unless current semantics and tests explicitly prove it is equivalent.

### 14. Interactive downsampling remains display-only and late

`max_points_per_cell` is a display point budget. Keep existing sequence:

```text
complete selected raw cycles
-> scientific transforms
-> protocol masks
-> selected channel/display coordinate
-> downsample
-> serialize
```

Do not use the 050.2 physical row-group target as an analysis downsampling rule.

Source-boundary points must remain preserved by the existing downsampling/boundary logic.

### 15. Full-resolution export remains exact

Current behavior treats:

```text
precision == "full" and compact == False
```

as the scientific data-export path and bypasses display downsampling.

Preserve it.

For a selected range, the indexed accessor may still avoid reading unselected cycles, but every row
of every selected cycle must be returned at full precision.

For an all-cycle full export, reading all raw row groups is expected and acceptable. Do not route
scientific export through any future overview cache.

CSV/XLSX/portable paths must retain the same values/provenance as before.

### 16. Saved plots and idle warmup use the same optimized compute path

Saved Time/Capacity previews call the normal backend endpoint with their saved scientific settings.
They should automatically benefit from the optimized backend path when their exact source caches are
indexed.

Do not create a second saved-preview-specific scientific implementation.

050.1's request cancellation/placeholder/autosave rules remain in force.

### 17. Legacy fallback remains available and testable

Keep the current full `stitch.stitch_raw()` behavior as a compatibility path at least for this
child, unless the reviewer can prove every supported live/pinned raw cache is always prepared by
050.2 before Time/Capacity can run.

Preferred transition design:

```text
try build indexed stitch plan
    indexed and complete -> new selective path
    valid raw but unprepared index -> legacy current full path
    genuinely missing raw -> existing fail-closed result
```

The fallback is scientifically equivalent, just slower.

Do not silently convert a legacy cache inside the request in order to avoid the fallback.

Add instrumentation/tests that can prove which path was taken without exposing an end-user debug
API.

## What the optimized request should look like

For a Cell:

```text
source A -> global 1-200
source B -> global 201-500
source C -> global 501-750
```

and request:

```text
cycles 487-510
```

the indexed path should conceptually do:

```text
read tiny A/B/C indexes
    -> establish complete dense global mapping
    -> requested maps to B:487-500 + C:501-510

read B row groups containing source-local requested cycles
read C row groups containing source-local requested cycles
DO NOT read A raw row groups

filter group spillover to exact requested cycles
map source_cycle -> global cycle
attach segment/source provenance
concatenate selected rows
run existing Time/Capacity transforms
downsample/serialize
```

The exact source-local labels may not equal the displayed global values; use the dense map, never
arithmetic assumptions.

## Profiling phase — mandatory during implementation

050.2 establishes storage-level measurements. 050.3 must profile the **complete Time/Capacity
request path** before and after integration.

### Required stages

Instrument or otherwise measure at least:

```text
1. relational selection/source/parser resolution
2. index/stitch-plan loading
3. Parquet row-group I/O
4. exact-cycle filtering + global mapping / concatenation
5. voltage capability/context + descriptors
6. continuous-time + phase + capacity
7. derivative when enabled
8. protocol masking
9. display coordinate + downsampling
10. JSON-safe conversion / serialization
11. frontend request-to-Plotly update where practical in a manual/browser profile
```

Do not leave permanent high-volume production logging. A profiling harness, optional diagnostics or
localized timing utility is preferable.

### Request matrix

Measure at minimum on representative long data:

```text
single cycle
~20-cycle range
few-hundred-cycle range
all cycles
```

For each, record:

```text
indexed versus legacy path
source count
row groups touched / total
raw rows materialized before exact filter
selected rows entering scientific transforms
returned points after downsampling
backend stage timings
serialized payload size
peak/working-set memory where practical
```

If practical, record browser-visible request/render timing too, but do not make an unrepeatable
manual stopwatch the only evidence.

### No universal wall-time gate

Hardware, disk cache and source density vary. Acceptance is structural plus measured:

- narrow requests must not materialize every row group/source;
- materialized raw rows must scale with requested cycles + row-group spillover rather than total
  experiment length;
- scientific-transform input rows must equal the exact selected cycles;
- measured backend time should show the removed full-source read/copy cost is materially reduced.

If the indexed path is not measurably better on the representative long source, stop before adding
more caching layers and diagnose why.

## Decision gate for reserved Child 050.4

After 050.3 measurements, the implementer and reviewer must explicitly record whether additional
interactive working-set work is justified.

### Author 050.4 only if evidence shows a remaining distinct bottleneck

Examples:

- **All cycles remains slow** because reading/transforming all detail rows is still dominant even
  though narrow ranges are fast -> consider a precomputed multiresolution/all-cycle overview.
- **Repeated neighboring narrow ranges remain perceptibly I/O-bound** after cycle-addressable
  Parquet -> consider bounded recent-chunk RAM LRU and/or neighbor prefetch.
- **Backend is fast but browser JSON/Plotly dominates** -> 050.4 should target payload/render level,
  not add another backend raw cache blindly.

### Do not author/implement 050.4 merely because it was reserved

If indexed detail requests and all-range interaction meet the user-visible target, record 050.4 as
not needed and leave Parent 050 open only for unrelated future measured performance children.

No 050.4 implementation belongs in this child.

## Required automated tests

### Stitch planning / selective source choice

1. Single indexed source, one requested global cycle -> only that source's mapped local cycle is
   requested from raw accessor.
2. `[1, 2, 4]` local labels remain dense globals `[1, 2, 3]`.
3. Two sources with restarted local numbering map correctly.
4. Explicit non-contiguous global cycles map to exact source/local cycle sets.
5. Range crossing source boundary reads both relevant sources.
6. Range wholly in later source reads no raw row groups from earlier source.
7. Requested cycles outside known range return no fabricated rows.
8. Missing middle raw source fails closed and later source is not rendered.
9. Missing/stale 050.2 index with valid raw selects legacy fallback, not `cache_missing`.
10. Parser identities remain exact per source in mixed-format/mixed-generation chains.

### Selected-row scientific parity

11. Indexed selected raw rows after stitching equal the legacy `stitch_raw()` then cycle-filter
    subset for the same request.
12. `_continuous_time()` result matches legacy path.
13. Phase classification and phase capacity match.
14. Specific capacity normalization matches imported/override active mass behavior.
15. Areal capacity matches metadata and custom area override.
16. Consecutive, overlap and mirror display modes match.
17. Time/capacity X-axis/unit choices match.
18. dQ/dV and dV/dQ outputs match for phase/smoothing/specific/absolute-discharge settings.
19. Derivatives remain based on primary `voltage_v`, not selected auxiliary voltage channel.

### Protocol filtering

20. Excluded target emits identical null gaps.
21. Hidden target emits identical null gaps.
22. Only-target behavior matches.
23. Legacy/current protocol signature aliases continue resolving as established before 050.
24. Missing/unmatched protocol metadata produces the same badges.

### Multi-voltage

25. Ordinary two-electrode source exposes only primary voltage.
26. Three-electrode working/counter availability comes from full-source index facts and does not
    flicker when selecting a cycle with no finite auxiliary value.
27. Mixed selection keeps an auxiliary quantity available when any selected sample has real data,
    while unavailable cells receive all-None traces.
28. Conflicting role/reference contexts retain the current mixed/generic labels.
29. Requesting unavailable channel never silently substitutes `voltage_v`.

### Provenance / boundaries

30. Source descriptors match legacy path for source/global cycle bounds, parser identities,
    timestamps, tracked-tail and missing status.
31. `source_cycle`, `source_position`, `source_filename`, `source_hash` arrays match returned rows.
32. Source-boundary indices are correct for a selected range crossing a continuation boundary.
33. A range wholly within one source does not invent a returned-row boundary while descriptors
    still represent the complete chain.

### Compact versus full/export

34. Standard compact request still honors point budget after all scientific transforms.
35. Full non-compact request returns every row in selected cycles at full precision.
36. Full all-cycle export remains complete even though it necessarily reads all detail groups.
37. Indexed versus legacy export projections are equal.
38. Saved Time/Capacity preview uses the same compute result contract.

### Cache/result identity

39. Physical raw-layout version/index presence alone does not change the Time/Capacity scientific
    result key/data signature.
40. Legacy and indexed computations for identical scientific inputs do not create different
    scientific identities merely because one source has optimized storage.
41. Existing Time/Capacity result-cache hit behavior remains valid after 050.1's family-specific key
    changes.

### Performance-structure tests

42. An instrumented 1-cycle indexed request does not call `cache.load_raw()` / `stitch_raw()` for
    the optimized path.
43. It requests fewer than all row groups on a synthetic many-group source.
44. It does not read raw rows from an unrequested earlier source needed only for global offset
    metadata.
45. Scientific transforms receive only exact selected-cycle rows, not row-group spillover.

## Golden/regression verification

Use the committed golden analysis corpus as the primary end-to-end scientific regression layer.
At minimum, run the current Time/Capacity baseline and derivative golden checks plus the focused
multi-voltage/continuation tests relevant to changed code.

Do **not** refresh expected golden scientific files to make a mismatch disappear. For this
performance-only child, the expected outcome is no scientific golden change. If a golden projection
must change for a legitimate payload-only reason, stop and document exactly why before updating it.

Where practical, tests should be able to force both:

```text

```

against the same canonical input and compare normalized results directly. This provides stronger
proof than checking only the final committed golden file through one path.

## Analysis cache / response version policy

### `CALC_VERSION`

Do **not** bump when the optimized path returns the same scientific meaning.

### `ANALYSIS_CACHE_VERSION`

Do not bump merely because backend I/O changed.

### `RESULT_SCHEMA_VERSIONS["time_capacity"]`

Do not bump if response shape/meaning remains byte-logically equivalent apart from volatile timing
or internal diagnostics not exposed in the persisted result.

If payload shape or meaning changes, bump only the Time/Capacity schema version and update saved
artifact/signature tests. Do not use a shared analysis-cache generation bump for a Time/Capacity-only
response change.

### Raw layout version

050.2's raw physical-layout version is not a scientific input and must not enter analysis result
keys.

## Database migration policy

No relational migration is expected.

Do not persist per-analysis cycle indexes, row-group offsets or session working sets in SQLite.
Those are regenerable cache/access concerns.

## Explicitly out of scope

- A persistent all-cycle overview cache.
- Multi-resolution plot tiles.
- Backend whole-cell/raw DataFrame RAM cache.
- Backend cycle-chunk RAM LRU.
- Neighbor-cycle prefetching.
- Frontend prefetch of adjacent ranges.
- Moving scientific phase/capacity/derivative calculations to TypeScript.

- Changing voltage roles/reference chemistry.
