## Goal

Use Parent 040's generic multi-voltage Time/Capacity capability to present BioLogic GCPL6 three-electrode data clearly, without creating BioLogic-specific plotting/scientific paths.

At completion, a supported three-electrode MPR source should let the user choose and compare:

```text
Cell voltage
Working electrode potential vs reference
Counter electrode potential vs reference
```

when those channels are actually available.

The UI should also expose concise source/reference context where useful, while ordinary two-electrode Neware/BioLogic sources remain as simple as before.

## Core rule: no BioLogic plotting fork

The data path is already canonical:

```text
BioLogic adapter
→ voltage_v / working_potential_v / counter_potential_v
→ Parent 040 Time/Capacity quantity API
→ existing Time/Capacity figure builder
```

Do not add:

```text
BioLogicPlotCard
if source.ext == "mpr" then separate Plotly path
Ewe/Ece-specific endpoint
```

The only BioLogic-specific presentation should be source metadata/labels derived from normalized capabilities.

## Quantity labels

Follow Parent 040's current landed quantity IDs and role metadata.

Preferred user-facing labels for a three-electrode full-cell source:

```text
Cell voltage (V)
Working potential vs ref (V)
Counter potential vs ref (V)
```

If explicit reference text is short and available, labels/tooltips may say:

```text
Working potential vs Li/Li+ (V)
Counter potential vs Li/Li+ (V)
```

Do not invent the reference electrode.

If source metadata explicitly establishes positive/negative battery roles, a tooltip may clarify:

```text
Working electrode (positive)
Counter electrode (negative)
```

but keep the primary selector labels based on canonical working/counter terminology unless the product already has a stronger role-label convention.

## Availability behavior

Use the exact multi-sample availability rule locked by Parent 040.4.

Requirements:

- only offer working potential when the selected analysis/sample context genuinely has it under that rule;
- only offer counter potential likewise;
- never show an auxiliary option that silently falls back to `voltage_v`;
- if a saved plot requests a channel that has become unavailable because a source changed, use the current family error/unavailable surface and explain the missing channel;
- do not render zero-valued dummy traces.

## Default behavior

For every existing analysis/saved plot that does not explicitly select a new electrode channel:

```text
selected voltage quantity = current primary voltage / voltage_v
```

Opening a new three-electrode MPR analysis should still default to Cell voltage, not Working or Counter potential.

This keeps the ordinary battery view consistent and avoids surprising existing scientific interpretations.

## Multi-plot / stacked-plot compatibility

If Parent 040/current branch has stacked Time/Capacity plots or per-plot quantity controls by implementation time, the auxiliary voltage channels should appear through the same quantity mechanism.

Do not create a special “three-electrode mode” that forces all three traces onto one plot.

The user may choose:

- one voltage profile;
- multiple Y series if current Time/Capacity supports it;
- separate stacked plots if that feature is current.

Follow actual post-040 UI architecture and keep scope to making the canonical quantities selectable.

## Axis labels and exports

Axis title must reflect the selected channel accurately.

Examples:

```text
Cell voltage (V)
Working potential vs Li/Li+ (V)
Counter potential vs Li/Li+ (V)
```

CSV/XLSX/data export should use stable canonical column/series labels, not vendor strings `Ewe`/`Ece` unless an optional source-native metadata column is deliberately included separately.

Plot image export/portable figure uses the same visible axis label.

## Source metadata presentation

Where the Cell/source detail or import preview already shows source metadata, add bounded useful BioLogic facts if they fit existing surfaces:

```text
Source format: BioLogic EC-Lab
Technique: GCPL / GCPL6 when explicitly decoded
Reference electrode: <source text>
Voltage channels: Cell + Working vs ref + Counter vs ref
Cell voltage: measured | derived from Working − Counter
```

Do not add all VMP settings to the Cell summary.

Full decoded settings remain in per-source header detail/on-demand raw metadata.

## Protocol structure presentation

The existing protocol viewer should display BioLogic-mapped canonical operations using current protocol components.

No BioLogic-specific protocol card is needed.

Verify labels make sense for:

- CC charge/discharge;
- CCCV where mapped;
- rest;
- loops/repeats;
- operational cutoffs/rates when available.

If capability warnings exist (e.g. semantic Chargeability conditions unavailable), use the current warning/info pattern and concise wording.

## Saved plot behavior

A saved Time/Capacity plot selecting Working/Counter potential must:

- persist the canonical quantity ID;
- restore on cold open;
- update/copy/delete normally;
- generate correct thumbnail/preview/full artifact;
- survive app restart through persisted analysis spec;
- enter/skip cache warmup under the same rules as other Time/Capacity plots;
- show unavailable state rather than substitute primary voltage if source capability later disappears.

No artifact renderer version bump is needed unless figure rendering logic changes in a way current versioning policy says requires one. Follow current `analysisPlotPolicy`/cache docs; do not bump versions reflexively.

## Portable report behavior

Portable report selection/figures must preserve:

```text
selected electrode-potential quantity
axis label
legend/series label
source/provenance
```

If original `.mpr` sources are embedded under current portable-source policy after 041.4, ensure source display name/type remains correct; no new portable package format is required solely for electrode channels.

## Loading/error/empty states

Follow current Time/Capacity family behavior exactly:

- delayed loading indicator policy;
- previous-data retention where current query policy uses it;
- clear no-data/unavailable state;
- no layout jump when selector options appear;
- no spinner for normal cached sub-250ms transitions if current shared policy suppresses it.

## Accessibility / geometry

Follow `visual-style-guide.md`:

- controls keyboard accessible;
- selector labels not color-only;
- tooltip for truncated reference label;
- dark/light chrome correct;
- Plotly remains current light scientific presentation if that remains canonical;

## Scientific family scope

Those continue using primary `voltage_v` or current established quantities.

A future spec may define electrode-specific scientific analysis meaning.

## Implementation record

### 041.6 supersession note

The metadata-only qualification in the historical 041.5 checkpoint is superseded for the verified
no-MPT CC/rest GCPL path by Spec 041.6. The generic Time/Capacity channel contract is now exercised
through normal MPR import, canonical cache, and analysis computation; the supported source exposes
Cell, Working, and Counter potentials with the recorded reference metadata. Unsupported MPR
variants still fail closed and the current production byte contract does not claim CCCV support
without a separately decoded measured-current field.

The implementation reuses Parent 040.4's generic `voltage_channel` Time/Capacity path. It does not add a BioLogic-specific plot, endpoint, analysis family, migration, or `CALC_VERSION` bump.

- Canonical labels remain `Cell voltage (V)`, `Working potential vs ref (V)`, and `Counter potential vs ref (V)`. A short explicit source reference is appended only when the contributing sources agree; missing, conflicting, placeholder, or overlong references fall back to the generic `vs ref` label. Explicit persisted voltage roles are preserved when unambiguous; mixed role context is reported neutrally as `Voltage role ambiguous (V)` rather than relabelled as cell voltage.
- BioLogic source detail/import presentation is bounded to format, technique, EC-Lab version, reference, channel capability, and measured/derived cell-voltage facts. Real MPR sources remain metadata-only under 041.4; this child does not claim real-file cycling acceptance before the independent MPR cycle-identity boundary is closed.
- Channel switches reject mismatched in-flight results; availability is retained across plot-only refetches and reset when selection or source/data identity changes; unavailable saved auxiliary channels stay pinned but show an explicit unavailable message; data export requests `precision=full` and `compact=false` so it is not limited to interactive downsampling, with exact raw semantic axis headers. Server-indexed thumbnail records carry the current scientific data signature, so a changed source hash/parser/capability cannot reuse an old image under the same plot signature. Every compute result now returns a server-owned artifact signature plus a render-mode-independent Time/Capacity source signature; artifact writes require the validated identity and key the stored artifact with that exact value. Saved result and thumbnail renderer versions were bumped for the changed response/figure semantics. Portable export always revalidates saved artifacts through the server and uses a shared selected-channel gate for generated snapshots. Chargeability and rate-capability saved plots use their own result-key families, and mixed-source parser identities are included in the Time/Capacity source signature.
- Foreground and warmup preview caches publish only after the server accepts the exact artifact identity; stale writes remove their local query entries. Warmup query keys include task generation/signature, and no-plottable-data results persist as an identity-bound unavailable disposition rather than pretending a thumbnail pair exists or requeueing forever. Portable snapshots carry both data identity and saved-plot revision, and the backend validates both immediately before packaging.
