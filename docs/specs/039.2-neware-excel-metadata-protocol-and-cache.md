## Goal

Integrate the raw parser created by 039.1 into CellXplorer's existing backend parser/cache/protocol
contracts.

This child must make a supported Neware Excel workbook scientifically equivalent to a binary source
at the backend service boundary by adding:

1. cheap metadata extraction from the workbook's metadata/protocol sheets;
2. reconstruction of the programmed Neware step plan into the existing flattened metadata grammar;
3. truthful capability flags/warnings for information the workbook does not export;
4. format dispatch through `backend/app/services/parsing.py`;
5. one deterministic parser-bundle version compatible with existing provenance/caches;
6. current raw/cycle cache integration;
7. independent cycle-summary validation against `calc.per_cycle`.

At the end of this child, backend code that is handed a `.xlsx` path directly through the parser/cache
services should obtain canonical raw data, canonical cycles and a usable declared protocol. The
user-facing import/file-picker/scanner paths still remain `.nda/.ndax` only until 039.3.

## Current verified backend contracts

### `parsing.py`

At the parent baseline:

```python
PARSER_VERSION = NewareNDA.version.__version__
```

`parse_timeseries` directly calls `NewareNDA.read(...)`, while `read_header_metadata` has a cheap
`.ndax` XML path plus a NewareNDA fallback. The metadata function ultimately returns normalized
fields plus one complete flattened raw metadata map under:

```python
result["raw"]
```

It already calls:

```python
protocol.reconstruct_protocol(flat, nominal_capacity_mah)
```

to derive operational charge/discharge cutoffs.

### `cache.py`

Current cache identity is:

```text
(file hash, parser version, calc version)
```

with files conceptually:

```text
raw__p<PARSER_VERSION>.parquet
cycles__p<PARSER_VERSION>__c<CALC_VERSION>.parquet
```

Important functions:

- `schedule_build`;
- `build`;
- `build_write_behind`;
- `raw_path`;
- `cycles_path`;
- `load_raw` / `load_raw_columns`;
- `load_cycles`.

`build` currently reuses an existing raw parser-version cache across calculation-version bumps and
runs:

```python
raw = parsing.parse_timeseries(source_path)
cycles = calc.per_cycle(raw)
```

The Excel path must fit that sequence.

### `protocol.py`

Current protocol reconstruction expects the flattened Neware-like key grammar:

```text
Step.Step_Info.StepN.Step_Type
Step.Step_Info.StepN.Limit.Main.*
Step.Step_Info.StepN.Record.Main.*
Step.Step_Info.StepN.Protect.Main.*
Step.Step_Info.StepN.Limit.Other.*
```

`STEP_TYPES` currently maps numeric type IDs including CC charge/discharge, CV charge, Rest, Cycle,
End, CCCV charge/discharge and other Neware step types.

`_step_conditions` preserves explicit Neware condition expressions and global-user assignments
rather than interpreting undocumented comparator IDs.

The Excel implementation should feed this existing structural model instead of creating a second
protocol result schema.

## Locked integration strategy

### 1. `neware_excel.py` remains the source-format owner

Extend the 039.1 module to own:

- workbook metadata-sheet parsing;
- programmed step-plan extraction;
- Neware-like metadata construction;
- Excel-specific summary validation.

`parsing.py` owns only:

- extension dispatch;
- shared flattening/normalized metadata extraction;
- global parser-bundle version.

`cache.py` owns cache lifecycle, not workbook semantics.

### 2. Build a Neware-like metadata tree

Do **not** add an Excel-only protocol response schema.

`neware_excel.read_metadata(path)` should return a nested dictionary whose important branch is
compatible with existing `_flatten(...)` and `protocol.reconstruct_protocol(...)`, conceptually:

```python
{
    "Step": {
        "Head_Info": {...},
        "Step_Info": {
            "Step1": {...},
            "Step2": {...},
            ...
        },
    },
    "Excel": {
        "SourceFormat": {"Value": "neware_excel"},
        "ParserRevision": {"Value": "1"},
        "Capabilities": {...},
        "Original": {...},
    },
}
```

Exact preservation keys under `Excel.Original` may be refined during implementation, but the
existing `Step.*` compatibility keys and capability meanings are locked.

### 3. Do not fabricate absent Neware semantics

Only emit protocol fields that are directly represented by the workbook.

In particular, if no condition expression/global-user assignment appears in the verified export:

```text
Excel.Capabilities.ProtocolConditions.Value = false
```

Do not synthesize `Limit.Other.Cnd*` expressions from current/capacity/cutoff values.

## Metadata-sheet parsing

The supplied workbook's `test` sheet has a metadata/information block above the `Step plan` marker.
The observed layout uses three label/value groups across columns approximately:

```text

D/F
G/I
```

Do not hard-code row numbers alone. Locate the `Step plan` marker and parse the information rows
above it using verified label/value positions.

### Normalize and extract verified metadata

When present, extract these source facts:

| Workbook label | Normalized CellXplorer meaning |
|---|---|
| `Start step ID` | `start_step_id` |
| `Volt. upper` | protection upper voltage |
| `Volt. lower` | protection lower voltage |
| `Builder` | builder/creator |
| `Remarks` | remarks |
| `Start time` | start time |
| `Barcode` | barcode |
| `Active material` | active mass in mg |
| `Nominal capacity` | nominal capacity in mAh |
| `Record settings` | record interval and optional V/I deltas |
| `P/N` | part number/raw source metadata |
| `Cycle count` | preserved raw source metadata |
| `Voltage range` | preserved raw source metadata |
| `Current range` | preserved raw source metadata |

Parse units explicitly.

Examples from the verified layout:

```text
19.21mg         → 19.21 mg
3.3mAh          → 3.3 mAh
3.85V           → 3.85 V
60s/0.01V/0mA   → 60 s, 0.01 V, 0 mA
```

Do not use an unqualified first-number regex for required normalized fields when the expected unit is
known. Reject contradictory units rather than silently converting an unrelated quantity.

### Optional `unit` sheet

Preserve useful source/unit values under `Excel.Original.Unit...` when present, but do not invent
`device_info`, `channel`, hardware IDs or binary `nda_version` from unlabeled numeric tuples whose
meaning has not been verified.

If a verified label clearly identifies a device/channel value, map it through the existing normalized
fields and add a test.

### Source-format metadata

Expose a bounded normalized indication that this source is a Neware Excel export. Preferred
normalized field:

```text
source_format = "Neware Excel"
```

Do not put arbitrary workbook contents in the preview-level normalized map.

## Parser-bundle version

### Why a bundle is required

Existing caches and analysis provenance use one `PARSER_VERSION`, not one version per source format.
A mixed analysis may include `.nda`, `.ndax` and `.xlsx` sources.

Do not refactor provenance in this feature.

### Locked version rule

Define separate components, for example:

```python
NEWARE_NDA_VERSION = NewareNDA.version.__version__
EXCEL_PARSER_REVISION = neware_excel.EXCEL_PARSER_REVISION
PARSER_VERSION = f"{NEWARE_NDA_VERSION}-cxp{EXCEL_PARSER_REVISION}"
```

The exact delimiter/prefix may change if required for safety/length, but:

- it must be deterministic;
- it must incorporate binary parser version;
- it must incorporate Excel parser revision;
- it must fit the existing `SourceFile.parser_version` column (verify current max length and test
  it; at the authoring baseline this is expected to be 30 characters);
- increment Excel revision whenever canonical Excel raw or normalized metadata/protocol meaning
  changes;
- do **not** bump Excel revision for comments/tests only;
- do **not** bump `CALC_VERSION`.

### Existing binary scientific output

The bundle-version change intentionally gives current binary sources a new cache filename/provenance
identity even though their numerical parser output is unchanged. This is acceptable because current
analysis provenance has one global parser version.

Do not modify NewareNDA raw mapping just to avoid that cache consequence.

Old parser-version caches should remain available for reproducibility; do not bulk-delete them.

## Cache integration

`cache.build` and `cache.build_write_behind` must remain the only normal owners of raw/cycle Parquet
creation.

### Required sequence

For any supported source:

```python
raw = parsing.parse_timeseries(source_path)
cycles = calc.per_cycle(raw)
parsing.validate_parsed_output(source_path, raw, cycles)
```

then publish caches atomically through existing paths.

Add a small parser-owned validation hook such as:

```python
def validate_parsed_output(path, raw, cycles) -> None:
    suffix = Path(path).suffix.lower()
    if suffix == ".xlsx":
        neware_excel.validate_cycles(path, raw, cycles)
```

Binary sources should be a no-op unless they already have an independent validation path.

Call the hook in both:

- `cache.build` after `calc.per_cycle`;
- `cache.build_write_behind` after `calc.per_cycle` and before return/background publication.

If there is another current path that derives a current cycle cache from an existing raw cache
without original source access, do **not** force an Excel workbook reopen there. Validation is a
source-parse/build guard, not a permanent requirement every time a cycle cache is derived.

## Cycle-summary validation

The supplied `cycle` sheet contains:

```text
Cycle Index
Chg. Cap.(mAh)
DChg. Cap.(mAh)
Chg.-DChg. Eff(%)
Chg. Energy(Wh)
DChg. Energy(Wh)
Chg. Time(min)
DChg. Time(min)
```

When present, compare CellXplorer's `calc.per_cycle(raw)` output against this independent summary.

### Identity

Require:

- same cycle count;
- same cycle indices/order after explicit sort;
- no duplicate summary cycle IDs.

### Capacity tolerance

Use:

```text
max(0.002 mAh, 0.1% × |summary value|)
```

The supplied workbook is substantially tighter than this and should be recorded separately.

### Energy tolerance

Convert workbook Wh to mWh and use:

```text
max(0.01 mWh, 0.1% × |summary value|)
```

### Time tolerance

Convert workbook minutes to seconds and use:

```text
max(2 seconds, declared record_interval_s)
```

If the record interval is unavailable, use 2 seconds.

### Coulombic-efficiency cross-check

Efficiency is secondary because it is derived from capacities. Compare when both charge/discharge
values exist, with absolute tolerance:

```text
0.05 percentage points
```

Do not use workbook efficiency as the canonical output.

### Validation failure

A large discrepancy is fatal for a full cache build because it indicates a likely unit/mapping or
execution-boundary defect.

Use concise messages identifying cycle and quantity, not entire rows.

### Missing cycle sheet

If absent:

- skip this independent validation;
- set capability false;
- do not replace it with guessed validation.
