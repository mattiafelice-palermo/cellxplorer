## Goal

Extend the canonical raw-data/cache/API/Time-Capacity path so one source can carry synchronized electrode-potential channels in addition to the existing primary `voltage_v`, while preserving ordinary two-electrode behavior exactly.

This child establishes the reusable three-electrode-capable data path **without adding BioLogic `.mpr` support yet**.

At completion:

- the canonical raw table may include `working_potential_v` and `counter_potential_v`;
- source metadata/capabilities can describe which voltage roles are available and what `voltage_v` means;
- Parquet cache, selective raw loading, source stitching and Time/Capacity APIs preserve those optional channels;
- Time/Capacity users can select the primary voltage or available electrode potentials as the plotted/exported Y quantity;
- existing `voltage_v` remains the default everywhere;
- Cycles, DCIR, Chargeability and Rate Capability do **not** silently switch to auxiliary electrode channels;
- two-electrode Neware sources do not gain confusing empty UI controls.

## Locked canonical names

Use exactly these canonical raw column names:

```text
voltage_v
working_potential_v
counter_potential_v
```

`voltage_v` remains required for normal cycling-capable sources and remains the default voltage quantity.

Do not introduce vendor names such as `Ewe`/`Ece` into downstream canonical APIs.

## Voltage-role semantics

### Two-electrode source

```text
voltage_v = measured primary/cell voltage
working_potential_v = absent
counter_potential_v = absent
```

### Three-electrode full-cell source

```text
voltage_v = full-cell voltage between working and counter electrodes
working_potential_v = working electrode potential vs reference
counter_potential_v = counter electrode potential vs reference
```

When the adapter derives `voltage_v = working - counter`, that derivation belongs to the **source adapter** and must be recorded in metadata/capabilities. This child only preserves/exposes already-canonical channels.

### Half-cell / single-reference-potential future case

Parent 040 does not force a source with only one electrode potential versus reference to fabricate both auxiliary channels. The adapter may still set `voltage_v` to its primary measured potential with a metadata role such as `working_vs_reference` if that source is scientifically supported.

The UI must label based on capability/role metadata, not infer electrode meaning from the mere presence of a column.

## Metadata/capability contract

Extend/reuse the bounded source capability representation established by 039/040.1.

At minimum the normalized header result must be able to express:

```text
primary voltage available
working potential available
counter potential available
role of voltage_v
reference electrode text when explicitly provided by source
whether voltage_v was measured directly or derived from electrode potentials
```

Conceptual representation only:

```json
{
  "capabilities": {
    "primary_voltage": true,
    "working_potential": true,
    "counter_potential": true
  },
  "voltage_roles": {
    "voltage_v": "cell",
    "working_potential_v": "working_vs_reference",
    "counter_potential_v": "counter_vs_reference"
  },
  "reference_electrode": "Li/Li+"
}
```

Requirements:

- preserve full source header once in `SourceFile.header_meta`;
- keep user-facing metadata bounded;
- do not create one DB row per signal or record;
- do not invent reference-electrode text when absent.

## Synthetic source strategy for 040

There is no BioLogic parser in this parent, so test the multi-voltage path with deterministic synthetic canonical frames and/or a generated parser test double at the source-adapter boundary.

A representative three-electrode frame should satisfy:

```text
working_potential_v = known values
counter_potential_v = known values
voltage_v = working - counter
```

This proves the application path without importing GPL-derived code or committing private BioLogic data.

## Cache behavior

Flat raw Parquet naturally supports optional additional columns. Preserve that design.

Required checks:

- `cache.build`/write-behind preserves the columns returned by a canonical parser;
- `load_raw` returns them;
- `load_raw_columns` can request them selectively;
- cache identity does not change merely because an optional column is absent from a source; parser identity already captures adapter semantics;
- no separate voltage-cache file is introduced.

No `CALC_VERSION` bump is required because existing derived formulas continue using `voltage_v`.

## Stitch behavior

`stitch_raw` must preserve optional voltage columns across source concatenation.

Pandas concatenation may yield NaN where one source has an auxiliary channel and another does not. That is acceptable at the raw frame level, but the API/UI must treat availability carefully:

- a plotted series for a Cell should only be offered when the relevant source/selection has meaningful data under current Time/Capacity selection rules;
- do not draw long zero-filled traces for missing sources;
- source-boundary/provenance remains unchanged.

Do not alter `stitch_cycles`: cycle summaries remain based on primary `voltage_v` unless a future scientific feature explicitly defines electrode-specific cycle statistics.

## Time/Capacity backend API

### Quantity selection

Reverify the current Time/Capacity request/response contract. Extend the existing Y-quantity model rather than add a separate endpoint.

Preferred stable internal quantity IDs:

```text
voltage              -> voltage_v
working_potential    -> working_potential_v
counter_potential    -> counter_potential_v
```

Exact existing naming conventions should be followed.

### Availability

The backend should provide enough capability/quantity metadata for the frontend to know which voltage quantities are available for the selected analysis samples.

For multi-sample analyses, use a conservative rule consistent with current family semantics:

- if a requested channel is missing for a sample, do not fabricate it;
- either omit that sample's trace for that quantity with a clear existing empty/unavailable treatment, or mark the quantity unavailable for mixed selections if the current UI requires common quantities;
- choose one rule based on the actual current Time/Capacity architecture and lock it in the implementation record/tests.

Do not silently fall back from `working_potential` to `voltage`.

### Downsampling/export

Display downsampling remains presentation-only. CSV/XLSX/other scientific data export must use the full selected canonical channel values under the current export contract.

### Derivatives

Current derivative views such as `dQ/dV` or `dV/dQ` have scientific meaning tied to the selected voltage axis.

For this child:

- if the implementation already computes derivatives generically from the selected Y voltage, allow auxiliary potentials only when the existing formula naturally follows the selected channel and tests can prove it;
- otherwise keep derivatives restricted to primary `voltage_v` and explicitly disable/hide them for auxiliary electrode potentials.

Do **not** guess. Inspect the current backend/frontend ownership and choose the smallest scientifically safe behavior. Record the decision in the child implementation record and durable docs.

## Frontend Time/Capacity UI

Expose voltage channels in the existing quantity selector/settings control.

Recommended labels:

```text
Cell voltage (V)            # when voltage_v role = cell
Working potential vs ref (V)
Counter potential vs ref (V)
```

If the role of `voltage_v` is not `cell`, use the truthful role-specific label supplied by capability metadata rather than hard-coded “Cell voltage.”

For ordinary current Neware two-electrode sources, the selector should look/behave as before except for any unavoidable internal refactor. Do not show disabled WE/CE entries merely to advertise a feature unavailable for that source.

### Reference-electrode context

If the source explicitly provides a reference electrode, a compact label/tooltip may append it, e.g.:

```text
Working potential vs Li/Li+ (V)
```

Do not make the selector excessively wide. Follow compact Mantine geometry and truncation/tooltip patterns from the visual style guide.

## Saved plots and persistence

Time/Capacity saved plots must persist the selected voltage quantity using the same family settings mechanism as existing quantities.

Requirements:

- old saved plots lacking the new setting still resolve to current default `voltage_v` behavior;
- opening/updating/copying a saved plot retains the selected channel;
- thumbnails, hover previews and full artifacts render the selected channel;
- artifact/query keys include the quantity setting if they do not already;
- no hidden fallback causes an old artifact for primary voltage to be shown for a newly selected electrode potential.

If a new setting changes the saved plot spec shape, use current normalization/defaulting rather than a relational migration.

## Portable reports

Portable Time/Capacity figures must preserve the selected voltage channel and axis label through the existing serialized Plotly/frozen SVG path.

Do not redesign portable security or source embedding.

## Other analysis families

### Cycles

Remain primary-voltage only. Existing mean/first/last voltage cycle metrics continue to derive from `voltage_v`.

### DCIR

Remain primary-voltage only. Do not compute electrode-specific DCIR in Parent 040.

### Chargeability

Remain primary-voltage only.

### Rate Capability

Remain primary-voltage/cutoff behavior only.

### Steps

If the current generic Steps quantity selector automatically exposes arbitrary raw voltage columns, do not expand it accidentally. Parent 040's user-visible alternate-potential support is deliberately scoped to Time/Capacity. A future spec may add electrode-specific Steps views.
