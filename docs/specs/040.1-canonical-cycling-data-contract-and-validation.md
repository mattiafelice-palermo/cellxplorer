## Current behavior to reverify

At the locked merge base, `backend/app/services/parsing.py` maps binary Neware output through `RAW_COLUMNS` and dispatches structured `.xlsx` to `backend/app/services/neware_excel.py`. The Excel parser is now revision `6` and emits the same core meanings plus `total_time_s` and `power_w` where available. Its normalized status aliases include `Rest`, `CC_Chg`, `CC_DChg`, `CV_Chg`, `CCCV_Chg`, and `CCCV_DChg`; reverify this list against the current module rather than trusting it, because the post-039 dialect work extended workbook variant handling.

That dialect work also introduced a unitless "record clock" variant. Its step-summary duration is reconciled against the record's step-relative elapsed column instead of the timestamp span, which can include a paused/restored gap. This does **not** redefine `time_s`, which remains step-relative in both dialects, but the documentation this child writes must describe both variants truthfully. Read `docs/neware-excel-variant-findings.md` alongside the parser module.

Important current downstream assumptions include:

- `calc.per_cycle` requires `cycle` and uses canonical capacity/energy fields when present;
- current phase classification recognizes Neware-like charge/discharge status strings;
- per-cycle charge/discharge totals are derived from per-executed-step counter deltas because Neware counters may reset at step boundaries;
- step duration calculation assumes `time_s` is step-relative;
- Steps analysis distinguishes programmed `step_index` from executed `step`;
- stitching expects cycle labels to be numeric/integer-like and preserves source order;
- raw Parquet caches are flat `pandas.DataFrame` tables.

Do not change those meanings in this child.

## Canonical field contract

Document and test the parent meanings exactly.

### `record_index`

Requirements:

- numeric/integer-like after normalization;
- no missing values for normal supported cycling sources;
- unique within one source;
- stable acquisition order;
- validation may sort-check but must **not silently reorder parser output** unless the parser explicitly owns that normalization.

### `cycle`

Requirements:

- numeric/integer-like;
- finite when present;
- logical source-local cycle label;
- gaps are allowed because `stitch.observed_local_cycles` already maps observed labels densely across source boundaries;
- validation must not invent missing cycles.

### `step_index`

Meaning:

```text
programmed protocol step identity
```

Repeated loop executions reuse the programmed step number.

### `step`

Meaning:

```text
unique executed step occurrence within the source
```

Requirements:

- numeric/integer-like when present;
- rows from one concrete execution block share the same `step`;
- a repeated execution of the same `step_index` uses a different `step`;
- do not derive `step` in the canonical validator; source adapters own execution-boundary reconstruction.

### `status`

Meaning:

```text
CellXplorer semantic operation/status
```

The canonical layer adopts existing Neware-like meanings rather than vendor-native arbitrary labels.

At minimum document the semantics already used by production calculations, such as:

```text
Rest
CC_Chg
CC_DChg
CV_Chg
CV_DChg
CCCV_Chg
CCCV_DChg
```

Only include values verified to exist/mean something in the current code. If the current implementation has additional established values, document them rather than silently dropping them.

Unknown/unsupported vendor operations may be preserved as a clearly non-recognized canonical status or fail format-specific capability validation; do not teach downstream scientific code arbitrary vendor strings in this child.

### `time_s`

Locked meaning:

```text
seconds elapsed since current executed step began
```

Requirements:

- numeric;
- finite where available;
- may reset when `step` changes;
- must not be redefined as whole-source elapsed time;
- validation should allow small source rounding effects but reject structurally impossible values such as clearly negative elapsed time when the parser claims normal cycling capability.

### `total_time_s`

Standard optional meaning:

```text
seconds elapsed since source acquisition began
```

When present it should be numeric and non-decreasing within normal acquisition order, allowing only tiny floating-point tolerance. It is auxiliary; current scientific code must continue to use `time_s` where it expects step-relative time.

### `voltage_v`

Locked meaning:

```text
primary voltage for ordinary existing CellXplorer analyses
```

040.1 does not add three-electrode fields yet. It only records their reserved names in the standard optional contract so later children do not invent incompatible names.

Reserved:

```text
working_potential_v
counter_potential_v
```

### `current_ma`

Document the current sign convention by measuring/asserting the existing Neware parser behavior in focused tests. Do **not** assume the sign from memory.

The implementation record must state the observed convention in plain language, e.g. whether canonical positive current corresponds to charge or discharge.

Once observed, add that convention to `docs/agent-knowledge/canonical-cycling-data.md` and lock it for future adapters.

### Capacity and energy

Canonical fields:

```text
charge_capacity_mah
discharge_capacity_mah
charge_energy_mwh
discharge_energy_mwh
```

The contract deliberately allows counters that reset at executed-step boundaries because current `calc.per_cycle` handles them by summing per-step deltas.

Validation must therefore check data type/finiteness/obvious negative-invalid states but must not require monotonicity across a whole cycle.

### `timestamp`

When present:

- normalize to pandas datetime-compatible values;
- absolute timestamps may be unavailable for some future formats;
- absence or NaT is a capability issue, not a reason to fabricate a date;
- do not infer a calendar date from file modified time.

## Validation boundary

The validator is a scientific safety check, not a data-cleaning engine.

It may:

- assert required column presence;
- coerce/check obvious numeric compatibility only where parsers already promise canonical values;
- reject non-finite/duplicate identifiers that make downstream calculations ambiguous;
- verify `step`/`step_index` structural consistency at a basic level;
- verify `total_time_s` monotonicity when present;
- verify reserved optional voltage columns have the same row count/index alignment by virtue of being DataFrame columns.

It must not:

- reconstruct cycles;
- reconstruct executed steps;
- infer charge/discharge from current;
- integrate capacity/energy;
- patch missing timestamps;
- rename vendor columns;
- change scientific values;
- perform file I/O.

Those are adapter responsibilities.

## Where validation runs

Preferred behavior after this child:

## Tests

Add focused tests to a new or existing canonical contract test module, e.g.:

```text
tests/test_canonical_cycling.py
```

Required cases:

1. minimal valid canonical cycling frame passes;
2. duplicate `record_index` fails;
3. non-integer/ambiguous `cycle` fails;
4. repeated `step_index` across distinct executed `step` values is accepted;
5. one executed `step` inconsistently maps to multiple programmed `step_index` values fails if that state is scientifically impossible under the current model;
6. `time_s` reset at an executed-step boundary is accepted;
7. decreasing `total_time_s` fails beyond tolerance;
8. missing optional energy/timestamp/auxiliary voltage columns remains valid when capability rules allow it;
9. malformed/non-numeric capacity/current/voltage values fail clearly;
10. current real/synthetic Neware binary parser output satisfies validation;
11. Parent 039 generated Excel parser output satisfies validation;
12. existing `calc.per_cycle` numerical output before/after validator insertion is identical for representative fixtures.

Use existing privacy-approved fixtures or generated sources. Do not commit new private source files.
