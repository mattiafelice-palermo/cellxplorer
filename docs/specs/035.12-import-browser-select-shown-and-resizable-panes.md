## Goal

Make the header checkbox and **Select shown** operate on all currently visible selectable entries,
including folders, and make the quick-access and file-browser panes horizontally resizable without
crowding the quick-access scrollbar against row content.

## Files and current anchors

Work primarily in:

- `frontend/src/importBrowserSelection.ts`
- `frontend/tests/importBrowserSelection.test.ts`

Do not modify `InboxPage.tsx`, backend endpoints, request shapes, import semantics, or continuation
behavior.

In `ImportFilesystemPickerModal.tsx`, verify these current anchors before editing:

- `visibleFiles`

- `someVisibleSelected`

- the header checkbox with `aria-label="Select all visible importable files"`

## 1. Select all currently shown entries

### Current

The header checkbox and **Select shown** button operate only on `visibleFiles`. They are therefore
disabled when a directory contains only subfolders, even though those folders can be selected
individually through their recursive-selection checkboxes.

### Target

Both controls select or clear every currently shown selectable entry:

- visible files;
- visible folders whose recursive-selection checkbox is enabled.

Use the existing folder-selection representation and `toggleImportFolderSelection`. Do not inspect
or enumerate folder descendants in the frontend.

The shared aggregate state is:

- **checked:** every shown selectable file and folder is selected;
- **indeterminate:** at least one, but not all, shown selectable entries are selected;
- **disabled:** there are no shown selectable files or selectable folders.

Search filtering defines “shown.”

**Clear shown** removes only entries currently shown by the active search. Selections hidden by the
search filter or made in another directory remain selected.

Folder-row clicks continue to navigate. Only the header checkbox, **Select shown / Clear shown**,
and individual row checkboxes change selection.

## 2. Resizable quick-access and file-browser panes

### Current

The quick-access pane has a fixed width of 235 px. Its scrollbar is visually too close to labels and
pin controls, and the user cannot allocate more width to long folder names.

### Target layout

Add a vertical drag divider between the quick-access pane and the right file-browser pane.

Implement in `ImportFilesystemPickerModal.tsx`:

1. Add `leftPaneWidth` state with an initial value of **235 px**.
2. Replace the left pane's fixed `w={235}` with:
   - `width: leftPaneWidth`;
   - `minWidth: 200`;
   - `flexShrink: 0`.
3. Keep the right pane flexible with:
   - `flex: 1`;
   - `minWidth: 560`;
   - `minWidth: 0` or `overflow: hidden` on the required inner wrappers so content does not force
     the modal wider.
4. Insert one dedicated resize divider between the panes.
5. Clamp resizing so:
   - the left pane is never narrower than **200 px**;
   - the left pane is never wider than **400 px**;
   - the right pane is never narrower than **560 px**.
6. Keep width state session-only. Do not add database state, API state, or `localStorage`.

Reuse an existing repository pointer-resize pattern found by searching for `col-resize` in
`ProjectsPage.tsx` or `AnalysisDatabaseTable.tsx`. Do not add a resize dependency.

### Divider interaction and appearance

- Pointer hit area: **10–12 px** wide.
- Visual grip: three narrow vertical lines centred inside the hit area, matching the existing
  CellXplorer resize-handle treatment used around analysis layouts.
- Cursor: `col-resize`.
- Neutral theme-safe colour normally.
- Current primary colour on hover, focus, and while dragging.
- Do not create a large visible gap between panes.
- Prevent text selection while dragging.
- End resizing on pointer release or cancellation, including when the pointer leaves the divider.

The divider must have:

```text
role="separator"
aria-orientation="vertical"
aria-label="Resize quick-access panel"
tabIndex={0}
```

Keyboard behavior:

- `ArrowLeft`: reduce the left pane width by 16 px.
- `ArrowRight`: increase the left pane width by 16 px.
- Apply the same limits used by pointer dragging.
- Show a visible focus state.

### Scrollbar clearance

Add internal right-side clearance inside the quick-access `ScrollArea` so labels and pin controls do
not touch the scrollbar:

- preserve the current 590 px scroll height;
- keep the scrollbar inside the bordered pane;
- leave at least **8 px** between row content and the scrollbar;
- do not create the clearance with margin outside the pane;
- preserve the current compact row geometry.

Prefer component-local Mantine styles or an inner wrapper with right padding. Do not add global CSS
unless the reused repository resize pattern requires it.

## Acceptance criteria

- In a directory containing only folders, the header checkbox and **Select shown** are enabled when
  at least one shown folder is selectable.
- Activating either control recursively selects every displayed selectable folder.
- Aggregate checked and indeterminate states match all currently shown selectable entries.
- Clearing shown entries does not clear hidden selections.
- The quick-access pane can be resized between 200 px and 400 px while preserving a usable right
  pane of at least 560 px.
- The divider supports pointer and keyboard operation with accessible separator semantics.
- Quick-access content has visible clearance from its vertical scrollbar.
- No backend, request-shape, import, continuation, or scientific behavior changes.
