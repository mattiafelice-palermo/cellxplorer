## Goal

Make selection scope explicit in both affected workflows:

- the import-browser header checkbox and **Select shown** include all currently visible selectable
  entries, including folders;
- the Cell Database keeps safe page-scoped header selection but offers an explicit second action to
  select the complete current search/filter result set;
- the import-browser quick-access and file-browser panes are horizontally resizable without
  crowding the quick-access scrollbar against row content.

## 1. Import browser: select all currently shown entries

### Current

The header checkbox and **Select shown** button operate only on `visibleFiles`. They are therefore
disabled when a directory contains only subfolders, even though those folders can be selected
individually through their recursive-selection checkboxes.

### Target

Both controls select or clear every currently shown selectable entry:

- visible files;
- visible folders whose recursive-selection checkbox is enabled.

Use the existing folder-selection representation and `toggleImportFolderSelection`. Do not inspect
or enumerate folder descendants in the frontend.

The shared aggregate state is:

- **checked:** every shown selectable file and folder is selected;
- **indeterminate:** at least one, but not all, shown selectable entries are selected;
- **disabled:** there are no shown selectable files or selectable folders.

Search filtering defines “shown.”

**Clear shown** removes only entries currently shown by the active search. Selections hidden by the
search filter or made in another directory remain selected.

Folder-row clicks continue to navigate. Only the header checkbox, **Select shown / Clear shown**,
and individual row checkboxes change selection.

## 2. Import browser: resizable quick-access and file-browser panes

### Current

The quick-access pane has a fixed width of 235 px. Its scrollbar is visually too close to labels and
pin controls, and the user cannot allocate more width to long folder names.

### Target layout

Add a vertical drag divider between the quick-access pane and the right file-browser pane.

Implement in `ImportFilesystemPickerModal.tsx`:

1. Add `leftPaneWidth` state with an initial value of **235 px**.
2. Replace the left pane's fixed `w={235}` with:
   - `width: leftPaneWidth`;
   - `minWidth: 200`;
   - `flexShrink: 0`.
3. Keep the right pane flexible with:
   - `flex: 1`;
   - `minWidth: 560`;
   - `minWidth: 0` or `overflow: hidden` on the required inner wrappers so content does not force
     the modal wider.
4. Insert one dedicated resize divider between the panes.
5. Clamp resizing so:
   - the left pane is never narrower than **200 px**;
   - the left pane is never wider than **400 px**;
   - the right pane is never narrower than **560 px**.
6. Keep width state session-only. Do not add database state, API state, or `localStorage`.

Reuse an existing repository pointer-resize pattern found by searching for `col-resize` in
`ProjectsPage.tsx` or `AnalysisDatabaseTable.tsx`. Do not add a resize dependency.

### Divider interaction and appearance

- Pointer hit area: **10–12 px** wide.
- Visual grip: three narrow vertical lines centred inside the hit area, matching the existing
  CellXplorer resize-handle treatment used around analysis layouts.
- Cursor: `col-resize`.
- Neutral theme-safe colour normally.
- Current primary colour on hover, focus, and while dragging.
- Do not create a large visible gap between panes.
- Prevent text selection while dragging.
- End resizing on pointer release or cancellation, including when the pointer leaves the divider.

The divider must have:

```text
role="separator"
aria-orientation="vertical"
aria-label="Resize quick-access panel"
tabIndex={0}
```

Keyboard behavior:

- `ArrowLeft`: reduce the left pane width by 16 px.
- `ArrowRight`: increase the left pane width by 16 px.
- Apply the same limits used by pointer dragging.
- Show a visible focus state.

### Scrollbar clearance

Add internal right-side clearance inside the quick-access `ScrollArea` so labels and pin controls do
not touch the scrollbar:

- preserve the current 590 px scroll height;
- keep the scrollbar inside the bordered pane;
- leave at least **8 px** between row content and the scrollbar;
- do not create the clearance with margin outside the pane;
- preserve the current compact row geometry.

Prefer component-local Mantine styles or an inner wrapper with right padding. Do not add global CSS
unless the reused repository resize pattern requires it.

## 3. Cell Database: explain page-scoped selection and offer all matching cells

### Current

The Cell Database header checkbox is correctly labelled **Select cells on this page** and adds only
`pageCells` to `selectedCellIds`. This is safe, but after the user selects every row on the current
page there is no visible explanation that additional matching cells exist on other pages.

### Locked behavior

Keep the header checkbox page-scoped. Do **not** silently change it to select the whole database,
because that could unexpectedly apply destructive or expensive bulk actions to cells the user has
not seen.

When every cell on the current page is selected, more cells exist in the current search/filter
result set, and not every matching cell is already selected, show one compact scope prompt.

Use these state definitions:

```text
allPageSelected = pageCells is non-empty and every pageCells id is selected
allMatchingSelected = filteredSortedRows is non-empty and every filtered row id is selected
showSelectAllMatchingPrompt =
  allPageSelected
  AND filteredResultCount > pageCells.length
  AND NOT allMatchingSelected
```

The prompt appears based on selection state, regardless of whether the page became fully selected
through the header checkbox, individual row clicks, Shift selection, or keyboard selection.

### Prompt placement and visual design

Render the prompt immediately:

1. after the bordered table `Paper` closes;
2. before the existing lower row containing `Showing ... of ...`, **Per page**, and pagination.

It spans the available table width and must not overlay the table, sticky toolbar, or pagination.
Use a compact Mantine `Alert color="orange" variant="light"` or equivalent bordered `Paper` with:

- a visible 1 px semantic orange border in light and dark mode;
- `radius="md"`;
- compact `xs`/`sm` padding and text;
- an information icon or equivalent non-colour cue;
- no modal, toast, animation, or layout jump inside the table.

Text:

- first sentence: `All X cells on this page are selected.`
- when any search or column filter is active, action label:
  `Select all Y matching cells`
- when no search or column filter is active, action label:
  `Select all Y cells`

Where:

- `X = pageCells.length` for the current page, including a shorter final page;
- `Y = filteredResultCount`, never the unfiltered database count while filters/search are active.

Use one compact action button or button-like link inside the prompt. It must be keyboard accessible,
have a clear focus state, and use orange semantic styling without becoming the page's primary action.

### Select-all-matching action

Activating the prompt action must:

1. replace `selectedCellIds` with the ids from every row in `filteredSortedRows`;
2. select no cell excluded by the current search or column filters;
3. preserve the current sort, filters, search, page, and page size;
4. clear `lastSelectedCellId` so a later Shift selection cannot use a stale page anchor;
5. immediately update the existing selected-count badge and every existing bulk action through the
   normal `selectedCellIds` state;
6. hide the orange prompt because `allMatchingSelected` is now true.

Do not add a backend request. The Cell Database already holds the current search result and applies
column filtering and pagination client-side.

Existing behavior remains unchanged when the user clears the header checkbox: only cells on the
current page are removed from the selection. If all matching cells were previously selected, this
therefore leaves cells on the other pages selected, which is consistent with the current page-scoped
checkbox contract.

### Scope changes

- If search or column filters change, retain the existing effect that prunes selected ids to the
  new `filteredSortedRows` set.
- If sorting or pagination changes without changing the filtered result set, preserve selections.
- Do not show the prompt when all matching rows fit on one page.
- Do not show the prompt when the current page is only partially selected.
- Do not show the prompt after all matching cells have been selected.

## Pure policy and tests

Keep selection-scope decisions out of ad-hoc JSX. Add the smallest useful pure helper module,
preferably `frontend/src/librarySelectionScope.ts`, owning:

- page-selected / matching-selected aggregate state;
- whether the all-matching prompt should show;
- the ids produced by the select-all-matching action.

Do not create a general selection framework or add DOM-testing infrastructure solely for this
child.

### Import-browser policy tests

Extend `frontend/tests/importBrowserSelection.test.ts` with coverage for:

1. selecting all in a folder-only view;
2. selecting all in a mixed file/folder view;
3. partial visible selection producing an indeterminate aggregate state;
4. selection under an active search filter;
5. clearing shown entries while preserving hidden selections;
6. excluding disabled empty folders from the aggregate calculation;
7. minimum and maximum width clamping, if width clamping is extracted into the policy module.

### Cell Database selection-scope tests

Add `frontend/tests/librarySelectionScope.test.ts` covering:

1. all current-page cells selected while additional matching rows exist → prompt shown;
2. partially selected current page → prompt hidden;
3. all matching rows already selected → prompt hidden;
4. one-page result set → prompt hidden;
5. shorter final page uses its actual page-row count;
6. select-all-matching returns all filtered ids and no filtered-out ids;
7. pre-existing selections on other matching pages do not prevent the prompt until every matching id
   is selected;
8. empty page/result state → prompt hidden.

## Acceptance criteria

### Import browser

- In a directory containing only folders, the header checkbox and **Select shown** are enabled when
  at least one shown folder is selectable.
- Activating either control recursively selects every displayed selectable folder.
- Aggregate checked and indeterminate states match all currently shown selectable entries.
- Clearing shown entries does not clear hidden selections.
- The quick-access pane can be resized between 200 px and 400 px while preserving a usable right
  pane of at least 560 px.
- The divider supports pointer and keyboard operation with accessible separator semantics.
- Quick-access content has visible clearance from its vertical scrollbar.

### Cell Database

- The header checkbox remains explicitly page-scoped.
- Fully selecting a page while additional matching cells exist shows the orange scope prompt in the
  required position.
- The action selects exactly the current search/filter result set and no filtered-out cells.
- Counts and wording distinguish the current page from all matching cells.
- The prompt disappears after all matching cells are selected.
- Existing selection pruning, pagination, sorting, range selection, and bulk-action behavior remain
  correct.

No backend, request-shape, import, continuation, database, or scientific behavior changes.
