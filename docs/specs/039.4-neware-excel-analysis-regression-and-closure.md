## Core rule: verify format neutrality

The strongest acceptance signal is that downstream scientific code **does not care** whether a raw
cache came from `.nda`, `.ndax` or `.xlsx`.

A correct final architecture looks like:

```text
.xlsx
  ↓
neware_excel + parsing dispatch
  ↓
canonical raw/protocol/cache
  ↓
existing analysis services
```

A wrong architecture looks like:

```text
if source.ext == "xlsx":
    use alternative cycle/step/dcir/rate/chargeability calculation
```

Search for and reject source-format branches inside scientific analysis modules unless a narrowly
justified provenance/display distinction is explicitly required by the parent.

## Steps regression

### Scientific path

One Steps point represents one executed occurrence of a selected programmed protocol-step block.

The test must prove the distinction locked by Parent 039:

```text
step_index → which programmed steps belong to the selected block
step       → which concrete execution occurrence rows belong together
```

### Required fixture

Include a loop where one programmed step executes twice in one cycle.

### Required checks

- `protocol.reconstruct_protocol` exposes the selected programmed step/group;
- segment target uses the correct protocol signature;
- selected `step_index` set finds both occurrences;
- block assignment separates the two executed `step` IDs;
- occurrence index increments twice;
- start/end cycle/step metadata are correct;
- duration/voltage/capacity quantities aggregate through existing `step_blocks.py`;
- occurrence/cycle/time X-axis choices remain valid;
- no Steps code branches on `xlsx`.

This is the definitive end-to-end proof that Steps support must **not** be removed for Excel.
