## Goal

Add a faithful Plotly-rendered legend preview below the existing scientific preview without allowing the legend to resize or distort that plot, then perform the cumulative integration/regression pass for Parent 046.

This child consumes selection/bulk behavior from 046.1 and ordering from 046.2; do not redesign them here.

## Current anchors after 046.1–046.2

`SeriesStyleModal.tsx` has the real family-specific `buildPreview` callback, fixed main Plotly geometry, effective rules/overrides, bulk legend membership, and persisted series order.

The main preview intentionally strips the legend:

```ts
showlegend: false
legend: undefined
```

That remains correct.

## A — Keep the scientific preview fixed

Do not put the legend back inside the main plot.

Its current width, height, margins, and axes remain stable regardless of:

- number of legend entries;
- long/renamed entries;
- legend orientation;
- show/hide membership;
- series ordering;
- switching Series / Rules / Palettes.

Preserve the object-identity performance lessons recorded in Spec 037: stable memoized Plotly layout/config/style objects matter.

## B — Add a separate `Legend preview`

The left side becomes conceptually:

```text
┌ Preview ──────────────────────┐
│ fixed scientific plot         │
├ Legend preview ───────────────┤
│ independent passive Plotly    │
└───────────────────────────────┘
```

Use normal CellXplorer bordered geometry. Do **not** build a hand-written HTML legend.

## C — Derive from the real Plotly preview traces

Build the detached legend from the same effective traces/layout produced by `buildPreview`.

A focused pure transformation helper is preferred, conceptually:

```ts
buildLegendPreview(preview)
```

Preserve each real user-facing legend trace's effective:

- `name`;
- `showlegend`;
- `legendgroup`;
- `legendrank` / ordering metadata;
- `line`;
- `marker`;
- mode.

Suppress scientific curve drawing while retaining genuine Plotly legend symbols. `visible: "legendonly"` or an equivalent supported transformation is preferred where appropriate.

## D — Helper traces must not leak into the legend

Audit the supported preview builders for shadows, bands, fills/confidence helpers, source-boundary helpers, and other internal traces.

Respect their existing `showlegend: false` / grouping semantics. The detached preview should represent the same entries as the real exported figure, not every internal Plotly trace.

Do not reconstruct entries only from `SeriesDescriptor` labels when the real trace builder already carries the correct legend semantics.

## E — Reflect all relevant appearance changes

The detached legend updates when any of these change:

- Legend name;
- colour;
- line style/dash/width where represented by Plotly;
- marker mode/symbol/open state;
- `show_in_legend`;
- series order from 046.2;
- palette Apply;
- applicable rules.

An effective `show_in_legend: false` entry must be absent.

## F — Preview eye remains independent

The middle-panel eye still means **hide/show in the modal's scientific preview only**. It must not remove the entry from the detached legend.

If the current preview-only hidden overlay removes a trace too early, construct the legend from an equivalent unhidden effective draft or otherwise separate the two preview paths. Do not change persisted `hidden` semantics.

## G — Respect stored series order

Consume the effective order established in 046.2:

```text
existing quantity-group order
→ user series order within that quantity
```

The detached legend and the real plot/export legend must agree.

## H — Detached legend geometry

Reuse semantic legend styling from the real layout where meaningful, e.g. orientation, font, grouping/order behavior, and item sizing.

Do not blindly reuse main-plot positioning (`x`, `y`, or margins designed around scientific axes). The detached surface owns safe local placement.

Keep the legend area bounded:

- a normal 5–10 series legend should be readable without excessive empty space;
- many entries must not expand the whole modal indefinitely;
- long names must not force modal-wide horizontal overflow;
- do not solve overflow by making text unreadably small.

The modal should remain inside its existing viewport cap; local scrolling is acceptable for the legend area.

## I — Passive interaction only

The detached legend is informative, not another editor.

Legend clicks/double-clicks must not unexpectedly:

- alter the real analysis plot;
- change `previewHidden`;
- change `show_in_legend`;
- change series selection.

Configure Plotly accordingly.

## J — Performance

Memoize transformed legend data, layout, config, and style objects.

Do not deep-clone the full analysis spec. The legend does not need full scientific x/y arrays; strip or replace large positional arrays where possible while preserving Plotly's authentic legend rendering.

If large arrays are intentionally stripped, pin that behavior with a focused pure test.

## K — Supported-family integration audit

Inspect each analysis family that **currently exposes Series appearance**. At minimum verify the existing Cycles, Time/Capacity, Steps, DCIR, Chargeability, and Rate capability integrations where they are currently supported.

For each supported family, confirm that canonical figure construction actually propagates:

- explicit fields exposed by 046.1;
- `show_in_legend`;
- ordering/legend rank from 046.2.

Do not claim a family is covered merely because the modal opens. Fix small missing presentation propagation through shared resolver/figure-builder paths, not family-specific modal hacks. Do not broaden Series appearance to an unrelated previously unsupported family.

## L — Live/saved/export consistency

Verify the same persisted overrides/order continue through the canonical figure builders used by:

- live plot;
- saved-plot restore;
- saved thumbnail/artifact;
- image export;
- portable figure.

The detached modal legend itself is transient and is neither persisted nor exported. Do not create an alternative export legend path.
