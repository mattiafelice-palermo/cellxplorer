# 035.9 — Create an Analysis from selected Cells

**Status:** Plan  
**Parent:** [035 — User experience and workflow optimization](035-user-experience-and-workflow-optimization.md)  
**Depends on:** 035.8 clean review.  
**Scope:** Cell Database toolbar action and shared Analysis-create UI.  
**Review document:** `reviews/035.9-create-analysis-from-selected-cells-review.md`

## Goal

Allow the user to select Cells in the Cell Database and immediately create a populated Analysis,
while preserving a clear way to create an empty Analysis.

## Existing implementation to reuse

### Cell Database

`frontend/src/pages/LibraryPage.tsx` already owns:

- `selectedCellIds`;
- selected-row count and toolbar;
- Cell order/filter/page state;
- query invalidation patterns;
- compact split/button geometry elsewhere in the app.

### Projects

`frontend/src/pages/ProjectsPage.tsx` already owns the intended interaction:

- `AnalysisCreateForm`;
- `openCreateAnalysis(entries)`;
- main `New analysis (N)` button;
- split-menu item for an empty Analysis;
- `POST /api/analyses` with `entries`;
- destination-folder selection and navigation after success.

### Backend

`backend/app/routers/analyses.py::create_analysis` already accepts:

```json
{
  "title": "Selected cells analysis",
  "folder_id": null,
  "entries": [
    {"kind": "cell", "ref_id": 12}
  ]
}
```

Do not add a new backend endpoint unless the current contract materially requires it.

## Required component extraction

Avoid copying the Projects form into Library. Extract a shared component, for example:

```text
frontend/src/components/AnalysisCreateModal.tsx
```

It owns:

- modal title/open/close behavior;
- Analysis title;
- optional folder destination;
- selected-entry summary;
- submit/cancel/loading/error behavior;
- request shape or a typed `onSubmit` callback;
- duplicate-title/server error display.

Both Projects and Library use the same visible contract after extraction. Preserve Projects
behavior exactly unless this spec explicitly changes it.

Do not broadly refactor either page.

## Library toolbar behavior

Add a compact split action matching the Projects control.

### With selected Cells

Main button:

```text
New analysis (3)
```

- opens the shared create modal;
- entries are the selected Cells only;
- entry order follows the current processed table order for visible selected rows, followed by any
  selected IDs retained outside the visible result in stable numeric order;
- duplicate IDs are removed;
- the modal summary states `3 selected Cells will be added`;
- changing current table filtering after the modal opens does not silently alter the captured entry
  list.

Dropdown item:

```text
Create empty analysis
```

- opens the same modal with no entries;
- does not clear the current Cell selection merely by opening it.

### With no selected Cells

- main `New analysis` opens an empty Analysis;
- keep the split-button geometry stable;
- the redundant dropdown item may remain or be disabled/omitted, but behavior must be obvious and
  keyboard accessible.

## Title and folder defaults

- Default title may be `Untitled analysis` or the current shared Projects default; use one shared
  policy.
- Cell Database is not folder-scoped, so default to no folder.
- Allow the user to select a destination folder through the shared form.
- Do not infer a folder merely because selected Cells share one or several folder references.
- Existing backend uniqueness rule per destination folder remains authoritative.

## Submission and success behavior

Request:

```json
{
  "title": "...",
  "folder_id": 7,
  "entries": [
    {"kind": "cell", "ref_id": 12},
    {"kind": "cell", "ref_id": 13}
  ]
}
```

On success:

- clear the captured/Library Cell selection;
- clear the range anchor;
- invalidate `['analyses']` and `['tree']`;
- navigate directly to `/analyses/{id}`;
- preserve standard Analysis workspace startup behavior;
- do not show a redundant success toaster if navigation is sufficient confirmation.

On error:

- keep the modal open;
- preserve title, folder, captured entries, and underlying Library selection;
- show the server message inline or through the established notification pattern;
- allow correction/retry.

## Loading, disabled, and accessibility behavior

- Selection itself does not disable creation.
- Disable submit only while submitting or when the title is invalid.
- Toolbar remains usable when the Cell list is empty so an empty Analysis can still be created.
- Split-button main/menu targets have distinct accessible names.
- Entry summary is readable without inspecting the table behind the modal.
- Long folder names truncate with tooltips.
- Keyboard operation matches the existing Projects action.

## State policy

Add a small pure helper only if needed:

```text
frontend/src/analysisCreationPolicy.ts
```

It should cover:

- deterministic selected-entry ordering;
- deduplication;
- populated versus empty action request;
- capture semantics when table/filter state changes.

Do not create a second Analysis-spec builder; the backend’s `default_spec` and existing endpoint
remain authoritative.

## Required tests

- no selection creates empty entries;
- selected Cell IDs create Cell entries only;
- deterministic visible-order plus hidden-ID fallback;
- duplicate IDs removed;
- captured entries do not change after filter/table changes;
- main versus dropdown action;
- successful response navigation target;
- selection cleared only on success;
- error preserves selection and form;
- Projects behavior remains equivalent after extraction;
- duplicate-title error remains visible/retryable.

## Acceptance criteria

- A populated Analysis can be created directly from Cell Database selection.
- Empty Analysis creation remains available even when Cells are selected.
- Projects and Library share one create form.
- No selected Cell is duplicated in the Analysis request.
- No Analysis scientific behavior changes.

- light/dark geometry.
