## Goal

Complete the BioLogic GCPL adapter's source metadata and declared-protocol semantics, including the three-electrode/full-cell voltage roles needed by GCPL6.

At completion, a supported BioLogic GCPL `.mpr` parsed directly through backend services must provide:

- normalized source/header metadata;
- acquisition start and channel/device/software facts when present;
- reference-electrode metadata when explicitly stored;
- a truthful CellXplorer declared protocol reconstructed from GCPL sequence settings;
- canonical voltage-role capabilities;
- `working_potential_v`, `counter_potential_v`, and correct primary `voltage_v` for supported three-electrode files;
- operational cutoffs/limits sufficient for existing analyses when the source actually provides them;
- explicit capability warnings for unsupported/absent protocol semantics.

This child still does not expose `.mpr` in the user import workflow; that belongs to 041.4.

## Source metadata ownership

The full decoded source metadata belongs once in:

```text
SourceFile.header_meta
```

through the existing normalized header path.

Curated Cell-level metadata remains bounded. Do not expand every GCPL setting/sequence field into `CellMetadata` rows.

## Settings module decoding strategy

Extend the independent format notebook and parser with the minimal verified `VMP Set` structures needed for:

- technique/GCPL-family identity;
- sequence count/order;
- per-sequence control/current/C-rate setting;
- current direction/sign setting where needed;
- voltage limit/cutoff;
- optional CV/hold/current cutoff behavior;
- rest duration;
- loop/goto/cycle repeat behavior;
- record interval/settings needed for scientific validation;
- active material/battery capacity/electrode area/reference text when present in independently verified header fields.

### Variable layout

If GCPL settings parameter blocks can appear at different offsets/software versions, do not hard-code a guessed list of offsets copied from another project.

Instead:

1. collect at least the supplied file and paired/other privacy-approved GCPL files;
2. identify the parameter-block structure independently from known settings exported by EC-Lab;
3. document the supported layout/version discriminator in `docs/biologic-mpr-format.md`;
4. fail clearly for an unrecognized settings layout.

The first supported contract may cover only the verified modern layout(s). Broad historical EC-Lab support is not required.

## Log module decoding

Independently decode only verified fields needed by CellXplorer, such as:

```text
channel number / channel serial if present
acquisition start timestamp
original filename
host/instrument address if useful
ec-lab software version

```

Do not parse every unknown log byte.

If absolute start timestamp is absent or unreliable:

```text

```

## Declared protocol target

Use CellXplorer's existing declared protocol schema. Do not add a separate BioLogic protocol API.

Parent 040/039 may still use a Neware-like internal protocol grammar before producing a normalized protocol response. Either:

- build that existing internal grammar truthfully from BioLogic GCPL sequence settings; or
- use a format-neutral canonical protocol builder if Parent 040 introduced one.

Follow the actual post-040 owner.

### Programmed sequence identity

Protocol step IDs must correspond deterministically to the `step_index` emitted by 041.2.

If 041.2 normalizes BioLogic `Ns` from 0-based to 1-based, protocol steps must use the same normalization.

### Step type mapping

Map independently verified GCPL sequence behavior to existing canonical protocol operation types, e.g.:

```text
CC charge/discharge
CV charge/discharge
CCCV charge/discharge
Rest
Cycle/loop control where represented
End
```

Do not map a voltage limit to CV merely because a limit exists; distinguish “CC until cutoff” from “CCCV with hold” using actual GCPL settings/control semantics.

### Limits/cutoffs

Map operational voltage/current/capacity/time limits only when explicit in the sequence settings.

Do not confuse:

```text
instrument protection/safety limits
```

with:

```text
programmed operational cutoff for a GCPL sequence
```

Current Rate Capability and other recognizers rely on this distinction.

### Loop/goto behavior

If GCPL sequence settings expose goto/repeat/cycle information, preserve it sufficiently for protocol structure and repeated step selection.

Do not invent Neware condition expressions/global-user variables.

## Protocol capability flags

## Three-electrode / GCPL6 voltage semantics

Official BioLogic documentation for GCPL6 establishes:

```text
Ewe   = working electrode vs reference
Ece   = counter electrode vs reference
Ecell = working-to-counter full-cell voltage
```

### Canonical mapping

For verified GCPL6/full-cell-control data:

```text
working_potential_v = decoded Ewe
counter_potential_v = decoded Ece
voltage_v            = decoded Ecell, if explicitly stored and verified
```

If the supported MPR does not contain a separate Ecell column but contains synchronized Ewe and Ece under a common reference:

```text
voltage_v = working_potential_v - counter_potential_v
```

### Sign verification

The supplied sample/paired `.mpt` must prove the subtraction order. Test several rows, not only one, and compare to EC-Lab full-cell voltage when available.

Do not assume `abs(Ewe - Ece)`; sign is scientifically meaningful.

### Measured vs derived metadata

Record:

```text
voltage_v role = cell
voltage_v origin = measured | derived_working_minus_counter
working_potential role = working_vs_reference
counter_potential role = counter_vs_reference
```

### Reference electrode

If EC-Lab settings explicitly store reference electrode text, preserve it.

Do not infer `Li/Li+` merely because the cell is a Li-ion battery or the official application note uses lithium.

### Positive/negative labels

Backend canonical roles stay working/counter.

If source settings independently establish which side is battery positive/negative, metadata may expose those roles. Otherwise the frontend should say Working/Counter, not Positive/Negative.

## Two-electrode GCPL behavior

Do not require auxiliary potential columns for normal supported two-electrode GCPL.

For a two-electrode file:

```text
voltage_v = verified source primary cell/working voltage
working_potential_v/counter_potential_v absent unless genuinely measured
```

Capability metadata drives the UI.

## Implementation record

Implemented on the shared `feature/biologic-mpr-gcpl-support` branch after the review-clean 041.2
checkpoint. The implementation is pending the focused Sol review loop for this child.

- Verified settings contract: VMP Set version `10/0`, technique discriminator `0x77`, parameter
  header at `0x1847`, `33` parameters, `108` bytes per sequence. The decoder preserves raw sequence
  fields and normalizes current/capacity units; it also records active mass, electrode area,
  material/electrolyte text, reference text, battery capacity, characteristic mass, and other
  explicitly bounded cell facts. Unrecognized technique/version/count/item-size layouts fail closed.
- Verified LOG contract: VMP LOG version `10/0`, channel at `0x0009`, channel serial at `0x00AB`,
  OLE start at `0x0249`, and bounded filename/host/address/software/device strings. The OLE value is
  interpreted as a naive local wall-clock timestamp; missing/unreliable values yield
  `absolute_timestamps=false` and canonical `NaT` timestamps.
- Protocol mapping uses the shared `backend.app.services.protocol` schema. CC-until-cutoff and CCCV
  hold are distinct; zero-current `tM` without an `EM` target is normalized as Rest for the verified
  GCPL6 layout; time/current/capacity/voltage limits, rest settings, and valid loops are exposed
  without fabricating Neware condition expressions. `semantic_conditions_available=false` is explicit.
- Three-electrode mapping publishes Ewe as `working_potential_v`, Ece as
  `counter_potential_v`, and signed `voltage_v = working - counter`, with
  `voltage_v_origin=derived_working_minus_counter`. A bounded Ece-absent layout treats Ewe as the
  measured two-electrode primary voltage and publishes no fake auxiliary columns. Explicit reference
  text is preserved only when present; the supplied sample stores `(unspecified)`.
- Review fixes keep only the exact full column layout or exact Ece-omitted layout, apply the verified
  zero-based `Ns` to one-based `step_index` (`+1`) and raw `goto Ns` mapping, validate observed `Ns`
  values against declared settings before full mapping, reject unknown unit/reference/sign codes,
  preserve active zero/negative voltage limits, normalize the raw zero-based LOG channel to the
  one-based display value while retaining the raw index, and keep unresolved C-rate directions as
  explicit Control steps without adapter-only protocol substeps. The declared protocol is persisted
  under the format-neutral protocol metadata key so continuation, rate-capability, chargeability, and
  analysis consumers reconstruct the same adapter-built protocol.
- `BIOLOGIC_GCPL_ADAPTER_REVISION` advanced from `gcpl1` to `gcpl2` because raw voltage-role and
  timestamp columns/metadata changed. No migration or `CALC_VERSION` change was made.
- Focused verification before review: `python -m compileall -q backend tests`; 186 focused tests
  passed across the MPR reader, GCPL mapper/metadata, protocol, parser dispatch/identity, and
  canonical contract; `git diff --check` passed.
- Private sample probe (not committed): header/module metadata succeeds; low-level full parse returns
  `5,483` rows and the exact three modules/column IDs recorded above; header metadata reports
  `2026-07-10T14:41:20.744000`, normalized channel `16` (raw zero-based index `15`), EC-Lab `11.60`, active mass about `1.0 mg`, area about
  `1.54 cm2`, no explicit reference text, three protocol sequences, a `0.2 V` discharge cutoff,
  `900 s` post-discharge rest, and a `3,600 s` final rest. The real canonical mapper remains
  fail-closed because the private constant-zero half-cycle does not establish an independent cycle
  identity; this is not an MPT parity claim.
- Header-only timing evidence: on the private sample, `read_mpr_header()` took `0.000488 s` versus
  `0.000924 s` for full record decode. On a generated `500,000`-row verified-layout file, the same
  paths took `0.021701 s` versus `0.077942 s`; the header path constructed no record array. No MPT
  file was available, so no MPT parity result is claimed.
