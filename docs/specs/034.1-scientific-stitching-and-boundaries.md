# 034.1 — Scientific stitching and source boundaries

**Status:** Implemented — awaiting review commit
**Parent:** [034 — Multi-source cell continuations](034-multi-source-cell-continuations.md)
**Scope:** Backend scientific primitive only; no import or UI workflow.

Read the parent first. Its virtual-merge, dense-observed-cycle, no-boundary-splice, and elapsed-time
decisions are locked.

## Current behavior and hazards

- `backend/app/services/stitch.py::stitch_cycles` loads per-cycle caches in supplied order and
  rewrites cycle numbers.
- `backend/app/services/analysis_engine.py::_stitch_raw` duplicates the same algorithm for raw
  caches.
- Both advance their offset with `last - first + 1`. A source containing observed local cycles
  `[1, 2, 4]` reserves an invented global cycle for missing local cycle `3`.
- Both overwrite `cycle` before preserving its source-local value.
- Segment dictionaries expose only hash, segment, global start, and global end.
- Missing cache handling skips a source and then permits later sources to slide earlier, which can
  make a partial result look continuous.

## Required implementation

### 1. One canonical stitch policy

Refactor `backend/app/services/stitch.py` so cycle and raw stitching share one cycle-mapping helper.
`analysis_engine._stitch_raw` must call the shared service or be removed. There must be one
implementation of:

1. determine observed local cycle labels in stable numeric order;
2. assign each observed label exactly one dense global cycle;
3. retain source-local cycle as `source_cycle`;
4. retain zero-based ordered source `segment`;
5. retain `source_hash`;
6. return segment metadata.

Do not infer or insert missing local labels. Reject/diagnose non-numeric cycle values rather than
silently coercing them into a different order.

### 2. Segment contract

For every non-empty source, return:

```python
{
    "file_hash": str,
    "segment": int,                 # supplied source position, zero based
    "source_cycle_start": int,
    "source_cycle_end": int,
    "source_cycle_count": int,      # count of distinct observed labels
    "cycle_start": int,             # first dense global cycle
    "cycle_end": int,               # last dense global cycle
    "incomplete_boundary_unknown": True,
}
```

The last field deliberately says that no scientific completion/splice inference was made. Do not
label a cycle incomplete solely because it is at a file boundary.

### 3. Missing sources fail closed

The stitch result may still return `missing`, but a missing source before a later available source
must not produce a seemingly valid compact continuation. Consumers must be able to distinguish:

- no data;
- a complete ordered stitch;
- an incomplete stitch with missing source positions.

Add enough result metadata for consumers to refuse scientific output when any ordered source cache
is missing. Do not silently concatenate around a hole.

### 4. Stable row ordering

- Per-cycle rows: order by segment and source-local cycle mapping.
- Raw rows within a source/local cycle: retain current source record order; use `record_index` when
  available and stable input order otherwise.
- Never sort raw rows globally by timestamp because restarted files can contain clock anomalies.

### 5. Cache version decision

This changes the meaning of stitched results for non-contiguous local labels and adds provenance
columns. Bump `CALC_VERSION` in `backend/app/config.py` if any persisted derived result/cache key can
otherwise reuse pre-change semantics. Record the exact reasoning in the implementation record and
update durable scientific knowledge if the mapping contract is not already documented.

## Required tests

Use synthetic pandas frames and patched cache loads; do not use or commit the private example files.

- Two sources with local cycles `1,2,3` and `1,2` map to global `1…5`.
- Local cycles `7,8,10` map to three global cycles, not four.
- The second source starts at global previous-count + 1 even when its first label is `0`, `1`, or
  another positive integer.
- `source_cycle`, `cycle`, `segment`, and `source_hash` are correct in both cycle and raw output.
- An incomplete final raw cycle remains a separate global cycle.
- A missing middle source is reported with its original position and cannot appear as a complete
  stitch.
- Cycle and raw stitching use the same mapping rules.
- Empty sources and entirely empty input have explicit, stable results.

## Acceptance

- There is one grep-able cycle-mapping implementation.
- Every observed local cycle maps once; no synthetic cycle is created.
- No boundary rows are merged or deleted.
- Provenance survives at row and segment level.
- Missing cache positions cannot masquerade as a valid continuous result.
- Existing single-source output retains the same displayed global cycle numbers for normal
  contiguous files.

### Files and behavior changed

- `backend/app/services/stitch.py` — Replaced max−min offset logic with one canonical path
  (`observed_local_cycles`, `build_dense_cycle_map`, `_stitch_ordered`) shared by
  `stitch_cycles` and new `stitch_raw`. Stitched frames add `source_cycle`, `segment`, and
  `source_hash`. Segment dicts follow the locked contract including
  `incomplete_boundary_unknown: true`. Missing or invalid-cycle sources set
  `frame.attrs["stitch_complete"]`, `missing_positions`, and `skipped_segments`; continuation
  mapping stops after the first gap so later caches are not compacted across a hole.
  `stitch_metadata(frame)` exposes completeness metadata.
- `backend/app/services/analysis_engine.py` — Removed duplicate `_stitch_raw`; all raw stitching
  calls `stitch.stitch_raw`.
- `backend/app/config.py` — `CALC_VERSION` `1.6.0` → `1.6.1`.
- `tests/test_stitch.py` — New focused synthetic/patched-cache suite covering dense mapping, gaps,
  missing middle sources, raw/cycle parity, empty inputs, and non-numeric rejection.
- `tests/test_analysis_engine.py` — Multi-source dense-stitch integration test; asserts
  `_stitch_raw` removed.

- `tests/fixtures/golden_analysis/expected/{steps_baseline,dcir_baseline,chargeability_baseline,rate_capability_baseline}.json` — `calc_version` only (`1.6.1`).

### Decisions

- **CALC_VERSION bump to 1.6.1:** Per-file per-cycle parquet derivation is unchanged, but global
  cycle numbers in analysis output and stitched provenance columns differ for non-contiguous local
  labels and multi-source chains. Bumping invalidates analysis provenance keyed on `calc_version`
  so cached results cannot silently reuse pre-034.1 global numbering. Single-source contiguous
  files keep identical displayed global cycles and golden scientific series.
- **Completeness via `DataFrame.attrs`:** Keeps the existing three-tuple return shape for
  `library.py` / `replicates.py` callers while exposing fail-closed metadata to future consumers
  (034.7+).
- **Gap handling:** After the first missing/invalid source, later available caches are listed in
  `skipped_segments` and excluded from the stitched frame rather than remapped as a continuation.
