# Spec 055.1 — Export without dirtying plot state

> Implementation branch base: `main` at `3714d3733c38a0a5ea1174b4b91f49df356e64ac` (2026-08-31), after Spec 054 closure.
> Branch: `feature/plot-workflow-polish`.
> Re-verify anchors against the live implementation branch before coding.

## Parent

`055-plot-workflow-polish.md`

## Goal

Downloading/exporting a plot image must not make an otherwise unchanged saved plot appear edited.

Observed failure to eliminate:

> Open a saved plot → `Update` is disabled → download PNG → `Update` becomes enabled even though no plot configuration was changed.

## Locked decisions

- Export is side-effect-free with respect to persistent analysis/saved-plot state.
- Export-only layout sizing, DPI/PPI, temporary trace conversion, and Plotly image-generation mutations must not enter the saved plot's persisted signature.
- `Update` is enabled only after an intentional persistent change to the active saved plot.
- Fix the state boundary/root cause; do not special-case "set dirty false after PNG".
- The invariant applies to all image formats and plot families that use the shared export path, even if PNG is the currently observed reproduction.
- Export preference changes that are intentionally stored in the saved plot style remain persistent edits **only if the current product already treats those preferences as part of the saved plot**. The act of producing a file is never an edit.
- Do not weaken real dirty detection.

## Current implementation and anchors

`frontend/src/features/analyses/editor/AnalysisEditor.tsx` computes dirty state approximately as:

- find the active saved plot;
- retain a baseline signature;
- compare `snapshotSignature(spec)` with that baseline;
- derive `activePlotDirty`;
- enable the saved-plot `Update` action only when the plot is actually dirty.

That model should remain authoritative.

Shared export code is under:

- `frontend/src/features/analyses/editor/plotting/plotExport.ts`

Family plot cards call export helpers. For example:

- `frontend/src/features/analyses/editor/families/cycles/CyclePlotCard.tsx`
  - `resolveExportPlan(...)`
  - `exportFigure(...)`
  - Plotly `toImage(...)`
  - `pngWithPpi(...)`
  - `downloadBlob(...)`

Other plot-family cards must be audited for equivalent paths.

`frontend/src/components/Plot.tsx` wraps Plotly and forwards `onInitialized`, `onUpdate`, and `onPurge`, so image/export operations must not accidentally feed a rendered/export-only layout mutation back into persistent spec state.

## Required investigation

Before patching, reproduce the bug and identify which persistent field/signature changes after PNG download.

Capture, at minimum:

- active saved-plot baseline signature before export;
- current `snapshotSignature(spec)` before export;
- current signature after export;
- the exact changed field(s).

The implementation/review note should state the root cause. Do not commit diagnostic logging unless it is useful permanent instrumentation.

Likely areas to inspect include:

- export aspect ratio/dimensions;
- plot style export fields;
- Plotly relayout/update callbacks;
- legend position;
- axis ranges/zoom memory;
- export-specific trace visibility;
- temporary sizing of graph divs;
- PPI/format fields;
- any callback that writes rendered layout back through `update(...)`.

Do not assume the root cause from this list.

## Target behavior

### Saved plot, unchanged

Given:

- a saved plot is open;
- `activePlotDirty === false`;
- `Update` is disabled;

when the user exports PNG/SVG/PDF or generates an export preview:

- the saved plot's persistent spec remains byte/signature-equivalent for dirty-state purposes;
- `activePlotDirty` remains false;
- `Update` remains disabled;
- no leave prompt appears solely because an export occurred.

### Saved plot, already edited

If the plot was already dirty before export:

- export does not clear the real dirty state;
- `Update` remains enabled.

### Draft/new plot

Exporting a draft/new plot:

- must not falsely mark unrelated persistent state as changed;
- must not convert the draft into a saved plot;
- must not interfere with draft save/discard prompts.

### Export preferences

If the user changes a persistent export-related control before downloading and that control is intentionally part of saved plot style:

- that control change may make the plot dirty;
- the subsequent download must not add any additional mutation.

This distinction should have focused test coverage.

## Implementation requirements

### 1. Separate export figure from live/persistent objects

Export helpers must operate on cloned/derived data structures where Plotly may mutate input figure objects.

Do not pass mutable references that are also used as the persisted plot spec or live layout state into APIs known to mutate them.

### 2. Keep transient render state transient

Zoom/axis range memory, export dimensions, or Plotly-calculated layout values must remain in local refs/state unless explicitly supported as persisted plot settings.

### 3. Do not patch dirty state after the fact

Forbidden pattern:

```ts
downloadPng();
setActivePlotBaselineSignature(snapshotSignature(spec));
```

or equivalent.

That would hide legitimate edits that existed before export.

## Tests

Add a focused regression test around the actual root cause.

At minimum test:

1. open/construct a saved plot baseline;
2. verify dirty is false;
3. run the export action/helper;
4. verify the dirty-signature inputs are unchanged;
5. verify dirty remains false.

Also test:

- already-dirty remains dirty after export;
- export helper does not mutate its source `layout`, `traces`, or style object if that is where the bug lives;
- all relevant formats share the side-effect-free path.

Prefer pure helper tests where possible rather than an oversized `AnalysisEditor` integration test.

## Manual checks

For at least:

- Cycles;
- Time/capacity;
- one additional family using shared plot export;

perform:

1. open a saved plot;
2. confirm `Update` disabled;
3. download PNG;
4. confirm `Update` still disabled;
5. repeat with SVG/PDF where available;
6. make one real plot edit;
7. confirm `Update` enables;
8. export;
9. confirm `Update` stays enabled;
10. discard/reopen and verify saved state unchanged.

## Acceptance criteria

- PNG export no longer enables `Update` on an unchanged saved plot.
- Other shared image export formats do not dirty the plot either.
- Exporting cannot clear a pre-existing real dirty state.
- Root cause is documented in implementation/review notes.
- No dirty-state reset workaround is used.
- Draft and leave-prompt behavior is unchanged.
- Focused tests pass.
- Canonical frontend/full preflight passes.

## Out of scope

- changing export visual quality;
- changing default PPI;
- renaming exports;
- saved-plot naming UI;
- legend interaction changes.
